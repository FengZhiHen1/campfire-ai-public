# verification 脚本索引

> 这些脚本产出 `DELIVERY.md` / `ACCEPTANCE.md` 里引用的每一个数字。
> **放在这里(而不是 `.tmp/`)** 是因为文档把它们列为「可复跑门禁」——
> 放在临时目录会让人以为它们不存在(独立终检就因此判定 4 个脚本缺失,见下)。
>
> 运行目录:**仓库根** `E:\Project\Web_Development\Campfire-AI`
> ```bash
> uv run python marketing/promo-shotcraft/verify/<name>.py
> ```
> 大多数脚本把结果写到 `.tmp/<name>.txt`(终端是 GBK,中文直印会乱码)。

## 门禁类(应当全绿)

| 脚本 | 验证什么 | 通过判据 |
|---|---|---|
| `doc-consistency.py` | 交付文档里的指纹/时长/**实测冻结段数**与工作区实际值一致;并逐文件 sha256 比对「成片对应当前源码」。成片名取自清单的 `film` 字段,不再写死 | 0 处不一致 |
| `audit-fixtures.py` | fixture 每条字符串 vs 数据库逐字比对 | 0 问题 |
| `classname-parity.py` | 影片复刻组件用的类名在产品 CSS 里都存在 | 无「无处定义」类名 |
| `goal-checklist.py` | 目标规格逐条(几何契约/九段/八题/两版) | 全部 ✓ |
| `render-manifest.py` | 生成/刷新 `render-manifest.json`(成片 ↔ 源码内容哈希)。成片名不再写死,取 `out/` 下最新 `promo-v<N>.mp4` | — |
| `source-delta.py` | **重渲是否只改了该改的**:文件宇宙取自清单(含 apps/web/audio/css),基线 = 两份清单的**内容哈希**比对 | 漂移 0 且非预期改动 0;**无基线即 exit 1**(不再假通过) |

> ★ **2026-10-07 用户裁决:运动量不设门。** `motion-gate.py` 已**退休为诊断工具**
> (声明侧 = `src/events.json`),**不再以非零退出码表示「不合格」**。
> 它现在的用途是:需要知道「**哪一段没有事件**」时,给出可定位的帧号。
>
> `doc-consistency.py` 里那条「实测冻结段数与文档一致」**保留** —— 它查的是
> 「**文档写的数字与实测是否一致**」,属于文档准确性,与「拿运动量判画面好坏」是两件事。

## ⚠ 已知的方法论陷阱(写在脚本注释里,也在此汇总)

1. **口径对、取样错** —— `edge-margin.py` 只抽 6 帧,漏掉了 `pushCamera` 的 `ty`
   摆动极值(真实最小 11px vs 抽样得到的 17px)。**结论偏乐观且看起来完全合理。**
   修法:关键量要么全扫描,要么先算清极值出现在哪。
2. **只读输出的最后一行** —— PSNR 曾因此写成「全部 inf」(实际仅约 3300–3700/5250)。
   修法:逐帧计数,不读末行。
3. **抽样撞上周期** —— S1 光标每 2 帧闪,我抽的三帧恰好同相位,得出「三帧逐字节相同」。
   修法:相邻帧逐个比,不跳着抽。
4. **换了度量口径才看得见** —— 空帧在帧差口径下表现为「静止」(不是缺陷),
   只有标准差口径才暴露「整屏单色」。**「我已全片扫过」必须说明用什么口径扫的。**
5. **度量的分辨率不够,却拿它下强结论** —— 用**成片 mp4** 逐帧比来判断
   「重渲是否只改了该改的地方」。实测噪声底:同源双渲 S5,mp4 就有
   329/1200 帧差异(平均 0.044、最大 0.082),而**同样帧的无损 PNG 逐字节相同**。
   于是这个判据:
     · **误报** —— S5 的纯编码噪声被当成改动;
     · **漏报** —— S4 逐字落位修正(0.028–0.069)落在噪声带里,根本看不见。
   修法:这类判断回到**源码层**(`source-delta.py`),或对**无损 PNG** 逐帧比。
   附带更正:文档说「确定性」时必须限定在 PNG 层,mp4 **不是位确定的**。
6. **零结果当成好结果** —— `motion-fresh.py` 第一版漏了 `metadata=print` 的
   `:file=-`,一个 YAVG 都没采到,却静默输出「静止率 0.0%」(看起来像完美)。
   修法:脚本在采不到数据时**报错**,不返回 0。
8. **判据的「灵敏度」没校准** —— 「空帧」一条我在四个口径下得到 0 / 151 / 21 / 0 帧。
   `std<0.5` **太弱**:纸面自带暗角,8 处段边界末帧(主体全部淡出、只剩纯纸面)
   被测成「不是空帧」;`深色像素<20` **太强**:暖灰文字(150–190 灰)在米底上
   清晰可见却不算深色,误报 151 帧。**两个都不是「错」,是分辨率不对。**
   修法:关键判据要做**灵敏度对照**(同一对象、多个阈值/口径),并报出口径。
   见 `blank-verdict.py` / `content-check.py` / `contact-sheet.py`。
10. **门禁自己会「永远成功」** —— `bezel-scan.py` 默认指向一个已删除的文件,
    输出「最小边距 **9999px**」并 **exit 0**;`s5-recheck.py` 还漏了 `:file=-`,
    输出「静止率 **0.0%**」并 exit 0。**它们看起来在检查,实际永远通过。**
    修法:① 默认参数必须指向真实存在的文件;② **采不到数据 = 失败**,不是 0;
    ③ 发现不一致要**非零退出**。
11. **清单会「看不见」一半代码** —— `render-manifest.json` 曾只 glob `src/**`,
    于是 37 个条目全是 `src/`,而 `src/` 从 `apps/web` import 17 处。
    复核者消融证实:改产品 `labels.ts` 的可见文案 → **画面变了**,门禁**全绿**。
    修法:清单必须从**入口的 import 闭包推导**(`render-manifest.py`),
    并加自检「apps/web 条目为 0 就报错」。
12. **清理旧文件会让「对照脚本」开始说谎** —— `seam-before-after.py` 的对照成片
    被删后,ffmpeg 读不到数据,脚本把每格记成 0 ⇒ 输出「修前全为 0 → 修后 8/8 提升」
    (真实是 7/8)。**「读不到」被当成了「那时什么都没有」。**
    修法:对照文件缺失即报错退出(`ab-diff.py` / `s5-why.py` / `seam-fix-evidence.py`
    也加了同样的守卫)。
13. **判据的「稳定域」没检验** —— 空帧口径 ②③ 在不同分析尺度下是
    146/112/101/90 与 14/5/2/1(①④ 恒为 0)。我和复核者因此对不上数。
    **不是谁算错了,是这个量本身不稳定。**
    修法:关键判据要做受控敏感度扫描(`blank-sensitivity.py`),
    只引用跨尺度可复现的量;报数时**必须带尺度与阈值**。
9. **只在「分段逐项」的框架里检查** —— 前四轮审查(含三位独立 subagent)都没发现
   「段边界末帧全空」,因为他们的检查项都是分段的(某段的滚动/边距/构图),
   而该缺陷只在**跨段接缝**上出现。修法:除了逐项核查,还要有**整体通看**
   (`contact-sheet.py`:每 2s 一帧拼成一张,一次看完)。
   **换个看的方式,比多看几遍同一个方式更有用。**
7. **把投影当实体** —— 上一轮有人用「偏离底色 > 6」当墨迹判据,把设备的**投影**
   (阴影铺到画布底)当成内容,测出假的「下间隙 0px」。判据要用**深色 bezel**
   这类有明确语义的特征。
14. **度量的分辨率不够,会把「事件」看成「静止」** —— 删掉相机周期漂移后,画面靠的是
    **逐字落位的单帧事件**(一帧多几个汉字)。`scale=320:180` 再取帧差会把这点变化
    缩放平均掉,于是 `motion-fresh.py` 把 v17 的 S5 报成**连续静止 23.70s**、
    全片静止率 **77.1%**;而**全分辨率**下同一段每约 20 帧就有一次 ≥0.37 的事件。
    ⚠ 同一次排查里还有**两层**坑:① 只看 `YAVG`(全帧平均)会把细线/小字事件判成
    「不可见」——实测 30/140 个事件被误判,加 `YMAX`(局部对比)后降到 1;
    ② 换成 `freezedetect` 才问对了问题(有没有「什么都没发生」的死段),
    它独立于声明、且在两种分辨率下结论一致。
    修法:**报任何静止率/运动量都必须带分辨率与口径**;跨版本比较静止率基本无效。
    见 `motion-gate.py`(口径与标定过程写在文件头)。
15. **终端是 GBK,非 GBK 字符会让门禁直接崩** —— `⚠`(U+26A0)、`✓`(U+2713)、
    `⇒`(U+21D2) **无法用 GBK 编码**;把它们 `print` 到 stdout 会抛
    `UnicodeEncodeError` 并以非零码退出 —— 看起来像「门禁发现了一个问题」,
    实际是**编码崩了**(而 stderr 的 SystemExit 会把它们降级成 `\u26a0`,更难辨认)。
    修法:写 UTF-8 文件再读;stdout/stderr 只用 ASCII 或确认在 GBK 内的字符(`★` 可以)。
    批量自查:`ast` 解析脚本、收集所有字符串常量、逐个试 `encode("gbk")`。
16. **守卫的判据取自「失败时才出现的信号」⇒ 守卫方向反了** —— 我给新门禁的
    `freezedetect` 步骤写了「日志里没有 `freezedetect` 字样 = 过滤器没跑起来 ⇒ 报错」。
    实测(`promo-v17.mp4`):`d=2s` 有冻结 → 日志 61 行、**含**该字样、5 次 `freeze_duration`;
    `d=999s` 无冻结 → 日志 46 行、**不含**该字样、0 次。⇒ 该字样**只在检出冻结时才出现**,
    于是「画面干净、零冻结」这个**好结果**恰好触发报错,检查**永远不可能通过**。
    **一个永远失败的检查,和永远成功的一样没用** —— 这是「永不失败」的镜像,
    同样是 AGENTS.md 禁止的东西(独立复核抓出,我复验确认)。
    修法:守卫要用**进程返回码**这类与业务结果无关的信号,不要用业务日志里的字样。
    同一处 `doc-consistency.py` 也犯了,一并改。
