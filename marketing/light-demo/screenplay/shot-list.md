## 录制技术要点(给 Playwright 阶段)

- viewport 390×844,`deviceScaleFactor: 3`(素材 1170×2532,保证 zoom 1.2 后字仍清晰);
- 每个子场景独立脚本独立录制,不强求一次录完;
- ③-c/④-c 涉及模型生成内容,每场景至少录 3 条备选,剪辑时择优;
- 不可控等待段用变速压进旁白窗口,结果段 Hold;
  **但变速后结果出现前必须保留 ≥2s 可感知等待**——不能在视觉上暗示「秒出」
  (与旁白脚本合规红线同时引入,2026-10-06)。

## 走查记录(2026-10-06,本地真实栈)

已用真实浏览器(demo-parent 账号)逐镜头核对,结论:

| 镜头 | 走查结果 | 判定 |
|---|---|---|
| ③-a 首页应急入口 | 「现在需要帮助」卡片居首 | ✅ |
| ③-b 八项采集 | 逐题制、进度条、「跳过=未排除,不会当作正常」提示、随时提交 | ✅ 比预期更好 |
| ③-c 追问一键选择 | 勾选卡片快速过题 | ✅ |
| ③-d Action Card | 01-05 编号区块、医疗风险三档、「来源:AI 推断·置信」逐条标注、未采集项诚实标注、过程链(查阅资料/案例)可展开 | ✅ 素材超出预期 |
| ④-a 待确认条目 | 「待确认(1)」独立分组、「AI 归纳」来源可见、与已确认条目可辨 | ✅ 种子数据已就位 |
| ④-b 纠正闭环 | 条目带「纠正/删除/确认」操作,纠正后旧条目转 historical、新条目带 supersedes 链 | ✅ 已实测 |
| ⑤ 案例库 | 4 案例入库(1 虚构样例 + 3 真实访谈),「虚构样例」与真实案例同屏可辨 | ✅ AC-06 达成 |

**关键拍摄情报**:
1. 应急分析实测 70-100 秒(模型多轮调用)——视频不能实时等待,等待段必须变速/跳切;也再次确认不能声称时延数字(AC-13);
2. Action Card 的「来源+置信」标注与「未采集=未排除」诚实标注是产品最强的视觉化价值观,③-d 镜头从「点开来源条目」改为「特写来源标注行」(UI 中直接可见);
3. 会话列表摘要含「本次未使用个性化档案」标注,可作 ④ 段过场;
4. Vite 代理对 GET 有数秒延迟——Playwright 录制必须等页面自然加载完成,不能依赖快速轮询。
