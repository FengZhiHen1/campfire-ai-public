## 一、功能模块需求

### M1 智能应急咨询（P0，核心模块）

| 需求项 | 说明 |
|---|---|
| **应急问答** | 照护者点选行为桶（可附文字描述），系统按「时刻分层」提供支持：危机当下秒级获得安全卡，稍后获得 RAG 驱动的结构化完整方案（[ADR-009](../技术设计/决策/ADR-009-应急链路时刻分层重构.md)） |
| **输出结构** | 时刻分层：此刻安全层（专家审核安全卡：桶 × 危机阶段 + 档案槽位填充）→ 完整方案层（四段式：即时安全干预动作 → 情绪安抚话术 → 后续观察指标 → 就医判断标准）；追问轮为自由会话 |
| **案例检索** | 优先匹配「同年龄段 + 同行为桶 + 同情绪等级」的真实干预案例 |
| **个性化增强** | 自动关联当前患者档案，检索时注入历史行为-情绪档案 |
| **来源溯源** | 每条建议必须标注来源案例/专家文章，附带免责声明 |
| **分级兜底** | 按风险差异化兜底：红线命中走高危桶卡 + 就医指引；确定性兜底信号（检索质量不足/用户标记未解决/连续追问未解决）命中时强制提示并支持一键转人工 |
| **红线安全门** | 点选高危桶（自伤/攻击/走失/用药）或输入命中关键词时直接硬拦截（纯规则判定，零 LLM 参与）：输出高危桶卡 + 就医指引，红线会话不进入完整方案层；行为桶兼任案例检索过滤维度 |
| **全龄覆盖** | 行为描述、分级标准与干预建议须考虑成年患者（体型、力量、家庭外场景） |
| **输入形式** | 桶选择 + 阶段 quick-reply + 可选文字补充；语音/图片输入为明确延期项 |
| **平台** | MVP 期 Web（家属 + 志愿者）；终态微信小程序（[ADR-006](../技术设计/决策/ADR-006-平台分工-小程序与Web.md)/[ADR-014](../技术设计/决策/ADR-014-MVP平台收束-暂缓小程序.md)） |

**边界**：不做医疗诊断、治疗方案开具、泛科普；所有建议附「仅供参考，不构成医疗诊断或治疗建议」声明。

机制设计见[智能应急咨询](../技术设计/机制/智能应急咨询.md)、[红线安全门与兜底策略](../技术设计/机制/红线安全门与兜底策略.md)。

### M2 个性化档案库（P0，核心模块）

| 需求项 | 说明 |
|---|---|
| **档案共建** | 家属记录日常行为/情绪事件（结构化 ABC 勾选，危机中一键打点 + 事后补全双模式）；老师/专家补充专业评估与干预记录，不可修改家属内容 |
| **多人档案** | 一个家庭账号下可创建多个患者的独立档案 |
| **全龄覆盖** | 年龄/年龄区间枚举覆盖儿童至成年 |
| **标签体系** | 预设标签 + 限定范围内自定义 |
| **档案驱动 RAG** | 档案数据作为检索过滤条件；危机预案层直接填充应急安全卡槽位（[ADR-010](../技术设计/决策/ADR-010-档案四层结构与事件记录ABC标准化.md)） |
| **关联管理** | 家属主动邀请老师/专家/协作照护者建立关联；家属可随时单方面解除 |
| **隐私控制** | 档案仅家属本人及关联者可见，严格脱敏 |
| **冷启动** | 「简化必填标签 + 后续逐步完善」，允许无档案模式运行 |
| **平台** | MVP 期 Web 全量（家属/协作照护者 + 老师/专家共建）；终态微信小程序（家属/协作照护）+ Web（共建）（[ADR-014](../技术设计/决策/ADR-014-MVP平台收束-暂缓小程序.md)） |

**边界**：家属拥有档案绝对控制权；档案访问严格基于关联关系；档案数据绝不入向量索引。

机制设计见[个性化档案库](../技术设计/机制/个性化档案库/README.md)。

### M3 真实案例库管理（P0，核心模块）

| 需求项 | 说明 |
|---|---|
| **案例录入** | 老师/专家上传真实干预案例（L1 叙事 → LLM 提取 → 专家微调为 L2 卡片） |
| **案例来源** | 专家/老师撰写 + 机构合作脱敏案例，双线并行 |
| **案例审核** | AI 辅助预审 + 专家终审（1-2 个工作日），驳回附修改意见 |
| **应急方案模板** | 从同类案例中提炼共性生成标准化模板，走审核流程（**暂缓**：2026-07 评审决定延后，MVP 不实现） |
| **双写机制** | 元数据入 PostgreSQL，切片入 pgvector 索引 |
| **切片策略** | 「场景-行为-干预-结果」强绑定切片，禁止拆分核心动作与适用前提 |
| **版本迭代** | 保留历史版本，RAG 检索默认使用最新版 |
| **失效下架** | 专家可标记「过时/有误/争议」；管理员可强制下架 |
| **权限分级** | 通用案例向家属开放（模板功能暂缓），个性化案例仅专业人员可见 |
| **平台** | Web（录入/审核） |

**边界**：不做激励机制；不做通用科普知识管理；严格脱敏，机构合作案例需签署脱敏使用协议。

机制设计见[标准案例库](../技术设计/机制/标准案例库/README.md)。

### M4 人工兜底通道（P2，延后实现）

> 应用初期专家资源整合途径不明，优先级较低，待专家合作渠道落实后启动。

| 需求项 | 说明 |
|---|---|
| **触发来源** | 确定性兜底信号（检索质量不足/用户标记未解决/连续追问未解决）、用户主动要求、高风险场景强制转人工 |
| **交互方式** | 异步工单式，同一工单最多 3 轮追问后自动关闭 |
| **紧急分级** | 三级（普通/紧急/特急），特急触发即时通知（短信/电话） |
| **响应时效** | 30 分钟内响应，超时提醒 + 转派；超时未接开放抢单 |
| **专家接单** | 智能分配优先，超时抢单；专家直连接单无需管理员二次审核 |
| **工单内容** | 完整对话上下文 + 档案摘要 + 兜底信号分析 + 检索来源 |
| **状态通知** | 家属可见「待接单 → 处理中 → 已回复」，关键节点推送 |
| **价值沉淀** | 一键脱敏沉淀为案例素材，走案例审核流程 |
| **满意度闭环** | 关闭时家属星级评分 + 确认是否解决 |
| **平台** | MVP 期 Web 全量；终态微信小程序（家属侧发起/查看）+ Web（专家侧接单/回复）（[ADR-014](../技术设计/决策/ADR-014-MVP平台收束-暂缓小程序.md)） |

**边界**：异步工单不做实时聊天；不做固定排班；沉淀必须走审核流程；不做通用客服。

机制设计见[人工兜底通道](../技术设计/机制/人工兜底通道.md)。

### M5 事件趋势复盘（P1，新增模块）

| 需求项 | 说明 |
|---|---|
| **趋势回顾** | 基于档案事件记录（Event Log）生成周期性趋势复盘：行为类型分布、触发因素高频项、干预有效性回顾 |
| **留存定位** | 日常留存引擎——给家属「每周回来看一眼」的理由 |
| **档案联动** | 复盘洞察引导补充档案标签；高频触发因素可在下次咨询中作为提示 |
| **数据来源** | 仅使用本患者档案数据，遵循档案隐私边界，不做跨家庭比较 |
| **平台** | MVP 期 Web；终态微信小程序（[ADR-014](../技术设计/决策/ADR-014-MVP平台收束-暂缓小程序.md)） |

**边界**：不做医学意义上的进展评估或诊断暗示；复盘内容附「基于家庭记录的统计回顾，非专业评估」说明。

**missing evidence**：复盘周期（周/月）、内容深度、是否引入 LLM 生成自然语言总结——延至模块设计阶段确定。

### M6 协作照护（P1，新增模块）

| 需求项 | 说明 |
|---|---|
| **志愿者注册** | 注册时可选「志愿者」角色（区别于家属） |
| **家庭邀请** | 家属主动邀请志愿者成为某患者的「协作照护者」 |
| **协作权限** | 协作照护者对受邀档案**只读** + 可添加事件记录（事件归属标记为志愿者所记） |
| **权限回收** | 家属可随时单方面解除协作关系，访问权限立即回收 |
| **应急同款** | 志愿者的应急咨询、科普查阅体验与家属一致 |
| **平台** | MVP 期 Web；终态微信小程序（[ADR-014](../技术设计/决策/ADR-014-MVP平台收束-暂缓小程序.md)） |

**边界**：协作照护者不可修改家属内容、不可管理标签、不可邀请他人；志愿者不进入案例生产与审核链路；解除关联后不留任何访问入口。

### M7 科普查阅（P2，附带功能）

| 需求项 | 说明 |
|---|---|
| **轻量科普** | 术语解释、干预方法介绍、诊断标准、康复指南，不作主入口 |
| **技术形态** | RAG + SSE 流式输出，无特殊格式约束，清晰说明型自然语言 |
| **案例关联** | 科普回答自动推荐相关真实案例 |
| **应急引导** | 检测到紧急/危机关键词时主动引导至应急咨询模块 |
| **知识来源** | 独立维护的科普知识库，与案例库分离 |
| **平台** | MVP 期 Web；终态微信小程序（[ADR-014](../技术设计/决策/ADR-014-MVP平台收束-暂缓小程序.md)） |

**边界**：不处理紧急应急场景（识别后引导跳转）；不提供医疗诊断或治疗建议。

机制设计见[科普查阅](../技术设计/机制/科普查阅.md)。

## 二、非功能需求

| 维度 | 要求 |
|---|---|
| **响应速度** | 红线安全门命中：**即时响应**（纯规则，无 LLM 依赖）；应急咨询生成：TTFT 设计目标 P50 ≤ 3 秒，不设全流程绝对时长指标——以输出长度预算（契约约束）与流式连续性（相邻 chunk 间隔 P95 ≤ 2s）替代；TTFT P95 > 5s 触发监控告警 |
| **可用性** | 7×24 可用，SLA ≥ 99.5% |
| **准确性** | 基于测试集的应急方案，专业人员认可度 ≥ 85%，零幻觉（严禁编造医疗建议） |
| **安全性** | 案例与档案严格脱敏；手机号仅管理员可见；所有建议带免责声明 |
| **合规性** | 明确标注「AI 建议仅供参考，不构成医疗诊断或治疗建议」 |
| **可扩展性** | 档案标签体系、案例分类体系预留扩展字段 |

## 三、风险与约束

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **案例真实性不足** | RAG 输出缺乏说服力 | 「老师/专家实名认证 + 案例审核」双保险；初期以专家撰写案例为主 |
| **个性化档案冷启动** | 新用户无档案，体验降级 | 允许无档案模式运行（纯案例检索），引导逐步完善 |
| **应急建议误用风险** | 照护者按错误建议操作造成伤害 | 强制免责声明 + 高风险场景自动转人工 + 「请在专业人员指导下使用」标注 |
| **算力与成本** | 全天候运行 + 向量检索成本 | 轻量模型（DeepSeek 等）+ 容器化自部署组件，控制 Token 消耗 |
| **隐私泄露** | 案例与档案涉及敏感家庭信息 | 上传时自动 PII 检测与脱敏；档案访问严格基于 RBAC；协作照护权限即时回收 |
| **志愿者误用** | 非专业者接触敏感档案 | 协作照护仅家属主动邀请、只读 + 限权记录、随时可单方面解除 |

## 四、验收条件

### 4.1 场景化验收（可观察结果）

| ID | 场景 | 成立标准 |
|---|---|---|
| **AC-1** | 危机应急 | 监护人在小程序打开应急咨询，秒级看到通用安全卡；点选行为桶后出桶专属安全卡（含档案槽位填充），回答阶段单点问题后卡片按阶段替换；完整方案随后流式输出四段式内容，附来源案例与免责声明 |
| **AC-2** | 高危拦截 | 点选自伤/攻击/走失/用药桶或输入命中高危词时，系统直接命中红线：输出高危桶卡 + 就医/紧急求助指引（走失桶出报警话术模板），标红置顶，不进入完整方案层，红线事件落库；M4 落地后追加：自动生成特急工单 |
| **AC-3** | 档案个性化 | 同一输入在有/无档案两种状态下，检索过滤条件不同（可用测试档案验证标签注入生效） |
| **AC-4** | 趋势复盘 | 档案事件记录达到最低条数的用户，能在小程序查看周期性趋势复盘，内容仅含本患者数据 |
| **AC-5** | 协作照护闭环 | 家属邀请志愿者 → 志愿者可查看该档案（只读）并添加事件记录 → 家属解除关联 → 志愿者立即失去访问 |
| **AC-6** | 案例入库闭环 | 老师在 Web 提交案例 → AI 预审 + 专家终审通过 → 异步索引完成 → 相似咨询可检索命中该案例 |
| **AC-7** | 工单闭环 | 确定性兜底信号命中或主动转人工 → 工单生成 → 专家在 Web 接单回复 → 家属在小程序看到状态流转并评分 |
| **AC-8** | 应急引导 | 科普查阅中输入危机关键词，系统主动引导跳转应急咨询 |

### 4.2 非功能验收

| 指标 | 验收方式 |
|---|---|
| 红线命中即时响应；TTFT P50 ≤ 3s（设计目标）、P95 ≤ 5s（告警线）；流式 chunk 间隔 P95 ≤ 2s；四段式输出长度符合契约预算 | 应急咨询链路压测与线上监控（P50/P95）；红线即时性由架构保证（无 LLM 依赖），不作统计验收 |
| SLA ≥ 99.5% | 监控告警与可用性报表 |
| 专业认可度 ≥ 85%、零幻觉 | 测试集评估 + 专家抽检（测试集构成为 missing evidence） |
| 隐私与脱敏 | PII 检测用例 + RBAC 权限矩阵测试（含协作照护越权用例） |

## 五、明确延期项

| 事项 | 延期原因 | 重访条件 |
|---|---|---|
| 语音/图片输入 | 文字链路未稳定前不增加输入通道复杂度 | 应急咨询文字链路验收通过后 |
| UGC 家属互助社区 | UGC 审核与错误建议传播的合规风险未解决 | 有明确的内容审核机制与运营人力后 |
| 微信登录（wx.login） | 现有账号体系可用 | 微信开放平台认证完成后 |
| 复盘 LLM 自然语言总结 | 形态未定（见 M5 missing evidence） | 模块设计阶段 |
