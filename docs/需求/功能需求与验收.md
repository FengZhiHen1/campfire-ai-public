# 功能需求与验收

> **本文唯一拥有**：各功能模块的需求项与优先级、非功能需求指标、风险与缓解约束。
> **来源**：[references/需求分析.md](../references/需求分析.md) §3-5，以及各模块设计对话中用户已确认的结论（原稿见 [references/原始设计意图/](../references/原始设计意图/)）。
> 机制与实现细节由[技术设计/机制](../技术设计/机制/README.md)拥有，本文不复制其字段、规则与状态机定义。

## 一、功能模块需求

### 1.1 智能应急咨询（P0，核心模块）

| 需求项 | 说明 |
|---|---|
| **应急问答** | 家属输入患者当前行为/情绪表现，RAG 基于案例库生成结构化应急方案 |
| **输出结构** | 四段式：即时安全干预动作 → 情绪安抚话术 → 后续观察指标 → 就医判断标准（用户确认） |
| **案例检索** | 优先匹配「同年龄段 + 同行为类型 + 同情绪等级」的真实干预案例 |
| **个性化增强** | 自动关联当前患者档案，检索时注入历史行为-情绪档案，生成「专属版」建议 |
| **来源溯源** | 每条建议必须标注来源案例/专家文章，附带免责声明 |
| **分级兜底** | 按风险等级实施差异化兜底策略（非单一一键转人工）；置信度低于阈值或涉及高风险（用药/自伤）时，强制提示「建议立即联系专家/就医」并支持一键转人工 |
| **危机分级** | 采用「行为类型 × 情绪等级」的细粒度组合划分（用户确认） |
| **输入形式** | MVP 阶段文字输入为主，语音+图片为后续拓展 |

**边界**：不做医疗诊断、治疗方案开具、泛科普；所有建议附「仅供参考，不构成医疗诊断或治疗建议」声明。

机制设计见[智能应急咨询](../技术设计/机制/智能应急咨询.md)、[危机分级与兜底策略](../技术设计/机制/危机分级与兜底策略.md)。

### 1.2 个性化档案库（P0，核心模块）

| 需求项 | 说明 |
|---|---|
| **档案共建** | 家属记录日常行为/情绪事件；老师/专家补充专业评估与干预记录，**不可修改家属内容**（用户确认） |
| **多人档案** | 支持一个家庭账号下创建多个患者的独立档案（用户确认） |
| **标签体系** | 预设标签（年龄、诊断类型、语言水平、刻板行为类型、情绪触发因素、既往干预反应等）+ 限定范围内自定义（用户确认） |
| **档案驱动 RAG** | 档案数据作为检索过滤条件，提升案例匹配精准度 |
| **关联管理** | 家属主动邀请老师/专家建立关联；家属可随时单方面解除关联、回收访问权限（用户确认） |
| **隐私控制** | 档案仅家属本人及关联老师/专家可见，严格脱敏 |
| **冷启动** | 「简化必填标签 + 后续逐步完善」策略，允许无档案模式运行（纯案例检索）（用户确认） |

**边界**：家属拥有档案绝对控制权；档案访问严格基于关联关系；标签自定义非完全开放。

机制设计见[个性化档案库](../技术设计/机制/个性化档案库.md)。

### 1.3 真实案例库管理（P0，核心模块）

| 需求项 | 说明 |
|---|---|
| **案例录入** | 老师/专家上传真实干预案例（场景描述 → 行为表现 → 干预动作 → 结果反馈 → 适用人群） |
| **案例来源** | 专家/老师撰写 + 机构合作脱敏案例，双线并行（用户确认） |
| **案例审核** | AI 辅助预审（格式完整性、PII 脱敏）+ 专家终审（1-2 个工作日），驳回需附修改意见（用户确认） |
| **应急方案模板** | 从同类案例中提炼共性生成标准化模板，走审核流程（用户确认） |
| **双写机制** | 案例元数据入关系型数据库（供人查阅），切片内容入向量索引（供 AI 检索） |
| **切片策略** | 「场景-行为-干预-结果」强绑定切片，禁止拆分核心动作与适用前提 |
| **版本迭代** | 支持版本迭代，保留历史版本，RAG 检索默认使用最新版（用户确认） |
| **失效下架** | 专家可标记「过时/有误/争议」，被标记案例从 RAG 检索排除；管理员可强制下架（用户确认） |
| **权限分级** | 通用案例/模板可向家属开放，个性化案例仅专业人员可见（用户确认） |
| **分级标准** | 平台自行定义简化等级（轻/中/重）（用户确认） |

**边界**：不做激励机制；不做通用科普知识管理；严格脱敏，机构合作案例需签署脱敏使用协议。

机制设计见[标准案例库](../技术设计/机制/标准案例库.md)。

### 1.4 人工兜底通道（P1）

| 需求项 | 说明 |
|---|---|
| **触发来源** | AI 置信度不足、用户主动要求、高风险场景强制转人工、连续追问未解决（用户确认） |
| **交互方式** | 异步留言（工单式：家属提问 → 专家回复 → 可追问），同一工单最多 3 轮追问后自动关闭（用户确认） |
| **紧急分级** | 三级（普通/紧急/特急），特急触发即时通知（短信/电话）（用户确认） |
| **响应时效** | 30 分钟内响应，超时提醒 + 转派；超时未接开放抢单（用户确认） |
| **专家接单** | 混合模式：优先按专业领域/负载/响应速度自动分配，超时未接开放抢单；专家直连接单，无需管理员二次审核（用户确认） |
| **工单内容** | 完整对话上下文 + 患者个性化档案摘要 + AI 置信度分析 + 检索来源（用户确认） |
| **状态通知** | 家属可见「待接单 → 处理中 → 已回复」，关键节点推送通知（用户确认） |
| **价值沉淀** | 工单解决后一键脱敏沉淀为案例素材，走案例审核流程（用户确认） |
| **满意度闭环** | 关闭时家属星级评分 + 确认是否解决，未解决可重新打开或转派（用户确认） |
| **值班机制** | 不设固定值班，特急工单群发所有在线专家，先抢先得（用户确认） |

**边界**：异步工单不做实时聊天；不做固定排班；沉淀必须走审核流程；不做通用客服。

机制设计见[人工兜底通道](../技术设计/机制/人工兜底通道.md)。

### 1.5 科普查阅（P2，附带功能）

| 需求项 | 说明 |
|---|---|
| **轻量科普** | 保留基础科普内容（术语解释、干预方法介绍、诊断标准、康复指南），不作主入口 |
| **技术形态** | RAG 系统 + SSE 流式输出，无特殊格式约束，清晰说明型自然语言（用户确认） |
| **案例关联** | 科普回答自动推荐相关真实案例，从「知道」延伸到「看到怎么做」（用户确认） |
| **应急引导** | 检测到紧急/危机关键词时主动引导至应急咨询模块（用户确认） |
| **知识来源** | 独立维护的科普知识库，与案例库分离、各自独立更新（用户确认） |

**边界**：不处理紧急应急场景（识别后引导跳转）；不提供医疗诊断或治疗建议。

机制设计见[科普查阅](../技术设计/机制/科普查阅.md)。

## 二、非功能需求

| 维度 | 要求 |
|---|---|
| **响应速度** | 应急场景 TTFT（首字延迟）≤ 3 秒，全流程生成 ≤ 10 秒 |
| **可用性** | 7×24 可用，SLA ≥ 99.5% |
| **准确性** | 基于测试集的应急方案，专业人员认可度 ≥ 85%，零幻觉（严禁编造医疗建议） |
| **安全性** | 案例与档案严格脱敏；手机号仅管理员可见；所有建议带免责声明 |
| **合规性** | 明确标注「AI 建议仅供参考，不构成医疗诊断或治疗建议」 |
| **可扩展性** | 档案标签体系、案例分类体系预留扩展字段，适配后续多维度分析 |

## 三、风险与约束

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **案例真实性不足** | RAG 输出缺乏说服力 | 「老师/专家实名认证 + 案例审核」双保险；初期以专家撰写案例为主 |
| **个性化档案冷启动** | 新用户无档案，体验降级 | 允许无档案模式运行（纯案例检索），引导用户逐步完善档案 |
| **应急建议误用风险** | 家属按错误建议操作造成伤害 | 强制免责声明 + 高风险场景自动转人工 + 所有建议标注「请在专业人员指导下使用」 |
| **算力与成本** | 全天候运行 + 向量检索成本 | 轻量模型（DeepSeek 等）+ 容器化自部署组件，控制 Token 消耗 |
| **隐私泄露** | 案例与档案涉及敏感家庭信息 | 上传时自动 PII 检测与脱敏；档案访问严格基于 RBAC |

## 四、验收语义

当前需求基线以**非功能指标**（上表）与**端到端场景可复现性**为验收依据。MVP 阶段的场景化验收标准曾定义于 2026-05-27 的裁剪版落地计划（见[历史/MVP落地计划-裁剪版-2026-05-27.md](../历史/MVP落地计划-裁剪版-2026-05-27.md) §八），该计划基于「无认证匿名用户」约束制定，已被后续实施超越，其中场景描述仍具参考价值但不构成现行验收基线。

**missing evidence**：面向现行系统（含认证、工单、科普）的端到端验收标准尚未成文，需在下个迭代补齐。
