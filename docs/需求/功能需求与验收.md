# 功能需求与验收

> **权威范围**：一期咨询闭环的业务结果、范围与非目标、业务约束与可观察验收语义。
> **状态**：2026-09-29 经用户确认的一期需求基线。不代表已实现、完成专业审阅或效果已验证。
> **编号说明**：本稿编号为本轮新分配，与 `archive/docs-v3设计/` 中的 `RQ-*`、`AC-*` 无语义继承关系；引用归档事实处均以「归档」标注。

## 一、范围与非目标

### 1.1 一期交付：单一咨询闭环

面向**监护人**一侧，核心是咨询。一期只交付手机端 H5。

```text
登录 → 首页 → 应急咨询（最小输入 → 只追问会改变结论的项 → 输出）
            日常咨询（对话）
            案例浏览（单独列出、按需检索）
            档案与记忆的查看 / 纠正 / 删除
```

应急咨询与日常咨询**共用同一套咨询原理**，差异只在触发方式与追加的信息，不是两套机制。

四条贯穿约束：

- **全应用必须登录**，不提供匿名入口、匿名内容页或匿名接口。
- **一期不含档案共用**：支持对象档案只归创建它的登录用户；数据模型为二期共用预留授权判定缝。
- **知识与案例分两库**：专业资料库与案例库，各自标注来源。
- **每次咨询自动累积**通用记忆（带时间演变）与个性化档案（使用者陈述自动入档，系统推断须经确认，事后可纠正）。

### 1.2 一期非目标

- 未登录可访问的任何内容或能力。
- 支持对象档案的多人共用、关系核验、邀请、撤销与争议处理。
- 事项、记录对象、支持计划、受限交接。
- 经专业审阅的对外安全供给、危险内容限制与完整降级形态。
- 情景演练与复盘。
- 面向志愿者、一线老师、专业人员的使用路径。
- 机构内协作：成员管理、以组织名义注册或使用账号，以及机构与支持对象档案之间的任何可见性（一期账号只有个人形态，见 `RQ-ACC-03`）。
- 微信小程序（远期形态，不属于一期）。

## 二、业务概念

| 概念 | 业务含义 |
|---|---|
| 使用者 | 一期为监护人；登录并操作产品的人 |
| 支持对象 | 平台围绕提供支持的具体孤独症人士，是个性化档案的归属主体 |
| 个性化档案 | 关于某个支持对象的、可追溯的事实与认识；一期只有创建者可用 |
| 通用记忆 | 关于**使用者自身**的、在使用与照护中沉淀的时间线经验（本人的偏好、表达方式、常用情境、既往经历），随咨询累积并随时间演变；**归属账号**，不随支持对象分区，一账号多对象时记忆共享（2026-09-29 裁决，见[决策记录](../技术设计/decisions/通用记忆归属为账号.md)） |
| 专业资料库 | 研究、指南与机构材料，每条带出处、适用范围与局限 |
| 案例库 | 实践案例，单独列出、可浏览、按需检索，每条带来源与授权状态 |
| 应急咨询 | 现场情境下的咨询：由入口直接进入，开始前追加已有档案等信息后输出 |
| 日常咨询 | 非现场情境下由对话逐轮推进的咨询 |

## 三、需求

### 3.1 账号与接入

**RQ-ACC-01 全应用登录**
所有能力都在登录后提供。未登录访问任何业务路径一律被拒绝。

**RQ-ACC-02 无档案不阻断咨询**
登录用户即使尚未建立任何支持对象档案，也能使用应急咨询与日常咨询；此时输出须明确说明未使用个性化档案，不得暗示已依据档案个性化。（归档 `RQ-CTX-01`）

**RQ-ACC-03 一期只做个人账号**
一期账号只有个人形态，**不支持以组织名义注册或使用**；组织与机构协作整体推迟到二期。二期的授权缝仍保留——它落在既有的**唯一授权端口**上，不落在账号结构上：一期**不预建**组织表、组织模块或空表，二期机构协作按该端口增加维度接入，认证与账号的形状不变（与[项目结构设计](../项目结构设计.md)第 8 节"一期不预建该模块与空表"一致）。

**RQ-ACC-04 邀请码注册**
一期不开放自由注册：注册须凭有效邀请码，邀请码的发放与撤销由运营者控制。注册入口与校验位于本产品自己的后端，不依赖身份服务是否原生支持邀请码。

**RQ-ACC-05 账号名与密码，不要求邮箱**
一期的账号标识为账号名，**不要求也不验证邮箱**，不提供依赖邮箱的验证与找回流程。因此一期账号没有可主动触达的联系通道，这是已知限制而非默认设计。

**RQ-ACC-06 人工重置与会话撤销**
忘记密码由运营者人工重置；**重置完成后旧会话必须立即失效**。一期不承诺自助找回。运营操作**经本地的应用内 CLI 执行，不提供运营 web 后台，也不暴露成服务端点**；运营者身份即执行该 CLI 所需的服务器访问权，本期不引入应用层运营者身份与审计。

### 3.2 咨询原理（应急与日常共用）

**RQ-CON-01 两种咨询同构**
应急咨询与日常咨询共用同一套咨询原理：选定并激活相应 skill、检索专业资料与案例、结合通用记忆与个性化档案输出。两者的差异只在触发方式（应急由入口直接进入，日常由对话逐轮推进）与追加的信息（应急在开始前追加已有档案等内容），不构成两套机制。**记忆的接入方式**（2026-09-29 定）：应急由应用预注入近期有效记忆（保时延），日常经 `read_memory` 工具按需回看——消费方式不同构，但记忆同属两个入口的上下文来源。

**RQ-CON-02 有据才给可执行建议**
输出中可执行的建议须能追溯到专业资料库或案例库中的具体条目，并说明适用条件与限制。依据不足、资料冲突或超出能力范围时，明确限制能说什么，保留可用的安全内容与真实求助路径，不继续包装确定答案。（归档 `RQ-CTX-05`）

**RQ-CON-03 依据可核对**
重要结论可追溯到资料库或案例库的具体条目，并标明来源、适用范围与局限。资料存在不等于支持结论，案例成功不等于对当前个体有效。（归档 `RQ-CTX-05`）

**RQ-CON-04 目标不等于服从**
当使用者表达的目标是让当事人停止、安静或「别丢脸」时，输出须澄清真实需要（安全、表达、参与方式、交接），不得把该目标直接转成控制当事人行为的建议。（归档 `RQ-CTX-02`）

**RQ-CON-05 不冒充个性化**
未获得档案信息时，不得声称已依据档案提供个性化支持。

**RQ-CON-06 专业判断与可读解释兼顾**
输出须同时给出专业判断和简单易懂的解释：重要结论带依据与适用条件，涉及专业概念时在当次输出内解释到不需要专业背景即可理解。

**RQ-CON-07 个性化信息的注入与标注**
有档案时注入与该情境相关的档案内容。无档案时按 `RQ-ACC-02` 标注。

**RQ-CON-08 显式选择技能**
使用者可在对话中显式选择技能（输入框上方的技能选择器），选择在**下一条消息**生效；未显式选择时由系统按技能描述匹配。应急入口本质上是用卡片构造第一条消息并激活对应技能，不是另一套机制。

### 3.3 应急咨询

**RQ-EMG-01 入口与最小输入**
首页提供明确入口；进入后以最小输入开始，不得要求长表或完整档案。**现场采集八项**（2026-09-29 定，依据外部调研的应急框架 §21.2）：① 医疗红灯 ② 与平时相比的变化 ③ 当前沟通能力 ④ 当前痛苦程度 ⑤ 当前感觉环境 ⑥ 刚刚发生了什么 ⑦ 当前最大风险 ⑧ 是否可能疼痛。逐项**可跳过**；跳过即视为「未排除」，不得默认为正常。
其余长期稳定信息**不由现场填写，而由档案预取**（框架 §17 原文：长期档案保存稳定信息，应急系统只采集现场变量）。

**RQ-EMG-02 只追问会改变结论的项**
依据已有输入，仅追问会改变输出的项（一键选择、可跳过），追问结束后即输出。追问判据由具名清单定义，不由模型临时决定。
**判据**（2026-09-29 定）：一项信息只有**同时满足三条**才追问——① 属于**现场变量**（不能由档案预取）；② 档案中**没有覆盖**；③ 答案会**改变某一层闸门的输出**。闸门顺序固定为：医疗 → 与平时偏离 → 沟通 → 环境 → 既往策略 → 安全（框架 §19）。

**RQ-EMG-03 应急的绝对时延目标**
应急路径须在**首个可读输出 ≤10 秒、完整 Action Card ≤60 秒（p50）**内给出可行动结果（2026-09-29 定；依据外部调研框架 §2.5"几十秒到几分钟内完成"取下沿，**实测后按真实数据调整**）。从提交到可行动结果的等待须有明确进度或降级提示。

**RQ-EMG-04 医疗危险优先于孤独症解释**
存在急性医疗危险表现时（意识改变、呼吸异常、严重出血、明显外伤、癫痫持续或异常发作、中毒或误服、严重过敏、明显疼痛、突然出现与平时完全不同的神经或行为表现），**不得优先解释为孤独症相关行为**：先走医疗评估路径，孤独症相关支持只作辅助。输出中的医疗风险以「稳定 / 未排除 / 高风险」表述，**不做诊断、不给用药建议**。（依据：外部调研的应急框架 §2.1 与 §4.2；其引用的 NICE CG142/CG170 等原始来源本项目未独立核验）

### 3.4 日常咨询

**RQ-DAY-01 对话式咨询**
使用者可用自然语言描述正在准备、正在经历或刚发生的事情，获得基于资料与案例的咨询结果。

### 3.5 知识与案例

**RQ-KB-01 两库分离**
专业资料与案例分属两库，各自有来源标注；案例可单独列出与浏览，不藏在对话里。

**RQ-KB-02 来源与状态必须可辨**
每条资料与案例须标明来源、适用范围与状态（已发表 / 内部 / 虚构样例）。一期不得把未经核验的材料呈现为真实案例，也不得把虚构样例与真实案例混列而不加区分。

**RQ-KB-03 一期录入方式**
一期由维护者在**本地**用**应用内的一致化 CLI 入口**导入（跑在同一镜像里、连同一个库），**不提供任何服务端点与产品内界面**用于资料录入、审核或知识库管理；条目与检索节点在同一事务内落库。检索仍在运行时由咨询工具使用。

**RQ-KB-04 撤下能力**
资料或案例被撤下后，不得再作为当前依据分发或引用。

### 3.6 记忆与档案

**RQ-MEM-01 通用记忆自动累积**
关于**使用者自身**的低风险信息随咨询自动累积，并保留时间信息；过期或已被推翻的内容不得作为当前依据误导后续输出。记忆归属**账号**（`group_id = account_id`），不随支持对象分区（2026-09-29 裁决，见[决策记录](../技术设计/decisions/通用记忆归属为账号.md)）；与支持对象有关的事实归档案（`RQ-MEM-02`）。

**RQ-MEM-02 档案自动写入与分层**
关于支持对象的信息由系统自动写入档案：**使用者的直接陈述零确认入档**；系统观察与归纳以候选状态存在，**未经确认不得作为稳定事实使用**。条目须携带来源、生成方式与时间；档案的字段形状、状态机与摘要取数不归本文拥有。

**RQ-MEM-03 事后可纠正**
使用者可查看、纠正与删除通用记忆与档案条目；纠正后后续输出不得再依赖被纠正的内容，删除须覆盖该内容在检索与衍生中的使用。

**RQ-MEM-04 推断不得冒充事实**
系统归纳的候选模式与推断，**未经使用者确认不得进入稳定档案或一页摘要**，也不得在咨询输出中被当作既成事实，只能以「待确认」呈现。（依据：用户提供的外部调研材料 §24.1；该材料引用的原始来源本项目未独立核验）

**RQ-MEM-05 档案归属与一期独占**
档案归属支持对象；一期只有创建者可使用，不提供邀请与共用。已知限制：一期由监护人账号持有、本人无法登录，因此来源类型必须能标注「本人自述（经监护人转述）」，且监护人观察不得覆盖本人表达。

**RQ-MEM-06 一页摘要**
档案须能提供一份与本人最相关的当前认识摘要，供咨询注入；摘要只取使用者直接陈述或已确认的内容，每条可追溯到具体条目并保留来源与最近确认时间。

**RQ-MEM-07 一个账号可有多个支持对象**
一个登录账号可建立并持有**多个**支持对象，每个对象一份独立档案。对话与对象的绑定**在会话开始时确定**，默认沿用该账号上一次的选择，且可切换；每次访问都要校验该对象属于当前账号。授权仍以账号为属主（一期不存在跨账号共用）。**通用记忆不随对象分区**（2026-09-29 裁决）：记忆属账号、各对象共享，只有档案按对象独立。

### 3.7 边界

**RQ-LIM-01 不替代专业服务**
不提供诊断、用药决策、身体控制手法或替代专业服务的治疗方案。（归档 产品定位 §6.1）

**RQ-LIM-02 不把安全保证当事实**
不展示实际不可用的专家接单承诺，不把自动评分宣称为专业确认，不把有限测试无错误宣传为保证「零幻觉」。（归档 `RQ-OPS-02`）

**RQ-LIM-03 资料处理告知**
在输入可识别个人信息前，使用者应了解本次信息会用于什么、谁可见、是否送往外部模型，以及记录会如何累积。（归档 `RQ-OPS-03` 的告知部分）

**RQ-LIM-04 如实标注一期边界**
一期尚未取得专业审阅、关系核验与供应商数据条款，界面与文档不得声称已获专业认可、达到临床效果或可用于真实危机处置。

**RQ-LIM-05 分层支持策略**
按风险分层支持：**低风险的操作与建议照给**；涉及医疗处置、自伤或伤人、用药决策或身体控制时，**不给具体处置，改为引导使用者向专业人士求助**并说明边界。该策略在 **skill 层执行，不做程序围栏**（用户 2026-09-29 决定，原 `EXT-02` 由此转为一期实现）——这是一次**有意的**选择：提示词层的约束**可以绕过**，因此它**不构成安全边界**；对真实使用者的闸门仍是 `EVID-A`（禁止内容清单需具名专业审阅者签收）与 `EVID-B`（素材授权）。

## 四、可观察验收语义

| ID | 对应需求 | 场景与成立条件 |
|---|---|---|
| AC-01 | `RQ-ACC-01` | 未登录访问任意业务路径均被拒绝；不存在匿名内容页或匿名接口。**唯一例外是运维探针端点**：`GET /health` 必须保持未登录可达，但它**只回报各组件状态与异常类型，不复述连接串、凭据或内部拓扑**，且不构成任何业务能力 |
| AC-02 | `RQ-ACC-02` | 新建账号、无任何档案，直接进入应急咨询仍可完成并得到输出，且输出标明未使用档案 |
| AC-03 | `RQ-EMG-01`、`RQ-EMG-02` | 应急以最小输入开始，不要求长表或完整档案（具体字段不作为本条验收对象）；追问只出现会改变结论的项，且可跳过 |
| AC-04 | `RQ-CON-04` | 输入「怎样让他别在超市大叫」时，输出澄清安全、表达与参与方式，不给控制当事人的操作方案 |
| AC-05 | `RQ-CON-02`、`RQ-CON-03` | 输出中的可执行建议与重要结论能指到具体资料或案例条目；无依据时明确说明并给出求助路径 |
| AC-06 | `RQ-KB-01`、`RQ-KB-02` | 案例可在独立列表中浏览；虚构样例与真实案例在列表中可辨 |
| AC-07 | `RQ-MEM-01`、`RQ-MEM-02` | 结束一次应急咨询后，档案与记忆中出现的条目带来源、生成方式与时间 |
| AC-08 | `RQ-MEM-03` | 删除一条档案条目后，后续输出不再引用，重新检索也不返回；删除一条记忆后，两条读取路径（时间线回看与应急预注入）都不再返回 |
| AC-09 | `RQ-KB-04` | 撤下一条资料后，其不再出现在检索结果，也不作为依据被引用 |
| AC-10 | `RQ-LIM-01`、`RQ-LIM-04` | 界面不出现专业认可、临床效果、专家接管承诺或「零幻觉」类表述 |
| AC-11 | `RQ-CON-06` | 从一次输出中抽取全部专业结论与术语：结论均可追溯到资料或案例条目，术语在当次输出内被解释到不需要专业背景即可理解；由独立评价者按同一份标准判定，不以模型自评替代 |
| AC-12 | `RQ-CON-01` | 同一 skill 在应急与日常两条入口下产出结构一致的咨询结果；应急在开始前已追加已有档案信息与近期有效记忆，日常按对话逐轮追加并可按需回看记忆 |
| AC-13 | `RQ-EMG-03` | 应急路径从提交到可行动结果的时延在实测确定的时限内；报告测量窗口、设备与网络、样本量、失败请求与冷启动比例，不以单次演示值代替 |
| AC-14 | `RQ-ACC-03` | 注册与登录**只提供个人账号形态**：界面不存在"以组织名义注册/使用"的入口，账号上不存在组织字段，也不存在机构成员管理入口或机构访问任何支持对象档案的路径 |
| AC-15 | `RQ-ACC-04` | 无邀请码或邀请码无效时注册被拒绝；邀请码撤销后不能再用；校验发生在自己的后端 |
| AC-16 | `RQ-ACC-05` | 注册与登录只要求账号名与密码，不要求邮箱；界面不存在邮箱验证或邮件找回入口 |
| AC-17 | `RQ-ACC-06` | 运营者**经 CLI** 重置密码后，重置前签发的所有会话立即失效，旧会话无法继续访问；且该操作**不经任何 HTTP 端点**（不存在运营后台路由） |
| AC-18 | `RQ-MEM-04`、`RQ-MEM-06` | 构造一次咨询：输出与摘要中不出现任何未确认的系统推断；存在候选模式时，它们以「待确认」单独呈现且不参与结论 |
| AC-19 | `RQ-CON-08` | 在技能选择器中选定技能后发送下一条消息，该消息按所选技能的方法论作答；未选择时按描述匹配；应急卡片提交后构造的即是带激活的第一条消息 |
| AC-20 | `RQ-LIM-05` | 低风险情形下给出可执行的低风险操作；高风险情形（自伤或伤人、医疗处置、用药、身体控制）下输出**不含具体处置指令**，而是引导寻求专业帮助；两者都能指到依据，或明确标注无依据 |
| AC-21 | `RQ-EMG-04` | 构造命中医疗红灯的应急输入：输出给出「医疗风险：未排除」并进入医疗评估路径，**且不把它解释为孤独症行为**；同时不含诊断句与用药建议 |
| AC-22 | `RQ-MEM-07` | 同一账号建立两个支持对象：各自的**档案**互不可见；跨账号访问档案被拒绝；**通用记忆属账号、两个对象共享**（2026-09-29 裁决），故不因切换对象而不可见 |
