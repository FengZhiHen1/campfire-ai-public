# 篝火智答需求文档

> **目标**：定义为什么建设、为谁建设、需要实现什么结果，以及如何判断需求成立。
> **状态**：v3.0 产品方向由用户确认，剩余需求于 2026-09-26 由用户授权自主收敛为目标设计基线；不等于代码已实现、专业/合规审阅完成或真实试点获准。

## 推荐阅读顺序

1. [产品定位与范围](./产品定位与范围.md)：产品目标、受益者、核心概念、场景与非目标。
2. [功能需求与验收](./功能需求与验收.md)：业务结果、约束与稳定 ID 验收语义。
3. [产品方向决策 PRD-001～PRD-009](./产品方向决策.md)：原有确认与用户授权收敛的自主裁决、被否决项及重访条件。
4. [技术设计入口](../技术设计/README.md)：项目级技术定调与目标机制，再核对旧实现差异。
5. [Web 视觉与页面设计](../design/README.md)：新 Web 目标设计契约及关键页面，不代表已完成用户测试。
6. [设计待办](../TODO.md)：真实缺失的外部证据、发布前置条件和延期能力。

## 新旧需求映射

本轮是经授权的产品语义重写，不是纯目录重排。旧编号继续标识历史，不复用到不同的新语义。

| 旧范围 / 验收 ID | 当前业务归属 | 变化与保留边界 |
|---|---|---|
| M1 应急咨询 / AC-1、AC-2、AC-8 | RQ-CTX、RQ-NOW；AC-CTX、AC-NOW | 保留即时已审阅支持与求助，不将行为桶、固定四段或关键词命中视为完整风险判断；内容及升级标准须真实专业审阅 |
| M2 档案 / AC-3 | RQ-SP、RQ-REC、RQ-PLAN；AC-SP、AC-REC、AC-PLAN | 从家庭账号档案变为个人支持空间；用户、支持对象和具体授权关系分离；不以检索过滤变化代替个性化有效性 |
| M3 案例库 / AC-6 | RQ-EVID；AC-EVID | 保留授权、审核与追溯，区分研究、实践及个人经验；L1/L2、向量化和案例数量不是本轮重新确认的业务门槛 |
| M4 人工兜底 / AC-7 | RQ-NOW、RQ-HAND；AC-NOW、AC-HAND；SCOPE-03 | 保留真实求助与交接需求；专家工单仍延期，30 分钟等历史规则不作为当前服务承诺 |
| M5 趋势复盘 / AC-4 | RQ-REVIEW、RQ-REC；AC-REVIEW、AC-REC | 从留存报表转为事件与认识修订；不把相关性解释为原因或效果 |
| M6 协作照护 / AC-5 | RQ-SP、RQ-HAND；AC-SP、AC-HAND | 从家庭邀请改为合法主体核验、受限委托与具体关系授权；核验渠道未落实时不开放真实共享 |
| M7 科普 / AC-8 | RQ-CTX、RQ-EVID；AC-CTX、AC-EVID | 知识解释服务具体事项，简单问答可直接结束；独立科普入口未重新确认为首期必做 |
| 旧非功能指标与风险表 | 需求第九、十节；EVID-03、EVID-05 | 可比生成性能与停止条件已明确；历史专业认可度需按可复核口径检验，不能把有限测试视为零风险证明 |
| 旧延期事项 | SCOPE-02～04 | 微信、小程序、人工通道与社区等由统一待办保留重访条件；语音等新输入仍延期 |
| 新增准备与情景演练 | RQ-PLAN、RQ-TRAIN；AC-PLAN、AC-TRAIN | 属目标方向，首轮先验证通用准备和私人复盘；共享计划/演练待审阅者与素材到位后另行开放 |

## 当前状态与已知偏差

- 当前文件记录已收敛的目标业务语义，不等于全部阶段同时交付、任何能力已实现或通过验收；各阶段必须满足[发布证据闸门](./功能需求与验收.md)。
- 旧技术正文、旧 ADR 与业务代码仍按应急中心基线演进；新[目标机制](../技术设计/目标机制/README.md)已明确替代方向，但当前代码不会因文档修改而自动迁移。
- 家属绝对控制、老师不得写观察、固定角色即全部权限及四段式输出是旧时点的规则，不是当前目标；项目级[技术栈](../技术设计/技术栈设计.md)和[结构](../技术设计/项目结构设计.md)已重定。
- 实际合法授权核验、审阅者资格与投入、模型供应商条款、试点参与者、权益与效果均为 `missing evidence`；缺少证据时按能力停用，而非用设计文本替代证明。
