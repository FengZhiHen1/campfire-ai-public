## 新旧需求映射

本轮是经授权的产品语义重写，不是纯目录重排。旧编号继续标识历史，不复用到不同的新语义。

| 旧范围 / 验收 ID | 当前业务归属 | 变化与保留边界 |
|---|---|---|
| M1 应急咨询 / AC-1、AC-2、AC-8 | RQ-CTX、RQ-NOW；AC-CTX、AC-NOW | 保留即时安全支持与求助，不再将行为桶、固定四段输出或特定关键词规则作为目标需求；风险机制待专业审阅 |
| M2 档案 / AC-3 | RQ-SP、RQ-REC、RQ-PLAN；AC-SP、AC-REC、AC-PLAN | 从家庭账号档案变为个人支持空间；用户、支持对象和具体授权关系分离；不以检索过滤变化代替个性化有效性 |
| M3 案例库 / AC-6 | RQ-EVID；AC-EVID | 保留授权、审核与追溯，区分研究、实践及个人经验；L1/L2、向量化和案例数量不是本轮重新确认的业务门槛 |
| M4 人工兜底 / AC-7 | RQ-NOW、RQ-HAND；AC-NOW、AC-HAND；SCOPE-03 | 保留真实求助与交接需求；专家工单仍延期，30 分钟等历史规则不作为当前服务承诺 |
| M5 趋势复盘 / AC-4 | RQ-REVIEW、RQ-REC；AC-REVIEW、AC-REC | 从留存报表转为事件与认识修订；不把相关性解释为原因或效果 |
| M6 协作照护 / AC-5 | RQ-SP、RQ-HAND；AC-SP、AC-HAND | 从附加的家庭邀请权限扩展为具体关系授权；不静默确定新的邀请批准人 |
| M7 科普 / AC-8 | RQ-CTX、RQ-EVID；AC-CTX、AC-EVID | 知识解释服务具体事项，简单问答可直接结束；独立科普入口未重新确认为首期必做 |
| 旧非功能指标与风险表 | 需求第九节；OPEN-04、OPEN-06 | 指标承接需明确决策，不静默降低；不把有限测试视为零风险证明 |
| 旧延期事项 | SCOPE-01～04 | 输入介质、微信、小程序、人工通道及社区等由统一待办保留状态与重访条件 |
| 新增准备与情景演练 | RQ-PLAN、RQ-TRAIN；AC-PLAN、AC-TRAIN | 属已确认产品方向；首期深度、情景审核与效果门槛未确定 |

## 当前状态与已知偏差

- 当前文件记录产品方向及其业务含义，不等于所有功能已排期、已实现或通过验收。
- 现有技术文档、旧 ADR 与代码仍按旧基线演进；本轮未审计代码，不推断功能完成度。
- 旧的家属绝对控制、老师不得写事件、固定角色能力、四段式输出等与新需求存在待协调之处；未重写技术机制不代表其仍是 v3.0 的需求约束。
- [AGENTS.md](../../AGENTS.md) 简介仍概括旧应急定位，本轮未修改项目指令；更新工作登记于统一待办。
- 合作机构、试点与科研线索仅支持继续验证；产品效果和可持续运营仍是 `missing evidence`。
