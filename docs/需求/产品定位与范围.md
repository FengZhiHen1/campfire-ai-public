# 产品定位与范围

> **本文唯一拥有**：产品定位、目标用户与角色、价值主张、范围边界、品牌命名、待确认事项。
> **状态**：需求基线 v2.0（2026-06-30 经用户确认）。相对 v1（2026-05 转型后基线）的变化：定位从「纯应急工具」延伸为「应急为核心 + 日常支持」，新增志愿者画像，患者覆盖从儿童扩展为全生命周期，明确平台分工。
> **来源**：v1 基线事实来自 [references/需求分析.md](../references/需求分析.md) 与 [references/项目转型叙事.md](../references/项目转型叙事.md)；v2 变化来自 2026-06-30 需求重构对话的用户确认。

## 一、产品定位

| 项 | 内容 |
|---|---|
| **平台名称** | 篝火智答（Campfire-AI） |
| **定位** | 孤独症垂直领域的**应急咨询与家庭支持平台** |
| **核心场景** | 孤独症人士突发行为/情绪危机时，为照护者提供即时、可执行的应急干预建议 |
| **定位结构** | **应急咨询为尖刀**（不可替代性），**日常支持为留存引擎**（档案记录、趋势复盘、科普） |
| **覆盖人群** | 孤独症人士**全生命周期**——儿童、青少年与成年患者的家庭均需服务 |
| **技术底座** | RAG（检索增强生成）+ 真实案例库 + 个性化行为-情绪档案 |
| **商业逻辑** | 使用频率 × 渠道：日常场景提供频率，应急场景提供差异化；机构合作（如大连爱纳）为 B2B2C 分发渠道 |

### 价值主张

以真实干预案例为知识燃料，以个性化行为-情绪档案为检索透镜，在孤独症家庭最紧急的时刻，提供即时、可信、可溯源的结构化应急建议；在日常中，帮助家庭沉淀干预经验、看清行为趋势。平台输出**不是诊断、不是治疗**，而是基于真实案例与专业经验的、可立即执行的参考方案。

### 转型背景（事实摘要）

项目原名「心青年」，定位为泛心智障碍科普问答平台。2026-05 与大连爱纳一线特教老师深谈后完成四项转型：从泛心智障碍收缩至孤独症垂直；从科普问答转向应急方案；从通用知识库升级为真实案例库；从单向咨询进化到个性化档案驱动。v2.0 在此之上做**场景延伸**（应急→应急+日常），但**不回泛心智障碍人群**——「服务对象越泛，专业深度越稀释」仍是成立的约束。

完整叙事见 [references/项目转型叙事.md](../references/项目转型叙事.md)。

## 二、用户画像

### P1 监护人（核心消费者）

| 维度 | 内容 |
|---|---|
| **谁** | 孤独症人士的照护者/法定监护人，覆盖患者**全年龄段**——儿童青少年患者的父母；成年患者的年迈父母、兄弟姐妹或其他照护人 |
| **核心场景** | 危机时刻（应急咨询）；日常（记录事件、看趋势复盘、学科普） |
| **痛点** | 危机时孤立无援；不确定做得对不对；家庭干预经验无法沉淀；机构学的方法回家不会用；成年患者家庭另有「照护者年迈、体力与知识更新力不从心」的长期焦虑 |
| **关键特征** | 危机时认知负担极重、情绪高度紧张 → 交互必须极简；非专业 → 话术必须可直读直用；微信原生用户 → 小程序零门槛 |
| **细分** | 新确诊家庭（0-1 年迷茫期：科普 + 引导需求强）/ 有经验家庭（记录沉淀 + 精细干预需求强） |
| **注意** | 成年患者的行为危机物理风险更高（体型、力量），危机场景可能发生在就业支持、托养机构等家庭外环境；产品话术不得以「孩子」为默认称呼 |

### P2 一线志愿者（需求侧）

| 维度 | 内容 |
|---|---|
| **谁** | 公益组织志愿者、社区工作者、融合活动支持者 |
| **核心场景** | 活动现场/陪伴过程中遭遇行为危机，消费应急建议；受家庭邀请后辅助记录 |
| **痛点** | 有爱心缺专业，最怕「好心做错事」 |
| **功能形态** | 注册时选志愿者角色；应急咨询/科普与监护人同款；可被家庭邀请为「协作照护者」，获得档案只读 + 事件记录权限 |
| **硬约束** | 只消费专家审核过的内容；**不进入案例生产与审核链路** |

### P3 老师（供给侧）

| 维度 | 内容 |
|---|---|
| **谁** | 机构特教/康复老师 |
| **核心场景** | 共建家庭档案、补充专业评估、上传案例、接工单 |
| **痛点** | 家庭泛化断层——机构训练的内容回家就断档；经验沉淀没有出口 |
| **价值闭环** | 平台是机构→家庭的延伸手臂（B2B2C 渠道的支点） |

### P4 专家（供给侧，稀缺资源）

| 维度 | 内容 |
|---|---|
| **谁** | 资深督导/医学背景专家 |
| **核心场景** | 案例终审、疑难/特急工单接管 |
| **设计约束** | 时间最稀缺，产品必须最小化其单位消耗（AI 预审前置、工单内容预组装） |

### 系统运营角色（不进用户画像）

| 角色 | 职责 |
|---|---|
| **管理员** | 平台运营与人员准入管理：案例/人员/工单调度、强制下架 |
| **维护人员** | 系统稳定与数据安全：运维监控、日志审计 |

## 三、范围边界

### 做什么

- 智能应急咨询（P0）：RAG 驱动的结构化应急干预建议，含红线安全门硬拦截；
- 个性化档案库（P0）：家属主导、老师/专家补充的行为-情绪档案，覆盖全年龄段；
- 真实案例库管理（P0）：案例录入、审核与检索入库（模板沉淀暂缓，见功能需求与验收 M3）；
- 人工兜底通道（P2，延后）：确定性兜底信号命中或高风险场景下的人工工单流转；初期专家资源整合途径不明，待专家合作渠道落实后启动；
- 事件趋势复盘（P1，新增）：基于档案事件记录的周期性趋势回顾，日常留存引擎；
- 协作照护（P1，新增）：志愿者独立角色、家庭邀请制、档案只读 + 事件记录；
- 科普查阅（P2）：轻量科普与案例关联，不作主入口。

各模块功能需求详见[功能需求与验收](./功能需求与验收.md)。

### 不做什么

- **不回泛心智障碍人群**：保持孤独症垂直（转型核心决策，继续有效）；
- **不做医疗诊断、治疗方案开具**，不替代专业人员；
- **本期不做 UGC 社区**（家属互助社区为后续迭代候选，需先解决 UGC 审核与错误建议传播的合规风险）；
- **不做实时聊天**（人工兜底为异步工单式交互）、**不做专家固定值班排班**；
- **不做案例/档案上传激励机制**，由平台运营或合作机构另行管理；
- **志愿者不进入案例生产与审核链路**；
- **明确延期**：语音/图片输入（危机时打字困难的体验优化，待应急咨询文字链路稳定后重访）。

## 四、平台分工

| 平台 | 服务画像 | 承载能力 |
|---|---|---|
| **微信小程序** | 需求侧（监护人 + 志愿者） | 应急咨询、档案记录与查看、趋势复盘、科普、工单家属侧 |
| **Web 端** | 供给侧（老师/专家）+ 管理员 | 案例录入与审核、工单处理、档案共建、平台管理 |

决策记录见 [ADR-006](../技术设计/决策/ADR-006-平台分工-小程序与Web.md)（该决策同时关闭 ADR-002 的重访条件）。

**过渡安排（小程序资质审核通过前）**：Web 端在供给侧之外同步承载需求侧内测服务，范围限定应急咨询 + 档案记录与查看，访问采用邀请码制，账号以手机号为统一锚点；小程序过审并稳定后逐步下线该入口，回归上表终态分工。决策记录见 [ADR-012](../技术设计/决策/ADR-012-内测期Web承载需求侧服务.md)。

## 五、品牌命名

「篝火」不是灯塔、不是路灯：它是寒夜中一团具体可感的温暖、荒野里一个可以围拢的聚集地、黑暗中一根随时可以点燃的火把。它照亮的不只是前路，更是此刻——此刻正在经历情绪崩溃的患者，和此刻正在颤抖的照护者。

品牌叙事全文见 [references/项目转型叙事.md](../references/项目转型叙事.md) §四。

## 六、待确认事项（missing evidence）

1. **案例来源**：现有可录入的真实案例数量？与大连爱纳等机构的脱敏使用协议签署状态？
2. **档案共建**：老师/专家参与档案共建的意愿与频次？是否需要激励机制（平台外）？
3. **志愿者组织合作**：目标志愿者组织（海洋天堂、地方家长组织等）的接触与合作意向？
4. **趋势复盘形态**：复盘周期（周/月）、内容深度、是否引入 LLM 总结——延至模块设计阶段确定；
5. **成年患者场景**：就业支持、托养机构等家庭外危机场景的具体形态，需与机构方访谈补充。
6. **小程序资质审核**：具体阻塞点（医疗健康类目资质要求？）与预期过审时间？内测期长度直接影响 [ADR-012](../技术设计/决策/ADR-012-内测期Web承载需求侧服务.md) 的退役时点。
