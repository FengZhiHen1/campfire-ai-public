## 一、产品定位

**篝火智答（Campfire-AI）是面向孤独症人士支持网络的 AI-Native 情境支持平台。**

以个人支持空间为中心，以授权关系连接支持者，以带来源的记录积累认识，以具体事项组织行动；基于科学研究与案例，由 AI 协助理解、提前准备、现场支持、协作交接和事后复盘。

平台直接服务家属、志愿者和一线老师等周围人群，核心受益者包括孤独症人士本人。不将本人直接操作产品作为当前前提，但不能因此忽略其意愿、表达方式与拒绝事项。

### 1.1 核心目标

- **实际有用**：帮助支持者获得适用于当前情境、能够执行的支持，而不只是获得一篇回答。
- **AI 核心参与**：项目用于强要求 AI 参与的比赛；AI 应承担理解、适配、练习或协作中的核心工作，而非附加聊天入口。
- **跨人协作**：减少支持者反复解释、从零学习及交接遗漏，同时避免扩大敏感信息传播。
- **尊重个体**：不以诊断标签概括个人，也不默认以服从、安静或继续参与作为成功标准。

AI 核心参与不等于每个功能、每个时刻都调用模型；应急支持的重要性也不意味着必须在危机当下自由生成完整方案。AI 可以主要在危机前后发挥作用。

### 1.2 需求起点与资源事实

以下为用户自述，未作独立现场核验：

- 用户参加非洲鼓志愿课堂时，一名孤独症人士突然大叫、到处跑，用户不知道如何处理。
- 项目与大连爱纳孤独症关怀中心有合作，可访谈家属并开展试点。
- 用户允许依据新定位进行彻底重构，不要求保留不合适的旧产品结构。

`missing evidence`：上述事件的诱因、即时危险程度和处置经过尚不清楚，不能认定由鼓声或感官过载导致。合作关系不等于已取得资料使用授权、足够样本或持续专业审阅资源。

## 二、受益者与使用者

| 对象 | 需要获得的支持 | 不应默认的前提 |
|---|---|---|
| 孤独症人士 | 支持符合本人意愿、沟通方式与实际需要 | 照护者方便就等于本人获益 |
| 家属、日常照护者 | 准备、应急支持、低负担记录与照护交接 | 家属身份等于永久绝对控制权 |
| 志愿者、临时支持者 | 必要信息、明确职责、演练、求助与交接 | 短期参与就需要查看完整档案 |
| 一线老师、机构支持人员 | 观察记录、跨场景协作、计划参与与经验沉淀 | 老师只能是内容供给方，或职业身份能访问所有人 |
| 专业人员、内容审阅者 | 在资质与授权范围内提供意见、审阅内容 | 参与审阅就等于实时应急值班 |
| 运营与维护人员 | 运营、准入、安全维护 | 后台管理身份就能读取所有个人资料 |

覆盖儿童、青少年及成年生活是产品方向，不等于首轮试点已覆盖所有年龄与支持需求。界面优先使用姓名或偏好称呼，不默认称呼所有人为“孩子”。

## 三、核心产品概念

这些概念描述业务对象，不规定数据库表、API 或框架。

| 概念 | 业务含义 |
|---|---|
| 用户 | 登录和操作系统的人，可参与多个个人支持空间 |
| 支持对象 | 平台围绕提供支持的具体孤独症人士，与登录账号相区分 |
| 个人支持空间 | 围绕一个人的长期协作空间，组织支持信息、关系、记录、事项和计划；同一空间不等于成员之间信息全量可见 |
| 授权关系 | 用户与具体支持对象之间获准开展的访问和操作，结合范围、期限或用途 |
| 记录 | 来自具体来源、发生在具体情境中的信息；包括观察、转述、解释、专业意见和 AI 整理草案 |
| 支持事项 | 正在准备、经历或复盘的一件具体事情，而非强制工单或无限聊天会话 |
| 支持计划 | 经适当确认、在一定条件下使用的支持安排，不是医疗处方 |
| 证据与案例 | 研究与指南提供适用依据，实践案例展示落实和失败边界，个人历史提供情境信息；三者不能相互替代背书 |
| AI 支持 | 在当前权限和情境内协助理解、准备、演练、交接及复盘，不拥有自主扩大授权的权力 |

### 3.1 人是长期中心，事是工作单元

同一用户可以支持多人，同一个人可以得到多名获授权用户的支持。用户账号退出或支持关系变化，不应在产品概念上等同于被支持的人消失。

同一空间可以承载就医准备、临时照护交接、持续困难复盘等事项。用户可以从任意事情进入，也可以仅补充一条记录或询问简单问题；不要求先创建任务或填写完整档案。

### 3.2 共同积累认识，不制造永久标签

不同支持者的记录可以有分歧，不同情境下的记录可以同时成立。一次观察不自动成为永久偏好，行动后出现变化不自动证明因果。信息被核对不等于相关解释被证实。

## 四、场景与价值闭环

| 用户需要 | 代表性情境 | 应获得的结果 |
|---|---|---|
| 接下来有件事，需要准备 | 就医、出行、换老师、搬家、临时照护 | 明确缺项、形成准备安排，必要时练习 |
| 现在遇到困难，需要支持 | 家庭、学校、机构或公共场所的突发困难 | 低负担取得适用支持、既有计划与真实求助路径 |
| 刚发生一件事，需要复盘 | 沟通中断、支持无效、反复出现的困难 | 核对经过、保留未知，形成待确认的后续行动 |
| 别人需要接手 | 家校沟通、照护轮换、志愿服务交接 | 获授权且适合接收者的必要信息与职责说明 |

场景不局限于活动，不按地点把产品割裂为互不相通的系统。应急程度与发生地点是不同维度。用户可以只使用闭环中的一段，不被强迫完成准备、演练、记录全流程。

## 五、AI 的价值定位

AI 的核心任务是将分散的信息和通用知识转化为当前情境下可用、可核对的支持：

- 理解自然叙述并澄清真正的支持目标。
- 保留个人信息的情境条件，识别分歧和缺项。
- 结合支持者能力与资源适配表达和安排。
- 将审核后的原则转化为按需情景演练。
- 整理交接材料、复盘记录和计划修订草案。

`missing evidence`：这些能力对本项目用户的实际效果尚未验证。不可替代性应体现为同等质量下显著降低时间、人力或成本，或改善行动质量，而不是仅凭使用大模型作出声明。

## 六、边界与非目标

### 6.1 核心边界

- 服务支持者并不会自动消除医疗风险，建议仍可能影响当事人的身体与权益。
- 不提供医疗诊断、用药决策、身体控制手法或替代专业服务的治疗方案。
- 不把情景模拟称为真实个体的内心模拟、数字孪生或确定性行为预测。
- 不把案例真实性、专家审阅、引用链接或免责声明当作效果与安全保证。
- 不自动将个人资料转成公共案例或训练数据，不因 AI 摘要而扩大分享范围。
- 不承诺尚未落实的实时专家接管或应急响应时限。

### 6.2 当前非目标

- 泛心智障碍通用平台、公开 UGC 社区或通用机构管理系统。
- 持续音视频监控、自动诊断或自动对外执行高影响操作。
- 将孤独症人士本人直接使用作为本期交付前提。
- 将全龄、全场景方向理解为首期必须全部实现。

## 七、品牌

保留“篝火智答 / Campfire-AI”名称。“篝火”代表具体、可依靠、可以围拢的支持；不是替人决定的权威，也不只是危机时的一次回答。
