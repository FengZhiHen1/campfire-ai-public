# 产品定位与范围

> **本文唯一拥有**：产品定位、目标用户与角色、价值主张、范围边界、品牌命名、待确认事项。
> **来源**：[references/需求分析.md](../references/需求分析.md) §1-2/§6、[references/项目转型叙事.md](../references/项目转型叙事.md)。

## 一、产品定位

| 项 | 内容 |
|---|---|
| **平台名称** | 篝火智答（Campfire-AI） |
| **定位** | 基于大模型的孤独症垂直领域全天候 AI 咨询平台 |
| **核心场景** | 孤独症人士突发行为/情绪危机时，为家属提供即时、可执行的应急干预建议 |
| **技术底座** | RAG（检索增强生成）+ 真实案例库 + 个性化行为-情绪档案 |
| **转型关键** | 从「泛心智障碍科普」收缩为「孤独症行为+情绪应急干预工具」 |

### 价值主张

以真实干预案例为知识燃料，以个性化行为-情绪档案为检索透镜，在孤独症家庭最紧急的时刻，提供即时、可信、可溯源的结构化应急建议。平台输出**不是诊断、不是治疗**，而是基于真实案例与专业经验的、可立即执行的参考方案——「聚焦应急措施建议，但是一定是建议」。

### 转型背景（事实摘要）

项目原名「心青年」，定位为泛心智障碍科普问答平台。2026-05 与大连爱纳一线特教老师深谈后确认：家属在危机时刻需要的是「孩子现在就在撞墙，我该怎么办」的应急方案，而非科普定义；服务对象越泛，专业深度越稀释。由此完成四项转型：

- 从「泛心智障碍」收缩至「孤独症垂直领域」；
- 从「科普问答」转向「应急方案提供」；
- 从「通用知识库」升级为「真实案例库」（核心资产为经脱敏的真实干预案例与应急方案模板）；
- 从「单向咨询」进化到「个性化档案驱动」（老师 + 家属共建行为-情绪档案）。

完整叙事见 [references/项目转型叙事.md](../references/项目转型叙事.md)。

## 二、目标用户与角色

| 角色 | 核心诉求 | 平台价值 |
|---|---|---|
| **患者家属（核心用户）** | 患者突发异常行为/情绪时，第一时间获得可参考的应急方案 | 7×24 即时响应，基于真实案例的个性化建议 |
| **特教/康复老师** | 沉淀干预经验，辅助家属进行家庭泛化训练 | 共建个性化档案，上传/审核真实案例 |
| **专家** | 把关案例与方案质量，处理 AI 无法覆盖的疑难场景 | 审核案例库、接管疑难工单 |
| **管理员** | 平台运营与人员准入管理 | 案例/人员/工单调度 |
| **维护人员** | 系统稳定与数据安全 | 运维监控、日志审计 |

> **角色调整说明**：原「心青年」方案的「志愿者」角色弱化或合并为「老师/专家」体系，突出专业干预经验的沉淀与流转。

## 三、范围边界

### 做什么

- 智能应急咨询（P0）：RAG 驱动的结构化应急干预建议；
- 个性化档案库（P0）：家属主导、老师/专家补充的行为-情绪档案；
- 真实案例库管理（P0）：案例录入、审核、模板沉淀与检索入库；
- 人工兜底通道（P1）：AI 置信度不足或高风险场景下的人工工单流转；
- 科普查阅（P2）：轻量科普与案例关联，不作主入口。

各模块功能需求详见[功能需求与验收](./功能需求与验收.md)。

### 不做什么

- **不做医疗诊断、治疗方案开具**，不替代专业人员；
- **不做泛心智障碍科普百科**，科普仅为附带功能；
- **不做通用客服**（商品/订单类）；
- **不做实时聊天**，人工兜底为异步工单式交互；
- **不做专家固定值班排班**，特急工单群发通知、先抢先得；
- **不做案例/档案上传激励机制**，由平台运营或合作机构另行管理；
- **MVP 阶段不做语音/图片输入**（文字输入为主），不做案例多媒体附件。

## 四、品牌命名

「篝火」不是灯塔、不是路灯：它是寒夜中一团具体可感的温暖、荒野里一个可以围拢的聚集地、黑暗中一根随时可以点燃的火把。它照亮的不只是前路，更是此刻——此刻正在经历情绪崩溃的患者，和此刻正在颤抖的家属。

品牌叙事全文见 [references/项目转型叙事.md](../references/项目转型叙事.md) §四。

2. **档案共建流程**：老师/专家参与档案共建的意愿与频次如何？是否需要设计激励机制？
3. **应急分级标准**：行为/情绪危机的等级划分是否有统一标准参考？（当前方案：平台自行定义简化等级，见[危机分级与兜底策略](../技术设计/机制/危机分级与兜底策略.md)）
