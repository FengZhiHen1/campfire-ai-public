# 页面设计：复盘与受限交接

> **页面目的**：帮助支持者核对事情经过、保留不同解释，并只在获授权且用户明确确认后把必要信息交给具体接收者。消费[设计契约](../DESIGN.md)，业务依据 `RQ-REVIEW-01～02`、`RQ-HAND-01`、`RQ-SP-04`。

## 页面与视觉结构

从事项详情进入“复盘”视图，左侧或上方按时间展示观察、参与者原话/转述、尝试过的行动与随后变化；右侧或下方分别列“我们还不知道”“不同人的看法”“可确认的下一步”。用户核对 AI 整理前，每一块都标为草案；不能把“采取行动后平静”自动画成“该方法有效”的因果箭头。本人当下表达的拒绝须单独可见，不因其他人意见多而消失。

交接是另一独立视图：先选获授权接收者与其职责，再预览仅该人可见的范围、信息来源、适用时限、失效的计划条目和“尚未发送”状态。用户逐条移除不需要的个人信息，确认后才发送站内资料；未落实站内接收或外部服务时只允许预览，不显示“已通知专家”。已外发副本需有明显“可能已过期”说明，撤销不承诺收回截图。使用 `ScopeChip`、`SourceNote`、`StateBadge`、`InputField`、`ActionButton` 和 `Feedback`。

手机时间线单列，交接发送按钮放在接收者与范围复核之后；桌面可对照时间线与解释栏，但不得同屏显示另一个 Space 的私人事项。按语义分隔比复杂配色更重要。

## 数据、文案与跳转

复盘可从 `POST /api/v2/assist/turns` 的 `intent=review` 和明确事项作用域取得 AI 草案，原记录写入仍经 `POST /api/v2/spaces/{id}/records` 与记录者核对。交接通过 `POST /api/v2/spaces/{id}/handoffs/previews` 取得接收者权限下的最小预览，`POST /api/v2/spaces/{id}/handoffs/{handoff_id}/send` 在用户确认后重新校验授权、当前计划和内容；回到事项详情可查看站内收取状态，非实际送达不得写成“已读”。

真实文案：“这部分是你核对后的经过”“不同意见还没有被证实”“准备发送给哪位获授权支持者？”“发送前再次核对范围”。不出现无法兑现的实时专家响应时间。

## 五态与边界

| 状态 | 复盘/交接 |
|---|---|
| populated | 分开呈现事实、解释、未知；交接显示当前接收者、来源、时限和未发送状态 |
| loading | 同形时间线骨架；交接预览与发送过程中不可乐观宣称通知完成 |
| empty | 没有记录时可先写一句经历；没有合格接收者时只保存私人草案或空间草案，不显示发送按钮 |
| error | 生成失败保留原话供人工核对，交接失败保留预览并显示实际状态；权限故障拒绝个人资料读取 |
| edge | 多人叙述冲突、授权到期、条目在预览后停用、消息发送失败、撤销后重开旧链接、正文过长均需重新核验且不泄露 |

## 平台、动效与验收

动作触区至少 48px，键盘和屏幕阅读器按时间顺序访问多方来源；历史/现行状态用文字与版本标注。不用“已送达”的动画掩盖异步失败。以 `AC-REVIEW-01`、`AC-HAND-01`、`AC-SP-05` 验证无自动因果、未经授权不通知、撤销后旧链接不可访问。真实接收者、站内送达机制与试点职责需发布前验证。
