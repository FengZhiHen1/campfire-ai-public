# 页面设计：共享计划与安全异议

> **页面目的**：在已核验空间内区分观察、草案、日常安排和经专业审阅的策略；任何获授权查看者能对具体条目提出正式安全异议并立即停止其平台分发。消费[设计契约](../DESIGN.md)，依据 `RQ-PLAN-01～03`、`RQ-HAND-01`。

## 布局与视觉层级

`/spaces/{id}/plans` 顶部显示空间名称、计划当前版本与“仅按当前权限查看”；先列当前有效条目，再分区列“待确认”和“暂时停用”。每个条目包含行动文本、适用情境、依据、确认人/时间、分类、版本、限制与明确状态。未确认提议不得与当前行动并列同一强调层级；已停用条目不可复制为当前交接建议，其原文和异议原因仅向有权成员在历史区可读。

打开计划条目后的“此建议可能不安全/不适用”进入对话式独立表单，显示目标条目与情境，询问观察到的风险或本人当下拒绝。普通文字更正另走“提出编辑意见”，避免一键误停用。提交时显示“正在提交，尚未确认停用”；**只有服务端事务确认后**才显示“已暂时停用，等待复核”，并让关联摘要/交接卡当前入口失效。没有人工复核者时状态一直停用，不显示倒计时自动恢复。使用 `PlanItem`、`StateBadge`、`SourceNote`、`InputField`、`ActionButton`、`Feedback`。

手机优先显示状态和下一步，不在窄屏堆叠多列；桌面可将适用条件和来源放侧栏。停用提醒不使用纯红大面积遮盖公开基础帮助；避免声称“请立即停药”等错误外推。

## 数据与跳转

条目集合读取 `GET /api/v2/spaces/{id}/plans`，详情读取条目版本，正式异议用 `POST /api/v2/spaces/{id}/plan-items/{item_id}/objections`，日常/专业确认通过 `/confirm` 并由服务器判权；复核与恢复入口只对具备原确认层级的成员呈现。数据需要 `item_id`、版本、分类、适用情境、来源引用、确认者、状态和受影响衍生物；服务端返回 412 时先刷新条目再允许用户核对重提。交接卡预览必须按接收者当前授权和条目最新状态重算。

文案示例：“这条内容目前未经过相应确认”“你的安全异议已经收到，这一条现已暂时停用”“已发出的副本无法收回，我们会提示有权接收者不要继续把旧版当作现行建议”。

## 五态、并发与失败

| 状态 | 列表/异议表单 |
|---|---|
| populated | 当前有效、草案、停用三组文字状态清楚，独立条目不互相误伤 |
| loading | 读取仅骨架；异议提交按钮锁定并显示处理中，不乐观宣称停用 |
| empty | 没有经确认计划时展示公开帮助与“可先记录准备问题”，不生成伪计划 |
| error | 状态库不可用时不展示旧缓存为有效；异议失败保留输入并提供可联系的现实求助入口，无复核者不伪报已送达 |
| edge | 重复异议、确认与异议并发、撤销中的成员、原确认者离职、衍生卡含多个条目、长篇来源都有独立提示与重试/历史路径 |

## 无障碍、动效与验收

状态必须有文本、时间和适用情境；键盘可到异议入口，表单错误回到字段，成功消息对屏幕阅读器可见。触区至少 48px，停用显示不等待动画。`AC-PLAN-01～04`、`AC-HAND-01` 的分级确认、即时停用、旧摘要不可再分发、超时不恢复和不同授权接收者均有可复跑页面路径。具体安全内容与专业资质需实际签收后才能启用页面的发布操作。
