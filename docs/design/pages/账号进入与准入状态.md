# 页面设计：账号进入与准入状态

> **页面目的**：在不误导为“登录即授权个人资料”的前提下完成试点账号登录，并清晰呈现审核中、拒绝和禁用状态。以[设计契约](../DESIGN.md)为视觉约束，业务依据 `RQ-CTX-01`、`RQ-SP-02～03`。

## 布局与区块

`/login` 保留公开基础支持的回退链接；单一主表单仅接收当前系统已支持的登录凭证，不把支持对象的生日、诊断或姓名放在账号注册前提。受控试点的加入资格由发布开关与实际运营流程决定，不能在页面虚构短信验证或微信静默登录。专业身份待审、资料驳回、账号禁用分别展示可理解的状态页，不将其伪装为登录错误。无权限访问某个空间时退回安全入口，不显示他人空间是否存在。

桌面窄列输入表单配一段“登录用于保存自己的事项，访问他人资料还需关系授权”的说明；手机先呈现字段与帮助入口，输入和主按钮全宽。组件使用 `InputField`（`.field`）、`ActionButton`（`.action`）、`ScopeChip` 和 `Feedback`；无品牌插画或虚构服务统计。

## 数据、文案与跳转

登录成功的用户可以进入 `/assist`；需要继续原先打开的合法私人事项时返回该资源，空间访问仍由服务端重新判定。未完成准入或被停用显示状态与可执行的联系/补充材料路径，仅在真实运营联系人存在时显示其渠道。公开帮助无需登录，页面始终能返回 `/`。密码错误只说“账号或凭证不匹配”，避免枚举账号。

## 五态、表单与平台

| 状态 | 表单/状态页结果 |
|---|---|
| populated | 字段真实标签、明示注册或加入试点边界、完成后的私人事项入口 |
| loading | 提交锁定防重复，告知正在验证；不刷新或丢失已输入内容 |
| empty | 尚无账号只显示可用的注册/邀请政策；不自动创建匿名的可回访事项 |
| error | 登录失败与服务不可用区分，保留手机号字段，密码清空；权限校验不可用不提供受限资料 |
| edge | 失效凭证、待审专业身份、禁用账号、从外部深链进入无权空间分别有独立提示；长错误不溢出手机宽度 |

字段先 blur 后显示错误；提交后聚焦错误摘要或首个无效字段。状态、焦点和错误由文字与 `aria-describedby` 同步表达，手机输入控件至少 48px。页面变化不强迫等待动画。以 `AC-CTX-01` 与 `AC-SP-02～05` 验证：登录本身不授予他人资料权、旧 Token 在关系撤销后也不可越权；实际账号注册/审核资源尚需运营证据。
