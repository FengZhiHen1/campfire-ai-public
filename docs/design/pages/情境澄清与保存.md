# 页面设计：情境澄清与保存

> **页面目的**：登录用户围绕眼前一件事得到通用或获授权的 AI 辅助，并明确决定是否保存私人事项。调性是[设计契约](../DESIGN.md)的暖纸面与克制状态反馈；业务依据 `RQ-CTX-01～06`、`RQ-NOW-01～02`。

## 布局与内容区

`/assist` 顶部显示当前范围：“仅依据你本次提供的信息”或“当前获授权空间：偏好称呼”；切换支持对象必须先结束或明确转换当前请求，旧对象的迟到结果不得出现在新对象屏幕。主要区块依次为情境输入、已审阅的公开基础支持（现场模式置顶）、本次 AI 整理的事实/未知/下一步、逐条依据、核对保存预览。简单问题只需回答与结束，不出现强制建档导流。

手机先显示主行动与短句，依据和来源可展开但不能隐藏“这只是草案”；桌面回答仍限制阅读宽度，右侧可放适用条件与公开基础支持。组件选择 `SituationEntry`、`InputField`、`PublicSafetyNotice`、`SourceNote`、`ScopeChip`、`ActionButton`、`Feedback`；“生成中”的标记不得看起来像已完成建议。

## 字段、文案和跳转

请求 `POST /api/v2/assist/turns` 使用 `scope`、叙述和可选明确授权的 `space_id`；回答按 `facts_from_user`、`unknowns`、`options`、`supporting_sources`、`limitations`、`save_preview` 分区（字段取值见[枚举与错误码](../../技术设计/technical-details/枚举与错误码.md)）。不向用户展示未验证的模型中间文本。事实栏题为“你提到的情况”，未知栏题为“还需要核实”；建议标注具体适用边界而非“肯定有效”。在输入真实个人信息前展示会否发送外部模型的可理解告知；未具备供应商条件的环境只接收虚构样例或关闭真实输入。

首次点击“核对后保存”进入保存预览，用户可逐项删除/改写目标、已知事实和下一步。若本轮只用通用资料，按钮为“保存为我的私人事项”，提交 `POST /api/v2/matters`；若本轮已使用空间资料，按钮为“保存到当前空间草稿”，重新核验权限后提交 `POST /api/v2/spaces/{id}/matters`，**不能改点私人保存来保留已撤销的信息**。成功后进入对应范围的事项详情。点击“暂不保存”或关闭页面不会生成可回访事项。需要协作时另有“了解如何建立共享空间”链接，不能自动邀请家属/老师。用户断网返回时未保存对话不承诺能恢复，页面明确说明。

## 五态与失败恢复

| 状态 | 输入/生成/保存预览 |
|---|---|
| populated | 输入可编辑，完整回答分清来源，用户手动核对预览并选择保存或结束 |
| loading | 只显示非行动性进度、已审阅公开支持与停止按钮；15 秒仍未完成时解释等待，不逐 token 展示未经检查的行动建议 |
| empty | 尚无输入时展示一个贴近就医/交接的真实任务示例（仅示例，不作为个人资料）；无 `save_preview` 不显示保存成功 |
| error | 模型失败时保留本次输入并提供公开内容与重试；保存失败保持预览与更改，不出现“已保存” |
| edge | 没有空间、资料冲突、来源撤下、生成中授权被撤销或慢网络时显示未知与限制，拒绝旧范围的迟到建议；长文字换行 |

## 可用性、动效和验收

手机主按钮热区至少 48px，字段有标签、聚焦和错误摘要；不把“服从”表述包装成计划，来源/范围不是仅凭颜色。结果出现可以短淡入，取消与撤销没有过渡等待。用 `AC-CTX-01～05`、`AC-NOW-01` 验证首次无空间、未保存退出、主动保存、相似行为不同条件及风险路径。用户是否理解“未保存”与“仅私人”尚未做真实试点。
