# 页面设计：对话页

> **追溯**：`RQ-CON-01`～`RQ-CON-08`、`RQ-DAY-01`、`RQ-EMG-03`（时延感知）、`AC-02`、`AC-12`、`AC-19`；事件到状态的映射、组件清单（Composer/Thread/QuestionCard/ActionCard 等）、失败语义全部由[咨询对话界面](../../技术设计/technical-details/咨询对话界面.md)拥有（本页只做视觉与交互呈现，不改任何机制）；端点与 SSE 传输形状见[HTTP/SSE 契约](../../技术设计/面/consult/HTTP与SSE契约.md)。
> **契约**：[DESIGN.md](../DESIGN.md) + [tokens.css](../tokens.css) + [components.html](../components.html)。
> **状态**：初稿，待用户确认。

## 页面目的与受众

Reading this as: 对话工作面 for 正在求助的监护人，with 读物正文的语言，leaning toward warm-editorial × 火焰橙。这是产品的心脏页：日常时它是"和一位可靠顾问的通信"，应急时它是"行动卡的阅读面"。视觉纪律 = 把阅读面积让给内容，chrome 全部退后。

## 布局结构

次级页面，不渲染 tab 栏。自上而下三段：

1. **页头（极简）**：`.subpage-head`——返回（「← 返回」）+ 会话标题（单行截断）+ 当前生效技能（`.tag.meta` 弱标签）。**多技能呈现（2026-10-01 授权语义重写后）**：`run_started.activated_skills` 的口径是「本次运行生效集合（历史推导 ∪ 本轮新增）」，会话中途激活新技能后会出现多成员——页头按激活时间顺序串联展示全部技能名（`.tag.meta` 之间留 `--space-2`，如「日常咨询」「档案整理」），不做"只显示最后一个"的裁剪（使用者有权知道当前有哪些操作纪律在场）；宽度不足时整体截断为「技能 N 个」——**不折叠为 +N 徽标**，避免"前面几个是什么"变成需要点开才能回答的问题。技能名映射由前端目录常量承担（与服务端技能名逐字对应），未知名显示原文名、不猜测翻译。高度 48px + `safe-area-inset-top`，sticky 吸顶。
2. **消息流（主体，占满剩余空间，独立滚动）**：
   - **使用者消息**：右对齐气泡——`--surface-warm` 奶油沙底、`--radius-md`（右上角 4px 小圆角，方向感）、`--fg` 文字 17px。
   - **助手消息**：**无气泡、全宽排版**——`--fg` 正文 17px、行高 1.62 直接落在 `--bg` 纸面上，左侧 2px `--border-soft` 细线标识归属。这是本页最重要的视觉决策：**助手输出是"读物"，不是"聊天气泡"**——与 warm-editorial 的杂志本质一致，长答案在气泡里是灾难。
   - 消息间距：同类 `--space-4`，说话方切换 `--space-6`。
3. **输入区（常驻底部）**：**SkillPicker 技能选择器**（`RQ-CON-08`）+ Composer 输入框 + 发送按钮。
   - **提问时收起（2026-09-30 用户确认）**：当前有待作答的问题组时，普通消息输入框、技能选择器及发送按钮一起隐藏，作答统一在提问卡内完成；收起题卡或切换题目不恢复输入区。整组提交、全跳过后提交或问题组被移除时恢复，未发送草稿与尚未消费的技能选择保留。历史已提交的提问记录不触发隐藏；运行中的进度与停止操作保持可用。
   - SkillPicker：输入框上方一行的横向滚动标签条——「自动」（默认态）+ 各技能 chip（`.tag` 变体）。选中技能 chip 为 `--accent` 边框 + accent 文字；「发送即消费」：发送后选择器视觉回归「自动」（技术设计 4.2 节定调）。chip 高度 ≥36px、热区 ≥44px。
   - Composer：`--radius-md` 输入区（`--surface` 底、`--border` 边框）、自适应高度（1–4 行）、右下发送按钮（`.btn-primary` 圆形变体 48px，箭头 SVG——运行中变为"停止"方块）。
   - 输入区底部预留 `safe-area-inset-bottom`。

**运行状态条**（progress 事件）：输入框上方 `.run-status`——「正在检索资料…」等文案 + 一枚 12px 小呼吸点（应急时延感知：10 秒未首字出现降级提示"正在生成…建议先按通用安全措施行动"，技术设计第 7 节定调）。

**候选轻提示**（candidate 事件）：消息流顶部 `.candidate-toast`——chip「有 N 条待确认」，点击**展开候选预览**（每条候选一句话 + 来源标注 + 「去档案确认」按钮跳档案页待确认分组），再点收起。**确认动作不在对话页就地执行**（技术设计第 5 节不变量：candidate 不进消息流；确认是候选转稳定层的闸门——`RQ-MEM-04`——在档案页的完整上下文里逐条确认，不做一键轻确认）。预览面板是临时 UI 层，不是消息 content、不参与历史水合。

## 组件选用

- `.subpage-head` — 页头（返回 + 标题 + 技能标签；多技能串联，见布局结构第 1 条）
- `.tag` — SkillPicker chip；`.tag.meta` — 页头技能标签（多技能时串联多个）、消息内元信息
- `.btn-primary`（圆形变体）— 发送/停止
- `textarea`（Composer 变体）— 自适应高度输入
- `.run-status` + `.flame-dot`（小号 12px）— 运行状态条
- `.skeleton`（bubble/doc 变体）— 历史水合骨架
- 以下为消息流自定义 part 渲染器与派生 UI（技术设计 4.2 节组件清单的视觉呈现）——**契约修订**（见下）

### 契约修订（已追加进 components.html，2026-10-06 经用户确认）

1. **`.bubble-user`**（`@source: project` — 使用者消息气泡）：右对齐、`--surface-warm`、`--radius-md`、最大宽 78%。
2. **`.msg-doc`**（`@source: project` — 助手消息正文容器）：无底色、全宽、左侧 2px `--border-soft` 细线、`--text-base` 17px、`--leading-body`。
3. **`.question-card`**（`@source: project` — 统一提问卡）：`.tile` 底、题干 `--fg`、编号选项与说明（整行 ≥48px）+ 与选项两列对齐的「自由回答」入口 + 底部题号、处理进度与上一题/跳过/下一题或提交。**2026-09-30 用户再次确认**：只保留一种提问结构，借鉴 DSH，一次可以提出多题；逐题作答，切换保留答案，返回可改选，整组统一提交。单题是同一组件的 1/1 状态；日常和应急只更换题目内容，点选均只暂存答案，取代此前应急点选即发送规则；事实问题不预选、不推荐答案。组件样例与手机对话直接复用同一模板、样式和控制器，不设手机专用变体。**已提交态**：整组题目、答案与显式跳过记录静态展示，禁止重复提交；未提交即发送后续消息时，旧卡保留未提交草稿，不标为已回答。收起仍保留当前题干；多题事件接入缺口见技术设计第 6.1 节与[HTTP/SSE 契约](../../技术设计/面/consult/HTTP与SSE契约.md)第 10 节。
4. **`.action-card`**（`@source: project` — 应急七节行动卡）：本产品**最重要的单组件**。`.panel` 底（`--radius-lg`、`--elev-raised`——海拔最高，慌乱中一眼锁定）；节标题行 = 序号 + 宋体小标题（`--text-base`、500）；「立即做」节动作行首加 `--accent` 对勾图标（可扫读）；医疗风险行 = `.status.stable/.unruled/.high` 三值徽章（`RQ-EMG-04` 硬校验三值）；每条动作尾部来源标注（六类）为 `--text-xs` `--meta` 上标样式（如「来源：本人报告」）；置信等级四档用文字标签（`confirmed→有据 / likely→较可能 / possible→可能 / unknown→未知`），不用彩色等级条（避免彩色噪声与"专业评分"错觉）；**失效态**（重复评估）：整卡 `--border` 虚线 + 顶部「已过期，见最新卡片」`.status.off` 样式条，不删除。
5. **`.citation-block`**（`@source: project` — 依据区，默认收起）：卡尾「依据 N 条」折叠头（`.tag.meta` 样式）+ 展开后列表——每条：**标题整体可点**（点击跳案例库浏览页 deep-link 定位：`/cases?item=<item_id>`，按 `library` 字段落到案例或资料分区）+ 来源 + 适用范围 + 状态徽章（`.tag.meta`：已发表/内部/虚构样例，`RQ-KB-02` 的界面呈现）。跳转前提是条目仍可检索；**目标已撤下**（检索文档第 4 节：历史引用保留但不得再作为当前依据）时标题不跳转、条目呈现「该来源已撤下」`.status.off`（灰调）标注——撤下判定来自 citation 载荷刷新，不由前端猜测。
6. **`.reasoning-row`**（`@source: project` — 思考折叠行）：默认收起一行「正在分析…」（应急）/「思考过程」（日常，可点开）；内容区 `--text-sm` `--muted`、左侧 `--border-soft` 细线——**视觉区隔于正文**（思考是中间态不是结论，技术设计 6.3 节呈现纪律）。
7. **`.tool-row`**（`@source: project` — 工具调用指示）：默认收起行「查阅资料（2 条）」样式（`--text-xs` `--meta` + 展开箭头）。
8. **`.candidate-toast`**（`@source: project` — 候选轻提示）：消息流顶部 chip + 可展开预览面板（候选一句话 + 来源 + 跳档案页按钮）；不进消息 content、不参与历史水合（Zustand 派生 UI）。

## 数据与文案

- 消息与卡片数据形状引用技术设计第 5 节的 citation 载荷与 6.2 节 action_card 载荷（`item_id/library/title/source/applicable_scope/status/locator/ranking` + 案例扩展字段）——**不新增字段**；行动卡取[通用基座](../../技术设计/technical-details/通用基座.md)第 7.3 节的**通用信封**（`card_id` / `title` / `sections` / `states` / `annotations`），七节的 `key` 与中文小标题、四个状态字段与来源六类的取值词表见[emit_emergency_action_card](../../技术设计/面/consult/tools/emit_emergency_action_card.md)。candidate 预览数据来自 Zustand 候选计数 store（技术设计第 5 节），预览面板只显示候选主题一句话与来源，确认操作去档案页。
- 状态条与错误文案按技术设计第 7 节失败语义表成稿：检索类失败 =「检索暂时不可用」（**不得**写"未找到相关内容"）；中断消息标「本次回答中断」；无档案标注（`AC-02`）由后端注入输出文本，前端原样呈现。
- 无编造指标；置信等级只用上述四档文字（skill 设计禁用无依据精确概率）。

## 状态覆盖

| 区块 | loading | empty | error |
|---|---|---|---|
| 消息流（历史水合） | 骨架屏 `.skeleton.bubble/.doc`（同真实消息形状：3–4 条灰底圆角块） | 不适用（直达此页必带 sessionId；新会话由发送首条消息开启） | `.error-card` + 「重试」+ 「返回列表」；**不显示空对话冒充成功**（技术设计 4.4 节） |
| 消息流（运行中） | 流式渲染本身即反馈：`.run-status` + 首字文本流 | — | `run_failed`：助手消息位 `.error-card`（原因 + 重试按钮）；partial text 保留 + 标「本次回答中断」 |
| SSE 断连 | `.run-status` 文案变「连接中断，正在重连」（重连期间输入框置灰可继续打字） | — | 重连耗尽：`.error-card` + 手动重试（不显示空对话） |
| 401 会话过期 | — | — | 清理本地状态跳登录（技术设计第 7 节） |

骨架屏与真实内容同形状（craft state-coverage）；运行中无 spinner 循环——流式文本即进度。

## 响应式与平台

- **仅手机端**（全局定调见 DESIGN.md）：平板/PC 经手机蒙版渲染；对话是窄阅读面，蒙版体验无损。
- 消息流字号 17px 底线；助手正文行宽即容器宽（≤480px，约 28–34 汉字/行，低于 50ch 上限——移动端阅读可接受）。
- 输入区与运行状态条常驻，拇指可达；发送按钮 48px。
- 长按消息无语境菜单（一期不做复制/编辑入口——技术设计第 9 节不做消息编辑）。

## 动效意图

运行中的动效预算全部给**流式文本**（每 token 追加即最直接的"在动"反馈）；状态条文案切换 150ms 淡入。ActionCard 到达时：整卡 240ms 渐入 + 8px 上移 + 一次 300ms 的 `--elev-raised` 阴影落定（"一张卡放到了你面前"的物理感）——这是全产品唯一的编排级动效时刻，与它"最重要组件"的地位相称。旧卡失效无动画（状态变化即时呈现，`prefers-reduced-motion` 下全部退化为直接呈现）。页面切换 ≤200ms（移动端红线）。

## token 使用

全部契约 token；本页新组件只引用既有 token。accent 配额：发送按钮 + 运行状态呼吸点 + SkillPicker 选中态同属"进行中"语义单元（一处）；ActionCard「立即做」对勾与失效条之外的强调（第二处）——恰在红线内。助手正文零 accent（读物的纸面纯净）。
