# 页面设计：档案页

> **追溯**：`RQ-MEM-02`（自动写入与分层）、`RQ-MEM-03`（查/纠/删）、`RQ-MEM-04`（推断不得冒充事实）、`RQ-MEM-05`（一期独占与来源标注）、`RQ-MEM-06`（一页摘要）、`RQ-MEM-07`（多对象与切换）、`RQ-CON-07`（注入与标注）、`AC-07`、`AC-08`、`AC-18`、`AC-22`；档案数据形状、稳定层/候选层规则、九个领域取值、纠错规则由[个性化档案](../../技术设计/technical-details/个性化档案.md)拥有（本页只做视觉与交互）。
> **契约**：[DESIGN.md](../DESIGN.md) + [tokens.css](../tokens.css) + [components.html](../components.html)。
> **状态**：初稿，待用户确认。

## 页面目的与受众

Reading this as: 档案管理页 for 想核对与纠正"系统对我的孩子记了什么"的监护人，with 一份可核对的个人手册的语言，leaning toward warm-editorial × 火焰橙。本页的全部设计张力在一条需求上：**`RQ-MEM-04`——系统推断不确认就永远只是"待确认"**，视觉上不得让候选内容看起来像事实。

## 布局结构

一级页面，渲染 tab 栏（当前态：档案）。**单页内切换对象**（页面清单确认时定：不拆两层）。自上而下：

1. **页头**：宋体标题「档案」（`--text-xl`、500）。
2. **支持对象切换器**：页头下横向滚动 chip 行——各支持对象名（`.tag`；当前对象 accent 边框选中态）+ 末尾「+ 新建对象」chip。点击切换**就地切换**整页内容（切换动画：内容 150ms 交叉淡入，无页面跳转——会话与对象的绑定在会话开始时定，本页切换不影响进行中会话，`RQ-MEM-07` 语义）。多对象互不可见由授权保证（`AC-22`），界面不重复表达权限语义。
3. **一页摘要区**：当前对象的 `.panel`（唯一抬升面板）——「关于 TA 的当前认识」：
   - 摘要条目按稳定层字段集分组呈现（偏好称呼、沟通方式、感觉需求、可能引起不适的事、如何帮助、Please do / Please don't、疼痛或不适的表达、重要的人、关键健康与安全信息——引用档案文档第 4 节摘要取数，**只取稳定层**）；
   - 每条带来源与最近确认时间（`--meta` `--text-xs`，如「本人自述（经监护人转述）· 10-02 确认」——`RQ-MEM-05` 来源类型直出）；
   - 每条尾部「纠正」文字按钮（`.btn-quiet` 小号）——点击进入该条的纠正流（见状态覆盖）。
   - 摘要区头部一行说明（`--muted` `--text-sm`）：「摘要只收你直接说过或确认过的内容」（`RQ-MEM-06` 语义的界面直译）。
4. **完整条目区**：摘要下方 `.tile` 列表（`--radius-md`、无阴影）——全部条目按九领域分组（关于本人、沟通、感觉、日常与变化、情绪与调节、支持策略、生活与适应、健康、安全与风险、其他；领域为可折叠分组头，`--fg-2` `--text-sm` 500）：
   - 条目行：主题（`--fg`）+ 描述（`--muted` `--text-sm`、两行截断）+ 元信息（来源类型 + 确认状态 + 时间，`--meta` `--text-xs`）；
   - `confirmation=unconfirmed` 的条目（含 `system_observation` / `ai_inference`）**整体呈现在「待确认」分组**——固定在完整条目区**最顶部**、分组头「待确认（N）」用 `.status` 的 `--status-unruled`（琥珀）小圆点标识，条目行加「待确认」`.tag`（`--meta` 色非彩色强调）+ 右侧「确认」/「删除」两个操作（`.btn-secondary` / `.btn-quiet` 小号）；
   - `freshness=stale`（90 天降权，档案文档第 3 节）的条目：行首「已降权」小标 + 描述折叠（点开可见，默认收起）；
   - 已确认条目行右侧操作：「纠正」「删除」（删除须二次确认——见状态覆盖）。
5. **新建条目入口**：完整条目区尾「补充一条」`.btn-secondary`（手动补充档案——`RQ-MEM-03` 查看纠正删除之外，档案文档第 5.2 节允许使用者补充）。

## 组件选用

- `.panel` — 一页摘要区
- `.tile` — 条目行、分组容器
- `.tag` — 对象切换 chip、领域分组头、「待确认」标
- `.status`（unruled 变体圆点）— 待确认分组标识
- `.btn-secondary` / `.btn-quiet` — 确认/纠正/删除/补充操作
- 删除二次确认 — **契约外新组件**（见契约修订）

### 契约修订（已追加进 components.html，2026-10-06 经用户确认）

**`.confirm-sheet`**（`@source: project` — 底部确认操作单）：底部滑入面板（`--surface` 底、顶部圆角 `--radius-lg`、`--elev-raised`）：标题 + 说明文字 + 操作按钮行（危险操作 `.btn-danger` + 取消 `.btn-quiet`）；背景 `--bg` 80% 透明遮罩（tap 关闭）；滑入 240ms `--ease-standard`。用于删除条目等不可即时撤销操作的确认（档案删除须覆盖衍生使用——`AC-08`，值得一次显式确认）。

## 数据与文案

- 条目字段引用档案文档第 2 节数据形状（domain/topic/description/contexts/manifestations/origin/confirmation/freshness/时间戳/superseded_by）与第 6 节九领域取值——**不新增字段**。
- 来源类型文案映射：`user_statement→你说过`、`guardian_observation→你的观察`、`third_party_report→第三方转述`、`document→文档记录`、`system_observation→系统观察`、`ai_inference→AI 归纳`——六类来源标签**全部可见**（`RQ-MEM-02` 条目须携带来源；skill 的 ActionCard 来源六类与此同源，用词对齐）。
- 纠正语义文案：纠正 = 「新增一条更正，旧记录保留为历史」——不写「修改」（档案文档第 3 节不变量 3：不物理覆盖，纠正的界面语言不得暗示覆盖）。
- 一页摘要区头的固定说明句（上文引号）直译 `RQ-MEM-06`；无编造内容。

## 状态覆盖

| 状态 | 形态 |
|---|---|
| loading（对象切换/首次） | 摘要区 + 条目区骨架（灰底同形块）；对象切换器静态先行 |
| empty（新对象，无任何条目） | 空态卡：「还没有记录」+ 一句"咨询中你说的关于 TA 的事，会自动记在这里；也可以现在补充一条" + 「补充一条」主按钮（首用空态即引导时刻） |
| error | 内联错误卡 + 重试；对象切换器保持可用（单对象失败不吞全局导航） |
| 删除确认 | `.confirm-sheet`：「删除这条记录？」「删除后咨询和检索都不会再用到它」+「删除」（danger）+「取消」 |
| 纠正流 | 展开内联表单（原条目下方）：预填原描述的 textarea + 提交「更正」——提交后原条目转历史态（行首「已更正」标），新条目进入列表 |
| 写入失败（补充/纠正提交） | 内联错误 + 保留已填内容（不清空） |

**候选层视觉不变量**（本页最重要的验收对象，`AC-18`）：unconfirmed 条目只能出现在「待确认」分组、只带「待确认」标、不进摘要区——三个呈现位置由布局结构保证，不由实现者自觉。

## 响应式与平台

- **仅手机端**（全局定调见 DESIGN.md）：平板/PC 经手机蒙版渲染。
- 条目操作按钮热区 ≥44px；对象切换 chip 横向滚动（不换行堆叠——切换是平级单选，滚动语义更准）。
- 长描述两行截断 + 展开（核对面板完整信息不因截断丢失）。
- 「确认」「删除」在待确认条目上**双按钮并排**、间距 ≥12px（防误触删除——确认是高频正向操作，删除是低频危险操作，不放在同一拇指滑动路径上）。

## 动效意图

对象切换：150ms 内容交叉淡入（切换是浏览不是导航，无需位移感）；待确认条目被确认后：该行 240ms 淡出 → 从「待确认」分组移入对应领域分组（位置变化的物理感传达"转正"）；`.confirm-sheet` 底部滑入 240ms。无循环动效。

## token 使用

全部契约 token + 一个新组件（confirm-sheet，仅引用既有 token）。accent 配额：当前对象 chip 选中态一处 + 空态主按钮一处。**待确认分组刻意不用橙色**（琥珀 `--status-unruled` 圆点）——待确认是"需要你留意"的中间态，不是强调态；橙色留给主动作。摘要面板靠海拔（`--elev-raised`）而非颜色获得重量。
