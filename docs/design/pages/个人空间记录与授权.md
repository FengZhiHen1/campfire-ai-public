# 页面设计：个人空间、记录与授权

> **页面目的**：让合法授权主体及获授权的支持者在明确的支持对象范围内积累带来源的观察，并精确管理有限成员访问。使用[设计契约](../DESIGN.md)；对应 `RQ-SP-01～05`、`RQ-REC-01～04`。

## 内容层级与页面划分

`/spaces` 列表按本人有权访问的空间显示偏好称呼及关系，不展示无权空间；切换对象先清除旧页面可见信息和流式请求。`/spaces/{id}` 详情先展示当前空间和本人可执行的动作，再分“事项”“记录”“已确认安排”“成员访问”四个入口；成员访问只对合法授权主体或范围内受托管理员可见。待核验的申请页独立表示 `pending_verification`，此时不邀请其他成员，也不上传共享个人资料。

记录区以时间和情境排序，卡片上明确作者、原话/转述/解释/AI 草案、发生时间与未知；不同观察并排出现而非合并为权威标签。新增记录输入允许简短自然叙述，AI 整理需原记录者核对后再提交。更正查看旧版、理由及谁提出，不用修改原文静默覆盖。成员区逐项展示允许查看的信息类别、操作、用途和到期时间；受托人界面禁止选择自己没有的权限，不能出现“自动继承所有成员”的快捷选项。

使用 `ScopeChip`、`StateBadge`、`InputField`、`SourceNote`、`ActionButton`、`Feedback`；高级授权区可折叠，但到期和接收者不得藏在 hover 内。手机记录保持单列，授权确认单独一步，桌面详情与来源可左右并列但不同时展示两个支持对象的内容。

## 数据、文案和流程

空间列表与详情来自 `GET /api/v2/spaces`、`GET /api/v2/spaces/{id}`，待核验申请由 `POST /api/v2/spaces` 创建；记录来自同空间的 `GET/POST /records` 及纠错端点。授权提交 `POST /api/v2/spaces/{id}/grants`，列出操作、类别、用途、期限和接收者；撤销提交 `/grants/{grant_id}/revoke`，收到服务端成功后界面立即移除该成员的当前可见权限并提示外发副本不可收回。若核验尚无可用负责人，只展示“共享暂不可用”并保留私人事项入口；不把待核验申请写成已经有权共享。

引导语：“你的角色不自动允许查看每个人的资料”“新成员只看到被明确授权的范围”“出现身份争议时相关授权暂时停用”。空间合并只在合法授权核实后由权利主体逐项批准，不提示未经核实的其他空间名称。

## 五态覆盖

| 状态 | 记录区 | 成员授权区 |
|---|---|---|
| populated | 来源、情境、原话/更正和分歧可追溯 | 范围、到期、授予来源及撤销动作明确 |
| loading | 同形短记录骨架，保持当前空间名称 | 禁止在权限未核实期间编辑授权 |
| empty | “还没有记录，可先写一句你观察到的事”，不要求填诊断 | “尚未邀请任何成员”，若申请待核验不出现邀请按钮 |
| error | 授权库不可用时整区拒绝，回到公开内容；不重用旧对象缓存 | 提交失败不展示邀请/撤销已生效，保留输入和错误追踪号 |
| edge | 两个同名空间、老师与家属观察冲突、长叙述、作者离开机构和修订 412 均保持来源 | 上游撤销、委托到期、争议与创建者退出时相关授权即时停用，不静默扩大访问 |

## 无障碍、动效与验收

文本状态标签不靠颜色，按钮热区至少 48px；更正/撤销有明确焦点返回与确认对话，提交错误聚焦摘要，长名称换行。切换对象无连续过渡动画以免残留旧人信息。检验 `AC-SP-01～05`、`AC-REC-01～03`：包括多空间切换、受托自我提权、待核验申请与异议冻结。真实身份核验流程、专业确认资源和用户能否理解授权范围仍缺证据。
