# 页面设计：私人事项与空间转入

> **页面目的**：让已主动保存的事项可回访、修订与关闭，同时避免私人草稿在建空间后自动变成共享档案。消费[设计契约](../DESIGN.md)，依据 `RQ-CTX-03/06`、`RQ-SP-02`。

## 结构与视觉优先级

`/matters` 的主区按“需要继续”“已完成”呈现**仅本人**事项；列表顶部保留“没有自动保存对话”的说明和“描述一件事”入口。`/matters/{id}` 先显示私人范围标识，再列目标、已知事实、未知和下一步，来源点按可核对；AI 草案与用户修改用文字标注，不能把保存视为长期诊断。只有用户主动点击“考虑与他人协作”才出现空间核验与转入流程。

转入采用独立核对页：第一屏选择**已核验且当前有权写入**的支持对象；第二屏逐项勾选记录/下一步并校对来源、接收者和可见类别；最后确认“转入的内容将由相应获授权成员看见”。未获核验空间时只能发起待核验申请，不显示伪造的已共享预览。使用 `ScopeChip`、`StateBadge`、`SourceNote`、`InputField`、`ActionButton` 和 `Feedback`，长列表不做强制卡片等宽网格。

## 数据、跳转和文案

私人事项来自 `GET /api/v2/matters` 及 `GET/PATCH/DELETE /api/v2/matters/{id}`；转入用 `POST /api/v2/matters/{id}/transfers`，载荷包含目标空间、所选字段与核对版本。成功后去目标 `/spaces/{id}/matters/{newId}`，私人原文保留在原范围；失败不改变原文，不显示“部分资料已共享”。用户可回 `/assist` 继续通用支持。不得在空间资料被撤销后通过私人列表再次打开旧摘要。

## 五态与边界

| 状态 | 列表/详情/转入 |
|---|---|
| populated | 每项显示范围、更新日期和下一个需核实动作；转入预览列明接收者与条目 |
| loading | 同形列表骨架和明确“正在核对权限”；提交等待不乐观展示已共享 |
| empty | “还没有保存的事项。描述一件事，核对后再决定是否保存。”并有入口 |
| error | 读取失败保留上次仅本页会话内视图但标识未更新；转入失败保留所选字段并提示重试，不泄露目标空间存在 |
| edge | 无合法空间、多个 Space 名称相近、授权中途撤销、长叙述、同时修改版本 412、重复提交均须停在预览并重新核对 |

## 响应式、无障碍和验证

手机单列逐项复核，主确认按钮 48px 热区并在最后一屏出现；桌面仅将来源侧注独立放边栏，主体文本仍限读宽。范围、草案和可见对象用文字而不是仅颜色表示；使用原生复选框语义和键盘顺序。可用 `AC-CTX-04～05`、`AC-SP-04～05` 验证未保存不出现、未经核验不共享、撤销后旧信息不能成为影子事项。真实用户是否能分清私人与共享尚未测试。
