# 页面设计：公开首页与现场支持

> **页面目的**：未登录也能取得已审阅的基础内容与真实求助路径；登录后从准备、正在发生、复盘三种情境自然进入。调性沿用[设计契约](../DESIGN.md)的暖纸面和低刺激阅读。业务依据 `RQ-CTX-01`、`RQ-NOW-01～02`；不是上线内容稿。

## 内容与布局

首页首屏先出现可理解的主句“先看眼前需要什么”，下方给“现在遇到困难”的直接入口，再排“接下来有件事”“刚发生一件事”。已审阅的公开内容作为始终可见的独立区块，注明适用边界、内容版本和现实求助渠道；无真实审阅时不放未经审核的安全步骤。底部明确“这里不提供诊断、用药或实时专家接管”。不展示旧行为桶选项或档案必填表。

桌面以一列短阅读宽度承载公开帮助，旁侧错落放置其他两种情境入口；手机单列，现场支持入口与求助链接靠近易触区域，导航不挤占可见安全内容。使用 `SituationEntry`（`.entry`）、`PublicSafetyNotice`（`.notice--public`）、`ActionButton`（`.action`）和 `Feedback`（`.feedback`），颜色只取 `tokens.css`，不新增组件。

## 数据、跳转与文案

`GET /api/v2/public/support?topic=<枚举>` 提供已发布内容、适用条件、审阅版本、更新时间和现实求助路径。公开区不得请求或展示空间资料。点击“查看基础支持”留在公开详情；选择其他情境进入 `/login`，登录后到 `/assist`，但不把登录前文本默默发送给模型。页面提示：“AI 情境澄清需要登录，公开基础内容不用登录”；不能显示“专家正在接管”之类不实文案。

## 五态与异常

| 状态 | 公开内容区 | 情境入口区 |
|---|---|---|
| populated | 显示审阅版本、适用范围和可达渠道 | 三个行动入口 |
| loading | 同尺寸骨架，保留已缓存的**公开**上一版本及明显时间提示；不伪称最新 | 入口不依赖生成，立即可点 |
| empty | 未有专业批准内容时明确“此项内容尚未开放”，不能由 AI 填空；提供可核实的现实求助说明（如渠道本身也缺证据则暂停公众发布） | 仍可了解后续登录流程，真实 AI 功能按发布开关启用 |
| error | 显示访问失败、重试与非模型求助方向；不把错误当空白 | 登录/跳转故障保留公开页 |
| edge | 断网只显示已取得的公开版本且提示非实时；长段内容分段，不以轮播藏第一行动 | 320px 宽手机按钮仍可触、字号不缩小 |

## 平台、动效与验收

Web 手机触区至少 48px，正文至少 17px；键盘能依次访问入口和求助链接，焦点清楚，语义标记不靠颜色。只允许导航短淡入，减弱动效时去除。验证 `AC-CTX-01`、`AC-NOW-01～02`：匿名用户可访问审核内容、不能调用 AI；模型、Redis 故障及离线不让旧私人计划冒充最新。视觉颜色对比与真实内容可读性尚未经用户和辅助技术测试。
