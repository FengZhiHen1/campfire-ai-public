# 页面设计：应急表单页

> **追溯**：`RQ-EMG-01`（最小输入、八项可跳过）、`RQ-EMG-02`（追问判据，前端只承载 question 卡）、`RQ-ACC-02`（无档案不阻断）、`AC-02`、`AC-03`；八项字段与预取逻辑由[应急 skill](../../技术设计/面/consult/skills/emergency-consulting.md)与[咨询对话界面](../../技术设计/technical-details/咨询对话界面.md)第 6 节拥有（本页只做视觉与交互）；提交端点的形状见[HTTP/SSE 契约](../../技术设计/面/consult/HTTP与SSE契约.md)第 5 节。
> **契约**：[DESIGN.md](../DESIGN.md) + [tokens.css](../tokens.css) + [components.html](../components.html)。
> **状态**：2026-10-11 用户授权全页面 UI 重构；布局结构记录本轮实现。业务字段与安全硬文案沿用原契约。

## 页面目的与受众

Reading this as: 应急采集表单 for 正在现场、可能只用一只手操作的监护人，with 稳定火光的语言，leaning toward warm-editorial × 火焰橙。这一页的设计目标只有一个：**让慌乱中的人 10 秒内能提交**——每多一个必填项、多一次键盘弹出，都是对 `RQ-EMG-01` 的背叛。多为勾选、全部可跳过、提交按钮永远可达。

## 布局结构

次级页面保留八题逐题采集与退出导航。跳过语义用轻量暖底说明明确展示；题号、进度、20px 题干、整行选择控件依次排布。单选与多选分别有圆形/方形指示，不预选事实答案。

底部控制区常驻屏幕：上一题保留在采集区，跳过/下一题与随时提交均可达，主体为控制区预留高度和安全区。失败保留已填内容。截图 fullPage 时显式将 emergency-controls 入流，截图之后恢复 fixed。

> 本轮布局结构与 DESIGN.md 的 2026-10-11 修订优先于下方早期组件与动效说明中的视觉细节；字段、归属、确认、失败及安全文案约束继续有效。

## 组件选用

- `.subpage-head` — 返回头（「← 退出应急」）
- `.flame-dot` — 标题区（应急身份标识，与首页应急入口同一记忆点）
- `.field` + `textarea` — 第七项自由文本
- `.btn.btn-primary` / `.btn.btn-quiet` — 下一题/跳过、提交
- `.tile.choice` — 三选一选择卡：选中态 = 1.5px `--accent` 边框 + `color-mix(accent, transparent 94%)` 背景 tint + 对勾
- `.check-row` — 多项勾选行
- `.progress-track` / `.progress-fill` — 分步进度
- `.error-card` — 提交失败

### 契约修订（已追加进 components.html，2026-10-06 经用户确认）

1. **`.check-row`**（`@source: project` — 勾选行）：min-height 48px、左侧 20px 方形勾选框（`--radius-sm` 小、1.5px `--border`；选中 = `--accent` 填充 + 白色对勾 SVG）+ 右侧标签（`--fg`）；整行可点；选中态不改变行高（防跳动）。
2. **`.progress-track` / `.progress-fill`**（`@source: project` — 细进度条）：2px 高、`--border` 轨道、`--accent` 填充；fill 宽度随题号过渡（240ms `--ease-standard`）；仅语义为"位置"不承载任何承诺。

## 数据与文案

- 八项题干与选项文案为**初拟成稿**（上文引号内），实现前须与 skill 的现场采集措辞对表校准一次——题干措辞以 skill 设计为准，本页只定呈现。
- 跳过语义文案固定："跳过 = 未排除，不会当作正常"（`RQ-EMG-01` 原文语义，不得弱化为"暂时跳过"）。
- 无档案时（`RQ-ACC-02`）：正常进入，**不显示任何档案相关提示**（有档案时的预取是无感的，无档案也不告知——输出阶段由后端标注"未使用个性化档案"，不在表单页预告）。

## 状态覆盖

| 状态 | 形态 |
|---|---|
| 分步中 | 静态题面直接渲染（八项是本地结构，无网络请求） |
| 提交 submitting | 按钮"正在提交…" + `disabled`；**不锁题面**（返回修改仍可行，直到会话建立） |
| 提交失败 | 按钮上方 `.error-card`：具体原因（网络/服务不可达）+ 「重试」；**不清空已填内容** |
| 网络离线预防 | 提交前检测 `navigator.onLine`，离线时直接给"网络不可用，请检查连接后重试"（不发起注定失败的请求） |

八项采集本身**无 loading/empty 态**——它是本地结构（skill 静态定义），不请求远端。

## 响应式与平台

- **仅手机端**（全局定调见 DESIGN.md）：平板/PC 经手机蒙版渲染；分步流在蒙版内不变。
- 单手可达：跳过与下一步按钮在屏底拇指区；勾选行全宽（整行热区）。
- 软键盘：第七项 textarea 聚焦时按钮区随视口上浮（`visualViewport` 处理），提交常驻不被键盘遮挡。
- 字号底线：题干 ≥16px（`--text-lg`）、选项 ≥16px（`--text-base`）。

## 动效意图

服务时延焦虑（`RQ-EMG-03`）：题间 240ms 方向性滑动（视觉上"在前进"）；提交后进入对话页的过渡**从快**（≤200ms，移动端页面切换上限）——从提交到"正在分析现场情况…"的首屏提示要无缝衔接，不留空白帧。进度条 240ms 平滑填充。无循环动效（呼吸点只在标题区一处，作为"火光仍在"的心理锚点，不参与交互反馈）。

## token 使用

全部契约 token；两个新组件（check-row、progress）也只引用既有 token。accent 配额：选择卡选中态 + 进度条填充 + 主按钮同属"当前正在推进"的语义单元，视作单屏一处强调；勾选框选中填充计入第二处——恰好在 ≤2 红线内。
