# 页面设计：应急表单页

> **追溯**：`RQ-EMG-01`（最小输入、八项可跳过）、`RQ-EMG-02`（追问判据，前端只承载 question 卡）、`RQ-ACC-02`（无档案不阻断）、`AC-02`、`AC-03`；八项字段与预取逻辑由[应急 skill](../../技术设计/面/consult/skills/emergency-consulting.md)与[咨询对话界面](../../技术设计/technical-details/咨询对话界面.md)第 6 节拥有（本页只做视觉与交互）；提交端点的形状见[HTTP/SSE 契约](../../技术设计/面/consult/HTTP与SSE契约.md)第 5 节。
> **契约**：[DESIGN.md](../DESIGN.md) + [tokens.css](../tokens.css) + [components.html](../components.html)。
> **状态**：2026-10-11 用户授权全页面 UI 重构；布局结构记录本轮实现。业务字段与安全硬文案沿用原契约。2026-11-18 角色化重做（本轮）：退出键改用共享返回字形但保留「退出应急」文字；去掉模板左边线与通用 `.selection` / `.progress-track` 装饰，选中、按压、当前题、提交中、失败各自成一套相符的形态；八项字段、跳过=未排除、提前提交、医疗风险与来源语义不变。

## 页面目的与受众

Reading this as: 应急采集表单 for 正在现场、可能只用一只手操作的监护人，with 稳定火光的语言，leaning toward warm-editorial × 火焰橙。这一页的设计目标只有一个：**让慌乱中的人 10 秒内能提交**——每多一个必填项、多一次键盘弹出，都是对 `RQ-EMG-01` 的背叛。多为勾选、全部可跳过、提交按钮永远可达。

## 布局结构

次级页面保留八题逐题采集与退出导航。跳过语义置于进度前。八段进度是一条 2px 的**位置线**：已作答=暖墨实线、已跳过=赭黄虚线、未作答=极浅点线，当前题不复用「更亮的橙线」而改成这一段上的**一枚圆点**——进度是位置，不和提交键抢「当前操作」的强调色。题干使用 22px 无衬线字（可访问下限 ≥16px）。整行选项用分隔线，单选与多选分别有圆形和方形指示，不预选事实答案。

底部常驻跳过、下一题和独占一行的提交按钮。第二题起显示「上一题」。主体为控制区预留空间及安全区。失败保留已填内容并显示重试入口。

### 交互状态的视觉分工（2026-11-18）

同一屏上五种状态各自成一套形态，互不借用同一条装饰：

| 状态 | 形态 |
|---|---|
| 未选中的选项行 | 无底色，只有一截文字侧的分隔线 |
| 按压（未选中行 `:active`） | 整行沉成暖沙底、轻微内缩——「手指按下去了」 |
| 选中（`data-checked`） | 整行浮起成暖白小卡（浅橙底 + 1.5px 橙描边 + 抬升阴影），方形/圆形标记填橙出对勾 |
| 当前题 | 进度线上的一枚橙圆点（带浅橙外圈），不放大面积强调色 |
| 提交中 | 题面容器 `inert` 且压暗，仍保持可读；三键禁用；提交键进入 `data-pending` 形态（非纯灰化）并附「正在提交，先别改题。」说明行 |
| 提交失败 | 提交区上方一张白卡：左侧危险色记号、标题即「出现了未预期的错误」、卡内「重试」；已填内容不清空 |

退出键与其它次级页共用 `shared/ui` 的返回字形（`BackChevron` + `.sp-back`），但**文字保留「退出应急」**——退出不是返回，是要丢弃现场采集的决定。它是 `button` 而非 `BackLink`，因为要先经控制器判定（有已填内容需确认）。

> 本轮布局结构与 DESIGN.md 的 2026-10-11 修订优先于下方早期组件与动效说明中的视觉细节；字段、归属、确认、失败及安全文案约束继续有效。

## 组件选用

- `.subpage-head` — 返回头：`shared/ui` 的 `BackChevron` + `.sp-back` 字形，文字保留「← 退出应急」
- `.flame-dot` — 标题区（应急身份标识，与首页应急入口同一记忆点）
- `.field` + `textarea` — 第七项自由文本
- `.btn.btn-primary` / `.btn.btn-quiet` — 确认单里的「退出并丢弃 / 继续填写」
- `.progress-track` / `.progress-fill` — **本页不再消费**：分步进度改由页面本地 `emergencyForm.module.css` 的 `.progressTrack`（八段位置线）实现（见「交互状态的视觉分工」）
- `.status.stable/.unruled/.high` — 提交失败区外，行动卡里的医疗风险三值徽章（对话页契约修订 4）
- `.error-card` — 提交失败（本页失败区用本地 `.failure` 卡 + 本区语义，保留 `role="alert"`）

### 契约修订（已追加进 components.html，2026-10-06 经用户确认）

1. **`.check-row`**（`@source: project` — 勾选行）：min-height 48px、左侧 20px 方形勾选框（`--radius-sm` 小、1.5px `--border`；选中 = `--accent` 填充 + 白色对勾 SVG）+ 右侧标签（`--fg`）；整行可点；选中态不改变行高（防跳动）。
2. **`.progress-track` / `.progress-fill`**（`@source: project` — 细进度条）：2px 高、`--border` 轨道、`--accent` 填充；fill 宽度随题号过渡（240ms `--ease-standard`）；仅语义为"位置"不承载任何承诺。
   - **2026-11-18 页内偏离说明**：这两条契约仍是别处可用的通用细线；**应急表单页不再使用它们**，而用页面本地 `.progressTrack`（八段、三种线型、当前题圆点）。原因：通用 2px 细条是装饰性进度，本页需要的是「八题现场位置 + 三种作答状态 + 当前题」的组合语义，把两者硬拼会在一条细线上塞进互相冲突的强调。契约外观本身未改，只是本页换了实现。

## 数据与文案

- 八项题干与选项文案为**初拟成稿**（上文引号内），实现前须与 skill 的现场采集措辞对表校准一次——题干措辞以 skill 设计为准，本页只定呈现。
- 跳过语义文案固定："跳过 = 未排除，不会当作正常"（`RQ-EMG-01` 原文语义，不得弱化为"暂时跳过"）。
- 无档案时（`RQ-ACC-02`）：正常进入，**不显示任何档案相关提示**（有档案时的预取是无感的，无档案也不告知——输出阶段由后端标注"未使用个性化档案"，不在表单页预告）。

## 状态覆盖

| 状态 | 形态 |
|---|---|
| 分步中 | 静态题面直接渲染（八项是本地结构，无网络请求） |
| 提交 submitting | 按钮"正在提交…" + `data-pending` 形态 + `disabled`；说明行改成"正在提交，先别改题。"；**题面与导航一并锁定**（题面容器 `inert` 并压暗，上一题/跳过/下一题同时禁用）——提交载荷在按下按钮时已经确定，此时仍允许改题会让界面答案与已提交内容不一致（见下方「功能语义审查修订」） |
| 提交失败 | 按钮上方失败卡（本地 `.failure` 卡，`role="alert"`）：左侧危险色记号 + 具体原因（网络/服务不可达）+ 「重试」；**不清空已填内容** |
| 网络离线预防 | 提交前检测 `navigator.onLine`，离线时直接给"网络不可用，请检查连接后重试"（不发起注定失败的请求） |

八项采集本身**无 loading/empty 态**——它是本地结构（skill 静态定义），不请求远端。

## 响应式与平台

- **仅手机端**（全局定调见 DESIGN.md）：平板/PC 经手机蒙版渲染；分步流在蒙版内不变。
- 单手可达：跳过与下一步按钮在屏底拇指区；勾选行全宽（整行热区）。
- 软键盘：第七项 textarea 聚焦时按钮区随视口上浮（`visualViewport` 处理），提交常驻不被键盘遮挡。
- 字号底线：题干 22px、选项 ≥16px（`--text-base`）。题目行高按 1.32 收紧，题干作为一屏最重一行。

## 动效意图

服务时延焦虑（`RQ-EMG-03`）：题间 240ms 方向性滑动（视觉上"在前进"）；提交后进入对话页的过渡**从快**（≤200ms，移动端页面切换上限）——从提交到"正在分析现场情况…"的首屏提示要无缝衔接，不留空白帧。进度条 240ms 平滑填充。无循环动效（呼吸点只在标题区一处，作为"火光仍在"的心理锚点，不参与交互反馈）。

## token 使用

全部契约 token；本页组件只引用既有 token，不写死颜色与间距。accent 用量（2026-11-18 复核）：须答中「当前题圆点」+ 选中行底与标记填充 + 提交主键 + 「上一题」按压反馈；集中在"当前这一题 / 当前这一项 / 主要操作"三处（[DESIGN.md](../DESIGN.md)「单屏 accent 只承担品牌、当前状态与主要操作」），因此不按处数计。医疗风险在行动卡中走稳定的三值语义色，不用 accent。
