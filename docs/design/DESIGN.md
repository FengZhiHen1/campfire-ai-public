# 篝火智答（Campfire-AI）Design System

> 2026-11-18 在原有篝火品牌上重构手机 H5。色彩、字阶和间距归 [tokens.css](tokens.css)，共享组件形状归 [components.html](components.html)，各页业务呈现归各自的页面设计。

## 调性与方向

篝火智答是面向孤独症人士及其支持网络的手机咨询应用。页面用近白暖底、系统无衬线和清楚的空间层级。品牌字标可以保留宋体，火焰橙用于品牌、当前状态和主操作。日常咨询的第一视觉焦点是输入与回答，应急时优先呈现当前问题、风险说明和可执行操作。

## 移动界面验收（2026-11-18）

- **首页**同时给出日常咨询和独立的应急入口。应急从首屏点一次进入现场采集。首页草稿转入会话后，用户明确发送才启动咨询。
- **对话**使用轻页头、可滚动消息区、常驻输入区。回复正文使用整幅阅读面。工具过程低权重，可独立展开。建议依据可从对应回答打开。停流、重连、失败恢复、跳过引导和待作答保持可操作。
- **应急**沿用八项现场采集。风险提示、进度、当前问题与提交有明确层级。逐项可跳过，跳过表示未排除。允许提前提交；最新行动卡及其医疗风险和来源保持可辨。
- **资料与记录**采用同一视觉体系。案例与专业资料保留分区和来源；档案候选和稳定记录有文字区分；纠正、删除和确认有明确反馈。
- **实现与检查**。复杂的交互状态和用例协调放在 ViewModel，视图保留布局、控件及焦点等 DOM 行为。以同一组虚构数据比对改造前后的手机截图。在 320–430 CSS px 核对首屏入口、输入与发送、无横向溢出；用键盘检查焦点，并分别记录真实设备和浏览器模拟的验证范围。正文至少 16 CSS px，主要交互热区至少 44×44 CSS px。


## 2026-10-11 全页面重构原则

依据：用户指出档案条目、案例展开、设置及几乎全部页面的 UI 均需要重构，并明确要求沿用原 DESIGN 意向、由实现方完成整体优化。本轮授权涵盖呈现与交互，不改后端 API、数据归属或权限纪律。

- **咨询优先**：首页直接写草稿；显式进入时调用现有建会话用例，草稿传入对话输入器，发送后才触发运行。失败保留草稿、防止重复创建；初始首页仍不请求数据。
- **长文阅读**。长回答按全宽正文排版。2026-11-18 起，字阶采用上文的移动界面规则。
- **轻量结构**：圆角 10/14/20px，抬升阴影改为 0 4px 16px、6% 暖墨；摘要、说明和时间线优先用分隔与留白，不把每段内容包成大面板。
- **记录与操作分层**：档案摘要正文独占一行，来源/时间与纠正分开；候选与稳定层仍逐条操作、删除仍二次确认。分区锚点协助长页定位。
- **渐进展开**：案例标题、摘要、发表/虚构状态与简短来源先行；完整来源与适用范围通过独立 disclosure 阅读。正文展开控件带 aria-expanded 与 aria-controls，正文分节排版。
- **设置可扫描**：账号、记录与帮助、数据告知、使用边界、退出五组。记忆与使用说明均可直接进入；安全硬文案与外部模型告知保留。
- **手机操作可达**：10 个页面保留手机单列与宽屏外壳；对话阅读和输入区在手机上同样有 16px gutter，应急提交常驻底部，内容预留空间；所有可操作元素至少 44px。
- **同一套状态**：骨架、错误、空态、确认单继续复用既有基元。新增空会话起点只填写草稿，不预选事实，不自动发送。

验收入口：前端 lint/typecheck/test/build、设计文档检查、shots（10 页×2 视口×2 图种）与 e2e（内容与关键交互）。关键状态截图统一在 .tmp/screenshots/states：`pnpm e2e` 的 `states-manifest` project 机械核对「声明的关键状态在两种视口均已取证、sidecar 批号属于本轮、逐张回读复算哈希一致」，核对通过后写出可复算的 `states/manifest.json`；过程截图不入库。

## 2026-10-11 功能语义与交互审查

用户最新裁决：排查并修复全部页面的问题，历史设计不构成保留错误交互的理由。本轮以真实任务、入口含义、数据可达和操作结果作为验收依据。

- 首页资料库入口明确命名「资料库」，进入资料分区；案例/资料分区各有自己的标题、搜索范围和空态，不暗示跨库搜索。
- 次级页返回实际来源，直接打开时使用合理默认入口；说明页提供对应功能入口，历史水合失败仍可返回咨询列表。
- 登录前即可看到人工重置提示，并明确账号名不要求邮箱。仅缓存展示名供刷新/同源新标签恢复；会话仍从 unknown 经真实查证建立，登出/匿名状态清除展示名，不存凭据或授权结论。
- 档案补充与纠正互斥；纠正领域只读，避免呈现不会保存的字段。切换对象前确认丢弃已编辑草稿，提交中的对象不能切换；旧对象迟到分页不混入新对象。
- 档案读取服务端下一页游标，后续记录可加载，失败保留当前内容并可重试；不把首批结果冒充完整数据。
- 应急跳过明确推进下一题，跳过仍按未排除；退出已填写采集须确认，提交中禁用题目切换和输入。
- 回答与资料按标题、段落、列表、引用、强调和行内代码排版，所有内容经 React 转义；流式未完成标记不阻塞渲染。
- 新咨询入口在动作函数内同步防重。记忆归属文案适用于支持对象，不限定为儿童。

本轮回归覆盖资料库入口/分区、返回来源、展示名恢复与鉴权边界、编辑草稿归属、分页失败与迟到响应、提交防重、应急退出、文本安全排版；真栈验证通过实际 API 和数据库写入建立前置状态。

## 品牌图标

- 图标源文件为 [`assets/brand-mark.svg`](assets/brand-mark.svg)：以一大一小两簇火光和收简的书页构成单色标记，使用 `#C2410C` 与透明留白；登录页与首页页头均与「篝火智答」名称搭配。
- 图标保持静态，不加渐变、发光或独立循环动效。与可读名称并列时，图标作为装饰，名称承担可访问的文字标识；首页页头的图标计作一处 accent。
- 缩小使用时保持原始比例和透明留白，不另加轮廓或细线。浏览器标签等极小尺寸仍需在实现期按实际设备复核。

## 色彩与排版

- 火焰橙 `#C2410C` 用于品牌、主操作和当前状态。应急风险徽章使用 stable、unruled、high 与对应的文字。
- 页面标题 24px，次级页头标题 16px，正文 16px。页面标题、正文和控件用系统无衬线。宋体仅用于品牌字标。
- `--border-control` 用于依靠边界识别的输入控件，表面分隔线用 `--border-soft`。
- 输入控件、分组与面板使用 10、14、20px 圆角。应急问题优先保留可点击区域和信息密度。
- 一期使用亮色主题。

## 布局与 posture 要点

- **仅适配手机端（2026-10-06 用户定调）**：所有页面只按手机单列设计；平板与 PC 端不做多栏适配，直接渲染为居中的手机宽度容器（手机蒙版，token `--phone-shell-max: 480px`）——容器外以 `--surface-warm` 暖沙色为蒙版底、容器本身带 `--elev-ring` 边界示意手机边界。禁止宽屏多栏布局、桌面 hover 信息分层等桌面专属设计
- **手机蒙版 + 宽视口设备外壳（2026-10-02 用户授权定型的规格）**：≥560px 视口下不再只是「居中的窄列」，而是把应用渲染进一台**手机外壳**里，使 PC/平板上的观感是「在一台手机里运行的应用」（用户原话：「需要做一个模拟手机外壳，模拟手机应用，而不是单纯减少宽度」）。几何：屏幕内容区 `390×844`、bezel `12px`（画在 390×844 之外，`box-sizing: content-box`）、圆角 `56px`、bezel 取暖色系深色（从 `--fg` 派生的 `color-mix`，**不用冷黑**——本系统是暖米纸 + 火焰橙，冷黑会与调性冲突）。结构与机制：

  - 三层结构 `.device-stage`（居中舞台）> `.device`（外壳本体）> `.device-screen`（屏幕区，外壳内唯一滚动容器）；
  - `.device` 带 `transform: translateZ(0)` 是**承重属性**：它让外壳成为其后代 `position: fixed` 元素的包含块，因此契约里的 `.tab-bar` 与 `.confirm-sheet` 无需从 `fixed` 改成 `absolute` 就会收进外壳（底边贴外壳内容盒底边、宽度为屏幕宽而不是视口宽）。移除它两者立刻逃到视口；
  - **外壳内不得用视口单位作尺寸基准**：`100svh` 解析为视口高而不是外壳高，会把 844px 的屏幕撑出无谓滚动；外壳内改用相对屏幕区的 `%`；
  - **<560px 行为不变**：三层包裹在该断点下退化为 `display: contents`（不生成盒子），真实手机仍是满幅、无 bezel 与投影；
  - 阈值取 560 而非 900：外壳外宽 414px 加舞台内边距后约 462px，560 给两侧留出呼吸；取 560 而非更高也让平板竖屏（768）获得同一观感。几何字面量是实现级派生值，集中在 `apps/web/src/shared/styles/global.css` 的设备外壳段落，不进 `tokens.css`。
- 单屏 accent 只承担品牌、当前状态与主要操作，不用来给每个分组或记录装饰；应急语义徽章仍使用对应语义色
- 卡片三层语言：`panel`（低海拔阅读面）> `tile`（平铺卡）> `mini-card`（warm 内衬）；阴影只在需要层级时使用，连续记录用分隔线，不嵌套卡片
- 状态确认 150ms、进入 240ms（移动端取短值）；唯一循环动效是篝火呼吸点（2s，respect `prefers-reduced-motion`）
- 移动端触控热区 ≥44×44px；正文 ≥16px；安全区预留 `safe-area-inset-*`
- 汉字排印使用系统无衬线。品牌字标用宋体 500。全大写仅用于短眉题。

## 下游消费指引

- 页面设计与实现前必读：本文件 + `tokens.css` + `components.html`
- token 契约：`tokens.css`（实现代码直接引用其中 CSS 变量）
- 组件形状：`components.html`（匹配而非发明；新组件走契约修订，标 `@source: project`）
- 页面设计文档：`docs/design/pages/`（逐页产出，经确认后为实现输入）
- 组件总览：base 继承（按钮/输入/卡片/徽章/链接/排版/布局）+ 项目组件（flame-dot、tab-bar、subpage-head、page-head、check-row、choice、progress、tag、bubble-user、msg-doc、run-status、skeleton、empty-state、error-card、question-card、action-card、citation-block、reasoning-row、tool-row、candidate-toast、confirm-sheet、list-row、group-collapse）——三态基元（skeleton / empty-state / error-card）是各页 loading/empty/error 形态的唯一来源，禁止页内自造
