# 篝火智答 v3 · Web 视觉设计契约

> Base：`.dsh/skills/design-spec-workshop/vendor/open-design/design-systems/cafe/`。
> 2026-09-26 由用户授权自主收敛；`tokens.css` 与 `components.html` 拥有具体 token/组件事实。**目标设计，非现有页面实现；尚未经过家属、老师或当事人的视觉/无障碍测试。**

## 调性与选择

面向成年支持者在不确定和可能紧张的情境下阅读：用暖纸面与清晰的正文层级传递“可依靠、可核对”，不采用幼态图标、情绪刺激的大面积警报色或医嘱式权威姿态。比较 `paper`（旧紫色点缀不合当前方向）、`friendly`（过于玩趣）和 `cafe`（暖色与低噪声阅读），选 cafe 作结构底座；现有 Web 琥珀 token 是旧实现事实，不证明品牌已审批。

## Overrides

- 品牌色：沿用 cafe token 源的暖棕 `--accent`，不是从真实品牌资产提取；是否符合用户认知需在试点检验。
- 中文字体：标题使用有衬线 CJK 后备，正文用本地中文系统字体栈；不依赖跨境字体 CDN，不把 Latin 展示字体硬套到长段中文。
- 密度/圆角/主题：正文保持 17px、读宽受控，普通页面留白而现场支持优先大字与短句；圆角按层级变化；首版仅亮色主题，暗色不假装已支持。
- 组件：继承 cafe 的按钮、面板、字段和状态壳；新增情境入口卡、公开安全提示、范围标识、带来源的建议、确认/停用状态、计划条目和异议表单，详见 `components.html`。

## 布局与姿态

- 手机先看到可用的公开帮助与当前情境入口，主操作位于易触区域，最低点击热区 48px；桌面阅读宽度有限，不让长段建议横贯全屏。
- 用文字和来源区分私人、共享、AI 草案、已确认与暂停；语义色只是辅助手段，不能独自承载状态。安全警示不用红色铺满整页，公开帮助始终可见。
- 整屏 accent 最多两处；用排版和非对称疏密体现“篝火周围逐步聚拢的信息”，不重复相同尺寸的卡片网格。
- 减少动效；页面状态变化可用短淡入，异议成功/权限撤销即时更新，不为品牌感增加等待；尊重 `prefers-reduced-motion`。

## 反模式

不使用表情符号充当功能图标、彩色左边条卡片、紫蓝信任渐变、虚构统计数据、“孩子都需要服从”的文案或没有状态说明的 AI 流输出。不能把过期计划以旧截图继续显示为有效，不以颜色单独表示安全级别。

## Craft 强制清单

`color, typography, anti-ai-slop, accessibility-baseline, state-coverage, form-validation, animation-discipline`。对比度和屏幕阅读器可用性必须在实现后测量；本文的颜色选择不构成 WCAG 达标证明。

## 下游消费

页面设计及实现前按顺序读取本文件、`tokens.css`、`components.html` 和 `pages/` 中对应页面；页面不得另造颜色/组件状态。实现时将旧 `--cf-*` 映射或迁移到本契约，不同时运行两套相互矛盾的视觉状态；现有代码仍是旧 UI，不因本文件自动更新。
