# DVC-001：视觉底座选 cafe，不沿用旧紫色点缀

> **决定**：以 `cafe` 品牌库为结构底座，新增情境入口卡、公开安全提示、范围标识、带来源的建议、计划条目与异议表单等项目组件。**理由**：面向成年支持者在不确定和紧张情境下阅读，需要暖色低噪声的可依靠感；`paper` 的紫色点缀与当前方向不符，`friendly` 过于玩趣。**被否决项**：沿用旧 Web 琥珀/紫色 token；采用 `friendly` 的玩趣调性。
> **状态**：2026-09-26 用户授权自主收敛后补记；未经真实支持者视觉与无障碍评审，相关证据见 `EVID-09`。

## 上下文

首版 Web 面向家属、志愿者与一线老师，使用场景包含现场突发困难——阅读者可能处于压力中，且常在手机上单手操作。视觉需要同时满足：可快速取得公开帮助、能分辨私人/共享/草案/已确认/暂停、在窄屏保持触区可用。

选择时实际比较了三个方向：

| 方向 | 保留的价值 | 代价或风险 |
|---|---|---|
| `paper` | 结构清晰、正文层级稳 | 紫色点缀与已确认的产品调性不符；中性感偏向工具而非支持 |
| `friendly` | 亲和、易接近 | 玩趣调性与"现场可依靠"冲突；在紧张情境下显得轻佻 |
| `cafe`（选定） | 暖色与低噪声阅读，适合长段中文与状态区分 | 品牌色沿用 token 源而非真实品牌资产提取，需在试点检验认知 |

旧 Web 的 `--cf-*` 琥珀 token 是**已有实现事实**，不构成品牌已审批的证据。

## 决定

1. 结构底座取 `cafe`；具体颜色由 [tokens.css](../tokens.css) 拥有，组件形状与修饰符由 [components.html](../components.html) 拥有，调性与反模式由 [DESIGN.md](../DESIGN.md) 拥有。
2. 品牌色沿用 cafe 的暖棕 `--accent`，不从真实品牌资产提取；是否符合用户认知待 `EVID-09` 检验。
3. 中文字体：标题用有衬线 CJK 后备，正文用本地中文系统字体栈；不依赖跨境字体 CDN。
4. 首版仅亮色主题，暗色不假装已支持；圆角按层级变化，正文 17px。
5. 新增项目组件限于：情境入口卡、公开安全提示、范围标识、带来源的建议、确认/停用状态、计划条目、异议表单。

## 后果与波及

- 波及文档：[DESIGN.md](../DESIGN.md)、[tokens.css](../tokens.css)、[components.html](../components.html)、[design/README.md](../README.md) 与 `pages/` 下 8 份页面设计；实现时旧 `--cf-*` 须映射或迁移到本契约，不同时运行两套矛盾的视觉状态。
- 直接约束：状态必须靠文字与来源表达，语义色只是辅助，不单独承载安全级别或权限；安全警示不用红色铺满整页，公开帮助始终可见。
- 待补：`superseded`/`retired` 两个计划终态缺少状态徽章表示，由页面设计文档补充，不因此改动机制取值。

## 重访条件

- `EVID-09` 的色彩对比、键盘与屏幕阅读器实测未达标 → 重审 token 与状态表示。
- 试点中支持者反馈"暖色不够醒目/不够冷静"或无法区分草案与已确认 → 重审调性与状态表达。
- 取得真实品牌资产 → 用实际品牌色替换 token 源的 `--accent`。
- 出现暗色主题的真实需求（夜间使用、系统级暗色）→ 单独评估，不预设支持。
