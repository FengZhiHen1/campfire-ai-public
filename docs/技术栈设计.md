## 1. 选型准则与现状证据

三条准则，按优先级：

1. **优先成熟、经年限检验的库**（用户 2026-09-29 在队列选型上明确）。年轻库默认不引入；若确有不可替代的能力而必须引入，其爆炸半径必须可控，并在本文写明例外理由。
2. **不自己造轮子**（用户立场 2）。但"轮子"的成熟度按上一条判断。
3. **单一 Agent 框架**：不叠加第二套 Agent 运行时——不用检索库自带的 Agent 循环，也不让记忆层自带编排。

已核实的现状证据（2026-09-29 实测，非推断；本节是快照，随落地工作更新）：

- 根 `pyproject.toml` 是虚拟工作空间根，唯一成员 `apps/api`（单应用、两个运行入口）；`pnpm-workspace.yaml` 只列 `apps/web`。
- 根已有 `apps/`（api、web）、`infrastructure/`、`scripts/`；**仍无** `packages/`。`docker-compose.yml` 编排五个容器：PostgreSQL 17、Redis 7、FalkorDB、SuperTokens core、MinIO。
- `uv sync`、`ruff`、`pytest`、`pnpm install` 可用；**迁移命令仍缺失**——Alembic 尚未落地，不是配置损坏。
- 应用侧依赖只声明运行外壳当前真实消费的部分。**2026-09-29 起 Agent 基座落地，以下依赖
  已安装并有了真实消费者**：`openai-agents`（`agent/model` 的模型网关与重试、`agent/runtime`
  的会话与运行编排）、`openai`（客户端与异常分类）、`pyyaml`（`SKILL.md` 的 frontmatter 解析）。
  **仍无消费者、因而仍未安装**：`llama-index-core`、`graphiti-core`、`falkordb`、
  `supertokens-python`、`alembic`、`pgvector`——第 2 节其余选型仍属待实施设计。
- **Agent 基座的实现状态**（2026-09-29）：`apps/api/src/campfire/agent/` 的六个子包
  （`runtime`、`skill_runtime`、`tools`、`context`、`model`、`observability`）已有实现与测试；
  `surfaces/`、`tools/`（产品侧工具）、`modules/`、`core/` 其余部分仍是占位包。
  未落地的部分与其条件写在各自模块 docstring 与 [设计待办](TODO.md) 里，不在本文复述。
- 归档的 `py-*` 包与 Nginx、监控资产是**可迁移候选，不是在位事实**：新选型不因它们存在而沿用。

## 2. 项目级技术选型

| 职责 | 选择与版本基线 | 选型理由与重访条件 |
|---|---|---|
| 语言与运行时 | Python ≥3.12 | 与既有工程配置一致、异步生态成熟。只按安全维护或已实测的性能证据升级主版本 |
| 后端框架 | FastAPI + Pydantic 2 | 类型化契约与既有工程纪律一致；不引入第二套 Web 框架 |
| 包管理 | uv 工作空间（Python）、pnpm 工作空间（前端） | 既有配置，实测可用 |
| Agent 运行时 | OpenAI Agents SDK | 原语少：Agents、tools、guardrails、handoffs、sessions、tracing、HITL、MCP。**已核实**：其 `skills` 能力只存在于 sandbox capabilities（原文为 Mount skills into a Codex auto-discovery root inside the sandbox），不是「领域方法论 + 工具范围按需激活」的一般原语，因此 skill 注册表与工具范围控制由本项目实现，其模块归属由项目结构设计拥有。重访条件：SDK 提供一般化的能力按需加载 |
| 模型与供应商 | 腾讯云 TokenHub 的 DeepSeek-V4.1-Flash，**全应用单一模型** | 用户选定。**已核实**：TokenHub 提供 OpenAI 兼容接口，Base URL 固定为 `https://tokenhub.tencentmaas.com/v1`，且**按开通地域选择接口、不支持跨地域调用**。重访条件：时延、质量或成本被实测证明不满足 |
| 数据主库 | PostgreSQL 17 + Alembic 迁移 | 事务边界留在关系库；不引入第二套关系库 |
| 向量检索 | pgvector | 与主库同事务，少一个服务 |
| RAG 框架 | LlamaIndex（`llama-index-core` + pgvector 存储集成与文档读取器） | 用户 2026-09-29 选定**全量引入**：摄取流水线、分块、嵌入适配、向量存储、融合检索与评测都交给它。**为什么可以接受**：委托出去的恰好是纯通用件，而领域规则（两库边界与状态、撤下传播、授权过滤、条目聚合、返回契约、注入预算、失败语义）仍在我们手里。**已核实**：MIT；最新 0.14.25 / 2026-09-21，近一年约 21 个版本（节奏明显放缓），仍在 1.0 之前；`PGVectorStore` **把 metadata 过滤下推到 SQL**（`MetadataFilters` 可嵌套、`indexed_metadata_keys` 可建索引），并支持自定义 `table_name`/`schema_name`/`use_jsonb` 与 `hnsw_kwargs`（**不自建 IVFFlat**：向量索引只在传入 `hnsw_kwargs` 时才建 HNSW，默认 `hnsw_kwargs=None` 即不建任何索引——与一期「不建向量索引」相容，`ivfflat` 只作检索参数 `SET ivfflat.probes` 出现）；`QueryFusionRetriever` 含 **RRF**（`reciprocal_rerank`）且可混合自定义检索器；`IngestionPipeline` 有 docstore 去重与可用 Redis 的 `IngestionCache`；`RetrieverEvaluator` 内置 `hit_rate`/`mrr`/`recall`/`ndcg`。**它替不掉、仍由我们写的三层**：① 分块后处理（表格与列表保护、超长二次切分——框架不做，而嵌入接口单条硬限 2000 字符）；② 字面路（它的 `hybrid_search` 建的是 **tsvector**，中文无分词器时基本不可用，与 `pg_trgm` 是两回事）；③ 条目聚合与返回契约。**例外说明**：框架仍在 1.0 之前且迭代快，按准则 1 属例外。**依赖代价（2026-09-29 实测）**：core wheel ≈11.9 MB、**29 个直接依赖**（含 `nltk`/`tiktoken`/`networkx`）；**全闭包实测 62 个包**，加 pgvector 存储集成 66、加文档读取器 76——原文「间接依赖通常上百」偏大，实测上限 76；只装 core 加所需集成，不装全家桶。**一期不接 PDF**（普通读取器不给标题层级，同时保住层级与表格要引入付费的 LlamaParse），语料在链外处理成 md/html 再进系统。重访条件：依赖体量与升级成本超过自研成本，或链外准备被证明不可持续 |
| 字面匹配 | `pg_trgm` | **已核实**：它是 PostgreSQL 官方随附模块（文档附录 F），标记 trusted，有 CREATE 权限即可安装；官方 `postgres` 镜像自带 contrib，可直接 `CREATE EXTENSION pg_trgm`（镜像只装 `postgresql-17`，该包内含 `extension/pg_trgm.control`）。**中文的三条硬约束**：① 是否识别汉字取决于 libc 的 `iswalnum`，**`C` locale 下汉字全被丢弃、相似度恒为 0**，部署 locale 不得为 C；② 需要**≥3 个连续汉字**才产生三元组，1–2 字的查询退化为全表/顺序扫描；③ 中文**不能走 `~`/`~*`**（不走索引），必须用 `LIKE`/`ILIKE '%中文%'` 才走 GIN。实现时仍需在容器内实测 locale 行为（`TECH-01`） |
| 通用记忆 | Graphiti + FalkorDB（镜像 `falkordb/falkordb`，本项目固定 `v4.20.7-alpine`） | 用户要求时间演变、避免过期记忆误导。**已核实**：Graphiti 必须有第三方图数据库后端（Neo4j / FalkorDB / Amazon Neptune），Kuzu 已弃用且上游不再维护。**版本口径已更正（2026-09-29）**：Graphiti 安装要求里的「FalkorDB 1.1.2」指的是它自己的**客户端依赖**（`graphiti-core` 声明 `falkordb>=1.1.2,<2.0.0`），**不是镜像 tag，也不是服务器版本**——`falkordb/falkordb` 仓库没有 `1.1.2`（经镜像 tag 接口核实为 404），其镜像版本线是 4.x；同一段里的「Neo4j 5.26」同样对应依赖 `neo4j>=5.26.0`。故镜像按实际存在的 tag 固定，`falkordb` 客户端版本随 `graphiti-core[falkordb]` 解析（当前最新 1.7.1） |
| 个性化档案 | PostgreSQL（对象归属 + 授权判定缝） | 档案归属支持对象，一期只创建者可用（`RQ-MEM-05`）。条目的数据形状与状态机已定，**不归本文拥有** |
| 队列与后台执行 | Taskiq + Redis broker，独立 Worker 进程 | **例外说明**：按准则 1 它属例外（MIT；最新 0.13.0 / 2026-09-26；约每月一版；未见停维声明；但 PyPI 分类器仍为 `Development Status :: 3 - Alpha`，即自报 1.0 前无稳定性承诺）。理由：**全异步栈零接缝**——本项目的 Worker 调用 Graphiti 的异步客户端，而同步/多进程模型要求每个 worker 进程自管事件循环与异步资源生命周期（异步引擎不能跨事件循环共享），那是一类隐蔽 bug 的来源。另一条让例外可接受：该位置对队列库成熟度的依赖被我们自己的记账机制抵消——待处理记录（PostgreSQL）是真相源，队列只负责投递，丢的任务可被检测与补救。重访条件：出现未被检测到的任务丢失或重复，或 Taskiq 停止维护 |
| 认证 | SuperTokens：Java core 容器 + Python SDK；账号与会话数据在自己的 PostgreSQL | **已核实**：core 是独立 Java HTTP 服务（官方连 JDK 一起打包，使其像普通微服务），**会话校验在 Python SDK 内完成、不经过 core**，core 只在注册、登录、重置、刷新时被调用；用户数据 100% 在自己库。**许可**：实测仓库树后，`ee/` 下只有许可与特性开关机制（`EEFeatureFlag`、`EELicenseCheck` 及许可 API 测试），EmailPassword 与 Session 不在其中，按定价页属 self-hosted 免费的开源部分。**账号名登录**：官方文档给出做法（复写 email 校验器），但标识**仍存放于 `email` 字段**；**已核实 SuperTokens 无原生 username**——没有 username recipe，User 对象只有 `emails`/`phoneNumbers`/`thirdParty`，文档原文亦称 "the field is still called email"，故这是长期已知偏差而非可消除项。**付费边界**：EmailPassword 与 Session 属免费开源、不限用户数；MFA、Multitenancy 与 SSO/SAML、Account Linking、攻击防护套件、以及 **Dashboard 超过 3 个用户**均属付费——因此运营操作走 SDK 或 Management API 而不依赖 Dashboard，登录限流与防爆破由我们自己实现。**本条修订了「不引入独立身份服务」**：接受多一个 Java 容器，换取不自己实现会话安全。重访条件：付费特性清单核实出所需能力被门禁，或 core 的版本兼容矩阵成为维护负担 |
| 前端 | React 19 + Vite + React Router + Zustand | 一期只交付手机端 H5。小程序是远期形态，届时另做并从已验证的 API 契约映射，不复用组件 |
| 前端样式 | CSS Modules + 契约里的 CSS 变量 | Vite 原生支持、零额外依赖；token 以 CSS 变量直接消费，不引入主题配置桥接，便于检查"实现侧不得另行定义色值与间距"。重访条件：布局重复度高到工具类能显著减少代码 |
| 对话面 | assistant-ui，走自定义 runtime（`LocalRuntime` + `ChatModelAdapter`） | **已核实**：官方支持任意后端，自控 wire format 时用 `LocalRuntime` 或 `AssistantTransport`；其框架适配器列表含 AI SDK、LangGraph、Google ADK、A2A，**不含 OpenAI Agents SDK**，故走自定义 runtime；React 19 受支持（peerDependencies `^18 || ^19`），`LocalRuntime` 与 `ChatModelAdapter` 无 `unstable_` 前缀、不在官方不稳定清单，**但 `ChatModelRunOptions` 内含 `unstable_getMessage`、`unstable_threadId` 等字段，用到它们即承担升级风险**。**例外说明**：它是较年轻的库，按准则 1 属例外；理由是爆炸半径限于前端呈现层，最坏情况是重写 UI，不动后端契约与数据。重访条件：出现阻塞性缺陷或停止维护 |
| 传输 | SSE，保留 AG-UI 升级空间 | 满足流式输出；不引入 WebSocket 带来的额外连接状态 |
| 缓存与限流 | Redis 7 | 既有编排；不承载长期业务状态，丢失不恢复已撤销状态 |
| 附件 | MinIO（既有编排），**一期不依赖** | 一期需求无附件；开放附件前须先补文件扫描、访问时效与删除验证 |
| 部署 | Docker Compose v2 单机：api、web、worker、postgres、redis、falkordb、supertokens、minio | 单机先行；不引入 Kubernetes、消息总线或通用工作流引擎 |
| 可观测 | OpenAI Agents SDK 内置 tracing + 结构化日志；一期不引入 Langfuse 一类平台 | 满足"每次运行可追"。跨运行的质量分析出现真实需求时再评估，登记于设计待办 |
| 评测 | 一期建立最小评测集，对齐需求稿[可观察验收语义](./需求/功能需求与验收.md)的场景与判定标准；不引入评测平台 | 需求要求依据可核对、结论可证伪；先跑通离线评测，再谈平台。**不写死 AC 编号区间**：验收行仍在增加（初版写 `AC-01`～`AC-12`，现已有 `AC-01`～`AC-22`），写死必然漂移 |

## 3. 模型路由

全应用使用**单一模型**，因此不存在"应急用强模型、日常用廉价模型"的分档——该分档已作废。模型选择经统一路由配置读取，业务代码不得硬编码模型名。两条入口的差异只在流程与上下文：应急由入口直接进入、上下文更短；日常由对话逐轮推进。

供应商约束：TokenHub 是外部数据处理方。在真实使用者资料进入前，须先取得其数据处理、跨境、保留、删除与训练条款（见[设计待办](./TODO.md) 的 `EVID-C`）；未取得前只发送虚构或经核准不可识别的样例（`RQ-LIM-03`）。

## 5. 失败语义与不变量

1. **图库写失败不得回滚已完成的主事务状态。** 记忆写入在请求路径之外执行；请求只负责与业务数据同事务地写入待处理记录。
2. **"没写进去"不得被当作"写进去了"。** 待处理记录按幂等键重试；超限转死信并告警，不静默丢弃、不假装成功。
3. **认证或授权不可用时拒绝受限操作**，不降级为放行。

Worker 采用全异步模型（Taskiq），**不引入同步与异步之间的桥接**；业务代码与 Worker 使用同一套异步客户端与连接管理。

## 6. 部署目标与兼容约束

- 单机 Compose，对外经 Nginx；Web 与服务端之间使用 TLS，密钥经环境注入，不入版本库。
- 全应用必须登录（`RQ-ACC-01`）：不存在匿名内容页、匿名接口或未登录可达的业务路径。
- 一期账号为账号名与密码，不要求邮箱；注册须凭邀请码；忘记密码由运营者人工重置，**重置后旧会话必须立即失效**（`RQ-ACC-04`～`RQ-ACC-06`）。
- 客户端凭据不得作为权限证明；服务端按请求重新查证。
- TokenHub 的接口地址与开通地域绑定，**不支持跨地域调用**；部署地域须与开通地域一致。
