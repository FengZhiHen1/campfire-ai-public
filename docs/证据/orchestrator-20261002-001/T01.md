## 目标

建立一套**可复现、免后端**的前端视觉截图基建，使后续每一个视觉改动都能被截图证据支持。

可观察的完成标准：
1. 一条命令能在两种视口下把 **10 个页面全部**截图为 PNG，且**每页都处于「有数据」状态**（不是空态/错误态）；
2. 截图过程**零真实后端依赖**（不需要 PostgreSQL/Redis/FalkorDB/uvicorn）；
3. 任何 `/api/**` 请求若未被夹具命中，脚本**以非 0 退出并点名该 URL**（fail-closed）；
4. 产出 `manifest.json`：每张图的路径、sha256、字节数、像素尺寸、以及「本次断言命中的内容特征串」。

## 本包裁决

以下为本包专属决定，设计文档未覆盖（**不得自行更改**）：

**A. 依赖与位置**
- `@playwright/test@1.63.0`（精确版本，不加 `^`）加入 `apps/web` 的 `devDependencies`。选此版本的理由见 facts.md §4：其要求的 chromium 修订 **1243 本机已缓存**，`npx playwright install` 无需下载。
- 截图脚本放 `apps/web/e2e/`，文件名 `*.spec.ts`。**不得**放 `src/` 或 `tests/`——vitest 的 include 是 `src/**` 与 `tests/**`，放进这两个目录会让 `pnpm test` 收集到 Playwright 用例而失败。
- Playwright 配置：`apps/web/playwright.config.ts`。
- 新增 npm script（放 `apps/web/package.json`）：`"shots": "playwright test"`。

**B. 被测产物与服务器生命周期**
- 截图对象是**构建产物**，不是 dev 源码：先 `vite build`，再用 `vite preview --port 4173 --strictPort` 提供服务。
- 用 Playwright 的 `webServer` 配置项托管该服务器（自动起停），`reuseExistingServer: false`、`command` 内先构建再 preview。
- **端口 4173**；脚本结束必须让端口释放（`webServer` 自动托管即满足）。若手工起过任何服务器，出场必须 `Stop-Process` 并复核端口（见 facts.md §9）。

**C. 登录态注入（免后端的关键）**
- 在 `page.goto()` **之前**，用 `page.addInitScript()` 写入两个 cookie：`sFrontToken`、`st-last-access-token-update`。
  - frontToken 载荷：`{uid, ate, up: {}}`，`ate` 取「当前时间 + 1 小时」（毫秒）。编码方式与 `parseFrontToken` 互逆：`btoa(unescape(encodeURIComponent(JSON.stringify(payload))))`。
  - 机制与实测依据见 facts.md §5——该注入使 `doesSessionExist()` 返回 `true` 且**零网络请求**。
- 断言该注入真的生效：任一页截图前确认 `document.querySelectorAll('[aria-live]')` 不含「正在确认登录状态」，且页面**未**跳转到 `/login`。若被重定向，脚本必须失败（不能截出一张登录页冒充目标页）。

**D. 数据夹具（不能用真实后端）**
- 用 `page.route('**/api/**')` 拦截并 `fulfill` 固定 JSON，逐页给夹具。
- **fail-closed**：注册一个兜底 handler，凡未被具体夹具命中的 `/api/**` 请求，记录 URL 并让**测试失败**（不许静默 404——静默 404 会渲染成空态/错误态，看起来"截图成功"实则没验证到目标形态）。
- SSE 类端点（咨询运行流）：用 `route.fulfill` 一次性返回完整 SSE 报文（含 `event:`/`data:` 帧）。若某页在无 SSE 时也能呈现目标形态，则在报告里说明该端点**为何不需要**，并把它加入「必须为空」清单（即断言该端点未被请求）。
- 夹具内容用**真实感中文文案**（不得用 `foo`/`lorem`/`测试1`），因为截图要用于人工目视判断版式；文案不得与设计文档的「硬文案」冲突——若某处需要展示设计硬文案，**逐字取自设计文档**。

**E. 视口与命名**
- 两种视口，均 `deviceScaleFactor: 2`：
  - `mobile` = 390×844（与设计渲染视图一致，见 facts.md §7）
  - `desktop` = 1280×1000（用于后续验证 PC 端设备外壳）
- 每页每视口一张图，文件名 `<page>-<viewport>.png`，`<page>` 用路由语义短名：`login` / `home` / `consult-list` / `chat` / `emergency` / `profile` / `cases` / `settings` / `memory` / `guide`。
- 产物落点：`tmp/screenshots/`（随 `tmp/` 被 gitignore；这是可重新生成的证据，**不进版本库**）。
- 脚本必须支持 `--out <dir>`（或等价的环境变量/配置）改写落点，默认 `tmp/screenshots`。理由：后续包要按轮次保留历史，覆盖默认目录会丢掉对照。

**F. 每页的内容断言（截图必须"有料"）**
逐页断言以下可观察特征至少一条命中（具体选择由执行者定，但必须写进 manifest 的 `assertedContent` 字段，并让审查者能据图复核）：
- `login`：品牌区标题与表单区同屏可见；
- `home`：应急入口与日常入口同屏可见；
- `consult-list`：≥1 条会话行（含标题与相对时间）；
- `chat`：≥1 条使用者气泡 **且** ≥1 条助手消息；
- `emergency`：≥1 个采集字段可见；
- `profile`：≥1 条档案条目；
- `cases`：≥1 条案例；
- `settings`：账号卡与操作区可见；
- `memory`：≥1 条记忆条目；
- `guide`：四节标题可见。

## 关键决策清单（why 注释供给源）

- 截图对象取**构建产物**而非 dev 源码 —— 「单测绿 ≠ 样式到运行时」，且 `check-contract-css.mjs` 只在 build 后跑（引自 facts.md §6 与 §7）。
- 用 `page.route` 拦截而非在生产代码里加 stub 开关 —— 生产代码不得为测试引入分支；拦截在传输层，产品代码零改动。
- 用 cookie 注入而非真实登录 —— facts.md §5 实测 `doesSessionExist` 由本地 cookie 判定、零网络，故免后端可得已登录态。
- 兜底 handler **fail-closed** —— 静默 404 会渲染成空态却"截图成功"，属假绿（code-craft：禁止让检查在失败时静默通过）。

## 质量地板

- 禁止空壳实现（空函数体 / 仅 `throw NotImplemented`）。
- 禁止裸 `any`；`@ts-expect-error` / `type: ignore` 必须带理由注释。
- 禁止静默吞异常（`catch {}`）；异常必须传播或携带上下文转译。
- 零 TODO/FIXME 残留；不留调试代码与注释残留。
- 公开符号注释按 code-craft 注释标准；why 注释取自本包「关键决策清单」。
- 只改「交付物」清单内文件；范围外问题写入报告「未决问题」节。
- 遵循 code-craft `references/slices/typescript.md` 的 TS-01 / TS-05 / TS-08，与 `references/slices/testing.md` 的 TEST-02 / TEST-04（按编号引用，不整份加载）。
