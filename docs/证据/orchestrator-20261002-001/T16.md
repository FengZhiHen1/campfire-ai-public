### 3.3 ★ 空/纯空白拒绝的**机制**（重要，写清证据边界）

空与纯空白确实被拒（上表），但**拒绝者不是我的校验器**，而是身份服务在调用校验器
**之前**的两步（源码已读）：

1. `recipe/emailpassword/api/utils.py:105-106`：email 字段的值先被 `strip()`；
2. 同文件 `:47-52`：字段「缺失、或值为 `""`」且 `optional=False` ⇒ 直接产出
   `Field is not optional` 并 `continue`——**`validate` 根本不会被调用**。

因此 `""`、`"  "`、`"\t\n"` 都在 `validate` 之前被拒（形态 `FIELD_ERROR` /
`email` / `Field is not optional`）。我在 `_validate_account_name` 里仍显式判空
（`not value.strip()`）作为**兜底**，理由是 `optional` 对 `id == "email"` 被 SDK
硬编码忽略、空值拒绝实际依赖 SDK 的非可选分支；若哪天该校验器被直接调用或 SDK 改变
归一化顺序，空账号名仍会被拒而不是静默放行。**兜底路径未被端到端触发**（见第 8 节）。

## 7. 缺陷/残余

1. **兜底判空路径未被端到端触发**（见 3.3）：`_validate_account_name` 里
   `not value.strip()` 这一支在真实 HTTP 路径上不可达（SDK 先拒空值、且先 `strip()`）。
   它由单元用例直接调用校验器覆盖，但**端到端只覆盖了「SDK 先拒」这一层**。
   保留它的理由与「两处判空不冲突」已写进 docstring。
2. **界面文案不再与真实原因脱节，但仍未做端到端 UX 复验**：
   修后「格式非法」这一条根因消失，`小安` 不再落到 `account-unusable`。
   但 `FIELD_ERROR`/`email` 这一形状同时承载「账号名已被占用」（既有路径），
   两者在前端**仍不可区分**——这是既有设计（`authPort.test.ts:198` 有断言钉住它），
   **本包未改前端、也未消除该合并**。若复查者认为「注册失败原因应可区分」，那是另一个
   `PROD`，不在本包授权内。
3. **`TECH-08` 偏差仍在**：账号名依旧借 `email` 字段承载（字段名 `email`、响应里叫
   `user.emails`）。本包按要求只修校验器、不改字段名——改名会同时动 SDK 契约与前端契约，
   超出授权。
4. **密码重置链路的行为变化（同源副作用，未新增测试）**：`utils.py:206-213` 的
   「生成重置 token」表单也复用同一个 `validate`。修后非邮箱账号名在**表单校验层**
   可通过，即不再被格式正则提前挡下；实际能否发出重置邮件取决于下游邮件投递（本项目
   未配置真实邮件服务）。**我未端到端验证密码重置**，这是本包已知的未覆盖面。
5. **未提交 git**（按要求）。工作区改动即上述两个文件。
