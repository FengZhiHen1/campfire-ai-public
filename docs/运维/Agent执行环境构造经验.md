# Agent 子代理执行环境构造经验

> **状态**：实测经验记录，**非设计真源**。
> **它拥有的事实**：在本仓库、在 DSH（`dsh@0.1.7-rc.2`）上派发子代理时，环境构造与派发配方的
> 可复现事实、失败模式与配方修正。**它不拥有**任何设计事实——模块边界归
> [项目结构设计](../项目结构设计.md)，命令集归 [AGENTS.md](../../AGENTS.md)，发布流程归
> [发布与回滚](发布与回滚.md)。与拥有者冲突时以拥有者为准。
> **证据基础**：2026-09-30～10-02 一次连续编排会话（约 80 个任务包、190 余次提交）的实测；
> 每条事实标注了取证方式，「未测」与「推断」分开写。§9 列出全部边界与推翻条件。

本文回答一个问题：**把一份任务交给子代理时，怎样构造它运行的环境，才不会得到假绿、假失败或丢失产物。**

---

## 0. 第一原则：环境协议必须本仓查证，不得照抄

编排器最容易犯的错，是把「上一轮项目好用的环境设置」当成「本项目必需的设置」，然后写成
「每条命令前必设」。**过度防御本身是缺陷**：它让配方变长、让失败的归因变模糊，而且会掩盖
真正承重的那一项。

本仓实测（2026-10-02）：

| 曾被写成「必设」的变量 | 实测结论 | 取证方式 |
|---|---|---|
| `PYTHONPATH=apps/api/src` | **不承重**，可省 | 不设该变量执行 `uv run python -c "import campfire"` → 成功，解析到 `apps/api/src/campfire/__init__.py`（uv workspace 可编辑安装） |
| `DATABASE_URL=<从 .env 读>` | **不承重**，可省 | `apps/api/src/campfire/core/config.py:19` 定义 `_ENV_FILE = _REPO_ROOT / ".env"`，`:45-47` 用 `SettingsConfigDict(env_file=_ENV_FILE)` —— pydantic-settings 自己读仓库根 `.env`；实测 `.env` 存在且已设该变量 |
| `UV_PROJECT_ENVIRONMENT=<仓库根>/.venv` | **未测** | 未做「省略后跑 uv」的对照实验，故不声明结论 |

**配方写法**：`uv run pytest ...` 直接跑；**若某命令确实需要变量，先在干净 shell 里跑一次
不带变量的对照**，把结论写进配方，而不是沿用别处的模板。

## 1. 命令纪律（逐条都有实测依据）

### 1.1 计数一律取机器读数，不取控制台

`pyproject.toml:11-13` 已有 `addopts = "-q --import-mode=importlib"` 与
`testpaths = ["apps/api/tests"]`。因此：

- **不要靠控制台行数/`-q` 输出计数**——它会随警告、摘要与并行输出漂移
- **一律加 `--junitxml=<path>`，从 XML 读 `tests/failures/errors/skipped`**

```bash
uv run pytest --junitxml=.tmp/<session>/verification/<id>.xml
```

**canary（防「通道其实没工作」）**：解析完 XML 后，要确认它**真的收集到了用例**——
例如按名字检索一条本轮新增的用例；再用一个**编造的用例名**确认检索为 0。只有「命中真名 +
不命中假名」同时成立，这次计数才算数。

### 1.2 Windows 控制台是 GBK，中文输出会炸

质量地板等脚本输出中文时，直接跑会 `UnicodeEncodeError`。取值：

```powershell
$env:PYTHONIOENCODING = 'utf-8'   # 或给脚本传 --output <path> 落盘再读
```

### 1.3 pwsh 的 `Select-String -Path` **不支持 `**` 递归**——且失败是静默的

实测（2026-10-02，同一批文件）：

| 写法 | 结果 |
|---|---|
| `Select-String -Path 'apps/api/src/**/repository.py' -Pattern 'async def'` | **0 条命中**（不报错） |
| `Select-String -Path 'apps/api/src/campfire/modules/profile/repository.py' -Pattern 'async def'` | 29 条命中 |
| `Get-ChildItem apps/api/src -Recurse -Filter repository.py` | 3 个同名文件确实存在 |

⇒ **`**` 把「有匹配」变成「0 匹配且无错误」**。这是本仓最危险的一类静默失败：它会让你
把「不存在」当成结论写进报告。

**纪律**：
- 全仓内容检索**用 grep 工具**（或 `Get-ChildItem -Recurse | Select-String`）
- **凡「0 条命中」的结论，必须配阳性对照**（见 §5.2）

### 1.4 长进程：入场清点、后台托管、出场清理

需要起 dev server / 长构建时，用后台作业并**记下 id 与端口**；收工必须显式清理并复核。

本仓实例：真机验证时起了前端 dev server 占 `5173`，会话结束后**端口仍在监听**，需显式
`Stop-Process`（取证：`Get-NetTCPConnection -LocalPort 5173 -State Listen` 仍返回 PID）。
「后台作业结束」不等于「它拉起的进程退出」。

## 2. 隔离与并发

### 2.1 每个写包独立 worktree

本仓曾以 `E:\Project\Web_Development\campfire-wt\<lane>\` + 分支 `lane/<id>` 隔离并行包
（实测：`campfire-wt` 下有 `t01`… 等多个 worktree 残留）。共享 venv 可复用以省安装时间。

### 2.2 同机并发跑 pytest 会互相污染

**这是本节最重要的一条。** 本会话中由**四个独立来源**观察到同一现象：并发跑测试时出现
与本轮改动无关的失败，且**收集到的用例数会漂移**（例：218 vs 正常 217）。

| 观察者 | 现象 |
|---|---|
| 编排器 | 一次全量从 12 条失败缩到 6 条（另一个包在改同一仓库时） |
| 包 A | 定向子集在**与后台全量并发**时 `4 failed + 1 error`；单跑 5 次均全绿 |
| 包 B / C | 各遇到 5~6 条、2 条无关失败 |

**处置**：
- **不要**把并发期间的失败当成缺陷证据
- 判失败必须：**隔离复跑** + 取**全量 junitxml** 逐用例对账（用**用例名集合差集**证明
  「净增 N、消失 0」，这同时能证否「兄弟包的改动混进来」）
- **写入包在跑时不要并行跑全量测试**；优先等待

**边界**：以上是**多次观察**，不是受控实验；机制（共享 PostgreSQL/Redis/FalkorDB 与
临时表/事务交叉）**未定位**。

### 2.3 并发写入包 ≤ 2

操作经验：同时 3 个**写入**包时，包失败（未给收尾消息就退出）的比例明显上升；2 个时稳定。
只读侦察包可与写包并行。**这是经验判断，非受控实验**。

## 3. 子代理的能力边界（决定任务包怎么写）

子代理继承父的工作目录与 skill 目录（可读 `read/grep/glob/pwsh/skill/todo_write`），
但有**三处不能**：

| 能力 | 子代理 | 实测拒绝原文（摘） |
|---|---|---|
| 问用户 | ❌ | `human interaction is unavailable while the calling agent is owned by another live agent` |
| 再派发 | ❌ | `subagent depth 2 exceeds maxDepth 1` |
| 请求提权/审批 | ❌ | 权限范围启动时固定；需审批的操作自动拒绝，不得重试被拒操作 |

**三条推论**：

1. **任务包必须自包含到「不问人也能做完」**——凡「需要澄清才能做」的包都是编排器的缺陷，
   应退回重写，而不是指望子代理来问
2. **派发是扁平的**（深度上限 1）：**任务粒度必须由编排器一次切到位**，子代理不会再拆包
3. 子代理的一切疑问只能写进**报告的「未决问题」节**，由编排器代问用户

## 4. 派发配方的实证修正清单

以下每条都是本会话中**真实踩过**并修正的（括号内是代价）：

| # | 修正 | 代价来源 |
|---|---|---|
| 1 | 计数用 `--junitxml`，不数控制台 | 多条结论依赖不可复现的行数 |
| 2 | 不用 pwsh `**` 做全仓检索 | **静默 0 命中**会被当成「不存在」（§1.3） |
| 3 | **复核性测量必须保留驱动源码** | 一次审查者的 harness 被删，导致「复现」与「未复现」双方结论**永久无法核对** |
| 4 | 前端包必须验证契约样式**到达构建产物**（不只是单测绿） | 「单测绿 ≠ 样式到运行时」 |
| 5 | 授权文件集与实测参考集**冲突时先问**，不要自行扩大 | 越权改动风险 |
| 6 | **无产物 ≠ 已死**：先发消息问，不要急着重派 | 曾把一个仍在跑全量基线的包判死并重派 → 同一任务两个包 |
| 7 | 子代理**禁止** `amend` / `rebase` / `reset` 共享分支 | 一次 `git commit --amend` 落在他人已推进的 HEAD 上，改动被折进别人的提交 |
| 8 | 收工**必须查未跟踪文件** | 一份 278 行的并发测试**从未被 `git add`**，差点随工作区清理丢失 |
| 9 | 消融/注入类验证**必须证明注入真的落地** | 见 §5.1（四例假绿） |
| 10 | 质量地板必须 `--root apps/api` | 基线路径与条目 `file` 键都相对扫描 root；换子根会**继承不到基线**而恒 fail |
| 11 | 环境变量先查证再写进配方 | §0：两条「必设」实测不承重 |
| 12 | 长进程出场清理 | §1.4：dev server 残留监听 |

## 5. 验证纪律：假绿与阳性对照

### 5.1 本会话出现四次假绿，全部由执行者自查发现

| # | 现象 | 为什么会假绿 | 抓法 |
|---|---|---|---|
| 1 | 消融注入后测试仍「绿」 | `.Replace()` 因 **CRLF/LF 不匹配**没命中，违规**实际没注入** | 改成按行插入 + **打印注入后的行号** |
| 2 | 同上 | Python 3.12 无 `Path.read_text(newline="")` → 脚本抛错、注入没发生，pytest 却报 `2 passed` | **强制打印从磁盘读回的内容** + `git diff --stat` |
| 3 | 新规则「主用例全绿」 | 正则拿**带 `.py` 的 basename** 比对，一整类写法**没收进来**，而该类被另一种写法顶上 | 自检里的**合成断言** |
| 4 | 门禁「照样绿」 | 探针 **argv 顺序写反** → 静默空转 | 改成「未知动作硬失败」后重做 |

**共同点：四次都是「只看绿」就会得出错误结论。** 因此：

> **凡「通过/未复现/0 失败/无匹配」的结论，都必须能回答「如果真相相反，我这个手段会不会红」。**

### 5.2 阳性对照（canary）怎么写

- **检索类结论**：「0 条命中」必须配**同一通道能找到已知存在物**的证明。例：查某异常类的
  引用先确认它命中 43 条，再用同 pattern 在归档目录命中 4 条 —— 证明通道在工作
- **未复现类结论**：必须有**合成对照**证明探针能检出该失效形态。一次真机验证的做法是：
  用「闭包旧值」与「函数式更新」两份最小状态机跑同一驱动，前者 **12/12 检出**、后者
  **0/12** —— **只切换那一行语义，结论翻转**，这才使「未复现」有意义
- **测速/采样类**：不要只跑一次；报告**出现率**（如 15 种写法 × 12 次 = 180 次，报丢 0 次）

### 5.3 「绿 ≠ 覆盖」的三种形态

1. **门禁绿 ≠ 前提成立**：静态类型检查对「运行期参数取值」无感——一条 `# type: ignore`
   的替代品（`cast` 收窄）能让 mypy 转绿，而真正承重的前提要靠**一条断言该前提的测试**守住
2. **单测绿 ≠ 真机能跑**：本项目三个 P0 都只在真实运行时暴露，而单测全绿
3. **断言存在 ≠ 断言有效**：本仓出现过**恒真断言**（两侧取自同一模块同一批常量）与
   **永不命中的守卫**。机械检查全绿，只有独立探针与消融能找到

### 5.4 「守卫恒真 / 永不命中」是一个独立缺陷族

要在派发里专门问一句：**这个检查在当前接线下有可能失败吗？** 若不会，它就不是守卫，
而是一行注释。同类还包括「注释声称有某条测试守住该性质，而那条测试**根本不存在**」——
后者的机械守门可覆盖「名字不存在」，但**覆盖不了「名字存在而断言不在」**（那需要语义理解，
硬做会造出有假阳/假阴的坏守门）。

## 6. 收口清单（本仓具体命令）

```bash
# 后端
uv run pytest --junitxml=<path>          # 从 XML 读计数
uv run ruff check . && uv run ruff format --check .
uv run mypy apps/api/src/campfire apps/api/tests   # 两个路径必须同时给（见 AGENTS.md）
uv run alembic heads && uv run alembic check        # 单 head + 无漂移

# 前端
pnpm --filter @campfire/web lint && pnpm --filter @campfire/web test && pnpm --filter @campfire/web build

# 文档与门禁
uv run python scripts/check_design_docs.py
uv run --no-project python .dsh/skills/code-craft/scripts/quality_floor.py scan --root apps/api
```

**收口三件事，缺一不可**：

1. **`git status` 查未跟踪文件**——本仓 `.tmp/` 与 `reports/` 被忽略，探针文件不会自动
   `git add`；既要**发现该提交的**，也要**明确不提交的**
2. **红线核对**：本仓 `docs/` 归设计方所有；若本轮授权不含改 `docs/`，用
   `git diff --name-only <base>...HEAD -- docs/` 确认结果为 0
3. **合并收口**：确认 `dev` 与工作分支一致（本仓用 fast-forward）

## 7. 仓级陷阱：`git diff` 为空**不等于**未改动

**本仓 `core.autocrlf=true` 且 `.gitattributes` 有 `* text=auto`。** 后果（实测）：

- `git checkout -- <file>` 与 Python `write_text()` 都会把文件 **LF → CRLF**
- **`git diff` 对这类变化失明**：实测 `git checkout --` 之后 `git diff` 为空，但**字节数从
  775 变成 795**

⇒ **「`git diff --stat` / `git diff --exit-code` 为空」不能作为「逐字节未改动」的证明。**

**正确复原**：按 `git cat-file blob HEAD:<path>` 取字节写回，再 `git add` 刷新 stat 缓存。

**加重与限定**：因为 `* text=auto` 在**提交时归一化**，CRLF 抖动**到不了提交**里，故影响
范围限于**工作树形态**与**「我已逐字节复原」这一类主张**。派发时若要求子代理证明「未改动
/ 已复原」，**要求 sha256 或 `git cat-file` 字节比对**，不接受只报 `git diff` 为空。

## 8. 证据边界

**做得成的**：本文全部事实均在 **Windows + Python 3.12.12 + DSH `0.1.7-rc.2`** 上实测，
取证方式逐条标在表内。

**没测的**：

- 省略 `UV_PROJECT_ENVIRONMENT` 后 `uv` 的行为（§0 已标「未测」）
- 非 Windows 平台；非 3.12 的 Python
- 并发污染的**机制**（只观察到现象，未定位到具体共享资源）
- 「并发写包 ≤ 2」是经验判断，**非受控实验**
- `--import-mode=importlib` 与 `conftest` 收集的交互，未查

**推翻条件**：

- 若 `pyproject.toml` 不再改 `addopts` / 不再提供可编辑安装 → §0、§1.1 需重测
- 若 `.gitattributes` 的 `* text=auto` 或 `core.autocrlf` 变更 → §7 失效
- 若 PowerShell 版本升级改变 `Select-String -Path` 的 glob 语义 → §1.3 需重测
- 若 DSH 版本换代（如 `maxDepth` 或子代理能力集变化）→ §3 需按对应 profile 重核
