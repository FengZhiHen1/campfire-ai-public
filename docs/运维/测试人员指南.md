## 0. 开始之前（**必读，能省你一半时间**）

### 0.1 你需要两样东西

| 东西 | 说明 |
|---|---|
| **一个邀请码** | **本次已签发**：`3K5PVU9D`（**到期 2026-11-04**）。**8 位、一次性**——用掉即失效，**多人共用会互相打架**（详见第 10 节） |
| **一个测试账号** | 自己起名。**⚠ 见 0.2——必须写成邮箱格式** |

> **⚠ 邀请码是一次性的**：`3K5PVU9D` **只能注册一个账号**。
> 若你要**多人/多轮**测试，**每位测试人员请向运营另索一枚**——
> 用同一个码重复注册，第二次会得到「邀请码无效或已被使用」，
> **那是正常的**（§2.3 正是要验它），**不要当成注册故障**。

### 0.2 ⚠ **账号名必须写成邮箱格式**（【已知】缺陷 `PROD-01`）

界面上这个字段叫「**账号名**」，**它不会告诉你需要邮箱格式**，但**实际会被拒**：

| 你输入 | 结果 |
|---|---|
| `xiaoshi` | ❌ 被拒：「**该账号名无法使用，请换一个**」 |
| `小安` | ❌ 同上 |
| `a@b` | ❌ 同上（格式太短） |
| **`tester01@example.test`** | ✅ **可以** |

**⇒ 请一律用「名字@example.test」这种形式**，例如 `zhang@example.test`。

**为什么**：真源设计要的是「账号名与密码、不要求邮箱」，但身份服务的默认邮箱校验器**从未被复写**
⇒ 实际退化成「必须邮箱格式」。已登记为 `PROD-01`（修它要动身份服务装配，属跨模块契约，待裁决）。

**⚠ 这条最重要**：不知道它的人会以为是「注册坏了」，其实只是名字格式不对。

### 0.3 密码规则

**至少 8 位，且同时包含字母与数字**（例：`campfire2026`）。
不满足时页面会直接提示这句，**不是错误**。

### 0.4 邀请码长什么样

**8 位**，取自 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`
（**注意：没有 `I`、`O`、`0`、`1`** —— 为免混淆被刻意排除，所以**看到 `0` 说明抄错了**）。
建议**粘贴**而不是手打。

### 0.5 测试前请记录

- 浏览器与版本、操作系统；
- 你的测试账号名；
- **遇到问题时的时间点**（便于对着服务器日志查）。

## 1. 冒烟：站点活着吗（30 秒）

| # | 做什么 | 通过判据 |
|---|---|---|
| 1.1 | 浏览器打开 <https://campfire.wenran.me> | 出现**登录页**（不是报错页） |
| 1.2 | 地址栏确认是 **`https://`** | 有锁标；`http://` 会自动跳 `https://` |
| 1.3 | 打开 `https://campfire.wenran.me/readyz` | 返回 **`{"ready":true, …}`**，7 个组件全 `ok` |

> `/readyz` 里 `ready:true` 是**服务端自检**（认证/数据库/队列/模型/图库/装配/skill）。
> 它是**必要条件，不是充分条件**——它绿不代表功能都对（本项目真发生过「探针全绿而记忆写入全坏」）。

## 2. 注册与登录（核心入口）

### 2.1 注册（用真邀请码）

1. 打开 <https://campfire.wenran.me/login>；
2. 页面底部切到「**注册**」（链接文案：`已有邀请码？注册账号`）；
3. 填 **账号名**（**邮箱格式！**见 0.2）、**密码**（≥8 位含字母数字）、**邀请码**（粘贴）；
4. 提交。

**通过判据**：注册成功并**进入需登录的页面**（首页）。**不弹错误。**

**⚠ 注册态应当只有三个字段**：账号名 / 密码 / 邀请码。
**界面上不应存在「邮箱」字段、不应有「忘记密码」入口**——若看到，是缺陷。

### 2.2 **关键负例**：用假邀请码注册（必测）

再切到注册态，填一个**假邀请码**（例：`ZZZZZZZZ`）+ 新账号名 + 合规密码，提交。

**通过判据**：出现**我方文案**「**邀请码无效或已被使用**」。
**❌ 不合格**：500 错误页、空白、或英文技术报错。
（文案故意**不区分**「无效 / 过期 / 已用」，避免被人枚举出哪些码存在。）

### 2.3 **关键负例**：同一个码用两次（必测）

用 **2.1 已用过的那个码**，再注册**第二个**账号。

**通过判据**：**失败**，同样提示邀请码不可用。
这条对应「**一码只用一次**」（`AC-15`），是硬约束。

### 2.4 登录与刷新保持

1. 回 `/login`，用 2.1 的账号登录；
2. 登录后**按 F5 刷新**。

**通过判据**：进入首页；**刷新后仍是登录态**（不掉回登录页）。
登录凭据是 httpOnly cookie，**刷新掉线说明 cookie 域或协议配错**，是缺陷。

### 2.5 登录负例：错误密码

用**存在的账号 + 错误密码**登录。

**通过判据**：提示「**账号名或密码不正确**」。
**故意不区分**「账号不存在」与「密码错」——同样是为防枚举。
**并注意**：**不要**期望它告诉你「该账号是否存在」。

## 3. 主链路：发一条咨询（**最核心**）

### 3.1 新建会话并发一条消息

1. 点底部 tab「**咨询**」（tab 栏四项：首页 / 咨询 / 档案 / 我的）；
2. 若列表为空会看到「**还没有咨询记录**」与「**开始新的日常咨询**」；
3. 新建会话，输入一句真实的话（例：「孩子早上不肯去幼儿园，我该怎么办」），发送。

**通过判据（三条都要看）**：

1. **文字逐字/逐段出现（流式）**，**不是整段一次性蹦出来**；
2. 回答结束后出现**依据区（引用卡片）**；
3. **不报错**；回答内容与你的问题相关。

> **为什么强调「逐字」**：SSE 被 nginx 缓冲时，状态码仍是 200、内容也完整，
> **唯一区别就是「一次性到达」**。⇒ **这一条必须用眼睛看**，看状态码看不出来。

### 3.2 刷新续传

在**回答还在生成时**，按 F5 刷新。

**通过判据**：回到**同一会话**、能看到完整回答（历史水合），**不丢消息、不重复发**。

### 3.3 取消

回答进行中，找「**停止**」（若有该入口；本轮该入口是否出现也请你记录）。

**通过判据**：流停止、界面回到可控状态、不报错。

### 3.4 应急入口

1. 打开 <https://campfire.wenran.me/consult/emergency>（或从页面入口进）；
2. 它会**逐题**问你现场情况（不是一页长表单）；**可以随时提交，无需答完**。

**通过判据**：提交后**直接进入对话页并开始回答**（不必再手工发一条消息）。

### 3.5 历史会话

回 `/consult`，列表里应看到 3.1 建的会话；点进去能看到历史消息。

## 4. 档案页

### 4.1 新建支持对象

tab「**档案**」→ 新建（填名称）。

**通过判据**：列表出现该对象；**刷新后仍在**（真落库，不是内存状态）。

**关键负例**：**名称留空**提交 ⇒ 应被拒（内联错误/422），**不是 500**。

### 4.2 改名 / 归档 / 恢复

对同一对象依次：**改名 → 归档 → 恢复**。

**通过判据**：每步生效，且**可重复做**（幂等，重复归档不报错）；
归档后**新条目被拒**、但**旧内容仍可读**。

### 4.3 条目与候选层

在对象下新增一条档案条目。

**通过判据**：新条目先进「**候选层（待确认）**」，**确认后**才进稳定层。
（这是刻意的产品约束：**系统推断不得当成既成事实**。）

## 5. 记忆页与案例库

### 5.1 记忆时间线

`/settings/memory`（或「我的」→ 记忆）。

**通过判据**：**空的时候返回 200 + 空列表是正常的，不是失败**；
有内容时能看到条目，并有「发生时间」。

### 5.2 记忆纠正 / 删除

对一条记忆先「**更正**」，再「删除」。

**通过判据**：删除后列表不再出现该条。
注意提示语：「**更正会新增一条，原记录不再作为依据**」——**更正不是覆盖**，是保留历史 + 新增。

### 5.3 案例库

`/cases`。

**通过判据**：**案例**与**资料**两个库**分开**取数；空库返回 200 空列表；
若传未知库别参数应返回 422。空库时可能看到「**案例库还在准备中**」。

## 7. 视觉：本轮前端美化专项（**请重点看这部分**）

本轮把宽屏渲染改成了「**手机外壳**」形态（而不是单纯收窄列宽）。请在**电脑浏览器**上验证：

| # | 做什么 | 通过判据 |
|---|---|---|
| 7.1 | 把浏览器窗口拉到**宽**（≥1200px）打开任意页面 | 内容**居中在一个手机外框里**（有边框/圆角/屏幕区域），**不是**一条窄窄的列贴在页面上 |
| 7.2 | 同上窗口，看底部 tab 栏 | tab 栏**在外壳内部**（贴着外壳底边），**不是**横跨整个浏览器宽度 |
| 7.3 | 把窗口缩到**窄**（≤430px，或直接用手机） | 外壳**消失**，内容**占满屏幕**（手机上是原生观感） |
| 7.4 | **键盘 Tab 键**逐个走一遍（登录页、对话页、确认单） | **每个可聚焦元素都有明显焦点框**（2px 橙色描边）；**焦点不会跑到外壳外面** |
| 7.5 | 打开任一「确认单」（例：删除记忆时的确认弹窗） | 弹窗出现时，**背景内容不可点击、不可 Tab 到**（模态语义）；**Esc 能关**；关闭后**焦点回到原来那个按钮** |
| 7.6 | 检查文案标点 | 按钮/标题类硬文案**句末不带句号**（与设计文档一致） |

**⚠ 已知**：`visibility:hidden` 的元素**仍可能被 Tab 聚焦**（守卫覆盖不到该形态，已登记）。
**若你遇到**，请记录元素与页面，**算已知问题**。
