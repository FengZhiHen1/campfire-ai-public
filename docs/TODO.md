## 一、已知限制（使用者会直接遇到）

| 限制 | 现状 | 影响 |
| --- | --- | --- |
| 注册是邀请制 | 邀请码由团队签发，公开仓不提供通用账号 | 无法自助注册；想自己跑需本地签发邀请码，见 [`README.md`](../README.md) 的快速开始 |
| 单机部署 | Docker Compose 单机 + Nginx，无多副本、无集群限流、无异地容灾 | 可用性取决于单台服务器，不适合直接承载规模化用户 |
| 上下文压缩未接线 | 记账端口尚无持久化实现，长会话的上下文窗口会退化为全量历史 | 方向安全（不丢内容），但长会话成本更高、时延更差 |
| 评测口径有限 | CareBench 的 40 例测的是整理过的单轮输入；评分由两套 AI 独立完成再加分歧裁定 | 不代表真实应急入口下的口语与碎片表达；**AI 评分不构成专家背书** |
| 语料不完整 | 真实访谈案例与部分第三方语料因授权范围不足不随仓分发 | 公开仓开箱的检索效果弱于产品实际；逐条原因见 `NOTICE` |
| 模型与嵌入绑定 | 全应用单一对话模型，走 OpenAI 兼容接口（可换网关）；嵌入维度固定 | 换嵌入模型必须整库重建，不能跟着对话模型一起换 |
| 形态单一 | 一期只交付手机端 H5，界面语言只有中文 | 桌面端未适配；非中文使用者不可用 |

## 二、面向真实使用者前的发布前置

这些不是功能，是**开门前的闸门**；未关闭前不应把产品当作可对公众开放的服务：

1. **真实语料录入与检索质量评测**——当前语料是已完成许可核查的子集，检索质量尚未在完整语料上评测；
2. **专业复核**——领域知识与应急判据需要专业方复核，AI 自评不能替代；
3. **隐私与服务文本**——数据用途说明、知情同意、儿童与家庭信息的处理边界，需在真实使用者入场前定稿；
4. **运营边界**——一期运营操作经 CLI，没有运营后台，运营者身份等同服务器访问权；
5. **容量与压测基线**——单机部署下的并发、时延与资源上限尚未给出可引用的读数。

## 三、实施前必须验证的技术事实

- **模型服务**：所用网关的可用性、计费与条款，以及是否稳定支持 tool calls 与流式；
- **嵌入模型**：维度与向量列的绑定关系（换模型即整库重建）；
- **图库**：Graphiti 与 FalkorDB 的版本匹配性；
- **前端运行时**：对话界面所选 runtime 与现有实现的兼容边界。

已在真实容器内实测确认、不再列为待验证的项（pg_trgm 的中文行为、向量存储接口形状）不在此重复。

## 四、可扩展方向（一期明确不做）

- **二期：支持空间与关系授权协作**——跨账号共享档案与机构协作；判据是出现真实场景，并在唯一授权端口上加维度，不新建第二套授权机制；
- **运营 web 后台**——一期运营经 `campfire.cli`；启用条件是非技术运营者、多人协作或需要应用层追责；
- **附件与多媒体**——编排里保留了对象存储，一期无消费者；
- **多端**——一期只手机端 H5，桌面端与小程序不在范围内。
