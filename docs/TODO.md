## 一、证据闸门（缺少证据时保持相应能力关闭）

| ID | 状态 | 所需证据与负责人 | 放行边界 |
|---|---|---|---|
| EVID-01 | missing evidence | 具名专业审阅者的资质、可持续投入与签收人；与合作机构确认可访谈参与者、老师及试点负责人，并为严重事故指定有权停服的人 | 未获审阅者不能对公众发布安全指导、专业策略、案例或演练；不能把合作意向当作已投入的服务 |
| EVID-02 | missing evidence | 逐一清点指南、研究、案例和训练情景的来源、引用/二次使用许可、脱敏和审阅记录；旧 BPI 翻译与“深压/前庭”标签如需复用须单独找证据 | 不继承旧“60 条/每类 5 条”作安全门槛；未经许可不建向量索引、不发布个人经验或虚构素材为真实案例 |
| EVID-03 | missing evidence | 在至少 12 名真实支持者、两类非活动情境的受控试点中记录可用下一步时间、错误、意愿尊重、交接遗漏与审阅返工；静态资料对照、个性化/反馈消融及未练过情景的独立评价 | 少样本只报告可行性，不声称临床疗效、个性化增益或演练迁移；真实个人输入另需 EVID-04 |
| EVID-04 | missing evidence | 核实每家模型/对象存储/日志供应商的数据处理、跨境、保留、删除、训练与审计条款及书面协议；形成可理解的用户告知 | 未落实前只用虚构内部数据，不向外部模型发送可识别个人信息 |
| EVID-05 | missing evidence | 以目标 `/api/v2` 完整可行动结果而非早期 token 测 P95；复测原可比 TTFT P50≤3s、P95>5s 告警、chunk P95≤2s、月可用性≥99.5%，以及历史专业认可度≥85%的分母、审核者资格、分歧与严重错误 | 旧指标是候选或旧交互对照，不假报已达标；严重安全/权限错误不因总体百分比高而放行 |
| EVID-06 | missing evidence | 在有权限的环境盘点旧 `users/profiles/consultations/cases` 的实际记录量、真实数据、附件引用与合法处置依据；验证可恢复备份与回滚演练 | 无清点和可恢复性证明前禁止清库、覆盖历史、`docker compose down -v` 或执行破坏性迁移 |
| EVID-07 | missing evidence | 由法律/数据保护与运营负责人逐项审定临时授权、未保存输入、审计、备份的暂定保留上限，纠错/导出/删除请求时限与法律保留例外 | 目标机制中的天数仅为暂定产品目标，不声称符合任何法域；无法执行删除或权利请求时不收集真实参与者资料 |
| EVID-08 | missing evidence | 确定成年本人/有效监护/机构委托的具体核验材料、失效与争议处理人力、重复空间冲突处置和受托管理员监督 | 无可操作核验就不开真实共享、邀请与交接；登录或创建账号不代表拥有他人资料权 |
| EVID-09 | missing evidence | 用家属和一线支持者核验 Web 首次使用、公开帮助、私人/共享范围、条目停用的理解；实施后实测色彩对比、键盘与屏幕阅读器、低带宽及触区 | [Web 设计契约](./design/README.md)未经用户视觉评审和设备测试，不得写成已可用或 WCAG 达标 |
| EVID-10 | missing evidence | 核实真实可达的现实求助渠道、公开基础内容的专业适用范围/版本/撤下流程及非服务时段责任 | 无签收时不公开声称安全处置或实时专家接管；仅内部虚构情境评审 |

## 三、明确延期与重访

| ID | 状态 | 重访条件 |
|---|---|---|
| SCOPE-01 | 延期 | 语音、图片等输入及长期离线存储需取得用户价值与数据权限证据；首期只保证公开已审阅内容的可达与明确降级，不承诺个人资料离线可用 |
| SCOPE-02 | 延期 | 微信登录、小程序和需求/供给双端终态仅在渠道资质、维护资源与实际用户场景明朗后重访；当前 Web 是唯一活跃端 |
| SCOPE-03 | 延期 | 专家工单、人工作答、30 分钟响应与固定轮次须有真实具名团队、排班和责任协议后单独决定，不属于当前服务承诺 |
| SCOPE-04 | 延期 | 社区、上传激励和用户生成公共案例需有适用授权、审核产能、传播和滥用治理后再设计 |
| SCOPE-05 | missing evidence | 商业模式、付费方、可持续运营及赛事评分属独立验证；不把 B2B2C 收入或评分优势写作事实 |
| SCOPE-06 | 延期 | 旧 ABC、BPI 与感官标签若再次成为目标功能，需专业审阅翻译、适用性和对应证据；旧目录中的“待补充”不是当前系统自动支持的依据 |

旧技术重构计划及旧 ADR 中的分散待办仅保留历史时点的来源作用，不作为执行队列；本表的实施工作必须先通过对应证据闸门，不能以文档完稿替代测试。
