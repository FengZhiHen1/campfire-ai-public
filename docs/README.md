# 篝火智答（Campfire-AI）设计文档

本目录是产品设计的**公开部分**：技术选型、领域机制与接口契约、视觉契约、工程约定，
以及还没做完的事。每份文档只拥有自己那一部分事实——要改某个结论，先改它的拥有者，
别在别处另立一份。

> **不在本仓的部分**：需求基线（`需求/`）、项目结构设计（`项目结构设计.md`）、
> 运维手册（`运维/`）、服务器选型事实基线（`服务器选型事实基线.md`）、材料落点说明
> （`development/materials.md`）与开发检查点（`development/checkpoints/`）。它们只在内部
> 开发仓维护，不随本仓分发；本目录不复制其内容。
>
> **未闭合的东西**（压缩未接线、发布前置闸门、评测口径局限）统一登记在[设计待办](./TODO.md)，
> 本文不重复清单。

## 四、技术决策记录（`技术设计/decisions/`）

[决策索引](./技术设计/decisions/README.md)列出全部 ADR：每条写清备选、评价、依据、后果与重访条件。
对读代码影响最大的几条：检索链归入 `library` 模块、通用记忆归属为账号、会话校验逐请求查证数据库、
一期只做个人账号、运营操作经 CLI、档案单写入路径按来源分流、应急卡片由产品侧工具产出、
激活记录即授权真源。

## 八、文档纪律

- **一份事实只有一个拥有者**：冲突时按拥有者判断，不在第二处改结论。
- **未确认的内容不进设计文档**：草案留在 Issue 或讨论里，落进 `docs/` 即视为已确认口径。
- **契约先改真源**：接口形状归各面契约，事件语义归通用基座，字段规则归对应 technical-details。
- **文档随代码同批改**：改了接口、配置、默认端口或许可边界，对应文档要同批更新。
