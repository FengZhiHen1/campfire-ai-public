# ADR-004：架构模式选择模块化单体

> **状态**：有效，已由 [DSR-001](./DSR-001-Hybrid-Monorepo.md) 演进为 Hybrid Monorepo 形态（2026-05-23 决策）

## 上下文

项目含 5 个功能模块，需选择代码组织与部署模式。

## 备选与评价

- **模块化单体（Modular Monolith）**：1-3 人团队不应引入微服务——将导致开发效率断崖式下降；5 个模块共享数据源（PostgreSQL），强行拆分增加网络通信开销；按 Python package 划分模块边界，后续可独立拆出为微服务。
- **微服务**：独立部署扩缩容，但对小团队运维成本过高。
- **Serverless**：冷启动与流式 SSE 场景不友好。

## 决定

模块化单体（Modular Monolith）。

## 后果

- 正面：开发/测试/部署极简；
- 负面：模块边界需纪律维护，不能独立部署和扩缩容。

## 重访条件

团队规模扩大或单一模块出现独立扩缩容需求时，按 packages 边界拆出微服务。
