# ADR-005：LLM 选择 DeepSeek API

> **状态**：2026-05-23 旧应急模型选型的历史决定；当前供应商仅为候选，真实资料处理须满足[技术栈设计](../技术栈设计.md)的数据边界，不以旧成本/上下文窗口描述代替核验。

## 上下文

应急咨询需要大模型生成结构化应急方案。

## 备选与评价

- **DeepSeek API**：性价比最优（约 OpenAI 1/10 成本），符合预算约束；百万 Token 上下文窗口可容纳大量案例切片；中文能力与应急建议场景高度匹配。
- **通义千问 API**：能力相当，成本约 3 倍。
- **本地部署开源模型**：数据不出内网，但运维与 GPU 成本不适合 1-3 人团队。

## 决定

DeepSeek API。

## 后果

- 正面：低 Token 成本支撑 7×24 全天候运行；
- 负面：依赖云服务，需熔断降级机制（见[总体架构](../总体架构.md) §6 风险表）。

## 重访条件

DeepSeek 服务稳定性或价格政策发生重大变化时，切换通义千问备用方案。
