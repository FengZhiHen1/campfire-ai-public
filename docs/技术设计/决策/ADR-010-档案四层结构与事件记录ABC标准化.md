# ADR-010：档案四层结构与事件记录 ABC 标准化

> **状态**：2026-08-03 旧四层档案方案，作为已实现代码与迁移对照；当前支持对象、空间、带来源记录及私人事项由[目标机制](../目标机制/README.md)定义。

## 上下文

ADR-009 时刻分层重构对档案提出了明确的槽位供给需求（称呼/安抚物/禁忌/走失报警信息等），对照 [references/孤独症家庭应急干预与行为支持_科学资料综述.md](../../references/孤独症家庭应急干预与行为支持_科学资料综述.md)（2026-07-30）审查现有档案模型，发现系统性差距：

1. **事件记录结构化不足**：触发/表现/干预/结果以自由文本为主且全部必填，而证据（附录 A.4）给出的政府模板级共识是「结构化勾选 + 最少自由文本」——自由文本既加重高压照护者负担，又让 M5 趋势复盘失去可靠数据基础；
2. **记录模式与场景不匹配**：单一完整表单在危机中不可用，证据要求「危机中一键打点 + 事后补全」双模式（§3.3）；
3. **应急槽位无字段承载**：有效安抚物、禁忌、走失报警信息等在模型中不存在；
4. **全生命周期支持薄弱**：`setting` 无工作场所/托养机构，无精神共病字段（成年 ASD 共病率 81%，§6.2）；
5. **枚举体系分裂**：档案 `behavior_type` 与 ADR-009 应急行为桶是两套枚举，而桶兼任检索过滤维度，分裂引入映射成本。

用户授权「不要有任何顾虑，一切只为了最优」，允许破坏性变更与数据迁移。

## 备选与评价

| 方向 | 评价 |
|---|---|
| **BSP 为中心**（档案即家庭行为支持计划，六要素为一等实体） | 专业纯度最高，但家属填写负担重、冷启动门槛高，与「非专业、危机认知负担重」的用户画像冲突；BSP 更适合作为导出物 |
| **保守修补**（三表不动只加字段） | 成本最低，但 A.4 结构化、双模式记录、量表等证据输入全部无法落地，复盘继续建立在自由文本上 |
| **分层重组** | 保留事件时间线为核心，四层各承一职；危机预案层集中供给应急槽位；与轻量启动兼容（仅走失组有冷启动引导，其余渐进完善） |

量表引入深度上，「BPI-01 仅作后台词表 + SC-ABC 老师侧可选 + QABF 预留字段延至 M5」在专业价值与家属负担间占优（58 题 SC-ABC 与家属画像冲突，填写率风险高）。

## 决定

1. **档案按四层结构重组**：身份基础层 / **危机预案层**（应急槽位唯一来源）/ 事件时间线层 / 专业评估层；BSP 与照护交接手册作为导出物，后续迭代；
2. **危机预案层字段集**：走失专项组（`physical_description` / `familiar_places` / `water_risk`）、`soothing_items`（有效安抚物，事件推导作兜底）、`avoid_list`（禁忌/无效方式，志愿者预案摘要中置顶）、`emergency_contacts`、`communication_methods`（语言水平 + AAC/视觉支持）、`medication_notes`（自基础层移入）；
3. **Event Log 按附录 A.4 结构化 ABC 标准重构**：新增 `behavior_form`（BPI-01 词表）、`duration`、`activity`、`people_present`、`physical_state`、`antecedent_category`（前事预置分类）；`intervention_tried`/`intervention_result` 重构为 `consequence`/`reaction`；自由文本从 4 个必填降为 1 个可选 `note`；**强度枚举 3 级改 4 级**（低/中/高/严重）；新增 `is_quick_log` 标记；
4. **双模式记录**：危机中一键打点（必填仅 `behavior_type` + 自动时间戳，可挂应急会话自动生成），事后引导补全（其余字段全可选）；
5. **量表深度**：BPI-01 仅作 `behavior_form` 后台词表（家属无感）；SC-ABC 为老师侧 Web 可选工具，MVP 不内置；QABF 预留 `function_hypothesis` 枚举字段（注意/逃避/实物/自动强化/躯体不适），填表交互延至 M5 复盘阶段；
6. **生命周期**：身份基础层新增 `comorbidities`（精神共病多选）；`setting` 枚举扩展 +工作场所/托养机构；burnout 监测与照护交接手册为后续迭代，不预留字段；
7. **枚举统一**：`behavior_type`/`primary_behavior` 新枚举（情绪崩溃/刻板行为/自伤/攻击/走失/用药相关/社交退缩/多动/其他），应急行为桶为其直接子集；**「情绪等级」维度退役**，检索过滤统一为「年龄段 + 行为桶」，`case_chunks.metadata.emotion_level` 的对齐列为案例库侧后续项；
8. 隐私：新增字段继承现有访问矩阵（档案仅家属及关联者可见），不作权限模型变更。

## 后果

- 正面：应急槽位有确定性的字段来源（不再纯靠事件推导）；事件数据结构化后 M5 复盘可做时间-行为热力图与触发因素聚合；填写负担不升反降（必填 4 文本 → 1 枚举）；档案与应急枚举统一，检索过滤零映射；
- 负面：**破坏性数据模型变更**——强度枚举、行为类型枚举、字段重命名均需迁移脚本与历史数据映射；危机预案层引入新的填写引导设计责任；BPI-01 词表需专业翻译审校（中文条目化）；
- 波及文档：个性化档案库文档组（数据模型重写、README/记录流程/应急联动注入修订）、智能应急咨询 §3.1 槽位表、需求/功能需求与验收 M2、决策 README、docs README；案例库 `case_chunks.metadata` 对齐为后续项。

## 重访条件

- M5 趋势复盘模块设计时：确认 A.4 字段集是否支撑散点图/帕累托图所需数据，激活 QABF 填表交互设计；
- 档案字段整体上线后，打点率/补全率数据显示负担仍过重时，精简补全引导字段顺序；
- 案例库 metadata 对齐（emotion_level 退役）实施时；
-  burnout 监测或照护交接手册立项时，回到本决策补充字段设计。
