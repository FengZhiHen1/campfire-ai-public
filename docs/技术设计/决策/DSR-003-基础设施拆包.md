# DSR-003：基础设施能力拆分为独立 package

> **状态**：有效（2026-05-24 决策）

## 上下文

项目结构 v1.0 将 RAG、LLM、Cache、Storage、Security 全放在 `apps/api-server/app/infrastructure/` 下，作为 api-server 的内部子目录。

## 决定

v2.0 将每项基础设施能力拆分为独立 package（`py-rag`、`py-llm`、`py-cache`、`py-storage`、`py-auth`、`py-logger`、`py-config`）。

## 理由

1. worker 的案例索引任务需要 RAG（切片+向量化）和 DB 能力，拆分后直接引用 package 即可，无需依赖 api-server；
2. 每个 package 有独立的 `pyproject.toml`（可独立测试、独立版本管理）；
3. 边界清晰——每个 package 只做一件事，符合单一职责原则。

## 后果

package 数量较多，首次 `uv sync` 需解析全部依赖；对于 1-3 人团队，初期可在根 `pyproject.toml` 中统一管理版本号。

> 备注：实施中 package 数量已从 9 个增至 11 个（新增 `py-health`、`py-security`），增量同步见[技术设计 README](../README.md#已知偏差与missing-evidence)。

## 重访条件

某个基础设施能力需要被仓库外的系统复用，或拆包粒度过细导致改动频繁跨包时。
