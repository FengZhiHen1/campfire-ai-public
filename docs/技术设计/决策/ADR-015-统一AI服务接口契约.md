# ADR-015：统一 AI 服务接口契约——契约层统一、端点按面保留

> **状态**：有效（2026-08-04 决策；依据 [Agent 基座](../Agent基座.md) 的分面执行策略与 Skill 清单，契约内容见 [AI 服务接口契约](../AI服务接口契约.md)）

## 上下文

AI 能力已按 [ADR-007](./ADR-007-Agent化-统一基座与分面自治.md)/[ADR-011](./ADR-011-Agent内核框架-内核加扩展与PydanticAI路线.md) 收敛为 6 个 Skill + 两个执行面（应急面/异步面），但对外 HTTP 接口契约分散在各机制文档（[智能应急咨询](../机制/智能应急咨询.md) §六、[科普查阅](../机制/科普查阅.md) §四、[人工兜底通道](../机制/人工兜底通道.md) §四），各自定义端点与协议形态，无跨模块统一约定。流式生成（应急咨询、科普问答）与后台任务（案例提取、预审、工单预组装、趋势复盘）将并存：若各模块自定协议，客户端需要多套流式/错误处理实现，观测（trace_id、Token 追踪）无法统一，新增 AI 能力（M5 趋势复盘等）也无落点模板。

## 备选与评价

- **契约层统一、端点按面保留（选定）**：统一一套 SSE 事件协议（生成型/任务型共用事件族）、错误语义与错误体、Pydantic 契约校验规则、观测约定；端点按执行面组织、按能力保留语义，OpenAPI 可读；与基座「统一内核 + 分面自治」同构；
- 收敛为通用 Agent 网关（如 `POST /agent/run` 少数通用端点，能力经参数路由）：端点数量最少，但 OpenAPI 语义丢失；应急面（此刻安全层 + 分层产出）与异步面（任务式）形态差异大，硬收敛会产生大量条件分支；
- 全异步任务式（所有 AI 接口统一为提交-轮询/回调）：与应急面同步 SSE、TTFT P50 ≤ 3s、单轮生成设计冲突（[ADR-009](./ADR-009-应急链路时刻分层重构.md)），丢失逐 Token 体验；
- 各自为政（现状延续）：多套协议实现成本持续累积，观测无法统一。

## 决定

1. **新建 [AI 服务接口契约](../AI服务接口契约.md) 为 API 契约层唯一事实源**（与 [Agent 基座](../Agent基座.md) 平级），拥有：统一 SSE 流式协议（事件类型族 `accepted/progress/chunk/result/heartbeat/done/error`、sequence 与 Last-Event-Id 断点续传、终态语义）、统一错误语义与错误体、请求/响应契约规则（`py-schemas` 唯一拥有）、观测约定（trace_id/Token/审计）、按面端点组织视图与 Skill 映射；
2. **端点按面保留**：应急面 = 会话流式端点族（POST 创建 → GET 事件流 + 追问轮 + 会话查询）；异步面 = 任务端点族（业务触发端点 + 统一任务事件流端点 `GET /api/v1/tasks/{task_id}/events` + 状态补查）；
3. **一套 SSE 协议承载两种形态**：生成型（`chunk` 文本增量：应急首份方案/追问/科普问答）与任务型（`accepted → progress → result`：案例提取/预审/工单预组装/趋势复盘）；
4. **执行面与接口形态解耦**：接口形态由用户交互语义决定（在线等待 = 生成型、后台任务 = 任务型）——`knowledge-qa` 由异步面 Skill 执行，但接口为生成型流式；
5. **两段式建连**：POST 创建/触发（校验 + 安全前置 → 返回 session_id/task_id）→ GET 事件流连接（EventSource 兼容、自动重连、续传）；
6. **机制文档接口章节改为引用契约文档**：端点业务语义与数据模型仍归各机制文档拥有，协议层细节不重复定义。

## 后果

- 正面：客户端一套 SSE 消费者 + 一套错误处理；服务端一个「内核事件总线 → text/event-stream」装配器（与 [项目结构 v3.0](../项目结构/目录骨架.md) 的 streaming/ 规划一致）；观测（trace_id/Token/审计）统一；新增 AI 能力按契约层模板落端点；
- 负面：两段式建连比单段式多一次往返（内网 RTT 可忽略）；应急面既有 SSE 事件（chunk/heartbeat/done/error）向后兼容保留，无需破坏性迁移；异步面任务事件流为新引入，案例提取/预审/工单预组装从「静默落库」改为「事件流可消费」，需要 worker 侧补事件发布（实施阶段的工作量）。

## 重访条件

- 出现需要第三类事件形态的 AI 能力（如 MCP 工具输出流、多路并行流），现有事件族无法表达 → 扩展事件族或重估协议；
- 出现无法使用 GET 流式/EventSource 的终端形态 → 重估两段式建连；
- 协作照护（M6）引入 WebSocket 实时会话通道 → 评估统一协议是否延伸到 WS 或保持双协议。
