# ADR-008：二元安全门取代三级危机分级

> **状态**：有效（2026-07-02 决策）

## 上下文

原危机分级机制（三层递进判定：前置勾选 → 规则引擎 → LLM 并行复审，轻/中/重三级 × 行为类型矩阵）在 Agent 基座落地前重新审视，发现三处成立性问题：

1. **「中度」的消费者缺席**：中度等级唯一承载的差异行为是「自动生成紧急工单、30 分钟响应」，但工单模块 M4 为 P2 延后（专家资源整合途径不明）；且人工兜底通道的工单触发源（低置信度、用户主动、高风险关键词、连续追问）本就不引用危机等级，优先级可由触发事实直接推导；
2. **LLM 细分级不可靠**：家属危机时刻的一句话描述，轻/中/重细粒度判定连专家都难以稳定区分，LLM 复审的一致性无法支撑差异化兜底语义；且错误代价不对称——轻↔中误判无害，重度漏判灾难，真正重要的判定天然是二元的；
3. **并行复审工程不可行**：LLM 复审与 SSE 流式生成并行、升级时「平滑切换应急模式」，引入流式中断、已输出内容回收与前后端竞态；复审串行前置则会吃光 TTFT ≤ 3s 门禁预算。

同时，四段式输出第 4 段「就医判断标准」已内置升级指引，降低了细分级的边际价值；「行为类型 × 情绪等级」的真实价值在案例检索过滤维度，而非危机定级。

## 备选与评价

| 方向 | 评价 |
|---|---|
| **保留三级 + 前置 LLM 分级**（与预取并行，生成前定级） | 分级独立性好，但 LLM 细分级可靠性问题不解决；TTFT 压门禁边缘；中度的消费者依然缺席 |
| **保留三级 + 流内嵌分级**（四段式契约头部加风险字段） | TTFT 最优、零额外调用；但分级与生成同源（生成 Agent 自评），削弱分级独立性，且需修订 ADR-007「分级在 Agent 之外」的字面约定 |
| **纯规则三级** | 中文程度副词与否定语义靠规则匹配极脆弱，轻/中细分不可行 |
| **二元安全门** | 判定纯规则（勾选 + 关键词 + 否定过滤 + 档案叠加），0ms、确定性、可测试；非红线侧正常生成 + 置信度兜底；消除复审、判定矩阵、平滑切换的全部复杂度；与 M4 延后的现状自洽 |

## 决定

1. **三级危机分级（轻/中/重）+ LLM 复审整体废弃**，重构为**二元安全门**：红线（勾选高危项或规则命中 → 硬拦截）/ 非红线（正常生成 + 置信度兜底）；
2. **判定零 LLM 参与**：红线判定为纯代码规则；补漏走生成侧软兜底（`emergency-consult` Skill 安全行为指令 + 四段式第 4 段就医判断标准 + 红线事件记录反哺词库）；
3. **前置勾选交互保留**（AC-2 锚定），勾选高危项直接命中红线；
4. **工单优先级按触发事实推导**（用户主动=普通、低置信度/连续追问=紧急、红线=特急），不再经过危机等级中转；M4 落地前，红线命中的行为为「安全提示 + 就医/紧急求助指引 + 红线事件落库」，自动特急工单随 M4 启动；
5. 「行为类型 × 情绪等级」从危机定级维度回归**案例检索过滤维度**；
6. 机制文档更名为「红线安全门与兜底策略」，需求 M1 对应条目与 AC-2 验收时点同步修订。

## 后果

- 正面：应急链路无并行复审竞态，TTFT 预算完整留给生成；判定确定性可测试，消除两个同名 0.7 阈值的语义混淆；机制与 M4 延后现状自洽；「宁过度拦截不漏风险」由纯规则天然继承（无 LLM 降级风险）；
- 负面：失去「中度自动紧急工单」细分（M4 设计时按触发事实映射，反而更准确）；规则词库的漏判残余风险由生成侧软兜底与运营迭代承担，无 LLM 实时补漏层；
- 波及文档：机制/红线安全门与兜底策略（新）、智能应急咨询、人工兜底通道、机制 README、Agent 基座、总体架构、层间数据流与依赖、科普查阅、需求/功能需求与验收、需求/产品定位与范围；ADR-007 安全约束中的「危机分级三层判定」表述由本决策演进。

## 重访条件

- M4 人工兜底通道启动设计时，按触发事实复核工单优先级映射是否足够，是否需要重新引入中间等级；
- 红线事件记录或运营数据显示规则漏判率不可接受，且生成侧软兜底不足以覆盖时，重新评估引入前置 LLM 安全判定层；
- 监管或合作医疗机构对危机场景处置提出更细粒度的分级要求时。
