# DSR-006：项目结构 v3.0 目标态收束

> **状态**：五层前端与 Hybrid Monorepo 仍有工程价值；按旧业务的一对一模块边界由 [DSR-007](./DSR-007-以支持对象与事项重定模块边界.md) 取代。文内“无兼容/无真实数据”是当时时点假设，真实迁移前须盘点。

## 上下文

项目结构文档组停留在 v2.0（2026-05-24）：按「Taro 小程序为唯一前端」设计、`py-agent` 以单包形式标注「规划」、根级 `skills/` 目录规划、api-server 内部为 api/v1 + 扁平 services 的旧描述、前端 views/logics 两层。此后 ADR-006/007/009/010/011/012/013 与 [Agent内核框架](../Agent内核框架.md) 已全面演进技术基线（双前端分工、内核+扩展物理形态、扩展本地 Skill 发现、时刻分层、档案四层、身份-凭证分离认证），结构文档与基线系统性脱节，[技术设计 README](../README.md) 已将其列为已知偏差。本次经用户授权「不考虑任何兼容（含数据库）」彻底重构，纯以优雅实现为目标。

## 备选与评价

**前端分层模型**：

- **物理五层（选定）**：目录即 `domain/ application/ viewModel/ view/ infrastructure/`，与 AGENTS.md 防穿透规则（Domain/Application/ViewModel/View/Infrastructure 依赖方向）及前端工具体系 1:1 对齐；代价是双前端目录重组（已授权无兼容负担），DSR-005 被取代；
- 逻辑五层、物理两层：维持 views/logics 顶层、内部按五层划分子目录；目录改动小，但层名与工具体系术语不直接对应，防穿透规则需靠自觉而非目录结构承载；
- 维持 views/logics（DSR-005）：最轻，但 AGENTS.md 的五层依赖方向继续无结构文档承载。

**api-server 模块划分**：

- **机制模块 1:1（选定）**：单一边界轴——api-server 模块、Agent 扩展、前端特性、py-db/py-schemas 文件域全部镜像机制模块边界（Agent基座「扩展边界=机制模块边界」的同轴延伸），新增能力无分组决策成本；
- 按技术角色分组（api/services/dependencies 扁平）：模块语义弱化，与扩展边界错位。

**文档组形态**：

- **目标态单一份 + 附录废止（选定）**：不再维持「现状/规划」双轨叙述，未落地部分以状态标注；附录（v1.0→v2.0 迁移对照等历史元信息）沉入 Git 历史，技术栈映射并入 README、最佳实践并入组织约定；
- 保留附录并增量修补：历史包袱持续膨胀，与「目标态基线」定位冲突。

## 决定

1. 项目结构文档组按 v3.0 目标态重写（README/目录骨架/层间数据流与依赖/组织与工程约定），附录.md 废止；
2. 前端双端统一物理五层（domain/application/viewModel/view/infrastructure），层内按特性组织；取代 DSR-005 的 views/logics 两层；`ts-shared` 维持纯类型定位；
3. Agent 物理形态按 ADR-011 落地：`py-agent-kernel`（零 Campfire 依赖、独立文档与测试）+ `py-agent-extensions`（单包多子包：security/emergency/case/profile/ticket/knowledge）；Skill 随扩展目录自动发现，**取消根级 `skills/` 规划**；
4. api-server 模块与机制模块 1:1：auth/emergency/crisis/profiles/cases/tickets/knowledge，模块内 routes → service → contract 三段式；启动装配集中 `agent_bootstrap.py`（security 首位 + 断言 + 面白名单）；
5. `py-llm` 从目标结构移除（ADR-007 退役，pydantic-ai provider 取代）；`py-rag` 保留为工具实现底座（LangChain 退出）；
6. 认证按 ADR-013 落结构：py-auth 承载 Token 家族与显式 RBAC，py-db 增 credentials/invite_codes 模型域；
7. 前端特性面按 ADR-006/012 收束：mini-program 不含 cases（供给侧能力回归 react-web），react-web 增内测需求侧特性（consult/profiles）与 auth 特性（登录/注册/准入管理）。

## 后果

- 正面：结构文档与技术基线恢复一致（消除技术设计 README 的两条已知偏差）；单一边界轴使新能力落位零决策；五层前端使 AGENTS.md 防穿透规则可执行；内核孵化形态（独立 docs/tests、零依赖声明）为框架抽离预留干净边界；
- 负面：双前端目录与 api-server 模块需按目标态重组（实施成本，已授权）；py-llm 移除与 py-rag 瘦身为破坏性变更；DSR-005 被取代需同步其状态。

## 重访条件

- py-agent-kernel 出现第二个消费者 → 抽离独立仓库并冻结扩展 API；
- 前端五层在双端落地后证明粒度过重（小团队简单页面上样板代码显著超收益）→ 重访逻辑层归并；
- workspace 包数量继续膨胀至维护成本超复用收益（DSR-001 重访条件联动）。
