# ADR-002：前端选择 Taro + 微信小程序

> **状态**：⚠️ 已被实施偏离，待重访（2026-05-23 决策）
>
> **偏离说明**：实施中 `apps/react-web`（React 19 + Vite）已成为主 Web 应用并通过 H5 部署；`apps/mini-program`（Taro）仍存在但不再是唯一前端。该偏离尚未形成新决策记录，本文保留原决策内容供追溯。

## 上下文

核心用户为国内家属，需要最低触达门槛的移动端方案。

## 备选与评价

- **Taro（微信小程序）**：微信小程序无需下载安装，家属触达路径最短；Taro 跨端能力为后续 H5 管理后台/支付宝小程序预留扩展空间；React 语法选型具有更广泛的 UI 生态复用性。
- **Vue 3 + Vite（Web 端）**：开发体验好，但移动端触达依赖浏览器/公众号，留存弱。
- **微信小程序原生**：性能最佳，但无跨端能力。

## 决定

Taro（React 语法）+ 微信小程序优先交付。

## 后果

- 正面：低门槛触达家属用户；
- 负面：小程序包大小有限制（2MB + 分包），编译层调试复杂。

## 重访条件

**已触发**：实施已形成「react-web 主 Web 应用 + mini-program 并存」的格局。需要新决策明确：小程序与 Web 端各自的功能范围、目标用户、优先级，以及 Taro 跨端路线是否继续。
