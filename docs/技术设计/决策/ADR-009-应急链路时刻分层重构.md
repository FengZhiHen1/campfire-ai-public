# ADR-009：应急链路时刻分层重构

> **状态**：有效（2026-08-03 决策）

## 上下文

2026-08-03 对智能应急咨询链路的产品审查（结合 [references/孤独症家庭应急干预与行为支持_科学资料综述.md](../../references/孤独症家庭应急干预与行为支持_科学资料综述.md)，2026-07-30 调研）发现原设计按「系统处理流程」而非「危机时刻用户状态」构建，存在三个成立性问题：

1. **输入要求与自家用户画像矛盾**：画像明确「危机时认知负担极重 → 交互必须极简」，原链路却要求危机中打字描述 + 回答 7 项前置勾选；综述证据（急性应激损害工作记忆，应激后 10–25 分钟最重）表明危机当下正是用户认知最差的时刻；
2. **四段式输出与消费时刻错位**：危机中家属无暇阅读长文，此刻唯一有用的是「即时安全动作」；其余段落是事后价值，却被压进同一次生成，徒增 TTFT 压力；
3. **红线命中等于拒绝服务**：最高危用户得到全产品最薄的响应（一句安全提示 + 就医指引），但红线 ≠ 不能给内容，而是不能给**未审核的生成**内容——已审核的脚本化内容完全可以确定性地供给。

同时，LLM 自报置信度被证实校准不良，用其做兜底路由与 ADR-008「LLM 判断不可靠 → 纯规则替代」的哲学自相矛盾——检索质量、用户未解决标记、追问轮次等确定性信号是更好的替代。

## 备选与评价

| 方向 | 评价 |
|---|---|
| **保留流程骨架，局部修复**（勾选后置、红线补静态内容、补追问路径） | 改动小、与已部署 MVP 兼容，但输入负担与时刻错位只缓解不解决，核心可用性风险保留 |
| **维持现状，先补调研证据** | 零改动成本，但若输入不可用成立，MVP 期间高危用户持续获得不可用/被拒绝的体验；调研周期不可控 |
| **逐孩 LLM 预计算个性化卡** | 个性化丰富度最高，但把幻觉风险重新引入安全层（无法逐张人工审核）、成本随档案变更放大、不可审计；危机时刻内容被压缩为几句指令，生成丰富度无处安放 |
| **时刻分层重构**（确定性此刻层 + Agent 完整方案层） | 直接解决三个成立性问题；安全层保持零 LLM、可审核、可复现；代价是输出契约、前端交互与多份文档修订 |

个性化机制上，「审核静态模板 + 档案字段确定性槽位填充」在安全性、成本、可审计性上均优于逐孩预计算，且覆盖危机时刻实际需要的全部个性化（称呼/安抚物/触发物/禁忌/走失报警信息），方向占优。

## 决定

1. **应急链路按「危机时刻分层」重构为两层**：
   - **此刻安全层**（代码层，秒级，零 LLM）：打开即出通用安全卡（0 输入）→ 家属点选行为桶（情绪哭闹/刻板升级/自伤/攻击/走失/用药/其他）→ 桶专属安全卡；卡片为**专家审核的静态模板（桶 × 危机阶段）+ 档案字段确定性槽位填充**；阶段由单点问题判定（每次一个大字 quick-reply 问题）；
   - **完整方案层**（Agent 层）：桶与阶段确定后**后台自动生成**完整方案（四段式契约不变）；家属可选补充文字细节触发精化重生成；
2. **桶选择兼任三职**：输入方式（取代独立的前置勾选步骤）、红线分流（自伤/攻击/走失/用药桶直接命中红线）、案例检索过滤维度；
3. **走失场景独立一键应急流程**：跳过常规问答，直接输出报警话术模板（档案自动填充姓名/特征/可能去向/水体提醒），转写自 AWAARE《Family Wandering Emergency Plan》；
4. **红线命中行为升级**：从「仅初步安全提示」升级为「高危桶卡（审核静态内容 + 槽位）+ 就医指引，标红置顶」；**AI 生成阻断保留**——红线会话不进入完整方案层；判定规则、事件落库、M4 特急工单不变（ADR-008 相应语义由本决策演进）；
5. **追问轮按通用 Agent 组织**：首份方案受四段式 Pydantic 契约校验；追问轮自由文本回复、不套契约，放行 `rag_search` 自主调用（应急面白名单微调）；红线关键词门对每条用户输入生效、免责声明常驻、受限自治不变；
6. **置信度路由废除**：兜底触发改为确定性信号组合——检索相似度/命中数阈值 + 用户「未解决」标记 + 连续追问轮次；`confidence_score` 字段保留落库仅作离线观测，不再驱动行为；MVP 阶段（M4 未落地）兜底行为为强提示 + 求助指引 + 事件落库，不建工单流转；
7. **界面形态**：危机桶选择为自定义界面，其余全程统一 AI 聊天容器（各层产出以 message 插入），消息样式分级——危机安全卡/阶段问题/红线指引用大字号强视觉样式（含 quick-reply 按钮），完整方案等事后内容用常规样式；
8. **内容生产责任**：卡片内容由专家撰写，作为独立内容类型复用 M3 案例库「录入 → AI 预审 → 专家终审 → 版本/下架」审核链路；M3「LLM 提炼模板暂缓」决定不变（暂缓的是生成式模板，卡片是人工撰写内容）；
9. **档案联动**：个人基础档案新增走失专项可选字段组（体貌特征、常去地点/可能去向、水体风险与游泳能力）；档案字段整体重设计单独立项；
10. **语音输入维持延期**（需求基线 §五不变）：细节补充步骤用文字输入；安全路由已由桶选择承担，语音未来重访时不影响安全语义；
11. 内容设计采用综述证据：meltdown ≠ tantrum 两问分流纳入桶/卡内容；危机话术写作规范工程化（祈使短句、一句一动作、列表 ≤5 项、无否定句、低素养审校）。

## 后果

- 正面：危机入口 0 输入即得安全价值；最高危场景从「拒绝服务」变「确定性内容供给」；安全层全链路零 LLM、可审核可复现；兜底路由与 ADR-008 哲学自洽；统一聊天容器使会话内追问自然成立；前置勾选摩擦消失；
- 负面：新增卡片内容生产与审核运营责任（桶 × 阶段变体约十余张 + 走失专项）；输出契约、前端交互、数据模型（会话结构）均需改造；时刻分层引入「桶 × 阶段」分类体系的概念成本；
- 波及文档：机制/智能应急咨询（重写）、机制/红线安全门与兜底策略（修订）、机制/人工兜底通道（触发源）、Agent 基座 §5.1（会话多轮与白名单）、需求/功能需求与验收（M1 与 AC-1/AC-2）、机制 README、docs README；ADR-008 的命中行为、勾选交互、置信度路由由本决策演进；个性化档案库数据模型（走失字段组，并入档案重设计工作坊）。

## 重访条件

- 卡片内容上线后，运营数据显示桶分类覆盖率不足（大量「其他」桶进入）或阶段问题回答率过低时，重审桶体系与阶段判定交互；
- 确定性兜底信号的阈值（检索相似度、追问轮次）经线上数据校准后确认失当时；
- 语音输入按需求基线重访条件启动时，复核其在细节补充步骤的安全语义；
- M4 人工兜底通道启动设计时，复核兜底信号到工单优先级的映射。
