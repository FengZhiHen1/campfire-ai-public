# 资料库面 HTTP 契约

> **权威范围**：案例库与资料库的**浏览、检索与条目展开**对前端暴露的端点形状——请求与响应载荷、撤下与 deep-link 的语义。**案例与卡片的单元结构、字段风险分级、审阅状态与呈现规则归[公共案例库](../../technical-details/公共案例库.md)**；**对外返回契约与撤下传播归[资料与案例检索](../../technical-details/资料与案例检索.md)**；**检索链的内部机制归[RAG 策略](../../technical-details/RAG策略.md)**。本文档只定"怎么传"，不定"存什么、怎么检索"。
> **状态**：2026-09-30 依已确认的两库边界、公共案例库与页面设计成形，**待用户确认**。不代表已实现（案例条目表与 `search_cases` 均未落地）。
> **追溯**：`RQ-KB-01`～`RQ-KB-04`、`RQ-CON-03`、`AC-06`、`AC-09`。
> **依据**：一期录入经应用内 CLI、不提供任何服务端点与产品内界面（`RQ-KB-03`、`AC-29`）——因此本面**只有读端点**，与那条不变量不冲突。

## 1. 为什么本面只有读端点

`RQ-KB-03` 与 `AC-29` 已定：资料与案例的导入、审核、知识库管理**只能**经应用内 CLI，不存在对应的 HTTP 端点与产品内界面。所以本面的端点全部是只读的——**不设**创建、更新、撤下、删除。

撤下由 CLI 在条目上打 `withdrawn`；本面只负责"撤下后不再返回"，这是 `RQ-KB-04` 的界面侧承载。

## 2. 通用约定

| 约定 | 内容 |
|---|---|
| 鉴权 | 全部端点须登录（`RQ-ACC-01`） |
| 传输 | 普通 JSON，不是 SSE——本面没有流式输出 |
| 库别 | 两库**分开取数**，不合并成一张表加类型标签（`RQ-KB-01`）；`library` 取 `knowledge` \| `case` |
| 缺字段 | 缺少来源或状态的条目**不进入任何结果，不补默认值**（[资料与案例检索](../../technical-details/资料与案例检索.md)第 1 节不变量） |

**错误码**：

| 码 | 情形 |
|---|---|
| 401 | 会话过期或未登录 |
| 422 | 载荷不合法（未知 `library` 取值、`limit` 越界） |
| 503 | 检索不可用 |

## 3. 浏览与检索

```text
GET /api/library/items?library=case|knowledge&query=&cursor=&limit=
响应 200：
{
  "library": "case",
  "items": [ … ],
  "next_cursor": null
}
```

- 空 `query` 即**全量浏览流**，按最近入库排序——不编造"热门"排序（[案例库浏览页](../../../design/pages/案例库浏览页.md)第 40 行：无真实行为数据支撑排序策略前只用时间序）。
- `library` 缺省为 `case`（页面默认落在案例分区）。
- 命中的**呈现单位是案例**、检索单位是卡片（[公共案例库](../../technical-details/公共案例库.md)第 2 节）：返回的是聚合后的条目，卡片级命中只在条目内体现，不另出一层列表。
- `limit` 未传时服务端必须有上界。

### 3.1 条目形状

| 字段 | 两库 | 说明 |
|---|---|---|
| `item_id`、`library`、`title`、`snippet`、`source`、`applicable_scope`、`status`、`locator` | 共有 | [资料与案例检索](../../technical-details/资料与案例检索.md)第 3 节返回契约 |
| `authorization`、`source_type`、`evidence_level`、`review_status`、`interview_at`、`makes_claims_high_risk` | 案例 | 同文第 3 节案例**必带**六项——缺任一个，页面就无法如实回答"谁说的、多可信、什么时候"（`AC-06`） |
| `inferred_fields` | 案例 | 被推断字段的清单；**不参与注入**，只作呈现标注 |
| `narrative`、`cards` | 案例（展开时） | 见第 4 节 |

**案例侧的六项必带字段不是可选装饰**：[公共案例库](../../technical-details/公共案例库.md)第 5 节的不变量是"案例输出必须能回答谁说的、多可信、什么时候，三者缺一不得作为依据"。列表若只给标题与摘要，本页就退化为无法核对的读物。

## 4. 条目展开

页面设计为**就地展开**（[案例库浏览页](../../../design/pages/案例库浏览页.md)第 22 行：无详情页）。因此展开内容随列表一并返回，而不是再发一次请求：

```text
GET /api/library/items?...&expand=<item_id>
响应中的该条目额外带：
{
  "narrative": { "sections": [ { "key": "…", "heading": "…", "text": "…" } ] },
  "cards": [ { "card_id": "…", "scenario": "…", "immediate_action": "…",
               "inferred_fields": ["…"], "risk_class": "low|mixed|high", … } ]
}
```

- 一次只展开一条（页面是单条就地展开，不需要一次拉多条全文）。
- **卡片的高风险字段照旧返回，但呈现纪律不在本面**：`immediate_action`、`medical_criteria`、`contraindications`、`caution_notes` 属高风险档（[公共案例库](../../technical-details/公共案例库.md)第 5 节），只能以**转述语**呈现、涉及医疗处置等须引导求助。**该纪律在 skill 与页面呈现层执行，本契约不拦截**——与 `RQ-LIM-05` 同源：提示词层不构成安全边界，真实闸门是 `EVID-A` 与 `EVID-B`。
- `review_status = owner` 必须能显示为"项目所有者核准"而非"已审阅"（同文第 7、8 节）——返回给的是原始取值，措辞由页面承担。

## 5. deep-link 与撤下

对话页的引用跳转落到 `/cases?item=<item_id>`（[对话页](../../../design/pages/对话页.md)第 46 行）。三种结果：

```text
GET /api/library/items/{item_id}
响应 200：{ "item": { … } }                          # 在库
响应 200：{ "item": null, "withdrawn": true, "title": "…" }   # 已撤下
响应 404：                                            # 不存在或非法 id
```

- **已撤下**返回 `200` 而不是 `404`，且**只带标题**、不带正文与其他字段：页面据此渲染单条撤下卡（标题 + 「该来源已撤下」+ 一行说明），不显示正文（[案例库浏览页](../../../design/pages/案例库浏览页.md)第 17 行）。撤下条目**不进列表**（`RQ-KB-04`：撤下即消失，无"已撤下"幽灵条目），只在这种定向查询下以一种克制形态出现。
- **撤下判定来自服务端，不由前端猜测**：历史引用是否仍可跳转，取决于这次查询的结果，而不是前端缓存的旧载荷。
- 非法 `item_id` → **404**，页面按普通进入处理（不报错、不留在空页）。

## 6. 失败语义

| 情形 | 服务端 | 前端 |
|---|---|---|
| 两路检索都失败 | 503 | `.error-card`「检索暂时不可用」+ 重试；**不得**写"没有找到相关内容" |
| 单路失败 | 200，结果内标注降级（[资料与案例检索](../../technical-details/资料与案例检索.md)第 5 节） | 照常呈现，不额外提示 |
| 检索为空 | 200 空数组 | 空态「没有找到相关内容」+ 换个说法的引导 |
| 库为空（`EVID-F` 未录入） | 200 空数组 | 空态「案例库还在准备中」——如实呈现，不放假数据 |

**空与失败必须可区分**：两者都是 200 vs 503 的差异，不是同一种空态。

## 8. 已知偏差与证据边界

- **案例侧尚未实现**（2026-09-30 实测）：`modules/library/models.py` 只定义 `campfire_knowledge_item`，无案例条目表；`LIBRARY_CASE` 常量无使用点；检索链硬编码只查资料库。因此本契约的 `library=case` 分支**当前恒为空**，落地顺序是案例条目表与迁移（含七个案例专属字段）→ 检索链按库别参数化 → `search_cases`。**不能用现有资料表凑一个案例列表**——那会恒返回空集，被读成"没有相关案例"。
- **一期语料只有 3 个案例、10 张卡片**，且 `EVID-F` 未录入前两库为空。本页在录入前只能呈现空态。
- **`EVID-B` 未关闭**：素材授权未取得前不得建索引（已有一例因授权冲突被排除）。本面的内容供给受此约束，不是工程问题。
- **未实测**：全部端点形状均为设计结论。
