# 记忆面 HTTP 契约

> **权威范围**：记忆面（通用记忆的查看、纠正、删除）对前端暴露的端点形状——请求与响应载荷、越权与失败语义。**记忆的时间模型、读路径、删除账本与分区键归[通用记忆](../../technical-details/通用记忆.md)**；`read_memory` / `write_memory` 的工具契约归[咨询面 `tools/`](../consult/tools/)；本文档只定"使用者怎么查看与处置自己的记忆"。
> **状态**：2026-09-30 依已确认的记忆机制与「删除走用户确认入口」裁决定形，**待用户确认**。不代表已实现（契约与承载页面此前均未成文）。
> **追溯**：`RQ-MEM-01`、`RQ-MEM-03`、`RQ-ACC-01`、`AC-08`。
> **依据**：[决策记录](../../decisions/记忆删除走用户确认入口.md)（不新增 `delete_memory` 模型工具）；[决策记录](../../decisions/通用记忆归属为账号.md)（分区键为账号）；承载页面为设置页下的次级页（2026-09-30 用户裁定）。

## 1. 为什么单独一面，以及它放在哪

记忆的查看/纠正/删除**不进模型工具**（`RQ-MEM-03` 的施事者是"使用者"，且 `read_memory` 的返回刻意不含 episode 标识，模型无从指名要删哪条）。因此它需要一个 HTTP 面。

**承载页面是设置页（「我的」）下的次级页**，不是档案页内的分组，也不是第五个 tab：

- 记忆归属**账号**，档案归属**支持对象**——两者的分区键不同（[决策记录](../../decisions/通用记忆归属为账号.md)）。放进按对象组织的档案页，会让"切换对象时记忆为什么不跟着变"变成一处需要额外解释的困惑。
- 设置页已有「关于你的数据」卡（`RQ-LIM-03`），其语义正是"关于我自己"，与记忆的账号级归属同构。
- tab 栏固定四项是已确认的视觉定调（[DESIGN.md](../../../design/DESIGN.md)、[首页](../../../design/pages/首页.md)），不为本页破坏它。

代价如实写明：层级深一层，可发现性弱于一级 tab。缓解是设置页的数据卡里给一个入口行。

## 2. 通用约定

| 约定 | 内容 |
|---|---|
| 鉴权 | 全部端点须登录（`RQ-ACC-01`） |
| 分区 | 取登录态（`group_id = account_id`），**不接受调用方传入**账号或分区键——因此"读别人的记忆"在构造查询前就不成立 |
| 传输 | 普通 JSON，不是 SSE；本面没有流式输出 |
| 幂等 | 删除幂等：重复删除返回 200 并带 `newly_deleted: false`，不报错 |

**错误码**：

| 码 | 情形 |
|---|---|
| 401 | 会话过期或未登录 |
| 404 | episode 不存在，或不属于当前账号（文案与"不存在"逐字相同） |
| 422 | 载荷不合法（纠正无新内容、标识形状非法） |
| 503 | 图库不可用 |

## 3. 查看

```text
GET /memory/episodes?since=&until=&query=&cursor=&limit=
响应 200：
{
  "items": [
    { "episode_key": "…", "occurred_at": "…", "content": "…", "source_session_id": "…" }
  ],
  "next_cursor": null
}
```

- **`episode_key` 是标识暴露面的临界点**：`read_memory` 的工具返回**刻意不含**标识（模型不需要它），而本面必须含——没有稳定标识就无法"列表 → 指认 → 删除"。给工具返回加标识会等于把这条不变量让给模型可见面，因此两者**分开定义**，不是同一份形状的两个视图。
- 返回的是 **episode 原文时间线**（回看语义），不转译、不摘要、不判失效；派生事实（应急预注入那条路径）**不在本面暴露**。
- **已删除的记忆不返回**（`AC-08`）：删除过滤在取数函数内部完成（[通用记忆](../../technical-details/通用记忆.md)第 7 节），调用方不传也无法传入"已删清单"，因此不存在漏传导致已删记忆被返回的实现路径。
- **只返回已真正写入的**（`pending_write.state = done`）：在途记录不得出现在列表里。
- `limit` 未传时服务端必须有上界——无界拉取会随记忆量增长。

## 4. 删除

```text
DELETE /memory/episodes/{episode_key}
响应 200：{ "episode_key": "…", "newly_deleted": true, "reason": "user_request" }
```

- **语义删除 = 写删除账本**，不是图库物理删除（[通用记忆](../../technical-details/通用记忆.md)第 7 节：账本过滤是唯一生效点）。因此删除**不会因图库不可用而失败**——账本写入是本库事务。
- 删除后**两条读路径都不再返回**（时间线回看与应急预注入），这是 `AC-08` 的验收对象；图库内残留不判失败。
- `reason` 如实回报账本里的原原因：一条记忆先按 `correction` 撤下、之后又收到删除请求时，账本里仍是 `correction`（幂等命中不改变原记录）。
- **二次确认是前端交互**（`.confirm-sheet`），服务端不做"猜你不是故意的"。

## 5. 纠正

```text
POST /memory/episodes/{episode_key}/correct
请求：{ "occurred_at": "…", "content": "…" }
响应 201：{ "episode_key": "新记忆的标识", "supersedes": "…" }
```

- 纠正 = **删旧 + 写新**，不是"改"（[通用记忆](../../technical-details/通用记忆.md)第 7 节：旧派生边不会因纠正指向更早时间而自动失效，正确性落在账本过滤上）。
- 顺序是**先撤下旧记忆再写新的**：反过来会有一段"新旧同时有效"的窗口。最坏情形是"暂时没有这条记忆"，比"旧错误内容继续被当作当前认识"安全。
- **两步的失败语义不同**，端点必须让调用方知道自己处在哪一步：撤下旧记忆是本库事务（要么成功要么回滚），写新记忆要走图库与模型抽取（可能失败、可重试）。因此响应区分——撤下成功而写新失败时返回明确的中间态（旧记忆已撤下、新记忆未写入），**不得**笼统报成功或笼统报失败。

## 6. 失败语义

| 情形 | 服务端 | 前端 |
|---|---|---|
| 图库不可用 | 查看返回 503；**删除与纠正的"撤下"步骤仍可用**（账本在本库） | 查看显示"暂时无法读取"，**不得**当作"没有记忆" |
| 查询返回空 | **不是失败**——200 空数组，不标注降级 | 空态，不报错 |
| 删除后仍能读到该记忆 | 不允许（`AC-08`） | — |
| 401 | — | 清状态跳登录 |

## 8. 已知偏差与证据边界

- **承载页面尚未成文**：`docs/design/pages/` 有档案页、无记忆页。本契约定义了它的**数据形状**，页面本身的视觉与交互未设计（2026-09-30 只定了放置位置：设置页下的次级页）。
- **单账号账本无配额**（[通用记忆](../../technical-details/通用记忆.md)第 9 节与[设计待办](../../../TODO.md) `TECH-22 ③`）：账本涨到上界后该账号两条读路径都会触顶整体失败。本面的"删除"会往账本里加行，因此**配额或分页须与本面同批考虑**——否则使用者删得越多、越容易把读路径用坏（有意的 fail-closed，但代价随使用增长）。
- **`derived_uuids` 是尽力清单**（[通用记忆](../../technical-details/通用记忆.md)第 7 节），不作过滤依据；本契约不向前端暴露它。
- **未实测**：全部端点形状均为设计结论；`episode_key` 的形状与 [通用记忆](../../technical-details/通用记忆.md) 第 3 节标识的校验同源，须在实现时确认一致。
