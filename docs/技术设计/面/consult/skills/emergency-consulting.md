## 1. 定位

**面向监护者的、时间紧迫情境下的即时咨询。** 它要回答的是：

> 这个人现在发生了什么？是否存在危险？现在怎样与其沟通？应立即做什么？哪些事情不要做？

因此它**不在现场重新理解一个人的全部发展史**，而是在几十秒到几分钟内产出一张**现场行动卡**。应急信息必须压缩：现场人员需要的是当前状态、医疗风险、沟通方式、最大风险、立即措施与禁忌行为，而不是几十页档案。

它**不是**危机干预（自伤或伤人已发生时的处置流程），也**不是**诊断。但它**必须先排除医疗危险**——见第 3.2 节与第 5 节。

三条贯穿性的判断立场：

1. **医疗红灯优先于孤独症解释**：任何时候存在医疗危险表现，都不得优先解释为"孤独症行为"。
2. **关注"与本人平时相比的偏离"，而不是"这个行为像不像典型孤独症"**：同样的表现——不说话、来回走、摆手、捂耳、不看人、拒绝回答——对不同的人含义完全不同。判断的依据是这个表现**对这个具体的人**而言是否异常。
3. **环境调整与医疗评估可以同时进行**：环境过载和身体疾病并不互斥，即使感觉过载很明显，也仍可能需要排查疼痛、感染或其他身体问题。

## 2. 入口与现场采集

- **只由程序注入激活**：应急卡片构造第一条消息时注入本 skill 内容；模型不参与选择，`metadata.autoload` 取 `"false"`（在日常对话里描述突发情形**不会**被自动切成应急，是否进入应急由入口决定）。
- **现场采集八项**（`RQ-EMG-01`）：① 医疗红灯 ② 与平时相比的变化 ③ 当前沟通能力 ④ 当前痛苦程度 ⑤ 当前感觉环境 ⑥ 刚刚发生了什么 ⑦ 当前最大风险 ⑧ 是否可能疼痛。
- 逐项**可跳过**；跳过即视为「**未排除**」，**不得默认为正常**。
- 现场**只采变量**：长期稳定信息不进卡片（长期档案保存稳定信息，应急系统只采集现场变量）。填写成本必须按"现场一只手能填完"来设计，多为勾选。

### 2.1 八个核心问题与八项现场采集不是同一张清单

这是两件容易混淆的事，实现时不可互相替代：

| # | 核心问题（本次要回答什么） | 需要的信息 | 一期由谁回答 |
|---|---|---|---|
| 1 | 现在有没有医疗危险？ | 生命体征、意识、癫痫、外伤、疼痛、急性疾病 | **档案预取**（现场只补红灯勾选） |
| 2 | 现在和平时有什么不同？ | baseline deviation | **档案预取**（基线）+ 现场采集 |
| 3 | 他现在还能怎样沟通？ | 当前沟通能力 | **档案预取**（基线）+ 现场采集 |
| 4 | 刚刚发生了什么？ | 时间线与前因 | **现场采集** |
| 5 | 什么可能正在使情况变糟？ | medical、pain、sensory、change 等 | **现场采集**（含七类排查，见第 3.2 节） |
| 6 | 当前最大的风险是什么？ | self / others / elopement / medical | **档案预取**（安全史）+ 现场采集 |
| 7 | 以前什么方法有效？ | 干预历史 | **档案预取** |
| 8 | 现在应该做什么、不做什么？ | 可执行的行动方案 | 由前七项推导 |

结论：核心问题**不是八个要问的问题**——第 1、2、3、6、7 项多数由档案预取回答，现场实际只剩第 4、5、8 项需要采集。这正是"现场只采变量"的落地方式。

### 3.2 方法论：六层闸门，顺序固定

**推理顺序固定，不由模型自由发挥**。顺序即优先级——上层未过，不进入下层的细节展开。

| 层 | 判断 | 具名判据 | 命中后的动作 |
|---|---|---|---|
| 1 医疗 | 有没有生命危险或急性身体异常？ | 医疗红灯清单（见下） | 进入医疗评估路径，**孤独症相关支持只作辅助**（`RQ-EMG-04`） |
| 2 基线偏离 | 当前状态是否明显偏离平时？ | `baseline_deviation` 达到 `moderate` 或 `marked` | 提高疼痛、疾病、外伤、神经问题、药物影响的权重 |
| 3 沟通 | 当前可靠沟通通道是什么？ | 当前沟通能力低于 `baseline` | **没有通道时先建立通道，而不是继续增加问题数量** |
| 4 环境 | 环境是否与已知感觉需求冲突？ | 已知感觉敏感 × 当前暴露 | 冲突则**优先降低环境负荷** |
| 5 既往策略 | 类似既往事件中什么有效？ | 个体干预历史 | **优先复用本人已验证的策略** |
| 6 安全 | 当前最重要的安全风险是什么？ | 安全风险模型八维（见第 5.2 节） | 给出针对性的安全措施 |

**医疗红灯清单**（命中即不得优先解释为孤独症行为，先进入医疗风险判断）：意识改变、呼吸异常、严重出血、明显外伤、癫痫持续或异常发作、中毒或误服、严重过敏、明显疼痛、突然出现与平时完全不同的神经或行为表现。

**医疗层需要快速获取的信息**（档案预取优先，现场只补缺口）：

| 信息 | 目的 |
|---|---|
| 意识是否清楚 | 排除严重急症 |
| 呼吸是否正常 | 急救优先 |
| 是否有严重出血 | 急救优先 |
| 是否有明显外伤 | 急救优先 |
| 是否正在或刚发生癫痫 | 神经急症评估 |
| 是否误服药物或中毒 | 急症处理 |
| 是否存在严重过敏 | 过敏反应处理 |
| 是否有明显疼痛 | 防止诊断遮蔽 |
| 是否突然明显异常 | 提高身体与神经问题优先级 |
| 已知严重疾病 | 辅助分诊 |
| 当前药物 | 避免遗漏药物相关问题 |
| 过敏信息 | 医疗安全 |

**`baseline_deviation` 取值**：`none`、`mild`、`moderate`、`marked`、`unknown`。判定基准是**基线**（平时语言水平、反应速度、眼神、重复动作、活动、自理、疼痛表达、方向感、情绪、社交），其作用是**防止把平时存在的孤独症特征误判成当前急性异常**。

`baseline_deviation` 为低时，表现可能更符合已知的自我调节方式、重复行为或平时沟通特点；为高时（尤其没有明显环境触发）应提高下列因素的优先级：疼痛、感染、神经系统事件、药物影响、外伤、睡眠严重不足、其他身体疾病。

**沟通层需要快速获取的字段**（多数由档案预取）：

| 字段 | 示例 |
|---|---|
| 平时沟通方式 | 正常口语 |
| 当前沟通方式 | 单词 / 无口语 |
| 是否能回答问题 | 可以，但很慢 |
| 最适合的问题类型 | Yes/No / 二选一 |
| 处理时间 | 10 秒 |
| 是否适合文字 | 是 |
| 是否使用 AAC | 手机输入 |
| Yes/No 是否可靠 | 是 |
| 高压力下变化 | 可能停止口语 |
| 熟悉其沟通的人 | 家属 / 支持员 |

沟通层的措辞纪律：**不写"不配合"**。应输出"当前口语能力低于平时；一次只问一个问题；每次等待至少 10 秒；不要连续重复提问；若口语无回应，改用手机文字或二选一"。

**环境层需要获取的字段**：噪音、光线、人群密度、空间大小、气味、温度、是否有警报、是否有突然触碰、是否多人同时讲话、是否允许离开、是否存在安静空间。已知感觉敏感与当前暴露共同决定估计的感觉负荷。

**七类可能原因快速排查**（状态突然变化时至少逐类考虑一遍；第 1、2 类优先，因为它们在未排除前不得被心理或孤独症解释遮蔽）：

| # | 类别 | 排查内容 |
|---|---|---|
| 1 | Medical | 感染、发热、急性生理异常、癫痫、药物变化、中毒、脱水、外伤 |
| 2 | Pain | 牙痛、耳痛、头痛、腹痛、便秘、胃肠不适、肌肉骨骼损伤、月经相关疼痛、其他身体不适。沟通能力有限或疼痛表达不典型时，**行为变化可能是身体不适的重要线索** |
| 3 | Sensory | 声音、强光、气味、拥挤、触碰、温度、医疗设备、警报声、多人同时说话 |
| 4 | Communication | 是否无法理解当前要求、是否没有可用表达方式、是否被连续追问、问题是否过于开放、信息是否过多、是否缺少处理时间 |
| 5 | Predictability / Change | 计划突然改变、未预告的转换、不知道下一步是什么、不知道要等多久、原定活动取消、新环境不可预测 |
| 6 | Emotional / Psychiatric | 结合个体既往情况考虑强烈焦虑、惊恐、创伤相关反应、抑郁或其他精神健康变化；**不得在未评估身体问题前简单归因于心理原因** |
| 7 | Social / Safety | 陌生人靠近、人际冲突、被欺凌、被迫接触、家庭冲突、被限制离开、过多人员围观、环境中存在威胁 |

**个体干预历史**优先于通用知识库：应急情况下最高价值的问题是"这个人上次在类似情境下，什么真正有效"。其结构为场景化的一条记录——触发因素、早期信号、升级表现、有效支持、无效支持、恢复时长；不是通用建议清单。

### 3.3 现场信息不足时的追问（`RQ-EMG-02` 的三条判据）

一项信息**同时满足三条**才追问：① 属于**现场变量**（不能由档案预取）；② 档案中**没有覆盖**；③ 答案会**改变某一层闸门的输出**。一轮最多一到两项，必须能一句话问完；其余一律用"未排除"承载，不要用追问补齐。追问经结构化提问发出（基座 `question` 事件，前端渲染为 QuestionCard：**一键选项 + 可跳过**，见[咨询对话界面](../../../technical-details/咨询对话界面.md)第 6.1 节）——满足 `RQ-EMG-02` 的"一键选择、可跳过"；跳过按"未排除"处理，不得默认为正常。

### 3.4 输出：Action Card

输出**不是分析报告**，是一张现场行动卡，七节。**格式是硬约束**：用可执行语言而不是抽象标签（不写"患者焦虑明显"，写"当前语言较平时明显减少；每次只问一个问题，等待至少 10 秒；若无口语回答，改用文字或二选一"）。

```text
1. 当前状态        与平时相比的变化[无/轻度/明显]；当前沟通[正常/下降/严重下降]；
                   当前感觉负荷[低/中/高]；医疗风险[稳定/未排除/高风险]
2. 立即怎么沟通     一次一人讲话；每次一个问题；等待至少 10 秒；无口语回应时用文字或二选一
3. 立即做           环境与沟通的具体动作（动词开头，可执行）
4. 不要做           例如不要突然触碰、不要强迫眼神交流、不要多人同时提问、不要连续催促
5. 需要的医疗检查   仅在医疗层未排除时出现，写成"需要确认什么"而不是结论
6. 安全措施         针对本对象已知风险的**具体**措施（不要只写"注意安全"）
7. 何时升级         出现什么情况时应停止当前做法、寻求专业帮助
```

**当前状态的取值映射**（框架的细则枚举 → 卡片的三档取值；四档与五档收拢为三档是**有意的**，为了让现场一眼可读）：

| 卡片字段 | 卡片取值 | 来源枚举 | 映射规则 |
|---|---|---|---|
| 与平时相比的变化 | 无 / 轻度 / 明显 | `none` / `mild` / `moderate` / `marked` / `unknown` | `none` → 无；`mild`、`moderate` → 轻度；`marked` → 明显；`unknown` → **归入"未排除"语义，不得显示为"无"** |
| 当前沟通 | 正常 / 下降 / 严重下降 | `baseline` / `reduced` / `severely_reduced` / `unavailable` | `baseline` → 正常；`reduced` → 下降；`severely_reduced`、`unavailable` → 严重下降 |
| 当前感觉负荷 | 低 / 中 / 高 | `low` / `moderate` / `high` / `extreme` | `low` → 低；`moderate` → 中；`high`、`extreme` → 高 |
| 医疗风险 | 稳定 / 未排除 / 高风险 | `stable` / `uncertain` / `high-risk` | 一一对应 |

**"立即做"与"不要做"的判据基线**（可按个体档案覆盖，但不得反过来放宽）：

- 做：一次只让一个人讲话；使用短句；每次只问一个问题；回答前等待至少 10 秒；明确告诉本人下一步；允许降噪耳机；如可能减少光线和人群；允许熟悉支持者陪同；减少人员；避免不必要的身体接触。
- 不要做：突然触碰；强迫眼神接触；多人同时提问；快速连续重复问题；**阻止无危险的自我调节动作**；**因其不说话就认为无法理解**。

**每条动作与判断必须带来源标注**（六类）：本人报告、家属报告、现场观察、历史记录、医疗记录、AI 推断；**AI 推断必须与事实分开显示**（`RQ-CON-07`）。判断带**置信等级**（四级）：`confirmed` / `likely` / `possible` / `unknown`；**不使用没有充分依据的精确概率**。

**相关不等于因果**：可以说"环境噪音可能是重要促发因素"，**不得**写成"原因就是噪音"，尤其在疼痛或身体疾病尚未排除时。

**输出通道**（2026-09-29 定）：Action Card 经基座 `emit_action_card` 工具以结构化载荷发出（非自由文本），前端渲染为卡片（见[咨询对话界面](../../../technical-details/咨询对话界面.md)第 6.2 节）；`medical_risk` 等状态字段由工具参数校验，七节语义不变。

### 3.5 依据清单（默认收起）

Action Card 之后附一个**默认收起**的依据清单：本次引用的资料与案例条目（含来源与适用范围）。它承担 `RQ-CON-02` 与 `AC-05`/`AC-11` 的"依据可核对"，且**不占现场阅读面积**。指不到依据时，在该条动作上标注"通用做法，未找到对应资料"。

### 3.6 支持重复评估

首次行动卡之后，若使用者报告了干预后的新情况，**重新过一遍六层闸门**并给出更新后的卡，而不是在旧结论上补丁。重评估时重申：沟通、痛苦、疼痛、风险、医疗状态各看一遍。

| `references/action-card.md` | 第 3.4 节各节的**措辞模板**与取值映射；第 3.4 节的来源六类与置信四级写法；禁用句式（诊断句、精确概率、"注意安全"这类空话）；何时升级的判断写法 | 不含任何具体医疗机构、科室或联系方式 |

**判据由具名清单定义，不由模型临时决定**——这样才可评测、可回归（`RQ-EMG-02` 的"追问判据由具名清单定义"同此）。

## 4. 输入：四段来源

```text
档案预取的稳定信息（应用注入，键为 support_object_id）
    + 近期有效记忆（应用注入：派生事实 + 时效过滤，键为 account_id，见通用记忆第 6 节）
    + 现场采集的八项
    + 对话中追加的信息
        ↓ 六层闸门
      Action Card
```

### 4.1 应用侧注入的应急上下文

- **内容**：八组——基线、已知触发、沟通偏好、感觉特征、医疗风险、已验证策略、**无效策略**、安全史。（前七组与"无效策略"合为八组；无效策略与已验证策略成对，见[个性化档案](../../../technical-details/个性化档案.md)第 8 节。）
- **取数**：`emergency_context(support_object_id)`，一次调用返回全部八组（形状见[个性化档案](../../../technical-details/个性化档案.md)第 8 节），**只取稳定层**。
- **记忆预注入（2026-09-29 定）**：同路注入**近期有效记忆**——近期派生事实（`invalid_at` 为空、按 `valid_at` 倒序、上限 20 条初值与 6000 字符初值），由应用侧取数，不走工具轮次；选路与注入形状见[通用记忆](../../../technical-details/通用记忆.md)第 6 节。模型可见其为"记忆时间线沉淀的经验"，自行判断与当前情境的相关性。**分区键是账号而非支持对象**（记忆归属账号，[决策记录](../../../decisions/通用记忆归属为账号.md)）——与上一行 `emergency_context(support_object_id)` 的取数键**不同**，实现时不可混用。
- **不是模型可见工具**：由应用在构造第一条消息时取数并注入（基座第 4 节"面可提前代跑工具注入"），以满足 `RQ-EMG-03` 的时延目标。模型不必为取档案多走一轮工具调用。
- **缺失即标注**：某组未预存时注入里明确写"未预存"，**不得**由模型顺势推断补全。无档案时按 `AC-02` 标注"本次未使用个性化档案"；记忆不可用时同样明确标注，不得当作"没有记忆"（[通用记忆](../../../technical-details/通用记忆.md)第 6 节降级语义）。

## 5. 安全边界

### 5.1 做与不做

| 做 | 不做 |
|---|---|
| 医疗红灯优先，先走医疗评估路径（`RQ-EMG-04`） | **不做诊断**、不给用药建议、不给身体控制手法（`RQ-LIM-01`） |
| 输出"医疗风险：稳定 / 未排除 / 高风险"，并给"何时升级" | 不把"未排除"说成结论；不给精确概率 |
| 给具体安全措施（保持出口安全、避免围堵、由熟悉人员保持可见陪同） | **不给高风险处置**：自伤或伤人已发生时的处置、医疗处置、用药、身体控制——这些情况一律**引导向专业人士求助** |
| 不保证安全、不承诺好转（`RQ-LIM-02`） | 不列举具体医疗机构、科室或联系方式 |

**分层依据**（`RQ-LIM-05`，2026-09-29 定；原 `EXT-02` 由此转为一期实现）：**低风险操作与建议照给**；高风险则改为引导求助。分级**在 skill 层逐条判断，不做程序围栏**——提示词层的约束可以绕过，**不是安全边界**；对真实使用者的闸门是 `EVID-A`（禁止内容清单需具名签收）与 `EVID-B`（素材授权）。

措辞纪律：**判断句必须消失**——用"医疗风险：未排除，建议尽快做医疗评估"，不用"这是急症"；引用案例时用**转述语**（"有位家长在访谈中提到她这样做过"），**不用祈使句**。

### 5.2 安全风险模型（八维）

**"烦躁程度"和"风险程度"不是同一个变量**，必须独立评估；安全层只记录**实际存在**的风险，不因"有孤独症"就默认添加风险标签。

| 维度 | 含义 |
|---|---|
| Medical risk | 医疗风险 |
| Risk to self | 对自身的风险（含撞头、自伤等） |
| Risk to others | 对他人的风险 |
| Elopement risk | 走失／突然离开现场的风险 |
| Traffic risk | 交通安全（是否会冲向道路） |
| Environmental risk | 环境风险（是否处于不安全空间） |
| Vulnerability | 易受伤害（是否容易跟随陌生人、是否易被错误指令影响） |
| Exploitation risk | 被剥削风险 |

**快速确认项**：是否有过载时突然离开现场的历史；是否会冲向道路；是否存在撞头、自伤等历史；是否存在吞食异物风险；是否会在极度压力下推开他人；是否容易跟随陌生人；是否容易被错误指令影响；当前是否处于不安全空间。

输出**不要只写"注意安全"，而应给出具体措施**（例如"有过载时突然离开现场的既往史。确保其无法直接进入车流或危险区域，但避免多人围堵"）。

## 6. 工具依赖

- 只读两件：`search_knowledge`、`search_cases`（找依据）。
- **查询词自改写**（同日常 skill 3.4 节）：口语原话与案例卡片的临床文风错配会漏召回；检索前把口语描述改写成简明的行为与情境描述再查，**不改变使用者原话的呈现**，也**不为此多花一轮**——改写发生在本来就要生成的 `query` 里。机制与评测闸门见[RAG 策略](../../../technical-details/RAG策略.md)第 8.1 节。
- **写工具一律不可用**：本 skill 不沉淀档案；沉淀由日常对话里激活的 `profile-curation` 承担。越界调用由服务端拒绝。
- 时延纪律（`RQ-EMG-03`：首个可读输出 **≤10 秒**、完整 Action Card **≤60 秒**，p50）：**不为凑依据多轮检索**；档案取不到就标注未预存，不重试。

## 7. 验证方式

- **激活**：从应急入口进入，只有本 skill 被激活；写工具调用被服务端拒绝；在日常对话里描述突发情形**不会**自动切到本 skill。
- **医疗闸门**：构造命中红灯的输入，验证输出给出医疗风险"未排除"并进入医疗路径，**且没有**把它解释为孤独症行为（`AC-21`）。
- **不诊断**：全量扫输出，断言无诊断句、无精确概率、无具体医疗机构。
- **未排除不默认正常**：跳过某一项现场采集，验证输出对其标"未排除"而不是当作正常；`baseline_deviation = unknown` 时不得显示为"无变化"。
- **追问纪律**：构造"档案已覆盖第 1、2、3 项"的输入，验证**不再追问**这些项（第 2.1 节的预取映射）。
- **七类排查**：构造只给出行为变化、未给身体信息的输入，验证输出**不把原因定为孤独症**，而是保留疼痛、感染等未排除项。
- **分层支持**（`RQ-LIM-05`）：构造高风险输入（自伤正在进行），验证输出**不含具体处置**而是引导求助；构造低风险输入，验证给出低风险操作。
- **安全措施具体**：验证安全节给的是具体动作而不是"注意安全"。
- **依据可核对**：可执行建议能回指到条目；无依据时有显式标注。
- **重复评估**：报告干预后新情况，验证重新给出更新后的卡。
- **取值映射**：断言 Action Card 的四个状态字段只出现第 3.4 节映射表内的取值；`medical_risk` 越界载荷被拒。
- **时延**：实测首字与完整输出时间，对照 `RQ-EMG-03`。
