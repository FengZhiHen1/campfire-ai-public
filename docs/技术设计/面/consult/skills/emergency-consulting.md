## 1. 定位

**面向监护者的、时间紧迫情境下的即时咨询。** 使用者此刻正面对一个无法应对的场面，需要知道**现在能做什么**。

它**不是**危机干预，也**不是**诊断工具——这两条是一期的硬边界，见第 6 节。

## 2. 触发

- **只由程序注入激活**：应急卡片用使用者填写的最小输入构造第一条消息，同时注入本 skill 的内容。**模型不参与选择**。
- 因此 `metadata.autoload` 取 `"false"`：不参与日常对话里的自动匹配。使用者在日常对话中输入类似"孩子突然打人"，走的是日常 skill，而不是被自动切成应急——是否进入应急由**入口**决定，不由模型判断。

## 3. `SKILL.md` 正文要点

### 3.1 frontmatter

```yaml
name: emergency-consulting
description: 用于监护者在突发情境下需要立刻可执行建议的即时咨询：当支持对象正在出现或刚刚出现让人当场无法应对的行为或状态，监护者需要知道现在能做什么时使用。方法论以「收敛到当下可执行的最小动作」为先，不做全景分析，不处理自伤或伤人风险的危机干预，也不做诊断或用药建议。
license: 项目内部内容，随应用发布，不单独授权
compatibility: 依赖 read_profile_summary、search_knowledge、search_cases 三个只读工具；不依赖脚本与外部二进制
metadata:
  surface: "consult"
  autoload: "false"
allowed-tools: read_profile_summary search_knowledge search_cases
```

> `description` 是**选择键**，必须同时说清"做什么"与"什么时候用"。此处按标准要求写成 what + when，并显式写出不做什么，以便将来若开启自动匹配时不会被误触发。

### 3.2 方法论（正文主体）

1. **先定紧迫性，再定问题。** 开口之前先判断：眼下的风险是"正在发生且会立刻恶化"，还是"已经发生、需要收拾"。前者只给当下动作，后者才允许做简短分析。
2. **只追问会改变结论的项**（`RQ-EMG-02`）。判据是一句话：**无论对方怎么答，我的建议会不同吗？不会，就不问。** 一轮最多问一到两项，问题必须能一句话问完。
3. **先给可执行动作，再给理由。** 输出顺序固定为：现在做什么（一到三条，具体到动作）→ 为什么（依据）→ 什么情况下要改变做法。
4. **不假装知道。** 信息不足时明说"这个判断需要看到实际情形"，而不是给出一个看起来完整的方案。
5. **不冒充个性化**（`RQ-CON-07`）：没有读取到档案时，必须在输出中标注"本次未使用个性化档案"，不得让使用者以为建议已考虑其孩子的具体情况。
6. **有据才给建议**（`RQ-CON-02`）：可执行建议要能指到具体依据；指不到时明说"这是通用做法，没有找到对应资料"。

### 3.3 输出结构

```text
1. 现在可以做的（一到三条动作，动词开头）
2. 依据（每条动作对应的资料或案例条目；无依据时显式标注）
3. 需要改变做法的信号（什么情况下停止当前做法、改为求医或求助）
4. 标注（是否使用了档案；本次是否只回答了部分问题）
```

**第 3 项的性质**：它只作**边界声明**（见第 6 节）——声明"出现以下情况时本 skill 的建议不再适用，应寻求专业帮助"，不判断严重程度、不建议具体医疗行为。

### 3.4 追问判据清单（初稿）

只在下列问题**会改变输出**时才问，且一轮最多一到两项：

- 现在还在发生吗？（决定"当下动作"还是"事后处理"）
- 有没有人正在受到伤害？（决定是否越出本 skill 边界）
- 当时的环境与在场的人（决定动作可行性）
- 已经试过什么（决定不要重复无效动作）

明确**不问**：诊断性细节、既往史、成长史、家庭结构——这些属于日常咨询或专业评估。

## 4. 工具依赖

只读三件：`read_profile_summary`、`search_knowledge`、`search_cases`。**写工具即使被调用，服务端也必须拒绝**（本 skill 不沉淀档案；沉淀由日常对话里激活的 `profile-curation` 承担）。

时延纪律（`RQ-EMG-03`）：工具调用要少——不为凑依据多轮检索；档案摘要取不到就不取，直接标注未使用。

## 5. 验证方式

- **激活**：从应急入口进入，只有本 skill 被激活；写工具调用被服务端拒绝。
- **追问**：构造"一项都不答也能给建议"与"不答就不能给建议"两类输入，验证前者不被追问。
- **标注**：无档案时输出含"本次未使用个性化档案"。
- **依据**：可执行建议能回指到具体条目；无依据时有显式标注。
- **不被误触发**：在日常对话中输入突发性描述，验证**不会**自动切到本 skill。

## 6. 安全边界（已裁决）

一期的安全层整体延期（`EXT-01`～`EXT-06`，见[设计待办](../../../../TODO.md)），因此本 skill **不做**危机干预、不做诊断、不做用药建议。

用户 2026-09-29 裁决：输出结构第 3 项**保留，但只作边界声明**——声明"出现以下情况时本 skill 的建议不再适用，应寻求专业帮助"，**不判断严重程度、不建议具体医疗行为、不给出具体求助路径**。

措辞纪律（写进 `SKILL.md` 正文）：

- 用"这种情况下应当寻求专业帮助"，不用"这属于急症""需要立即就医"这类判断句；
- 不列举具体医疗机构、科室或联系方式；
- 不承诺"按以上做法就会好转"。

这条边界的分工是：本 skill 只负责**把"该停下来找人"这件事说出来**，不负责判断"是不是真的危险"——后者需要专业训练与现场信息，一期不做。
