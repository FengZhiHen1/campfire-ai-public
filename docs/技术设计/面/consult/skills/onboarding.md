# onboarding

> **权威范围**：该 skill 的设计说明与 `SKILL.md` 正文要点——一次性引导对话的四段流程、种子问题集以 `emergency_context` 八组为纲、共用纪律的适用与豁免。引导状态表与完成/跳过信号见[技能设计](../../../technical-details/技能设计.md)总纲第 4 节；档案条目字段见[个性化档案](../../../technical-details/个性化档案.md)；支持对象的实体与生命周期见[支持对象](../../../technical-details/支持对象.md)。
> **状态**：2026-09-30 依用户确认的四项裁决（一次性自动触发、同会话收场、状态表双通道、范围四件事与应急八组种子）设计，待用户确认。不代表已实现。
> **追溯**：`RQ-ACC-09`、`RQ-ACC-02`、`RQ-LIM-03`、`RQ-MEM-01`、`RQ-MEM-02`、`AC-02`、`AC-25`。

## 1. 定位

**账号的第一次日常会话里，完成一次结构化的建档与导览。** 它做四件事：告知（先于任何询问）、创建第一个支持对象、播下档案种子（以应急八组为纲）、建立对使用者本人的基本认知；收束时给出使用说明页的跳转并调用 `finish_onboarding`。

它**只由程序注入激活**（`autoload: "false"`），模型自动匹配被禁止——防止日常对话被误触发引导。触发与一次性语义由应用侧持有（查 `campfire_onboarding` 状态表），不在本 skill 的职责内。

## 2. 触发（应用侧，与应急同路）

- 账号**首次创建日常会话**时，应用查 `campfire_onboarding`：无行或 `state = in_progress` → 程序注入本 skill + 静态告知文本；`completed` / `skipped` → 不注入。
- **应急会话永不触发**（`RQ-EMG-03` 时延硬约束）；用户的第一次对话若是应急，引导顺延到其首次日常会话。
- 会话收场（2026-09-30 裁决）：引导会话**延续为日常对话**；会话中创建的第一个对象**补建**该会话的唯一绑定——从无到有的首次绑定不是改绑，不违反[支持对象](../../../technical-details/支持对象.md)第 6 节「绑定不可变」的本意。
- **首次注入只注入一次，授权不靠重复注入维持（2026-10-01 裁决）**：`campfire_session.first_run_injected` 只结算「告知消息 + 首条合成激活记录」这一次注入；引导的多轮推进（八问一次一问、提问即中止运行）依赖**授权跨运行**——首次运行的合成激活记录落会话历史后，后续运行从历史推导工具授权（[技能设计](../../../technical-details/技能设计.md)第 4 节、[通用基座](../../../technical-details/通用基座.md)第 3 节）。引导状态表的 `in_progress` 判定不再承担授权续期职责，只保留「另开新日常会话时是否再注入引导」的判定（无行或 `in_progress` → 注入，与既有语义一致）。

## 3. `SKILL.md` 正文要点

### 3.1 frontmatter

```yaml
name: onboarding
description: 仅在账号首次日常会话中由系统注入激活，不通过模型描述匹配。用于完成一次性引导：告知数据用途、创建第一个支持对象、播下档案种子、了解使用者本人的照护经验，并指引使用说明。
license: 项目内部内容，随应用发布，不单独授权
compatibility: 依赖 create_support_object、read_profile_items、propose_profile_item、write_memory、finish_onboarding；不依赖脚本与外部二进制
metadata:
  surface: "consult"
  autoload: "false"
allowed-tools: create_support_object read_profile_items propose_profile_item write_memory finish_onboarding
```

### 3.2 方法论（正文主体）

1. **先告知，后询问**（`RQ-LIM-03`）：告知文本由应用作为静态消息注入、先于任何询问到达；skill 不得在告知前发起提问。告知内容三件事：内容会用于什么、谁可见、是否送往外部模型。
2. **对象创建问称呼，不问身份**：`display_name` 由使用者自起；不问姓名、出生日期、联系方式等可识别身份信息（[个性化档案](../../../technical-details/个性化档案.md)第 6.3 节的禁采清单同样适用于引导）。
3. **档案种子以 `emergency_context` 八组为纲**（2026-09-30 裁决）：基线、已知触发、沟通、感觉概况、医疗风险、有效策略、无效策略、安全史——每问有明确的下游消费者（首次应急的档案预取）。八问，**一次一问**，每一问都经 `ask_user` 发出（`question` 事件带选项与跳过），可跳过、跳过即留空、**不猜**。
4. **使用者认知写记忆，不写档案**：关于使用者自身的照护情境与既往经验（`RQ-MEM-01` 低风险信息）经 `write_memory` 写入，2–3 问；凡是关于支持对象的事实必须走档案，不得借记忆通道绕过确认。
5. **种子条目带真实 `origin`**：监护人陈述直接进稳定层（零确认，既有分流裁决）；skill 自己的归纳（如"您似乎更关注感官问题"）不得写入——引导期不做推断候选，信息不足就留空。
6. **收束必须完整**：跳转说明页 → 调用 `finish_onboarding`。即使全程跳过，收束段仍要走完——跳过档案种子不等于跳过引导。
7. **阶段可跳过，跳过不补问**（`RQ-ACC-02` 同源）：每段给显式跳过选项；跳过的段不再以其他措辞重复。

### 3.2.1 提问的唯一通道（硬约束）

**需要使用者作答的内容只能出现在 `ask_user` 的 `items` 里；正文只写不需要作答的话**（回执、确认、收束说明）。正文里不写问句、不预告题目或题单；收束的 `finish_onboarding` 同样必须真的调用，正文写「引导已完成」不算收尾。

**与基座工具描述的分工（2026-10-29 订正）**：基座 `ask_user` 描述同时给出两种合法用法——同一批要一起确认的题放同一次调用，而流程分阶段推进时按阶段每轮一题也合法。引导属于后者：八问逐题推进、答完再问下一题，因此一次调用只放一道题。**这条节奏归本文与 `SKILL.md` 拥有，不写进基座描述**——基座只给「这批答案要不要一起去确认」这条通用判据，不含任何领域词。

**为什么写成硬约束**：`ask_user` 一调用即结束本次运行，使用者拿到的是有选项、可跳过的卡片；正文里的问句只是文字，没有作答入口（`RQ-CON-02` 的引导形态不成立）。这条只能靠内容约束（服务端不解析正文猜提问，也不改写正文），因此 `SKILL.md` 的合同要短而可执行，并给正例；判据见第 4 节「提问只有一条通道」。

### 3.3 共用纪律的适用与豁免

三条共用纪律中：**目标不等于服从**与**专业判断与可读解释**不适用（引导不产出咨询建议）；**有据才给可执行建议**以弱形式适用——引导中不得给出任何具体照护建议，使用者中途提出真实咨询问题时，**先完成或跳过引导段**，再由后续消息走日常咨询路径作答。本 skill 不含 `shared:` 标记块（无共用正文），一致性检查豁免，理由：共用纪律的语义前提（产出咨询输出）在本 skill 不成立。

### 3.4 输出结构

```text
1. 告知确认（静态注入文本的回应，不重复念一遍）
2. 对象创建（称呼 → 回执对象名）
3. 档案种子（一次一问；每问一次 ask_user 调用，2–4 选项 + 自由回答 + 跳过）
4. 使用者认知（2–3 问，同上）
5. 收束：使用说明页跳转 + finish_onboarding 回执
```

## 4. 验证方式

- **注入即激活且不被自动匹配**：`autoload: "false"` 下模型侧 `skill` 工具调用被拒；日常会话首次触发注入、二次不触发（状态表驱动）。
- **授权跨运行（2026-10-01 裁决新增）**：引导会话「首次注入 → 提问中止 → 回答触发的第二次运行调用 `create_support_object`」全程不被 `tool_not_available` 拒绝；`finish_onboarding` 在多轮引导的最后一轮可正常调用。这是原验证方式未覆盖的缺陷形状：注入时机的隐含假设（一次运行跑完整个引导）与「一次一问 + 提问即中止」相矛盾。
- **提问只有一条通道（2026-10-29 新增）**：`SKILL.md` 的短合同与正例在正文里且在渲染载荷（`render_activation`）里；基座 `ask_user` 描述同时表达「同批一起确认」与「按阶段每轮一题」两种用法且不含领域词；三份引导内容不出现「结构化提问事件」这类无主语措辞。机械判据见 `apps/api/tests/test_onboarding_skill_contract.py`。
- **第三轮工具范围（2026-10-29 新增）**：引导第三轮（请求不携带激活、授权只能来自历史激活记录）里 `ask_user` 与五个引导工具全部可用——「工具被收回」这一假设由此被排除。同文件用例。
- **遵守度不保证**：上述判据只证明约束进入了模型读到的输入。模型是否遵守只能用真模型校准观察，校准脚本与合成状态 fixture 在同文件末尾（`python apps/api/tests/test_onboarding_skill_contract.py --runs 4 [--state seeds]`），记数含端点失败的尝试。
- **告知先于询问**：会话首条 assistant 消息之前不存在任何 `question` 事件。
- **种子同构**：抽取种子问题集，验证每组都能映射到 `emergency_context` 的八组之一。
- **跳过即留空**：跳过任一种子问题后，该组在 `emergency_context` 中返回 absent，不由模型补全。
- **记忆不越界**：使用者认知段产出的条目全部落在通用记忆（账号级），档案中不出现关于使用者自身的事实。
- **收束完整性**：全程跳过档案种子的会话仍调用了 `finish_onboarding`。
- **身份信息拒收**：构造包含姓名/联系方式的回答，验证条目不落这些字段。
