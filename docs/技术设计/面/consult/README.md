## 1. 这一面是什么

对话是主要工作面，领域功能由 skill 与工具承担。本面包含**两个入口**，它们共用同一套基座与工具池，差别在**第一条消息怎么构造**：

| 入口 | 第一条消息 | 激活方式 |
|---|---|---|
| 应急 | 由 UI 卡片构造：现场采集**八项**（`RQ-EMG-01`）＋ 应用预先注入的**应急上下文**（档案七组稳定信息）＋ 程序注入的 skill 内容 | 程序注入（模型不参与选择） |
| 日常 | 使用者自己输入；可先在输入框上方选定技能 | 使用者选定（下一条消息生效）或模型按 `description` 匹配 |

**首页**是导航外壳，不属于本面；它只负责把使用者带进这两个入口。

**激活的语义只有一套**：在一次对话中选定某个 skill，**其后输入的消息**按该 skill 处理。三种来源（使用者选定、程序注入、模型匹配）语义相同，区别只在谁发起——机制由[通用基座](../../technical-details/通用基座.md)第 3 节拥有，此处不复述。

## 2. 为什么应急与日常是两个 skill

两者的**方法论不同**，不是同一套方法的两个入口：

- 应急的目标是**收敛**——在信息不足的情况下尽快给出现在能做的事，因此少问、短答、不做全景分析；方法论是**固定顺序的六层闸门**、输出是一张 Action Card，时延是硬约束（`RQ-EMG-03`：首字 ≤10 秒、完整 ≤60 秒 p50）。
- 日常的目标是**展开**——可以多轮澄清、可以检索资料与案例、可以沉淀档案，时间不紧迫。

把两者合成一个 skill 会让"该快的时候在分析、该细的时候在抢时间"，因此拆开；而**沉淀档案**又是第三件事（它在日常对话里被激活，且需要写工具），所以也是独立 skill。

## 6. 验证方式

- **入口**：应急卡片能构造出合法第一条消息；日常入口在未选技能时用默认工具集作答。
- **激活**：选定技能后**下一条消息**生效；应急入口不存在"未激活"的中间态。
- **工具越界**：分别以应急、日常身份调用写工具，服务端拒绝且给出明确错误，不静默降级。
- **共有约束**：三个 skill 的共用纪律块逐字一致（一致性检查）。
