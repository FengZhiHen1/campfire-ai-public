# read_profile_summary

> **权威范围**：该工具的契约——用途、参数、返回形状、实现层硬约束、失败语义、验证方式。档案条目的数据形状与稳定层规则见[个性化档案](../../../technical-details/个性化档案.md)；工具归属见[技能设计](../../../technical-details/技能设计.md)总纲。
> **状态**：2026-09-29 依已确认机制设计，待用户确认。
> **追溯**：`RQ-MEM-06`、`RQ-CON-07`、`AC-02`。

## 1. 用途

取支持对象的**一页档案摘要**，用于注入对话上下文。它是最常用的只读工具，也是"个性化注入"的主要来源。

## 2. 参数

```text
support_object_id: string   # 必填
```

`support_object_id` 一期是否需要使用者显式选择（一个账号能否有多个支持对象）**待确认**；在确认前按必填处理，由调用方传入。

## 3. 返回

```text
summary: string        # 来自稳定层的自然语言摘要
item_count: number     # 参与摘要的条目数
generated_at: string   # 生成时间
possibly_stale: bool   # 摘要可能未包含最新写入（写入是异步的）
```

## 4. 硬约束（实现层）

- **只从稳定层取数**。候选层条目**不得**进入摘要、不得以事实语气出现（`RQ-MEM-05`）。
- **只读**：不产生任何写入。
- 无档案时返回明确的"无档案"结果，而不是空对象——调用方需要据此在输出里标注"本次未使用个性化档案"（`AC-02`）。
- `possibly_stale` 在有未完成的待处理记录时必须为真。

## 5. 失败语义

| 情形 | 处置 |
|---|---|
| 支持对象不存在或不属于当前账号 | 明确失败；**不得**返回其他人的档案，也不得返回空摘要冒充"没有档案" |
| 无档案 | 正常返回"无档案"标记 |
| 取数失败 | 明确失败；模型须标注"未使用档案"，不得静默当作没有档案 |

## 6. 验证方式

- **稳定层隔离**：写入一条候选条目后立即调用，验证摘要里没有它。
- **越权**：以账号 A 请求账号 B 的支持对象，验证被拒绝。
- **无档案**：全新账号调用，验证返回的是"无档案"标记而非空对象。
- **滞后标注**：有待处理记录在途时，验证 `possibly_stale` 为真。
