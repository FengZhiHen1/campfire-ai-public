# read_profile_items

> **权威范围**：该工具的契约——用途、参数、返回形状、实现层硬约束、失败语义、验证方式。档案条目的字段与领域取值见[个性化档案](../../../technical-details/个性化档案.md)。
> **状态**：2026-09-29 依已确认机制设计，待用户确认。**2026-09-29 领域架构裁决后更新**：领域过滤取十四个一级模块。
> **追溯**：`RQ-MEM-02`、`RQ-MEM-04`、`RQ-MEM-05`、`RQ-MEM-06`。

## 1. 用途

按条件读取**具体档案条目**，用于需要条目级细节的场合（比较几种支持方式、核对某条记录、整理去重）。

与 `read_profile_summary` 的分工：概览用摘要，细节用本工具。

## 2. 参数

```text
support_object_id: string    # 必填
domains: string[]            # 可选，按领域过滤（十四个一级模块之一或「其他」）
include_candidates: bool     # 可选，默认 false
limit: number                # 可选，默认值待确认（登记于设计待办）
```

## 3. 返回

条目数组，每条为[个性化档案](../../../technical-details/个性化档案.md)定义的结构，**必须**包含 `origin`、`confirmation`、`freshness` 三个字段。

## 4. 硬约束（实现层）

- **候选层条目必须自带标记返回**，调用方与模型都不得把它当作事实。`include_candidates=false` 时不得混入候选。
- `superseded_by` 非空的条目默认不返回（已被替代）。
- **`confirmation = rejected` 的条目一律不返回**：使用者否定过的内容不得再作为上下文进入对话。
- **只读**。
- 返回必须带上 `origin` 与 `confirmation`——**不得**为了"让输出干净"而省略来源与确认状态。

## 5. 失败语义

| 情形 | 处置 |
|---|---|
| 越权访问 | 明确失败 |
| 过滤条件非法（未知领域名） | 明确失败，不静默忽略条件 |
| 取数失败 | 明确失败，不返回部分结果冒充完整结果 |

## 6. 验证方式

- **候选不冒充事实**：写入一条 `origin = ai_inference` 的候选，验证返回中它带候选标记。
- **不得省略来源**：断言每条返回都含 `origin` 与 `confirmation`。
- **已替代条目不返回**。
- **非法过滤**：传入未知领域名，验证明确失败而非空数组。
