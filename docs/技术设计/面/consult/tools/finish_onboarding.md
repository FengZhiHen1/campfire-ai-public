# finish_onboarding

> **权威范围**：该工具的契约——用途、参数、返回、失败语义、验证方式。引导状态表 `campfire_onboarding` 的形状与归属声明见[认证与账号](../../../technical-details/认证与账号.md)；引导流程见 [onboarding](../skills/onboarding.md)。
> **状态**：2026-09-30 依一次性引导设计新增，待用户确认。不代表已实现。
> **追溯**：`RQ-ACC-09`、`AC-25`。

## 1. 用途

把该账号的引导状态置为 `completed`。它是引导收束段的最后一步：模型在流程走完（含全程跳过的情形）时调用，使后续日常会话不再注入引导。

**双通道的另一半**：使用者经对话页 UI 的显式跳过入口（HTTP 端点）写 `skipped`；本工具只写 `completed`，两者互不代写。

## 2. 参数

```text
skipped_sections: string[]   # 引导中被跳过的段名（onboarding / profile_seed / memory_seed），
                             # 仅作记录，不影响状态取值
```

不收 `account_id`——键取登录态。不收 `state`——状态取值由工具定死为 `completed`，不给模型选择 `skipped` 的通道。

## 3. 返回

```text
state: "completed"
```

## 4. 硬约束（实现层）

1. **只在引导激活期间可用**：未激活 onboarding skill 时，服务端按工具范围拒绝调用（基座第 5 节——工具可见性不是安全边界，服务端照常拒绝越界）。
2. **幂等**：重复调用不报错、不重置时间戳之外的状态。
3. 工具实现归 `modules/accounts`（状态表所有者），契约映射之外不写逻辑。

## 5. 失败语义

| 情形 | 处理 |
|---|---|
| 未激活引导时调用 | 明确拒绝（工具范围硬边界），不静默成功 |
| 未登录 | 明确失败（`RQ-ACC-01`） |
| 状态表写入失败 | 明确失败——**不得**回执 completed；失败后 UI 跳过入口仍是补救通道 |

## 6. 验证方式

- 引导收束后创建新日常会话，验证不再注入引导（状态表驱动，非时间推导）。
- 未激活引导的会话中调用，验证被服务端拒绝。
- 模型侧完成判定是**提示词层约束**（与 `RQ-LIM-05` 同源，不构成安全边界）：构造模型未调用本工具的失败注入，验证状态保持 `in_progress`、后续会话再次注入引导且 UI 跳过入口可写 `skipped` 补救——**漏写的最坏后果是重复注入，不损失数据**。
- 写入失败注入：验证工具返回失败且回执不是 completed。
