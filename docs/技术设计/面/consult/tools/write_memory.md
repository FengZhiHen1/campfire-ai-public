# write_memory

> **权威范围**：该工具的契约。异步写入路径见[写入路径](../../../technical-details/写入路径.md)。
> **状态**：2026-09-29 依已确认机制设计，待用户确认。
> **追溯**：`RQ-MEM-01`、`RQ-MEM-02`、`RQ-MEM-03`。

## 1. 用途

把一段对话内容作为**记忆片段**提交，供以后按时间回看。

## 2. 参数

```text
support_object_id: string
content: string          # 要记住的内容
occurred_at: string      # 这件事发生的时间（不是提交时间）
source: object           # 会话 id、消息定位、时间
```

## 3. 返回

```text
pending_id: string
state: "submitted"
```

## 4. 硬约束（实现层）

- **落在待处理记录里**，由 Worker 异步写图库；工具不等待完成。
- **幂等键由 `pending_id` 派生**：图库对 episode 写入**没有官方的重试或幂等承诺**，所以确定性标识与我方"已写入"标记必须由我们自己在同一流程内校验（见[写入路径](../../../technical-details/写入路径.md)第 5 节）。
- **不得用它写档案**：档案只能经 `propose_profile_item` 进候选层。
- 来源与发生时间必填：没有时间的记忆无法回看。

## 5. 失败语义

| 情形 | 处置 |
|---|---|
| 待处理记录写入失败 | 明确失败；不得回执 submitted |
| 图库写入最终失败 | 记录转 `dead` 并**告警**；不得静默丢弃，也不得让对话表现为已记住 |
| 重复提交 | 靠幂等键去重，不产生重复片段 |

## 6. 验证方式

- **异步回执**：验证返回 `submitted`，且在 Worker 完成前不会表现为已生效。
- **幂等**：同一 `pending_id` 重复投递，验证只写入一次。
- **不越界**：尝试用本工具写档案，验证不产生档案条目。
