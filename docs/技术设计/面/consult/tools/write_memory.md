# write_memory

> **权威范围**：该工具的契约。异步写入路径见[写入路径](../../../technical-details/写入路径.md)；记忆单元粒度、时间模型与删除账本见[通用记忆](../../../technical-details/通用记忆.md)。
> **状态**：2026-09-29 依已确认机制设计，待用户确认。**2026-09-29 记忆归属裁决后更新**：归属改为账号，参数去掉 `support_object_id`（见[决策记录](../../../decisions/通用记忆归属为账号.md)）。**2026-09-30 补 `origin` 参数**（`AC-07` 的一致性要求）。
> **追溯**：`RQ-MEM-01`、`RQ-MEM-02`、`RQ-MEM-03`、`RQ-MEM-07`。

## 1. 用途

把一段对话内容作为**记忆片段**提交，供以后按时间回看。

**归属**：记忆**归属账号**（`group_id = account_id`，[通用记忆](../../../technical-details/通用记忆.md)第 1 节），**不随支持对象分区**；一个账号多个对象时记忆共享。分区键取自登录态，**不作为参数传入**。内容是**关于使用者自身**的经验；与支持对象有关的事实走 `propose_profile_item`。

## 2. 参数

```text
content: string          # 要记住的内容：一件值得记住的事，一个 episode
occurred_at: string      # 这件事发生的时间（不是提交时间）
origin: string           # 生成方式，取值见第 4 节
source: object           # 会话 id、消息定位、时间
```

## 3. 返回

```text
pending_id: string
state: "submitted"
```

## 4. 硬约束（实现层）

- **落在待处理记录里**，由 Worker 异步写图库；工具不等待提交后的写入完成。
- **`origin` 必填**（2026-09-30 补）：`AC-07` 要求记忆条目带来源、**生成方式**与时间，生成方式就是 `origin`；[写入路径](../../../technical-details/写入路径.md)第 3 节把该字段列为待处理记录的一部分且存储层为 `NOT NULL`，而本契约此前未列出它——与 `propose_profile_item` 第 2 节对同一字段的处理不一致。
  **取值与[写入路径](../../../technical-details/写入路径.md)第 3 节的词表同源**（该节列六个：`user_statement`、`guardian_observation`、`third_party_report`、`document`、`system_observation`、`ai_inference`），本契约**不另立一份定义**；越界取值由服务端拒绝，不静默改写。
  ⚠️ **已知不一致（非本条引入）**：存储层 CHECK 目前只接受**四个**取值（缺 `third_party_report` 与 `document`），与第 3 节的六值词表不符，已登记于[设计待办](../../../../TODO.md)。**记忆侧当前只会用到 `user_statement`**（写入方是 `profile-curation`），故该缺口不阻塞本工具，但**不得**据此在本契约里写死四值——那会制造第三份定义。
  **与档案侧的差别**：记忆**不做落层分流**——候选层与稳定层是档案的概念（[个性化档案](../../../technical-details/个性化档案.md)第 3 节）；`origin` 在记忆侧只如实记录「这条内容是怎么来的」，供审计与后续判断。`RQ-MEM-04`（推断不得冒充事实）在记忆侧的落法是「可辨识」：`origin` 如实记录、读路径如实返回写入状态。
- **投递在请求事务提交之后**（[写入路径](../../../technical-details/写入路径.md)第 4 节）：投递失败**不影响**已落库的待处理记录，记录留在 `pending` 由兜底扫描重投。工具**不得**因投递失败而回滚业务事务或回执失败。
- **幂等依据是派生的确定性 episode uuid**：图库对 episode 写入**没有官方的重试或幂等承诺**，且 episode 的身份是 `uuid` 而非 `name`——确定性 uuid 必须显式传给图库写入，并在我们自己表里记"已写入"标记，两者在同一流程内校验（见[写入路径](../../../technical-details/写入路径.md)第 5 节）。
- **不得用它写档案**：档案只能经 `propose_profile_item` 进候选层。
- 来源与发生时间必填：没有时间的记忆无法回看。

## 5. 失败语义

| 情形 | 处置 |
|---|---|
| 待处理记录写入失败 | 明确失败；不得回执 submitted |
| 图库写入最终失败 | 记录转 `dead` 并**告警**；不得静默丢弃，也不得让对话表现为已记住 |
| 重复提交 | 靠幂等键去重，不产生重复片段 |

## 6. 验证方式

- **异步回执**：验证返回 `submitted`，且在 Worker 完成前不会表现为已生效。
- **幂等**：同一 `pending_id` 重复投递，验证只写入一次——**且是用确定性 episode uuid 做到的**，不是靠 `name`。
- **不越界**：尝试用本工具写档案，验证不产生档案条目。
- **归属不可指定**：验证参数中无法传入分区键；两个支持对象之间写入的记忆相互可见（账号级）。
