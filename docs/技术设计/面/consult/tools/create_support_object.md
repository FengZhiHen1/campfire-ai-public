# create_support_object

> **权威范围**：该工具的契约——用途、参数、返回、失败语义、验证方式。对象的实体形状、生命周期与授权端口见[支持对象](../../../technical-details/支持对象.md)；对象创建用例归 `modules/profile`，本工具只做契约映射。
> **状态**：2026-09-30 依一次性引导设计新增，待用户确认。不代表已实现。
> **追溯**：`RQ-ACC-09`、`RQ-MEM-05`、`RQ-MEM-07`、`AC-22`、`AC-25`。

## 1. 用途

在对话中创建一个支持对象并返回其标识。它是引导对话建立**第一个**对象的通道，也可在引导之外的对话中创建后续对象；档案页「+ 新建对象」表单走同一创建用例的 HTTP 端点——**对话式创建是一等入口，表单是补充路径**（2026-09-30 裁决）。

## 2. 参数

```text
display_name: string    # 对象名，使用者自起的操作标签；非空、去空白后长度 > 0
```

不收 `account_id`——属主由登录态决定，不接受调用方传入（[支持对象](../../../technical-details/支持对象.md)第 4 节创建操作的不变量）。

## 3. 返回

```text
support_object_id: string    # 新建对象的 UUID
display_name: string        # 实际落库的对象名
```

## 4. 硬约束（实现层）

1. **空名拒收**：空白或去空白后为空 → 明确失败，不静默填默认名（存储层 CHECK 兜底，[支持对象](../../../technical-details/支持对象.md)第 8 节）。
2. **属主取登录态**，不从参数取。
3. **不设数量上限**（一期，[支持对象](../../../technical-details/支持对象.md)第 4 节）；同名不拒（第 3 节）。
4. 工具只做契约映射，创建语义在 `modules/profile` 的创建用例内——不在工具实现里写领域逻辑。

## 5. 失败语义

| 情形 | 处理 |
|---|---|
| `display_name` 为空或全空白 | 明确失败（存储层 CHECK 亦兜底） |
| 未登录 | 明确失败（`RQ-ACC-01`） |

## 6. 验证方式

- 引导对话中创建对象后，该账号的对象列表出现它、其他账号不可见（`AC-22`）。
- 直连数据库插入空白名，验证 CHECK 拒绝（不变量在存储层，不只在应用层）。
- 引导会话中创建的第一个对象补建为该会话的唯一绑定（[支持对象](../../../technical-details/支持对象.md)第 6 节）；同一会话再建第二个对象，验证绑定不改变。
