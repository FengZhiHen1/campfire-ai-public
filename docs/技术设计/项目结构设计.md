# 项目结构设计

> **权威范围**：目标仓库模块、目录职责、依赖方向，以及跨切能力的归属（授权判定入口、事务与 outbox、工程支撑层）。业务语义、状态取值与失败语义不由本文拥有；命名、文件组织、依赖注入、错误处理、静态检查与测试分层等工程纪律由[工程约定](./工程约定.md)拥有。
> **追溯**：`RQ-SP-01～05`、`RQ-REC-01～04`、`RQ-CTX-03/06`、`RQ-PLAN-01～03`、`RQ-OPS-03～05`、`AC-SP-01～05`、`AC-OPS-02`。
> **状态**：2026-09-26 用户授权自主收敛的 v3.0 目标结构；不是当前代码目录已迁移的声明。仓库根没有 `apps/`、`packages/`、`infrastructure/`。

## 1. 结构原则与现状

保留 uv + pnpm 双工作空间、单仓和薄运行入口。目标按**公开支持、情境辅助、用户事项、个人空间、记录、交接、共享计划、证据、演练**的业务职责划分，不按旧“应急行为桶”复制一套新轴。只迁移被新需求使用的能力；不创建未使用的空包。

依赖原则：业务用例持有授权、发布和停止决定；数据库/队列/模型/Agent 是可替换执行手段，不能反过来决定业务状态。每个跨模块操作只有一个状态所有者；读者不得从另一个模块的缓存推断权限。

已核实现状（2026-09-26 实际读取，不是推断）：根 `pyproject.toml` 的 `[tool.uv.workspace] members` 为空、`pnpm-workspace.yaml` 只列尚未创建的 `apps/react-web` 与 `packages/ts-shared`、`pnpm-lock.yaml` 已按当前工作空间重建；根不存在 `apps/`、`packages/`、`infrastructure/`；`docker-compose.yml` 仅编排 PostgreSQL 17、Redis 7、MinIO 三个数据容器。旧实现与旧结构文档（含旧项目结构组、总体架构、重构计划）已整体移入 `archive/`；`archive/infrastructure/` 含 nginx、monitoring 与部署脚本，`archive/scripts/` 含部署与重建脚本，二者**不是新目标归属**，且归档脚本禁止执行。`.github/workflows/` 仍在根并引用已归档的 `apps/`、`packages/`、`scripts/`，在按新结构重写前必然失败。

## 2. 后端职责与依赖

| 目标业务模块（`apps/api-server/app/modules/`） | 拥有的用例 | 不得承担 |
|---|---|---|
| `auth` | 身份、凭证、账号状态；供关系核验的用户标识 | 对某个支持对象的实际访问授权 |
| `public_support` | 公开已审阅基础内容、真实求助路径和撤下 | 个性化生成或未经审阅的现场处置 |
| `assist` | 带作用域的情境澄清、受限模型调用、完整回答的核对与临时预览 | 在用户确认前持久化事项或替代授权判定 |
| `matters` | 私人与空间事项、用户明确保存、并发修订与逐项转入请求 | 因聊天而创建共享档案或长期标签 |
| `spaces` | 支持对象、授权主体、关系委托、撤销、争议与重复空间；**授权判定入口**与数据权利请求的状态 | 以职业角色代替关系核验 |
| `records` | 带来源的观察、纠错、分歧及记录核对 | 将记录自动发布为计划 |
| `handoffs` | 接收者受限预览、明确发送与送达/失效状态 | 无权通知、以“已受理”冒充已送达 |
| `plans` | 分级确认、条目版本、安全异议及恢复 | 将审核权交给 AI 或访问管理员 |
| `evidence` | 研究/案例/安全内容的审阅、版本、撤下和依据索引 | 将私人记录自动用于公共检索 |
| `practice` | 审阅情景与演练反馈 | 冒充个人行为预测或专业诊断 |

`apps/api-server` 中模块包含薄路由、用例服务和端口；它们使用 `packages/py-db` 的 ORM/仓储与迁移、`py-schemas` 的对外 DTO、`py-auth` 的身份原语、`py-security` 的安全原语。

### 2.1 授权判定入口的形状

**授权语义（条件如何取交集、期限与争议如何生效）由[空间授权机制](./机制/空间授权与数据生命周期.md)拥有；本节只定义入口的位置与调用形状**，二者不得互相复述。

- 位置：`apps/api-server/app/modules/spaces/` 内以端口 + 用例服务暴露，是**唯一**的授权判定入口。
- 调用方：其余模块的用例、Worker 读取任务、缓存键校验，一律经该入口取决策，不自行读取角色枚举、Grant 表或 JWT 声明构造授权。
- 入参形状：`account_id`、`space_id`（可空表示私人范围）、`resource`（类别 + 版本 + 所属来源）、`action`、`purpose`、`at`（判定时刻）。
- 返回形状：`allow` / `deny`、`grant_ref`、`auth_epoch`、`granted_categories`、`valid_until`、`reason_code`（取自[错误码表](./枚举与错误码.md)）。
- 不可用时返回 `deny`，由调用方降级为公开基础内容；入口本身不缓存否定结果以外的结论。

`py-security` 只提供脱敏、PII 检测与危险内容原语，**不是**授权判定入口：它可以缩小范围，不能放行。

### 2.2 事务边界与 outbox 归属

授权撤销、异议停用、计划确认与交接发送的状态写入必须与业务数据在同一主库事务内完成。跨事务副作用走持久化 outbox：

- 归属：`apps/api-server/app/core/operations/` 拥有 outbox 写入与异步操作查询（`/api/v2/operations` 的状态所有者）；`apps/worker` 只消费，不拥有状态。
- 形状：`OutboxEvent(event_id, business_key, topic, payload, state, attempts, next_attempt_at, created_at)`。写入与业务状态变更同库同事务；消费端按 `business_key` 幂等，重试上限由[工程约定](./工程约定.md)统一规定，超限转死信并告警。
- 边界：outbox 失败不得回滚已完成的主事务状态；异步完成前，Worker 不得把未确认内容作为当前有效内容发布。

`/api/v2/data-requests` 的状态所有者是 `spaces`（核验与请求状态机）；`records`、`matters`、`handoffs`、`plans`、`evidence` 各自提供本域处置能力并回报结果，不各自维护第二份请求状态。

### 2.3 依赖白名单

| 成员 | 允许依赖 | 禁止 |
|---|---|---|
| `api-server` | 全部 `packages/py-*` | 直接 import `worker` |
| `worker` | `py-db`、`py-schemas`、`py-cache`、`py-config`、`py-logger`、`py-rag`、`py-storage`、`py-agent-kernel`、`py-agent-extensions` | 直接 import `api-server`、经 RPC 回查业务用例 |
| `py-agent-extensions` | `py-agent-kernel`、`py-rag`、`py-db`、`py-schemas`、`py-security`、`py-config`、`py-logger` | 反向依赖任何 app；扩展间互相 import；绕过事件总线直调模型 |
| `py-agent-kernel` | 仅 pydantic-ai 与三方库（零本项目包依赖） | import 任何 `py-*` 或 app |
| `py-rag` | `py-db`、`py-config` | 调用业务用例或判定授权 |
| `py-auth` | `py-config`、`py-cache` | 判定空间授权 |
| `py-security` | `py-config`、`py-logger` | 放行或构造授权决策 |
| 其余能力包 | `py-config`（按需 `py-logger`） | 依赖业务模块 |
| `apps/react-web` | `@campfire/ts-shared`、自身五层 | 见 §4 |

`app/modules/*/routes.py` 不得直接 import `py_db/models/`（经用例服务与仓储）；app 之间禁止互相 import；Python 不 import TypeScript 包，反之亦然。

`apps/worker` 只处理可重试的证据索引、站内交接投递、专业审核通知和撤下后索引清理。

## 3. Agent 与基础能力边界

`packages/py-agent-kernel` 继续承载通用模型运行、事件和工具适配；`py-agent-extensions` 只承载项目批准的整理、检索和演练工具。二者不是授权服务器：可用工具和检索上下文由 API 用例在调用前生成并校验，模型输出在写入记录或对外显示前再次按身份、内容类别、来源和当前状态校验。安全门不能只依赖“安全扩展优先加载”，即使扩展缺失、调用超时或模型拒绝配合，服务端仍阻断受限操作。`py-llm` 若仍被旧功能使用只作为迁移期现状，不为新能力扩展。

`packages/py-rag` 只索引当前被批准用于对应受众的研究、指南与案例；个人记录保留在带空间作用域的关系型数据中，按授权加载后再交给生成任务。

`py-config` 是配置的唯一入口（环境注入、`.env` 解析与按特性开关的读取），各模块不得各自读取环境变量形成第二真相；`py-health` 承载技术栈设计要求的四类健康检查信号与告警出口。`py-cache`、`py-storage`、`py-logger` 分别承载临时协调、受控附件及去敏审计，不能成为个人资料的隐式复制渠道。技术选型与版本仅由[技术栈设计](./技术栈设计.md)拥有。

## 4. 前端组织和接口接缝

`apps/react-web/src/` 沿用已在项目规范中的单向五层：`domain/`（无框架业务类型）←`application/`（用例与端口）←`viewModel/`（交互状态与 Hooks）←`view/`（页面与组件）；`infrastructure/` 实现 application 端口，经装配注入，不让 `view` 直接请求 HTTP、读取 JWT 或跨层导入仓储。按 `public_support`、`assist`、`matters`、`spaces`、`records`、`handoffs`、`plans`、`evidence`、`practice`、`auth` 在层内组织；跨特性元素只在确有第二消费者时进入 shared。

`view` 不得直接调用 HTTP、读写 token 或跨层导入 `infrastructure`；`viewModel` 不得导入 `view`；`application` 不得导入任何框架或 HTTP 库。状态归属分三类：跨介质 UI 状态归 `viewModel`，组件内视觉状态归 `view`，业务驱动的视觉决策由 `viewModel` 经 Props 下传。

公开基础内容路由可在未登录时读取，AI 入口必须经过登录及真实服务端守卫；前端守卫只负责体验，不充当权限证明。选择当前空间与切换支持对象时，清除前一个人的可见缓存和正在运行的流；任一旧请求迟到的响应不得显示到新对象页。`packages/ts-shared` 限于跨端 DTO 与枚举，不复制业务规则、不含运行时逻辑。

`apps/mini-program` 冻结：不为它新增页面、功能分叉或微信登录承诺；日后重启再从已验证的 Web 业务契约映射，而非复制 Web 的敏感客户端缓存。

## 6. 验证与失败边界

- 静态依赖检查应拒绝前端 view 直接访问 infrastructure、领域包反向依赖 app、跨 app import 与双模块各自维护授权规则；工具与规则由[工程约定](./工程约定.md)拥有。
- 集成用例覆盖用户同时参与两个空间、取消请求后切换对象、Token 有效但关系已撤销、Worker 重放任务与缓存落后数据库的情况；授权不一致时拒绝受限操作，公开内容仍可达。
- 先列迁移映射和回退点，逐阶段核对 API、schema 和资料权限；阶段切换不以“测试环境无真实用户”替代生产数据核查。未实现或未测试的路径标明差异，不宣称结构已落地。

## 7. 重访条件

- 新增业务模块使跨模块事务协调成本持续高于单模块维护成本，且两者始终共同修改、缺乏独立不变量 → 合并实际相邻模块。
- `packages/py-*` 数量膨胀至维护成本超过复用收益，或出现需要独立技术栈的新应用 → 重审包边界。
- `py-agent-kernel` 出现本项目之外的第二个消费者 → 抽离独立仓库并冻结扩展 API。
- 前端五层在首个特性落地后被证明样板代码显著超过收益 → 重访层的物理粒度。
- Worker 任务增长到需要任务路由、优先级或正式任务框架 → 独立评估，不默认引入。

重访以变更耦合、越权测试和维护成本为证据，不以旧目录先存在为理由。

## 已知偏差与证据边界

- 仓库根目前没有新设计的实现；旧实现（含 `profiles.caregiver_id`、`/api/v1`、应急行为桶与四层档案）已整体移入 `archive/`，仅作参考。
- `py-config`、`py-health` 与工程支撑层在归档中有对应资产但归属旧结构；新归属由本文定义，尚未落地。
- 真实数据量、供应商条款、专业审阅资源与合法关系核验渠道仍为 `missing evidence`，登记于[设计待办](../TODO.md)；这些缺口不因结构文档完稿而关闭。
