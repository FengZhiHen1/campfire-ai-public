# 技术栈设计

> **权威范围**：目标技术选型、版本基线、部署与兼容约束以及选型理由。模块位置由项目结构设计拥有；业务行为由需求拥有；运行机制由目标机制文档拥有。
> **状态**：2026-09-26 用户授权自主收敛的 v3.0 目标技术基线。以下是待实施设计，不宣称现有代码、部署或供应商已满足。

## 1. 选型边界与现状证据

目标优先复用已在仓库的技术而不是为新概念引入服务。已读取根 `pyproject.toml`、前后端应用包清单、`docker-compose.yml` 与 `docker-compose.prod.yml`：现有 Python 工作空间包含 `py-agent-kernel`、`py-agent-extensions` 和待退役的 `py-llm`；Web 使用 React、Vite 和 Zustand；生产部署是单机 Compose。现有档案 ORM 仍由 `caregiver_id` 归属、要求出生日期和行为类别，说明迁移未实施。运行中数据量、真实供应商合同、线上可用性和审阅资源均为 `missing evidence`，不得由代码形态推断。

选型须满足 `RQ-SP-02～04`、`RQ-CTX-01～06`、`RQ-NOW-01～02`、`RQ-OPS-03～05`：权限在业务事务内验证，AI 无权扩大视角，公开基础安全内容不依赖模型，真实个人资料的外部处理以可核实的供应商条款为前提。

## 2. 项目级技术选型

| 职责 | 目标选择与版本基线 | 取舍及重访条件 |
|---|---|---|
| 后端运行 | Python ≥3.12、FastAPI 与 Pydantic 2，uv 工作空间；具体解析版本由 `uv.lock` 锁定 | 保留现有异步接口与验证生态；只有安全维护或性能证据要求时升级主版本 |
| Web | React 19、TypeScript ~6.0、Vite 8、React Router 7、Zustand 5；pnpm 工作空间 | 当前唯一活跃客户端；不为尚未启动的小程序并行维护第二套新页面 |
| 主数据与检索 | PostgreSQL 17、pgvector；SQLAlchemy 2 与 Alembic | 授权、记录、计划及审计的事务边界留在关系库；公开已审核资料才进入向量索引，个人空间不作公共向量化 |
| 临时协调 | Redis 7 | 用于限流、短暂会话协调与异步任务；不作为授权真相或唯一持久记录，丢失不应恢复已撤销访问 |
| 附件 | 现有 MinIO S3 兼容服务 | 首期纯文本事项不依赖上传；开放附件前增加文件扫描、访问时效与删除验证，不增新存储系统 |
| 生成与结构化处理 | 已依赖的 Pydantic AI 2.x 和现有 `py-agent-kernel`，只用于受控任务；模型经可替换适配端口调用 | AI 整理、解释和演练不得决定权限、发布、撤销或危险处置；内核和扩展不能代替代码层强制校验 |
| 知识嵌入 | 现有 `py-rag` 与已配置的嵌入服务，仅处理获授权且已审阅的供给资料 | 向量索引可重建，撤下须先同步禁止使用再异步重建；供应商若不能满足资料条款则停止真实数据处理 |
| 队列与部署 | 独立 Worker、Docker Compose v2、Nginx；单机先行 | 只让可重试的索引/通知/整理任务异步化；授权变更与条目停用在主请求事务内完成。未经恢复演练不声明单机 SLA 达标 |

不新增独立向量库、Kubernetes、通用工作流引擎、消息总线或新的前端状态库。`py-llm` 目前仍在根依赖与 API 依赖清单中，目标不再新增调用；退役必须在迁移阶段先核查实际使用并运行回归，不在文档阶段删除依赖。精确供应商模型名称及价格以部署时验证的配置为准，旧文档中的模型代号不是可用性证据。

## 3. 执行与安全边界

- 公开基础安全内容经批准后由 Web/Nginx 与 API 可独立提供；模型、Redis 或个人数据库异常不应造成错误的个人建议。离线仅保证已取得的公开内容，不缓存个人计划作为“最新”。
- 登录身份可以沿用现有身份—凭证分离和短期访问凭证；空间范围、数据操作、期限、当前暂停状态都须在服务端按请求重新查证。JWT 声明或 Redis 缓存不能单独放行个人内容；数据库或授权检查不可用时拒绝受限操作。
- 与外部模型的连接须明确区域、用途、日志、二次训练、留存和删除条款。未取得可核验的适用约束时，只运行虚构或经核准不可识别的内部样例；不能靠提示词承诺供应商不留存。
- Web 与服务端之间使用 TLS，生产密钥经环境/密钥管理注入，不放入文档或版本库。运营与维护身份不能因有数据库运维权限就获得产品内的个人空间业务访问；备份恢复及密钥轮换需演练。
- 健康检查分别报告“公开内容可达”“数据库授权可用”“模型可用”“异步索引滞后”；任何监测信号须用人为制造故障证明能告警，不能用一个 `/health` 全绿表示所有能力安全。

## 4. 迁移与发布依赖

前端仍以 Web 承载真实试点，小程序保持冻结。旧应急问答、四层档案与 Agent 扩展可作为现状材料，但目标行为以新需求与目标机制为准。现网是否有真实用户、档案或文件尚未核实：在迁移前必须导出只读清点、验证备份可恢复、形成映射与回退步骤，不得引用旧 ADR 的“无真实用户数据”假设直接删表或改权限。

发布之前需要实际供应商合同、专业审阅供给、合法关系核验者及安全测评结果；这些是外部证据闸门，不由技术选型自动满足。若某一环节缺失，对应能力不开，而不是改用宽松的鉴权或未经审阅的生成内容。
