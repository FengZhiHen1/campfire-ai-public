# 通用基座

> **权威范围**：基座的产品无关职责与机制——运行与会话、开放标准 skill 机制的落地、上下文装配端口、工具池与权限、模型路由、流式事件、可观测钩子及其失败语义。skill 内容由各 `SKILL.md` 拥有；工具实现由产品侧拥有；模块边界由[项目结构设计](../../项目结构设计.md)拥有；技术选型由[技术栈设计](../../技术栈设计.md)拥有。
> **状态**：2026-09-29 依用户确认的项目结构设计与开放标准设计，待用户确认。不代表已实现。
> **追溯**：`RQ-CON-01`、`RQ-CON-02`、`RQ-CON-03`、`RQ-CON-06`、`RQ-EMG-02`、`RQ-EMG-03`、`RQ-LIM-04`、`AC-11`、`AC-12`、`AC-13`、`AC-18`。
> **标准与实现依据**：Agent Skills 开放标准（frontmatter 六字段、渐进披露三层、`skills-ref validate`）、Claude 平台与 Claude Code 的 skill 文档（作为实现参照）、OpenAI Agents SDK 官方文档（其 `skills` 仅存在于 sandbox capabilities）。

## 1. 定位与边界

一句话判定标准：**基座知道自己如何运行，不知道自己被用在哪件事上。**

| 基座拥有 | 基座不含 |
|---|---|
| 运行 loop、会话与运行状态 | 任何领域术语（咨询、档案、案例、支持对象…） |
| skill 机制：发现、元数据装载、激活、主体与资源按需加载、校验 | skill 内容本身 |
| 上下文装配端口与预算 | 记忆、档案、检索的语义与生命周期 |
| 工具池与权限系统 | 工具的具体实现 |
| 模型网关与路由 | 面向用户的输出结构与呈现 |
| 流式事件与可观测钩子 | 业务授权判定 |

不变量：基座不得 import 业务模块；出现领域术语即位置错误；基座不自行判定业务授权，也不自行发明事实。

## 2. 运行模型

一次**运行**（run）的生命周期：

```text
created → assembling → running → succeeded | failed | cancelled
```

| 阶段 | 基座做什么 | 谁决定 |
|---|---|---|
| 入口 | 接收运行请求：会话标识或一次性、上下文提供者集合、**初始激活的 skill 集合及其来源**、面提前代跑得到的上下文块（可空） | 面 |
| 装配 | 调用各上下文提供者，按优先级与预算装配，标注来源 | 面提供提供者，基座决定装配顺序 |
| 运行 | 模型调用 → 工具调用 → 回填，循环至结束或触顶 | 基座 |
| 输出 | 流式事件序列（见第 7 节） | 基座 |
| 结束 | 把本次可沉淀物交给面（**基座不写业务数据**） | 面 |

**上限**：步数、token、墙钟时间三重上限，超限以明确原因结束（第 9 节）。一期上限的具体数值**待确认**。

## 3. skill 机制的落地

| 环节 | 行为 |
|---|---|
| 发现 | 扫描配置根目录下的 `*/SKILL.md`；解析 frontmatter；**不合法即拒绝加载并在启动时失败**，不得以空元数据静默加载 |
| 元数据装载 | `name` 与 `description` 常驻系统提示；`metadata` 中的自有字段由基座读取但不送入模型。本项目约定两个自有键：`autoload`（是否允许模型自动匹配）与 `surface`（所属面，供元数据预算分组用） |
| 激活 | **激活 = 在一次对话中选定某个 skill**；选定后该 skill 的工具在此对话内可用，选择在**下一条消息**生效。来源有三种、语义相同：使用者在输入框上方的技能选择器中选定、程序注入（应急卡片构造第一条消息时注入）、模型按 `description` 自动匹配。运行上下文维护**激活集合**，一次对话可先后激活多个；同时激活的数量上限**待确认** |
| 加载 | 激活时把 `SKILL.md` 主体渲染为一条消息进入上下文；同一次运行内重复激活同一 skill 不重复注入 |
| 资源 | `references/`、`assets/` 按需读取；相对路径、一层深，不做多级引用链 |
| 校验 | `skills-ref validate` 纳入工程检查 |

**一期不做**：skill 的安装、市场与运行时下发（skills 随应用发布）；`scripts/` 执行（保留运行器端口，见第 10 节）。

**上下文预算**：元数据列表受预算约束。一期 skill 数量小、全量装载；预算阈值与"仅名称加载"策略**待确认**。

## 4. 上下文装配端口

```text
ContextProvider:
    name: str
    async gather(request) -> list[ContextBlock]

ContextBlock:
    source_kind     # session | memory | profile | library | cases
    source_id       # 业务侧可解析的标识
    title
    content
    token_estimate
    priority
    provenance      # 谁在什么时间产生
```

- 基座只负责：按优先级与预算装配、去重、保留 `provenance`、把可引用块登记为引用候选。
- 面负责：提供哪些 provider、如何取数。
- 面可**提前代跑工具**并把结果作为上下文块注入（应急用它压缩首字时间）；这些块同样必须带 `provenance`。
- **不变量**：没有 `provenance` 的块不得成为"可引用依据"；装配失败必须显式标注该来源不可用，不得静默当作没有该信息。

## 5. 工具池与权限

工具注册形状：

```text
ToolSpec:
    name
    description
    parameters      # JSON Schema
    handler         # 由产品侧注册
    risk            # low | medium | high（一期全为 low）
    requires_approval: bool
```

- **权限在执行前校验**，不靠隐藏 schema；工具不可见不是安全边界。
- skill 的 `allowed-tools` 是**预授权**，交宿主权限规则匹配；它不限制工具池本身。
- 一期没有高风险动作，因此不实现人工审批流程（HITL 延后，见第 10 节）。
- 失败语义：工具自身错误作为结果回给模型（可恢复）；权限拒绝返回明确错误码，**不静默降级为其他工具**。

### 工具范围随激活集合变化

- 运行上下文维护**激活集合**；工具的 `is_enabled` 读取它，决定该工具此刻是否对模型可见与可派发。
- **不变量**：激活前不注入也不派发该 skill 的工具；未激活任何 skill 时只有面配置的默认工具集（一期只含只读类）。
- **省 token 的可选手段**：`@tool(defer_loading=True)` 与 `tool_namespace(...)` 配一个 `ToolSearchTool()`。**这条依赖 OpenAI 的 Responses 语义**，而本项目模型是 TokenHub 上 OpenAI 兼容端点里的 DeepSeek-V4.1-Flash，是否支持**待核实**（`TECH-09`）；不支持时退化为仅用 `is_enabled` 过滤。
- 与开放标准的对应：skill 的 `allowed-tools` 既作为本次激活的工具集合来源，又保留其"预授权"语义。标准只定义后者，本条属**超集用法**。
- **暴露范围不是安全边界**：SDK 文档原文即为此——`is_enabled` controls visibility and dispatch; it does not replace authorization。服务端仍按请求与参数校验权限。

## 6. 模型路由

- 统一配置入口，**业务代码不得硬编码模型名**；接口保留用途分档（一期只有一个值）。
- 失败语义：超时、限流与供应商错误按策略重试；重试耗尽则本次运行失败并给出原因。**不得**用缓存或旧结果冒充当前结果。

## 7. 流式事件

事件类型（一期经 SSE 传输，名称与语义对齐 AG-UI 以便升级）：

| 事件 | 含义 |
|---|---|
| `run_started` | 运行开始，含本次激活的 skill 与装配的来源清单 |
| `text_delta` | 文本增量 |
| `progress` | 进度提示（用于长等待，例如检索中） |
| `tool_call_started` / `tool_call_finished` | 工具调用与其结果摘要 |
| `citation` | 一条可引用依据（对应 `ContextBlock`） |
| `candidate` | 档案候选条目（未确认，供面呈现为"待确认"） |
| `run_finished` | 正常结束，含结束原因与引用清单 |
| `run_failed` | 异常结束，含错误码 |

## 8. 可观测与评测钩子

- 每次运行记录：模型、token、时延、激活的 skill、装配的上下文块来源与数量、工具调用、引用、错误、结束原因。
- **触发准确性与输出质量分开测**（标准建议）：前者用"应为/不应为触发"的提示集测触发率，后者用对齐 `AC-11` 的独立评价判定。

## 9. 失败语义与不变量

| 情形 | 处置 |
|---|---|
| 上下文提供者失败 | 标注该来源不可用并继续；不得假装已获取 |
| skill frontmatter 不合法 | 拒绝加载并在启动/校验时报错；不得静默加载 |
| 工具失败 | 作为结果回给模型；重试耗尽则以明确失败结束本次运行 |
| 模型不可用 | 本次运行失败并给出原因；不返回缓存内容冒充当前结果 |
| 触顶（步数/token/时间） | 以明确原因结束，保留已产生的引用 |
| 运行被取消 | 立即停止调用；业务侧的幂等由面与待处理记录承担 |

## 10. 扩展缝

| 缝 | 一期状态 | 启用条件 |
|---|---|---|
| 脚本运行器 `ScriptRunner`（`scripts/`） | 不实现，仅保留端口 | 出现必须自带脚本的 skill，且有受限执行环境 |
| 人工审批（HITL） | 不实现 | 出现 medium/high 风险工具 |
| 子代理与并行研究 | 不实现 | 出现上下文隔离或并行调研的真实需求 |
| 按面分组或按需筛选的 skill 装载 | 不实现 | 元数据列表触及上下文预算 |
| AG-UI 传输 | 不实现 | 需要结构化状态同步时 |

## 11. 验证方式

- **标准一致性**：`skills-ref validate` 通过；非法 frontmatter 有拒绝加载的测试用例。
- **触发准确性**：每个 skill 准备"应为触发"与"不应为触发"的提示集，分别测触发率。
- **装配与引用**：缺来源时输出明确标注；每条引用可回指到 `source_id`。
- **失败注入**：制造提供者失败、模型失败、工具失败、触顶与取消，验证事件与降级信号真的出现（"坏了没人知道"的机制必须反向验证）。

## 12. 不在本文范围

- 各 skill 的内容与其 `references/` 组织。
- 工具的具体实现与检索策略。
- 业务授权判定。
- 档案与记忆的数据形状。
