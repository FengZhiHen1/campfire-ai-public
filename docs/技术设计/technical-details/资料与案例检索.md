# 资料与案例的检索

> **权威范围**：专业资料库与案例库的检索机制——两路检索与合并、返回契约、来源与状态如何随结果传递、撤下如何传播到检索与引用、以及失败语义。**内部机制与参数**（语料与分块、嵌入与向量列、索引条件、候选数、注入预算、评测）见 [RAG 策略](RAG策略.md)。存储选型由[技术栈设计](../../技术栈设计.md)拥有；`search_knowledge` 与 `search_cases` 的用途与工具范围由[技能设计](技能设计.md)拥有；录入与审阅流程不在本文（`RQ-KB-03` 已定一期手动导入）。
> **状态**：2026-09-29 依已确认的需求与技术选型设计，待用户确认。不代表已实现。
> **追溯**：`RQ-KB-01`、`RQ-KB-02`、`RQ-KB-04`、`RQ-CON-02`、`RQ-CON-03`、`AC-05`、`AC-06`、`AC-09`。
> **依据**：pgvector 与 pg_trgm 的官方文档；技术栈设计的 `TECH-01`（官方镜像内 `pg_trgm` 的启用方式与中文三元组行为**待核实**）。

## 1. 两库的边界

- 专业资料库（研究、指南、机构材料）与案例库是**两个独立集合**，各自带来源与状态；不合并成一张表加类型标签（`RQ-KB-01`）。
- 每个条目必须有：来源、适用范围、状态（`published` / `internal` / `fictional`）、版本与撤下标记（`RQ-KB-02`）。
- **不变量**：缺少来源或状态的条目不进入检索结果，**不补默认值**。

## 2. 两路检索与合并

```text
query ──┬─→ 向量检索（pgvector，语义）
        └─→ 字面检索（pg_trgm，三元组相似）
                    │
              合并与去重 → TopK → 返回
```

- **向量路**取语义候选；**字面路**取字面候选，覆盖人名、机构名、缩写与专有名词——这些恰是纯向量检索最容易漏的。
- **合并规则**：按条目 id 去重；两路都命中的条目上提；各路内部顺序保留。一期用「路内排名 + 命中路数」排序，**不做跨路分数的加权归一化**——那会引入无法解释、也无法调试的魔数。
- 每路候选数与最终 TopK **待确认**。
- **字面路的中文约束**（已核实）：① 需要 **≥3 个连续汉字**才有可用三元组，**1–2 字的查询不走字面路**（只用于元数据过滤），否则退化为顺序扫描；② 中文**必须用 `LIKE`/`ILIKE '%中文%'`**，`~`/`~*` 不走索引；③ 部署 locale **不得为 `C`**（`C` 下汉字被全部丢弃、相似度恒为 0；默认 locale 下是否可用仍需实测，见 `TECH-01`）。

## 3. 返回契约

```text
KnowledgeResult:
    item_id
    library          # knowledge | case
    title
    snippet          # 用于注入上下文
    source           # 出处：机构、年份、链接或文件引用
    applicable_scope # 适用人群与情境
    status           # published | internal | fictional
    locator          # 页码或章节，用于引用
    ranking          # 路内排名与命中路数，供排序与调试
```

- 结果**必须**带回 `source` 与 `applicable_scope`，因为 `RQ-CON-03` 要求输出能说明适用条件与局限。
- 案例结果另带 `authorization`（授权状态），因为 `RQ-KB-02` 要求真实案例与虚构样例在列表中可辨。

## 4. 撤下如何传播

- 撤下 = 在条目上打 `withdrawn` 并记录时间与原因（`RQ-KB-04`）。
- **检索在查询时过滤 `withdrawn`**，不依赖索引清理完成：因此"撤下即刻不可检索"与向量索引重建的滞后解耦。
- 已经产生的引用：历史对话中的引用保留，但呈现时标注"该来源已撤下"，**不得再作为当前依据**分发。

## 5. 失败语义

| 情形 | 处置 |
|---|---|
| 向量路失败 | 只用字面路返回，并在结果中标注"语义检索不可用" |
| 字面路失败 | 只用向量路返回，并同样标注 |
| 两路都失败 | 工具返回明确失败；**模型不得据此声称"没有相关资料"** |
| 检索为空 | 返回空并明确"未找到"；**不得**解释为"该做法不存在或没有风险" |
| 条目缺来源或状态 | 该条目不进入结果 |

## 6. 与工具的关系

`search_knowledge` 只查资料库，`search_cases` 只查案例库；两者的参数与返回形状一致，差别只在 `library` 与状态字段。两个工具都是只读，服务端仍按请求校验权限。

## 7. 验证方式

- **撤下生效**：撤下一条资料后检索不再返回；历史引用被标注（`AC-09`）。
- **有据可核对**：输出的可执行建议能指到具体条目，且条目带来源与适用范围（`AC-05`）。
- **虚构与真实可辨**（`AC-06`）。
- **中文检索**：用一组查询验证上面的约束真的成立——含 ≥3 字的中文词、机构名与缩写走字面路；1–2 字的短词确认其走向量路而非字面路；并在容器内实测默认 locale 下汉字是否被认作词字符（`TECH-01`）。
