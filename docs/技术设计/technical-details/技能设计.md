# 技能设计（一期）

> **权威范围**：一期有哪些 skill、每个 skill 的契约（`name`、`description`、激活来源、工具范围、`references/` 的组织与内容边界、输入输出纪律），以及共用纪律的一致性维护方式。skill 机制由[通用基座](通用基座.md)拥有；工具实现与检索策略由产品侧拥有；档案的数据形状由[个性化档案](个性化档案.md)拥有。
> **状态**：2026-09-29 依用户确认的划分与激活语义设计，待用户确认。不代表已实现。
> **追溯**：`RQ-CON-01`～`RQ-CON-04`、`RQ-CON-06`、`RQ-CON-08`、`RQ-EMG-01`～`RQ-EMG-03`、`RQ-DAY-01`、`RQ-MEM-02`、`RQ-MEM-04`、`AC-11`、`AC-12`、`AC-13`、`AC-18`、`AC-19`。
> **标准依据**：Agent Skills 开放标准——`name` 须与目录名一致且仅小写字母、数字与连字符；`description` 是选择键；主体建议不超过 500 行；`references/` 一层深；**每个 skill 是自包含目录，且标准不支持 skill 之间互相依赖**。

## 1. 一期的三个 skill

| `name`（目录名） | 激活来源 | 方法论要点 | 工具范围 | `references/` |
|---|---|---|---|---|
| `emergency-consulting` | 程序注入（应急卡片构造的第一条消息） | 现场、少追问、快；不生成危机处置步骤；把未知显式保留 | 只读：档案摘要、资料、案例 | `triage.md`、`unknown-and-referral.md` |
| `daily-consulting` | 模型按 `description` 匹配；使用者也可在选择器中选定 | 多轮渐进澄清；准备与理解；依据与适用条件并给 | 只读：档案摘要、档案条目、资料、案例 | `clarification.md`、`evidence-and-options.md` |
| `profile-curation` | 模型在对话中激活；使用者也可在选择器中选定 | 从对话中提炼候选；标注来源、生成方式与时间；**只写候选层** | 读档案条目 + 写候选与记忆 | `extraction-rules.md`、`source-and-status.md` |

**三条共同纪律**（三份 `SKILL.md` 都必须含）：

1. 有据才给可执行建议；依据不足、资料冲突或超出能力时明确限制，并给出真实求助路径（`RQ-CON-02`）。
2. 目标不等于服从：不把"让他听话、安静、别丢脸"转成控制当事人的建议（`RQ-CON-04`）。
3. 专业判断与可读解释并给：涉及专业概念时在当次输出内解释到不需要专业背景即可理解（`RQ-CON-06`）。

另有一条只在咨询类 skill 出现的纪律：**只把注入的稳定层内容当事实**，候选层内容只能以"待确认"呈现（`RQ-MEM-04`）。

## 2. 共用纪律的一致性维护

标准不支持 skill 间依赖，且每个 skill 必须自包含，所以共用段落必然有多份拷贝。用标记块 + 工程检查防漂移：

```text
<!-- shared:evidence-discipline -->
…共用纪律正文…
<!-- /shared:evidence-discipline -->
```

检查规则：**同名标记块在全部 skill 中必须逐字一致**；不一致即工程检查失败。标记块之外的正文各自不同。

## 3. 各 skill 的契约

### 3.1 `emergency-consulting`

- **`description` 草稿**：现场情境下的应急咨询。当使用者描述正在发生或刚刚发生的困难、需要在短时间内决定怎么办时使用；用已注入的档案与已审阅资料给出可行动结果与真实求助路径，并把无法确认的部分标为未知。
- **主体大纲**：适用与不适用 → 第一条消息里有什么（卡片构造）→ 分诊顺序 → 追问纪律 → 输出结构 → 禁止事项。
- **追问纪律**：只问会改变结论的项，一键选择、可跳过；**不为补全档案而追问**（`RQ-EMG-02`）。判据清单放在 `references/triage.md`，由具名清单定义而非模型临时决定。
- **输出结构**：可行动结果 → 依据与引用 → 显式未知 → 求助路径。
- **禁止**：生成危机处置步骤（调研 §16.1 那类内容只能来自使用者陈述或已确认内容）；做诊断、用药或身体控制的判断；因风险而停止一切帮助。
- **工具范围**：`read_profile_summary`、`search_knowledge`、`search_cases`。**不含写入工具**——现场路径保持只读、无副作用。

### 3.2 `daily-consulting`

- **`description` 草稿**：日常咨询。当使用者想为一件还没发生的事做准备、想理解一个反复出现的情况、或想梳理刚发生的事时使用；通过多轮对话逐步澄清，结合已审阅资料与案例给出带依据的理解与可选方向，并标明适用条件与未知。
- **主体大纲**：适用与不适用 → 澄清顺序与停止条件 → 依据与引用的纪律 → 输出结构 → 禁止事项。
- **停问条件**：追问必须服务于改变下一步行动；简单问题允许直接回答并结束。
- **输出结构**：对情境的理解（区分已知与未知）→ 可选方向与各自的适用条件 → 依据与引用 → 求助路径。
- **禁止**：把一次观察写成长期特征；把案例成功等同于对当前个体有效；越过专业服务边界。
- **工具范围**：`read_profile_summary`、`read_profile_items`、`search_knowledge`、`search_cases`（全为只读）。

### 3.3 `profile-curation`

- **`description` 草稿**：从当前对话中提炼关于支持对象的候选档案条目与通用记忆，标注来源、生成方式与时间并写入候选层；由系统在对话中激活，不直接面向使用者作答。
- **`metadata`**：`autoload: "true"`、`surface: "consult"`。
- **主体大纲**：何谓值得沉淀 → 三分（使用者陈述 / 他人观察 / 系统推断）→ 来源与时间标注 → 禁止事项。
- **禁止**：确认自己的推断；把推断写入稳定层；把一次观察写成特征；为凑满档案而制造条目。
- **工具范围**：`read_profile_items`、`propose_profile_item`、`read_memory`、`write_memory`。
- **硬约束在工具实现层，不靠提示词**：`propose_profile_item` 必须拒绝 `origin` 属于 `system_observation` 或 `ai_inference` 且 `confirmation = confirmed` 的输入；写入一律先落待处理记录（与业务数据同事务），重活由 Worker 完成。

## 4. 一期工具清单

| 工具 | 读写 | 归属模块 | 说明 | 使用它的 skill |
|---|---|---|---|---|
| `read_profile_summary` | 读 | `profile` | 取一页摘要；只含稳定层 | 应急、日常 |
| `read_profile_items` | 读 | `profile` | 按领域或情境取条目；可含候选层，但必须带 `confirmation` 标记 | 日常、沉淀 |
| `propose_profile_item` | 写 | `profile` | 写使用者陈述或候选条目；只写待处理记录 | 沉淀 |
| `read_memory` | 读 | `memory` | 按情境取通用记忆，含时间与失效状态 | 沉淀 |
| `write_memory` | 写 | `memory` | 写通用记忆；只写待处理记录 | 沉淀 |
| `search_knowledge` | 读 | `library` | 检索专业资料，返回来源与适用范围 | 应急、日常 |
| `search_cases` | 读 | `library` | 检索案例，返回来源与授权状态 | 应急、日常 |

**未激活任何 skill 时的默认工具集**：一期只含 `read_profile_summary` 与 `search_knowledge`（只读）。

## 5. 激活与工具范围的关系

- 激活集合决定工具可见性；`allowed-tools` 是这套关系的声明处（基座第 5 节）。
- 应急卡片构造的第一条消息**就是**一次程序注入的激活；它只带来只读工具。
- 一次对话可先后激活多个 skill：例如现场问答结束后，模型激活 `profile-curation` 把这次对话沉淀为候选。同时激活的数量上限**待确认**。
- **暴露范围不是安全边界**：服务端仍按请求与参数校验权限。

## 6. 验证方式

- **标准校验**：三个 skill 均通过 `skills-ref validate`。
- **一致性检查**：同名共用标记块逐字一致。
- **触发准确性**：`daily-consulting` 与 `profile-curation` 各准备"应为触发"与"不应为触发"的提示集；应急验证"注入即激活"。
- **工具范围**：断言 `emergency-consulting` 激活时写入工具不可调用（服务端拒绝）；`profile-curation` 无法把推断写成已确认。

## 7. 不在本文范围

- 工具的实现与检索策略（两路检索、来源与状态标注、撤下传播）。
- 档案的数据形状与摘要取数。
- 基座的运行机制、上下文装配与事件。
- 面向用户的输出结构与页面呈现。
