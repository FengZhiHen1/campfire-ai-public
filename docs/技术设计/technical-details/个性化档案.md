## 1. 目标与边界

档案是**关于某个支持对象**的可追溯认识，用于让咨询结果适配这个具体的人。它不承载关于使用者自身的长期偏好（那属于通用记忆），也不承载会话工作状态。

档案描述的是一个**人**，不是一个病例：以本人为中心而不是以诊断为中心，**优势与需求并列**，记录可观察事实而不是宽泛标签，并且**每个重要条目都要回答"因此别人应该怎么做"**——只记录困难、不记录支持方式的条目实际价值低。

明确不做的事：

- 不从诊断推断需求，不把诊断当能力（智力功能与实际适应功能可能明显不同）。
- 不使用严重度打分或等级（如"社交 2/5、沟通 3/5"）——信息密度低，且无法指导行动。
- **不由 AI 生成危机处置步骤**；安全与风险领域只记录使用者陈述或已确认的事实。
- **不把一切行为解释成孤独症**：疼痛、睡眠不足、胃肠问题、焦虑、环境噪音、药物、人际冲突都可能是原因，在它们尚未排除时不得归因为孤独症特质。
- **条目不存在不得被解释为"该情况不存在"**，也不得据此补全为事实。
- **不永久化过时信息**：能力、支持需求、环境与策略都会变化，故一切条目带时间与失效判定（第 3 节）。

## 2. 数据形状

```text
profile_item
├── item_id              条目标识
├── support_object_id    归属支持对象（一期：只有创建者账号可读写）
├── domain               领域取值，见第 6 节（十四个一级模块之一）
├── topic                该领域下的具体特征或主题（自由文本）
├── description          可观察、可执行的描述
├── contexts[]           情境：拥挤室内、医院候诊、放学时段…
├── manifestations[]     表现：捂耳、停止回应提问、离开环境…
├── person_report        本人怎么说（一期只能由监护人转述，须标注转述者）
├── probable_need        可能的需求
├── helpful_support[]    有效支持
├── unhelpful_support[]  无效支持
├── origin               生成方式，见下表
├── source               来源定位：会话 id、消息定位、工具名、时间；转述者记于此
├── confirmation         unconfirmed / confirmed / rejected
├── freshness            current / historical / stale
├── first_recorded_at
├── last_confirmed_at
├── superseded_by        被取代时指向新条目；旧条目不删除
└── pending_id           产生本条目的待处理记录，幂等键（第 7 节）
```

四个字段分工，不合并成一个枚举：

| 字段 | 取值 | 回答的问题 |
|---|---|---|
| `origin` | `user_statement`、`guardian_observation`、`third_party_report`、`document`、`system_observation`、`ai_inference` | 谁在什么位置上说的（生成方式） |
| `source` | 会话 id、消息定位、工具名、时间、转述者 | 这句话在何处可复核 |
| `confirmation` | `unconfirmed`、`confirmed`、`rejected` | 是否被使用者确认过 |
| `freshness` | `current`、`historical`、`stale` | 是否仍是当前认识 |

`origin` 与 `source` 不可互相代替：`origin` 是**生成方式**（`RQ-MEM-02` 的"生成方式"），`source` 是**来源定位**（同条的"来源"）；`AC-07` 要求的"来源、生成方式与时间"由这三个字段共同承载。

**"本人自述（经监护人转述）"的承载方式**（`RQ-MEM-05`）：`origin = user_statement` 表示所记录的是**本人的表达**，"经监护人转述"这一事实记在 `source.relayed_by`。不为此增设第七个 `origin` 取值——转述是一条来源定位，不是一个不同的生成方式。

`rejected` 的语义：使用者明确否定该条目。**不物理删除**（"使用者否定过这件事"本身是可追溯事实），但此后不进入一页摘要、不参与注入、**不得再次作为候选提出**——除非使用者本人重新提起。这条堵住"被否定的推断反复回来"。

`confidence` 元字段**一期不取**：档案存的是"谁在何时说的"，其可信程度由 `origin` 与 `confirmation` 表达；对事实本身打置信分与第 1 节拒绝的严重度分级同源。应急输出中的置信等级（`confirmed / likely / possible / unknown`）是**当次推断**的标注，不是条目字段。

## 3. 稳定层与候选层

档案的演进是五级：原始事件 → 观察 → 候选条目 → 使用者确认 → 稳定档案。分级的意义是**避免错误长期固化**——推断不得自动升级为事实。

**落层判定（唯一判据）**：`freshness = current` 且（`origin` ∈ {`user_statement`、`guardian_observation`、`third_party_report`、`document`} 或 `confirmation = confirmed`）。

| 来源 | 落层 | 入档时的 `confirmation` | 理由 |
|---|---|---|---|
| `user_statement` | **直接稳定层** | `confirmed` | 一期使用者即陈述人，陈述本身即确认，无需第二次确认（`RQ-MEM-02`"直接陈述零确认入档"） |
| `guardian_observation` | **直接稳定层** | `confirmed` | 一期使用者即监护人，其观察是本人的观察 |
| `third_party_report`、`document` | **直接稳定层** | `unconfirmed` | 明确提供的信息，但未经使用者本人确认 |
| `system_observation`、`ai_inference` | **候选层** | `unconfirmed` | 系统观察与归纳，未经确认不得作为稳定事实 |

其余条目（`freshness = historical` 或 `stale`）不参与稳定层取数。

不变量：

1. 候选层内容**不得**进入一页摘要，**不得**在咨询输出中被当作既成事实，只能以"待确认"呈现（`RQ-MEM-04`）。
2. 稳定层条目必须可追溯到来源与时间。
3. 纠正以"新增条目 + 旧条目转 `historical` 并互指"表达，不物理覆盖，也不静默改写。

**单次观察即可成为候选条目**：`system_observation` 与 `ai_inference` 提出一条就是一条候选，**不设重复阈值**。此前设计稿要求"同一主题在 ≥2 次不同对话中出现才可归纳"，该阈值约束的是**跨对话的模式归纳**——模式归纳一期不做（扩展缝见第 12 节），故阈值一期无适用对象。

**降权时限**：长期未确认的候选条目 **90 天**未再出现即降权——不再进入一页摘要与默认读取，但**不删除**（`freshness` 转 `stale`；被检索到时须标注其陈旧）。90 天够长到不误伤低频但真实的观察，够短到不让陈旧推断污染输出。

## 4. 一页摘要

供咨询注入快速读取的当前认识，取数限定在**稳定层**，目标是让第一次接触本人者能在 **30–60 秒**内掌握最关键的信息。

十二个字段，各自的取数领域如下：

| 摘要字段 | 取数领域（第 6 节） |
|---|---|
| About Me（我是什么样的人） | 关于本人、优势、兴趣与目标 |
| How I Communicate | 沟通 |
| What Is Important to Me | 关于本人、优势、兴趣与目标 |
| My Strengths | 关于本人、优势、兴趣与目标 |
| My Sensory Needs | 感觉处理 |
| Things That May Distress Me | 触发因素与支持策略 |
| How You Can Help | 触发因素与支持策略 |
| Please Do | 触发因素与支持策略 |
| Please Don't | 触发因素与支持策略 |
| How I Show Pain or Distress | 感觉处理 |
| Important People | 关于本人、优势、兴趣与目标 |
| Critical Health / Safety Information | 身体与医疗、风险与危机 |

- 摘要由系统维护，但**只从稳定层取数**，每条可追溯到具体条目。
- 摘要中的每条带来源与 `last_confirmed_at`；`stale` 条目在摘要与注入中降权并标注时效。
- 摘要不新增事实：它只选编与压缩，不产生稳定层之外的内容。
- 十二个字段**全部有对应领域**——这是第 6 节领域取值覆盖性的判据：摘要字段与应急预取的稳定信息都必须能从该枚举生产出来。

## 5. 完整与纠错规则

1. 咨询中的追问只由"会改变当前结论"触发（`RQ-EMG-02`）；**不为补全档案而追问**，追问所得答案顺带沉淀。
2. 使用者可在档案页补充、纠正、删除条目；删除须覆盖该内容在检索与衍生中的使用（`RQ-MEM-03`）。
3. 系统可提示缺项，但提示必须与当前情境相关且不阻塞当次结果。
4. 长期未确认的条目降权并标注时效，**不自动删除**。
5. 纠正即"新增取代条目"：新条目承载新认识，旧条目转 `historical`，两者互指（`superseded_by`）；旧条目此后不参与注入，但可回看。
6. 使用者否定一条候选（`rejected`）后，该内容不得再次作为候选提出（第 2 节）。

### 6.1 三个需要固定结构的子形状

多数领域的条目是"主题 + 描述 + 情境 + 表现 + 支持"，无需额外结构。以下三处内部结构固定，因为闸门与注入直接依赖它们：

**状态相关变化（沟通领域）**——同一人在不同状态下沟通能力不同，必须成对记录：

| 状态 | 沟通能力（示例形状） |
|---|---|
| 平静 | 可正常对话 |
| 中度焦虑 | 回答明显变短 |
| 高度压力 | 更适合文字 |
| 过载 | 可能暂时无法口语沟通 |

**功能分析链（触发因素与支持策略领域）**——不得只记录"会摔东西"：

```text
触发（前因） → 内部状态 → 行为 → 可能功能／需求 → 有效支持 → 恢复
```

示例：原定计划突然改变 → 反复确认原计划、语速加快 → 拒绝继续活动、可能提高音量 → 重新获得清晰可预测的安排 → 提供新时间表、简短明确语言、减少追问、允许暂时离开 → 通常需 20–30 分钟低刺激环境。

**危机计划（风险与危机领域）**——按固定顺序组织，与应急 skill 的六层闸门同向：

```text
可能触发因素 → 早期预警信号 → 升级过程 → 应立即采取的措施
→ 绝对不要做的事情 → 需要联系谁 → 何时需要专业医疗或急救
```

### 6.2 协助等级（日常生活与适应功能领域）

每项日常能力按六级取值记录，并要求补充情境描述——只写等级不写情境无法指导支持：

```text
独立完成 / 需要提醒 / 需要部分协助 / 需要持续协助 / 目前不适用
```

### 6.3 一期不采集的字段

材料模块一含**可识别身份信息与第三人联系信息**。一期不采集下列字段：姓名、出生日期、性别、照片、联系方式、居住环境；紧急联系人、家庭主要联系人、医疗联系人、学校或机构联系人、社会服务联系人。

理由：咨询输出只需要**偏好称呼**与语言信息；可识别身份与第三人信息属最小必要之外的收集，而数据处理与保留条款尚未核实（`EVID-C`、`EVID-D`）。第三人联系信息另登记为扩展缝（[设计待办](../../TODO.md) `EXT-07`，含第三人的授权与删除处理）。监护或代理关系是**档案归属的说明**（`RQ-MEM-05` 一期由监护人持有），不是联系人记录，故保留。

模块一余下的档案元数据中，一期只取**创建时间与最近更新时间**（由第 2 节的时间字段承载）；"谁参与了填写""谁拥有编辑权限""下次建议复核时间""版本号"依赖多主体权限与版本历史，一期不存在（第 9 节授权缝只有属主）。材料的字段级权限与分享范围（本人可编辑／医疗可见／紧急状态可见等）同属二期共用，一期不实现。

## 7. 写入路径与失败语义

**档案只有一个写工具**（`propose_profile_item`），落层由 `origin` 决定（第 3 节的表），不在工具与 Worker 之间分散判定。

档案写入**不在咨询请求内同步完成**（技术栈设计第 5 节）：请求只在业务事务内写入待处理记录，由 Worker 异步消费。

| 失败情形 | 处置 |
|---|---|
| 待处理记录写入失败 | 整个请求失败并明确报错；不得返回"已记录" |
| Worker 消费失败 | 按幂等键重试；超限转死信并告警 |
| 重复消费 | `pending_id` 唯一约束保证不产生重复条目 |
| 推断被尝试写成稳定层 | **请求被拒绝**，而不是被静默降级改写（`RQ-MEM-04`） |
| 写入成功但摘要未刷新 | 摘要可暂时滞后；滞后时注入须标注"摘要可能未含最新内容" |

**落层判定的位置**：稳定层与候选层的判定在**工具实现层硬卡**（`origin` 属于 `system_observation` 或 `ai_inference` 时不得写成 `confirmed`、不得直接进稳定层）；Worker 只消费显式载荷，不重新判定归属。授权在领取时按当前态重新判定（[写入路径](写入路径.md)第 6 节）。

## 8. 接口形状

供下游实现直接取用；只列形状，不含实现。

```text
resolve_for_context(support_object_id, situation, include_candidates) -> list[ProfileItem]
    # 供 consult 装配上下文；include_candidates 为真时，候选条目必须带 confirmation=unconfirmed 标记
    # rejected 条目一律不返回

write_from_pending(pending_id) -> WriteResult
    # Worker 调用；幂等键为待处理记录 id；落层按 origin 判定

confirm(item_id, account_id) -> ProfileItem
    # 候选条目经使用者确认后进稳定层；rejected 只能由使用者显式否定产生
correct(item_id, patch, account_id) -> ProfileItem
    # 新增取代条目，旧条目转 historical
delete(item_id, account_id) -> None
    # 删除须覆盖该内容在检索与衍生中的使用（RQ-MEM-03）

summary(support_object_id) -> ProfileSummary
    # 一页摘要；十二个字段见第 4 节；每条带 item_id、origin 与 last_confirmed_at

emergency_context(support_object_id) -> EmergencyContext
    # 供应急应用侧预注入；框架的七组另加「无效策略」，共八组：
    # baseline、known_triggers、communication{baseline, best_mode, processing_time_seconds}、
    # sensory_profile、medical_risks、proven_strategies、unhelpful_strategies、safety_history
    # 只取稳定层；某组未预存时显式返回 absent，不由调用方推断补全
```

`confirm`、`correct`、`delete` 的**调用方是档案面与对话页的确认入口**（HTTP），不是模型可见工具——模型侧十个工具里没有它们（[技能设计](技能设计.md)第 3 节）；"模型推断进候选、使用者确认才进稳定层"正是靠这条分工成立的。HTTP 形状见[档案面 HTTP 契约](../面/profile/档案面HTTP契约.md)。

## 9. 授权缝

一期只有创建者账号可读写档案，判定经 `core/authz` 的唯一入口（属主即允许）。二期机构协作在同一端口增加维度，**本节的形状与第 2 节的数据形状不变**。

支持对象的每次访问都要校验该对象属于当前账号（`RQ-MEM-07`、`AC-22`）——对象实体的形状、归档语义与端口的两个具名函数（`require_owned` / `require_writable`）见[支持对象](支持对象.md)第 3、5 节。**本文只声明档案侧要调用它**：读路径（`read_profile_summary`、`read_profile_items`、`emergency_context`）用 `require_owned`，写路径（`propose_profile_item`、Worker 领取 `profile_item`）用 `require_writable`；归档对象**可读、不可新增写入**。

## 10. 验证方式

对齐 `AC-07`（条目带来源、生成方式与时间）、`AC-08`（删除后不再被引用）、`AC-18`（未确认推断不得进入摘要与结论）、`AC-22`（跨账号访问被拒、两个对象的档案互不可见）。

另需验证：

- **落层分流**：以四种非推断 `origin` 各提交一条，验证直接进稳定层；以 `ai_inference` 提交，验证只进候选层且摘要中不出现。
- **推断不得自认已确认**：以 `ai_inference` + `confirmed` 调用，验证被拒绝且未落库。
- **否定不再回来**：否定一条候选后，验证它不再被提为候选、不参与注入。
- **降权**：把候选条目的 `last_confirmed_at` 置为 90 天前，验证其不进摘要与默认读取、被检索到时标注陈旧，且**未被删除**。
- **纠正**：纠正后验证新旧条目互指、旧条目转 `historical`、注入只含新条目。
- **摘要覆盖性**：断言第 4 节十二个字段都能从第 6 节领域取值生产出来；构造只有候选条目的对象，验证摘要返回"无档案"而非空对象。
- **缺项不被当作否定**：构造某领域无条目的对象，验证输出不声称"该情况不存在"。

## 11. 已知偏差与证据边界

- **所有权分歧**：外部调研材料引 NHS 立场——档案应由本人拥有、本人决定记录什么与分享给谁；一期是监护人账号持有、本人无法登录。缓解：来源类型必须能标注"本人自述（经监护人转述）"，且监护人观察不得覆盖本人表达（第 2、3 节）。本人身份、访视与共享登记为后续重访方向。
- **支持对象实体形状已定**（2026-09-29）：见[支持对象](支持对象.md)——对象实体归 `modules/profile`，生命周期为创建／改名／归档／恢复（无删除），授权经 `core/authz` 的 `require_owned` / `require_writable`。
- **确认入口的后端契约已配合成文**（2026-09-30）：[档案面 HTTP 契约](../面/profile/档案面HTTP契约.md)（对象端点、`confirm` / `correct` / `delete` / `reject`、补充条目）。仍缺的是 `modules/profile` 本身的实现与迁移。
- **四个领域一期无下游消费者**：执行功能、社交与关系、学习与工作、目标与长期计划不在第 4 节摘要字段与应急预取之内。启用它们的理由是换取分类歧义最小（"任务启动困难"归执行功能而不必勉强塞进日常生活），代价是一期多出四个无直接消费者的枚举面。
- **`pending_write.origin` 的存储约束仍是四值**：迁移 `5e27503214c3` 与 `core/pending_write` 的 CHECK 只接受四个取值，缺 `third_party_report` 与 `document`（[设计待办](../../TODO.md)）。
- 紧急联系人等第三人信息无落点（第 6.3 节，`EXT-07`）。
- 材料未入库且其引用的原始来源未经本项目独立核验；专业审阅、供应商条款与真实数据盘点为 `missing evidence`，一期只用虚构或经核准不可识别的样例。

## 12. 不在本文范围

- 通用记忆的时间演变与失效判定。
- 专业资料与案例的来源、状态与撤下。
- 账号、会话、邀请码与人工重置。
- 候选确认卡与档案页的视觉与交互（属页面设计）。
- **跨对话的模式归纳**（一期不做）：把同一主题在多次对话中的出现聚合为"候选模式"。重访条件：单次观察候选的量级使使用者的确认负担成为真实问题，且评测能证明聚合判据比逐条候选更准。
- **档案的版本历史与定期复核**：材料要求的能力变化追踪与复核提醒。重访条件：出现真实的多主体协作或长期随访需求（与二期共用同批）。
