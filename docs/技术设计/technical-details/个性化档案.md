# 个性化档案

> **权威范围**：档案条目的数据形状与状态、稳定层与候选层的划分、一页摘要的取数、完整与纠错规则、以及写入路径的失败语义。业务结果与验收语义由[功能需求与验收](../../需求/功能需求与验收.md)拥有；模块归属由[项目结构设计](../../项目结构设计.md)拥有；技术选型由[技术栈设计](../../技术栈设计.md)拥有。
> **状态**：2026-09-29 依用户确认的写入模型与外部调研材料设计，待用户确认。不代表已实现。
> **追溯**：`RQ-MEM-02`、`RQ-MEM-03`、`RQ-MEM-04`、`RQ-MEM-05`、`RQ-MEM-06`、`RQ-EMG-05`、`AC-07`、`AC-08`、`AC-18`。
> **设计依据**：用户提供的外部调研材料《孤独症人士个性化档案：信息架构、字段设计与实施建议》（未入库）。该材料引用的原始来源为 NICE CG142 / CG170 / CG128、WHO ICF、NHS Health and Care Passports、AASPIRE AHAT 等；**这些原始来源本项目未独立核验**。

## 1. 目标与边界

档案是**关于某个支持对象**的可追溯认识，用于让咨询结果适配这个具体的人。它不承载关于使用者自身的长期偏好（那属于通用记忆），也不承载会话工作状态。

明确不做的事：

- 不从诊断推断需求，不把诊断当能力（调研 §25.2）。
- 不使用严重度打分或等级（调研 §21.1、§25.1）。
- **不由 AI 生成危机处置步骤**；安全与风险领域只记录使用者陈述或已确认的事实。
- **条目不存在不得被解释为"该情况不存在"**，也不得据此补全为事实。

## 2. 数据形状

```text
profile_item
├── support_object_id    归属支持对象（一期：只有创建者账号可读写）
├── domain               领域取值，见第 6 节
├── topic                该领域下的具体特征或主题（自由文本）
├── description          可观察、可执行的描述
├── contexts[]           情境：拥挤室内、医院候诊、放学时段…
├── manifestations[]     表现：捂耳、停止回应提问、离开环境…
├── person_report        本人怎么说（一期只能由监护人转述，须标注）
├── probable_need        可能的需求
├── helpful_support[]    有效支持
├── unhelpful_support[]  无效支持
├── origin               来源类型，见下表
├── confirmation         unconfirmed / confirmed / rejected
├── freshness            current / historical
├── first_recorded_at
├── last_confirmed_at
└── superseded_by        被取代时指向新条目；旧条目不删除
```

三个字段分工，不合并成一个枚举：

| 字段 | 取值 | 回答的问题 |
|---|---|---|
| `origin` | `user_statement`、`guardian_observation`、`third_party_report`、`document`、`system_observation`、`ai_inference` | 谁在什么位置上说的 |
| `confirmation` | `unconfirmed`、`confirmed`、`rejected` | 是否被使用者确认过 |
| `freshness` | `current`、`historical` | 是否仍是当前认识 |

## 3. 稳定层与候选层

**进入稳定层的唯一判定**：`freshness = current` 且（`origin` ∈ {`user_statement`、`guardian_observation`、`third_party_report`、`document`} 或 `confirmation = confirmed`）。

其余条目属于**候选层**：`system_observation` 与 `ai_inference` 未经确认时只在此存在。

不变量：

1. 候选层内容**不得**进入一页摘要，**不得**在咨询输出中被当作既成事实，只能以"待确认"呈现。
2. 稳定层条目必须可追溯到来源与时间。
3. 纠正以"新增条目 + 旧条目转 `historical` 并互指"表达，不物理覆盖，也不静默改写。

## 4. 一页摘要

供咨询注入快速读取的当前认识，取数限定在**稳定层**，字段集对应调研 §20.1：偏好称呼、沟通方式、感觉需求、可能引起不适的事、如何帮助、Please do / Please don't、疼痛或不适的表达方式、重要的人、关键健康与安全信息。

- 摘要由系统维护，但**只从稳定层取数**，每条可追溯到具体条目。
- 摘要中的每条带来源与 `last_confirmed_at`；长期未确认的条目在摘要与注入中降权并标注时效（阈值**待确认**）。
- 摘要不新增事实：它只选编与压缩，不产生稳定层之外的内容。

## 5. 完整与纠错规则

1. 咨询中的追问只由"会改变当前结论"触发（`RQ-EMG-02`）；**不为补全档案而追问**，追问所得答案顺带沉淀。
2. 使用者可在档案页补充、纠正、删除条目；删除须覆盖该内容在检索与衍生中的使用（`RQ-MEM-03`）。
3. 系统可提示缺项，但提示必须与当前情境相关且不阻塞当次结果。
4. 长期未确认的条目降权并标注时效，**不自动删除**。
5. `ai_inference` 与 `system_observation` 只在同一模式重复出现达到阈值后才生成候选条目，避免一次观察即成候选。阈值**待确认**。

## 6. 领域取值

一期取九个领域，另设「其他」兜底，保证不丢失：关于本人、沟通、感觉、日常与变化、情绪与调节、支持策略、生活与适应、健康、安全与风险。

扩展路径为外部调研材料的十四个一级模块；新增领域只改取值集合，不改第 2 节的数据形状。

## 7. 写入路径与失败语义

档案写入**不在咨询请求内同步完成**（技术栈设计第 5 节）：请求只在业务事务内写入待处理记录，由 Worker 异步消费。

| 失败情形 | 处置 |
|---|---|
| 待处理记录写入失败 | 整个请求失败并明确报错；不得返回"已记录" |
| Worker 消费失败 | 按幂等键重试；超限转死信并告警 |
| 重复消费 | 同一来源与内容的写入必须幂等，不产生重复条目 |
| 写入成功但摘要未刷新 | 摘要可暂时滞后；滞后时注入须标注"摘要可能未含最新内容" |

## 8. 接口形状

供下游实现直接取用；只列形状，不含实现。

```text
resolve_for_context(support_object_id, situation, include_candidates) -> list[ProfileItem]
    # 供 consult 装配上下文；include_candidates 为真时，候选条目必须带 confirmation=unconfirmed 标记

write_from_pending(pending_id) -> WriteResult
    # Worker 调用；幂等键为待处理记录 id

confirm(item_id, account_id) -> ProfileItem
correct(item_id, patch, account_id) -> ProfileItem
    # 新增取代条目，旧条目转 historical

summary(support_object_id) -> ProfileSummary
    # 一页摘要；每条带 item_id、origin 与 last_confirmed_at
```

## 9. 授权缝

一期只有创建者账号可读写档案，判定经 `core/authz` 的唯一入口（属主即允许）。二期机构协作在同一端口增加维度，**本节的形状与第 2 节的数据形状不变**。

## 10. 验证方式

对齐 `AC-07`（条目带来源、生成方式与时间）、`AC-08`（删除后不再被引用）、`AC-18`（未确认推断不得进入摘要与结论）。另需验证：候选层不出现在摘要中；纠正后旧条目不参与注入；缺项不被当作否定。

## 11. 已知偏差与证据边界

- **所有权分歧**：外部调研材料引 NHS 立场——档案应由本人拥有、本人决定记录什么与分享给谁；一期是监护人账号持有、本人无法登录。缓解：来源类型必须能标注"本人自述（经监护人转述）"，且监护人观察不得覆盖本人表达。本人身份、访视与共享登记为后续重访方向。
- **两个阈值待确认**：长期未确认条目的降权时限；候选模式的重复阈值。
- 调研材料未入库；其引用的原始来源未经本项目独立核验。
- 专业审阅、供应商条款与真实数据盘点为 `missing evidence`；一期只用虚构或经核准不可识别的样例。

## 12. 不在本文范围

- 通用记忆的时间演变与失效判定。
- 专业资料与案例的来源、状态与撤下。
- 账号、会话、邀请码与人工重置。
