> **状态**：2026-09-29 依用户确认的三项决定（同意范围覆盖到 AI 检索与建议、只接导出物不搬 ASR、这些案例导入时标为已核准）与上游 skill 的实际值域设计，待用户确认。不代表已实现。
> **追溯**：`RQ-KB-01`、`RQ-KB-02`、`RQ-KB-03`、`RQ-KB-04`、`RQ-LIM-01`、`RQ-LIM-05`、`RQ-CON-02`、`RQ-CON-03`、`AC-05`、`AC-06`、`AC-09`。
> **上游依据（已读实际文件）**：`E:\Project\Tool\speech-to-text` 的本地转写工具（FunASR：paraformer-zh + cam++ 说话人分离 + VAD + 标点；数据不出本机；有热词库与手机号/身份证脱敏；其设计文档要求"采访前已获得家长录音及文字转写的知情同意"）与其 `case-extraction` skill（`references/ebp_reference.md` 定义值域、`scripts/validate_l2.py` 校验、`scripts/render_l2.py` 生成审阅报告）。导出物为 3 个案例包、共 **10 张 L2 卡片**。

## 1. 定位与边界

**公共案例库是"访谈得来的实践经验"，不是"经同行评议的循证结论"。** 它必须始终带着这个身份进入输出。

| 本项目拥有 | 不拥有 |
|---|---|
| 案例条目与卡片的形状、状态、审阅状态与入库契约 | 上游转写与抽取流程（留在链外，见第 6 节） |
| 字段的风险分级与呈现规则 | 检索的内部机制（[RAG 策略](RAG策略.md)） |
| 案例的撤下与来源回指 | 对外返回契约（[资料与案例检索](资料与案例检索.md)） |

**不变量**：案例输出必须能回答三个问题——**谁说的**（来源类型与对象）、**多可信**（循证等级与审阅状态）、**什么时候**（访谈时间）。三者缺一，该案例不得作为依据。

## 2. 单元结构：案例与卡片

上游导出就是两层的，我们照它的形状收：

```text
case_item（案例，条目级）
├── narrative（L1：五节叙述——场景背景 / 患者特征 / 行为表现 / 干预过程 / 结果与反思）
├── cards[]（L2：3–4 张结构化卡片）
└── review_report（_review.md：人类可读渲染物，仅作人工阅读附件，不参与检索）
```

- **检索单位是卡片**，**呈现单位是案例**：卡片提供细粒度命中与元数据过滤，命中后聚合回案例（与 [RAG 策略](RAG策略.md)第 4 节的"节点→条目聚合"同一形状）。
- `narrative` 的各节也作为可检索节点。

## 3. 案例条目形状（我们侧的真源）

```text
case_item:
    case_id            # 系统分配的内部 id
    external_key       # 上游目录名，如 2026-11-06_1000_fictional-supermarket-meltdown（不重写，用于追溯）
    title
    source_type        # 专家访谈转写（一期只有这一种）
    subject_type       # 家长 | 老师 | 专业人员 | 其他
    interview_at       # 访谈时间（上游目录名里的时间戳）
    consent_scope      # 见第 5 节；一期为 ai_retrieval_and_advice
    consent_recorded_at
    evidence_level     # EBP | INSTITUTIONAL | OBSERVATIONAL（沿用上游值域）
    review_status      # professional | owner | pending
    reviewer           # 仅 review_status = professional 时必填（具名）
    authorization      # 素材授权状态（沿用检索机制文档的字段语义）
    status             # published | internal | fictional（沿用）
    withdrawn
    makes_claims_high_risk  # 是否含高风险内容（见第 5 节），用于过滤与呈现
    keywords / aliases
    transcript_ref     # 上游转写稿引用（本地路径或批次标识；不复制转写原文入库）
    narrative_sections # 五节
    cards[]            # 见第 4 节
```

> **不复制转写原文入库**：转写稿可能含未脱敏内容，且它属于上游。案例库只存**抽取后的案例与卡片**，并以 `transcript_ref` 回指。

## 4. 卡片形状

**上游 19 个字段原样保留**（`title`、`scenario`、`behavior_type`、`age_range`、`severity_level`、`setting`、`ebp_tags`、`parent_category`、`immediate_action`、`comforting_phrase`、`observation_metrics`、`medical_criteria`、`evidence_level`、`caution_notes`、`contraindications`、`is_template`、`_inferred`），我们只补四件事：

```text
card_id              # 系统分配，替代上游的 {AWAITING_SYSTEM}；规则 <external_key>#<NN>
case_id              # 回指案例
inferred_fields[]    # 由上游 _inferred 的键推出：哪些字段是推断值（见下）
risk_class           # low | mixed | high（默认档，见第 5 节）
```

**`_inferred` 的处理**（与 `RQ-MEM-04` 同源）：上游用 `_inferred` 记录了推断值与依据（有的还含 `source_type`、`parent_category_candidates` 候选分类与选择理由、`ebp_reverse_check` 标签成立性核对）。入库时：

- `_inferred` 的**每个键**都在 `inferred_fields` 里登记，**被推断的字段在输出中必须标为推断**，不得作为事实；
- `_inferred` 的内容**本身也保留**（它是判断依据，人工复核时有用），但**不参与检索注入**。

**值域不重写**：`behavior_type`（6 值）、`severity_level`（3 值）、`setting`（5 值）、`parent_category`（6 值）、`evidence_level`（3 值）、`ebp_tags`（NCAEP 2020 的 28 项）**全部沿用上游 `ebp_reference.md` 的定义**，导入校验器直接复用 `validate_l2.py` 的约束（必填 14 字段、`contraindications` 可选、`_inferred` 值为字符串）。

## 5. 字段风险分级与分层支持（`EXT-02` 的一期形态）

用户 2026-09-29 决定：`EXT-02`（危险内容限制）**不再延期**，改为一期的**分层支持策略**——**低风险操作与建议照给；高风险时引导使用者向专业人士求助**；因为是一期，**这部分在 skill 层执行，不做程序围栏**。

**字段默认档**（给 skill 的提示，不是强制拦截）：

| 默认档 | 字段 | 一期用法 |
|---|---|---|
| **低风险** | `scenario`、`observation_metrics`、`comforting_phrase`、分类字段（`behavior_type`/`setting`/`age_range`/`severity_level`/`ebp_tags`/`parent_category`） | 可作为依据或转述，带来源与等级 |
| **高风险** | `immediate_action`、`medical_criteria`、`contraindications`、`caution_notes` | **不得以祈使句直接给出**；只能作为"访谈中有人这样做过"的转述，并在涉及医疗处置、自伤伤人、用药或身体控制时**引导寻求专业帮助** |

- 分级**按内容而非仅按字段**：`immediate_action` 里"降低声音、减少在场人数"是低风险动作，"清场＋默默关注"、"不进行身体约束"属高风险。所以最终逐条判断在 **skill**（[应急](../面/consult/skills/emergency-consulting.md)与[日常](../面/consult/skills/daily-consulting.md)）里完成，`risk_class` 只是提示与过滤维度。
- **不做程序围栏的后果要写明**：提示词层的约束**可以绕过**，因此它**不是安全边界**（与"暴露范围不是安全边界"同一条纪律）。对真实使用者的闸门仍是 `EVID-A`（禁止内容清单需具名专业审阅者签收）与 `EVID-B`（素材授权）——这两条不因本决定而取消。
- `makes_claims_high_risk` 为真的案例，`search_cases` 返回时**必须**带该标记，供 skill 决定呈现方式。

## 6. 入库路径与 manifest 契约

- **只接导出物**（用户 2026-09-29 定）：ASR 与案例抽取**都留在链外**。FunASR/torch 与 1–2 GB 模型权重不进本仓库依赖，抽取质量与人工校对的责任也在链外。
- 走 [RAG 策略](RAG策略.md)第 7 节的**应用包内 CLI**（同一镜像、同一 lockfile、一份文件一个事务）。
- **manifest 是必须补的一环**：上游把元数据写在 `L1_*.md` 的页脚里，机器不可读。入库要求每个案例包含 `manifest.json`：

```json
{
  "external_key": "2026-11-06_1000_fictional-supermarket-meltdown",
  "title": "…",
  "source_type": "专家访谈转写",
  "subject_type": "家长",
  "interview_at": "2026-05-25T14:48:00+08:00",
  "consent_scope": "ai_retrieval_and_advice",
  "consent_recorded_at": "…",
  "evidence_level": "INSTITUTIONAL",
  "review_status": "owner",
  "reviewer": null,
  "authorization": "…",
  "transcript_ref": "…",
  "files": { "narrative": "L1_*.md", "cards": ["L2_*_01.json", "…"], "review_report": "_review.md" }
}
```

- **缺失即拒绝导入**：`manifest.json` 缺字段或卡片不通过值域校验时**整包拒绝**，不做部分导入。

## 7. 审阅状态：三档，不冒充专业认可

| `review_status` | 含义 | 能否作为依据 |
|---|---|---|
| `professional` | **具名专业审阅者**签收（含资质与时间） | 可以 |
| `owner` | **项目所有者核准**——不等于专业审阅 | 可以，但输出必须显示"项目所有者核准" |
| `pending` | 未审 | 可检索、可浏览；**不得作为依据** |

用户 2026-09-29 决定：**当前这 3 个案例导入时标为已核准**（`owner`），以便一期取用。系统**不得**把它显示为专业审阅——上游自称 `INSTITUTIONAL（待专家审核）`，把它写成"已审阅"就是冒充专业认可。

## 8. 呈现规则

`search_cases` 的结果与引用必须带：**来源类型 + 循证等级 + 审阅状态 + 访谈时间**。此外：

- 高风险内容一律用**转述语**（"有位家长在访谈中提到她这样做过……"），**不用祈使句**；
- 推断字段（`inferred_fields` 里的）必须标为推断，不得当作案例事实；
- `review_status = owner` 时，标注写"项目所有者核准"，不写"已审阅"；
- `withdrawn` 的案例不返回（同[资料与案例检索](资料与案例检索.md)第 4 节）。

## 9. 一期不做

| 不做 | 重访条件 |
|---|---|
| 应用内上传、知识库管理与审核界面 | 有真实运营需要与多人协作时 |
| ASR 与案例抽取进入本仓库 | 链外准备被证明不可持续，或抽取规则需要版本化复现 |
| 按 `ebp_tags`／`parent_category` 自动推断（上游已做） | 上游不再提供，或需要重抽 |
| 案例的专业审阅流程与签署 | 找到具名专业审阅者（`EVID-A`） |

## 10. 验证方式

- **值域**：导入校验器直接复用上游约束；构造越界值（如 `behavior_type = "焦虑"`）验证整包被拒。
- **manifest 缺失**：删一个必填字段，验证整包拒绝且不留半个案例。
- **推断标注**：断言被 `_inferred` 覆盖的字段在检索结果里带推断标记。
- **审阅标注**：`review_status = owner` 的案例，输出里**不出现**"专业审阅""已审阅"字样。
- **高风险转述**：命中含高风险内容的卡片时，验证输出是转述语而非祈使句，并出现引导求助。
- **撤下**：撤下后不再返回，历史引用被标注（`AC-09`）。
- **追溯**：任一案例可回指 `external_key` 与 `transcript_ref`。

## 已知偏差与证据边界

- **只有 3 个案例、10 张卡片**（一期全部语料）；案例库的"库"目前名不副实。
- **没有专业审阅签署**：`_review.md` 是 `render_l2.py` 的渲染物，**不含审阅裁决**；三个案例的 `review_status` 是 `owner`。
- **枚举来自上游 skill**：NCAEP 2020 的 28 项清单与中文译名抄自上游 `ebp_reference.md`，**本项目未独立核验 NCAEP 原文**（其中 23–28 项上游自称"补充项、译名以官方术语为准"）。
- **内容含高风险处置**：卡片里有自伤处置与就医判断标准；即使标为已核准，风险分级与"引导求助"仍是**提示词层**的约束。
- **同意范围由用户确认**（已覆盖到 AI 检索与建议），但本项目**未看到同意文本本身**；`consent_recorded_at` 的填写依赖上游记录。
- 未核实：上游是否保留完整转写稿与其脱敏检查记录（`transcript_ref` 目前只能指向上游本地路径）。
