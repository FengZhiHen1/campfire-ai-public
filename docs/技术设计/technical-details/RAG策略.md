# RAG 策略

> **权威范围**：索引与检索的**内部机制与参数**——语料形态与分块、嵌入与向量列、索引策略（含何时建索引）、候选与合并的取值、条目聚合、上下文装配预算、时延预算与评测方案。**对外行为**（两库边界、返回契约、撤下传播、失败语义）由[资料与案例检索](资料与案例检索.md)拥有；供应商与技术选型由[技术栈设计](../../技术栈设计.md)拥有；`search_*` 的参数与返回由[咨询面 `tools/`](../面/consult/tools/)拥有。
> **状态**：2026-09-29 依用户确认的四项选择与已核实的供应商事实设计，待用户确认。不代表已实现。
> **追溯**：`RQ-KB-01`、`RQ-KB-02`、`RQ-KB-04`、`RQ-CON-02`、`RQ-CON-03`、`RQ-EMG-03`、`AC-05`、`AC-06`、`AC-09`、`AC-11`。
> **依据（已核实的供应商与扩展事实）**：TokenHub 向量模型文档——`POST /v1/embeddings` 兼容 OpenAI Embeddings 结构；`Kinfra-Text-Embedding-0.6b` **1024 维**、`Kinfra-Text-Embedding-4b` **2560 维**，均 32k 上下文，**维度固定不可自定义**，`encoding_format` 仅支持 `float`，**单条文本 ≤2000 字符**、单请求建议 ≤128 条，支持中文等 30+ 语言并标注为 CMTEB；TokenHub 模型列表共八类（语言/视觉/图像/视频/3D/语音/多模态理解/向量），**没有重排模型**；pgvector README——`vector` 建索引上限 **2000 维**、`halfvec` **4000 维**（此限**只限制建索引，不限制列类型**），且**近似索引下过滤在索引扫描之后应用**，0.8.0 起支持 iterative index scan。

## 1. 语料与分块

### 1.1 语料形态

- **专业资料**：指南、研究、机构材料——长文档，含标题层级、表格与列表。
- **案例**：真实案例与虚构样例，**两者必须可辨**（`RQ-KB-02`）。
- 一期**手动导入**（`RQ-KB-03`），因此导入脚本与校验属于一期工作。

### 1.2 分块：结构优先

- 目标块长 **400–800 字符**，**硬上限 2000 字符**（嵌入接口的单条限制）。
- 按**标题层级与段落**切；**不切断表格、列表项与引用块**——切断了就直接制造错误依据。
- 超长段落按**句边界**二次切；仍超限的**不可分单元**（例如整页表格）标记为"未嵌入"并进人工处理队列，**不静默截断**。
- **结构边界处不重叠**：重叠会让同一内容在引用里出现两次，也让 locator 变得含混。
- 每块携带：`item_id`、`chunk_index`、`heading_path`、`locator`（页码或章节）、`char_count`。

### 1.3 条目侧新增字段

- **`keywords`** 与 **`aliases`**：导入时填写（机构名、缩写、常见俗称、英文原名）。
- **字面路只查 `title` + 这两个字段，不查正文**——中文正文的 trigram 噪声很大，而真正需要字面命中的恰是机构名与缩写这类短词。

## 2. 嵌入与向量列

| 项 | 取值 |
|---|---|
| 服务 | TokenHub `POST /v1/embeddings`（OpenAI Embeddings 兼容） |
| 模型 | `Kinfra-Text-Embedding-4b` |
| 维度 | **2560**（固定，不可自定义） |
| 单条上限 | 2000 字符 |
| 单请求 | 建议 ≤128 条 |
| 编码格式 | `float` |

- **列类型 `vector(2560)`**。
- **一期不建向量索引**（2026-09-29 定）：一期语料是手动导入的百条量级、块级几千条，**精确检索（顺序扫描）既足够快，又保证召回 100%**；而 2000 维的限制**只作用于建索引**，不建就不受限。
- **切换条件**：块数超过**约 5 万**，或单次向量检索 SQL 超过**100 毫秒**，改为 `halfvec(2560)` + HNSW（表达式转换建索引），并同时启用第 3.2 节的过滤扫描设置。切换是一条迁移，**不改返回契约**。
- **嵌入时机**：导入脚本内批量嵌入；查询时对 query 调一次嵌入（计入时延，见第 6 节）。

## 3. 索引

### 3.1 字面路：GIN trigram

- 对 `title`、`keywords`、`aliases` 建 GIN trigram 索引。
- 查询用 `LIKE` / `ILIKE '%词%'`，**不得用 `~` / `~*`**（中文不走索引）。
- **需 ≥3 个连续汉字**：1–2 字的查询**不走字面路**，只走向量路与元数据过滤。
- 部署 locale **不得为 `C`**（`C` 下汉字被全部丢弃、相似度恒为 0）；默认 locale 下是否可用仍需实测（`TECH-01`）。

### 3.2 向量索引（现在不建，条件触发）

- 若建：`halfvec(2560)` + HNSW，`m = 16`、`ef_construction = 64`、查询侧 `hnsw.ef_search` 与业务过滤配合。
- **必须同时启用 iterative index scan**：pgvector 的过滤在索引扫描**之后**应用，而我们的每条查询都带过滤（库别、状态、撤下、授权），不启用就会出现"过滤后只剩很少结果"。设置 `hnsw.iterative_scan = relaxed_order` 并给 `hnsw.max_scan_tuples` 一个上限。
- 建索引的运维前提：按 HNSW 要求配置 `maintenance_work_mem` 与并行度（README 明确索引图放不进 `maintenance_work_mem` 时构建会显著变慢）。

## 4. 查询构造与候选

- 模型给的是**自然语言 query**；**一期不做查询改写、不做多查询扩展**（理由与重访条件见第 8 节）。
- 两路各自取候选：**向量路 top-30**、**字面路 top-30**（数值**待确认**，取值受块数与评测结果影响）。
- 过滤条件（库别、状态、撤下、授权）**在 SQL 内完成**，不放到应用层——否则会先把无关结果取回再丢弃。
- **合并规则**（路内排名 + 命中路数、不做跨路加权归一化）由[资料与案例检索](资料与案例检索.md)第 2 节拥有，此处只给取值：合并后取 **top-8 条目**。
- **条目聚合**：同一 `item_id` 多块命中时**只保留名次最高的一块**作为 snippet，并把该条目的名次上提；**同一轮不重复注入同一条目**。
- **一期不做重排**（2026-09-29 定）：没有语料可调阈值，且加一次模型调用会吃掉应急的时延预算。

## 5. 上下文装配

- 注入形状与返回契约一致：标题、snippet、来源、适用范围、状态、locator。
- **预算：检索结果占模型窗口不超过 8%**（**待确认**）；超出时按名次截断，并标注"未全部注入"。
- **应急路径更紧**：只注入 **top-3**，且**不为凑依据追加检索**（`RQ-EMG-03`）。
- 每条注入都进**引用索引**（[基座](通用基座.md)第 4 节），以便输出回指。
- 顺序按最终名次；**不按库别分组**——避免制造"资料先于案例"这类隐含偏好。

## 6. 时延预算

- 一次检索 = **一次 query 嵌入（网络往返）+ 一次 SQL**（一期无索引，几千块的顺序扫描）。
- 日常路径不设单独指标；**应急路径首字 ≤10 秒**（`RQ-EMG-03`），因此**嵌入调用必须与档案预注入并行**，不能串行等待。
- 实测一次嵌入往返作为基线；若它接近应急预算，优先把档案注入与检索并行化，而不是砍掉检索。

## 7. 评测

**一期没有语料**（`EVID-F` 未完成），所以先建**评测骨架**而不是跑一个分数：

- 手工构造 **20–30 条查询 + 期望条目**，覆盖四类：机构名与缩写、1–2 字短词、纯语义改写、跨语言术语。
- 指标：**recall@8**、**MRR**，以及**字面路与向量路各自贡献了多少命中**——合并规则的取值依赖后者。
- **中文约束回归组**单独列：≥3 字、1–2 字、机构名缩写各若干条。
- 附带指标：单次检索的嵌入 + SQL 耗时、注入 token 数。
- 语料到位后用**同一套用例**重跑，形成前后对比；在此之前任何"效果良好"的判断都不成立。

## 8. 一期不做与重访条件

| 不做 | 重访条件 |
|---|---|
| **重排**（无供应商可用，且伤时延） | 评测显示向量路 recall@30 尚可但 top-8 精排明显差——说明是**排序问题**而非召回问题 |
| 查询改写与多查询扩展 | 评测显示同一问题换一种说法后召回骤降 |
| 向量索引 | 块数超过约 5 万，或单次向量检索 SQL 超过 100 毫秒 |
| 条目摘要嵌入、父子块 | 评测显示长文档的**局部细节**检索不到 |

## 10. 记忆侧的嵌入（Graphiti）

- Graphiti 需要一个**嵌入器**，必须配置为**同一个 TokenHub 向量模型**——否则会引入第二个供应商的凭据，与"单一供应商、少基础设施"相悖。
- 维度一致性：Graphiti 侧的向量维度与 FalkorDB 的向量索引维度必须匹配（2560）；**FalkorDB 是否支持 2560 维的向量索引尚未核实**（登记为 `TECH-13`）。
- 记忆写入在 Worker 内异步执行（[写入路径](写入路径.md)），嵌入调用计入 Worker 的成本与重试预算；**嵌入失败按记忆写入失败处理**，不回滚业务主事务。
