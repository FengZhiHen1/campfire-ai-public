## 1. 命名与文件组织

| 元素 | Python | TypeScript |
|---|---|---|
| 包目录 | snake_case：`py_config/`、`py_agent_kernel/` | kebab-case：`ts-shared/` |
| 层目录（前端） | — | 固定五名：`domain/`、`application/`、`viewModel/`、`view/`、`infrastructure/` |
| 模块文件 | snake_case：`auth_service.py`、`grant_policy.py` | 组件 PascalCase：`StateBadge.tsx`；工具/Hook camelCase：`httpClient.ts`、`useSpaceScope.ts` |
| 类 / 接口 | PascalCase：`GrantService` | PascalCase：`IMatterRepository`、`MatterProps` |
| 函数 / 变量 | snake_case：`resolve_grant()` | camelCase：`resolveGrant()` |
| 常量 | `UPPER_SNAKE_CASE` | `UPPER_SNAKE_CASE` |
| 私有成员 | `_leading_underscore` | `private` |
| 测试文件 | `test_<模块名>.py` | `*.test.ts` |

文件组织规则：

1. 每个文件只导出一个主要类/函数/组件，辅助类型与工具可共存。
2. Barrel 导出：Python 经 `__init__.py` 显式声明 `__all__`；TypeScript 经 `index.ts`。
3. 后端模块内部四件套：`routes.py`（接口层）、`<模块>_service.py`（用例编排）、`<模块>_contract.py`（服务抽象）、`exceptions.py`（业务异常）。
4. `packages/py-db/py_db/` 四件套：`database.py`（引擎与 AsyncSession 工厂，所有应用经此取连接）、`models/`（按业务域分文件）、`repositories/`（封装 ORM 查询与数据访问规则）、`migrations/`（Alembic，schema 单一真相来源）。
5. `packages/py-schemas/py_schemas/` 按业务域分文件，另设 `agent/` 承载模型输出契约；契约集中管理以便 Alembic 全局视角与跨端对齐，但不退化为单个巨型文件。
6. 扩展物理约定：目录型扩展含 `extension.py`（工厂入口）+ `extension.yaml`（名称/版本/内核兼容）；`skills/<skill>/SKILL.md`（frontmatter + metadata）随扩展目录自动发现，不设根级 `skills/`。
7. 测试镜像目录：应用测 `apps/*/tests/`，包测 `packages/*/tests/`，跨服务集成在根 `tests/`；临时产物入 `.tmp/`（Git 忽略）。
8. 行数控制：前端单文件 ≤200 行；Python 函数 50–80 行内，超出拆分。
9. 只为已确认需求创建目录；规划中的位置仅在文档标注，不创建空包。

## 2. 依赖注入与配置

- 后端依赖注入集中在 `apps/api-server/app/core/dependencies/`：当前身份、DB 会话、授权判定入口、配置均由用例显式声明依赖，不在模块内自行构造或在函数内直接读取环境。
- 配置唯一入口是 `packages/py-config`：环境变量与 `.env` 只在此解析，按域分段（数据库、缓存、对象存储、模型供应商、JWT、限流、功能开关），下游按类型注入。禁止在业务模块中直接 `os.environ` 或 `dotenv` 读取形成第二真相。
- 前端 `infrastructure/` 经装配注入实现 `application/ports/` 的接口；`view` 与 `viewModel` 不得接触 HTTP 客户端或 token 存储。
- 功能开关在服务端强制读取，前端隐藏按钮不构成关闭。

## 3. 事务、outbox 与异步纪律

- 授权变更、异议停用、计划确认、交接发送的状态写入与业务数据在**同一主库事务**内完成，先持久化关键状态再返回成功响应。
- 跨事务副作用写入 outbox（形状与归属见[项目结构设计 §2.2](../../项目结构设计.md)）：写入与业务状态同库同事务，消费端按 `business_key` 幂等。
- 重试上限 3 次，指数退避；超限转死信并告警，不静默丢弃。异步失败不得回滚已完成的主事务状态，也不得把未确认内容提前作为当前有效内容发布。
- Worker 崩溃不影响 API 进程；同一消息重复投递必须产生同一结果。

## 4. 错误处理与错误码

- 统一错误体为 `{code, message, trace_id, retryable}`，HTTP 状态到语义的映射与业务 `code` 取值集合由[枚举与错误码](./枚举与错误码.md)唯一拥有；本文只规定处置纪律。
- 业务异常定义在各模块 `exceptions.py`，统一转换为上述错误体；禁止把原始输入、他人授权信息或供应商原文写入 `message`。
- 对不可向用户展示的内部故障，仅记录去敏 `trace_id`，日志不落原始叙述。
- 受限资源在授权库不可达时不得返回缓存的 200；公开已审阅内容可以独立返回。这条是 fail-closed 的硬边界，不允许为可用性降级为 fail-open。

## 5. 静态依赖检查

[项目结构设计](../../项目结构设计.md)声明的依赖方向与安全禁令必须由可执行检查保证，不能只靠文档自觉。所需检查项：

| 检查 | 工具方向 | 失败处理 |
|---|---|---|
| Python 包间 import 白名单、禁止循环依赖 | import 图检查脚本或 `import-linter` 契约 | CI 阻断 |
| `routes.py` 不得直接 import `py_db/models/`；app 之间禁止 import | 同上契约 + 路径规则 | CI 阻断 |
| `py-agent-kernel` 零本项目依赖 | 依赖声明检查（`pyproject.toml` 解析） | CI 阻断 |
| 前端五层依赖方向、禁止 `view` 直接调 HTTP | oxlint `no-restricted-imports` 规则 | CI 阻断 |
| 双模块各自维护授权规则 | 授权判定入口调用点扫描（仅允许 `spaces` 提供） | CI 阻断 |

工具选型与规则配置在实现落地时确定并写入本节；未配置前，上述方向仍是硬约束，靠评审与集成测试兜底，不得宣称已有自动保障。

## 6. 测试分层

| 层级 | 工具 | 位置 | 必测类型 |
|---|---|---|---|
| 领域与用例单元 | pytest + pytest-asyncio | `apps/api-server/tests/`、`packages/*/tests/` | 状态机全路径、并发版本冲突 |
| 接口与权限 | pytest + httpx AsyncClient | `apps/api-server/tests/` | **跨空间越权矩阵**、撤销后旧端点再读、幂等重放 |
| Worker 任务 | pytest | `apps/worker/tests/` | 重放、重试上限、死信 |
| 跨服务集成 | pytest | 根 `tests/` | 生成中撤销、备份恢复后删除墓碑复活 |
| 前端组件与 Hook | Vitest + @testing-library/react | 与被测文件同目录或 `__tests__/` | 五态、切换对象清除旧缓存 |
| 契约一致性 | schema 序列化对比 | `packages/py-schemas/tests/` | DTO 与前端 `ts-shared` 对齐 |

每条需求验收 ID 至少关联一项可复跑用例；失败不可通过跳过、降低覆盖或只留演示脚本消除。

## 7. 可观测性与告警

- 结构化 JSON 日志统一经 `py-logger`，含 `trace_id`、操作类型、主体 pseudonymous id、资源 id、结果与耗时；禁止写入原始叙述或附件 URL。
- 健康检查分离报告四类信号：公开内容可达、数据库授权可用、模型可用、异步索引滞后。任一信号须经人为制造故障证明能告警，不以一个全绿 `/health` 代表所有能力安全。
- 产品侧可测量性（`AC-OPS-01` 的记录耗时、重复解释、审阅返工，`RQ-OPS-05` 的消融对照）需要在用例边界采集计时与返工计数；采集字段与埋点位置在实现时定义，不得把模型自评或满意度当作效果证据。

## 8. CI/CD 前置

当前 `.github/workflows/` 引用已归档的 `apps/`、`packages/`、`scripts/`，在新结构落地前必然失败。重写须与工作空间成员同步：先使 `uv sync`、`ruff`、`pytest`、`pnpm install`、`oxlint` 与前端构建在新路径下可运行，再恢复 CI 与部署触发。归档 `scripts/` 中的部署与重建脚本禁止执行。
