# 机制：计划确认与安全异议

> **权威范围**：共享计划条目、内容分级、确认权限、异议即时停用、复核与衍生材料失效的状态及并发失败语义。个人空间访问由空间授权机制拥有；公共知识审阅由证据机制拥有。
> **追溯**：`RQ-REC-04`、`RQ-PLAN-01～03`、`RQ-HAND-01`、`PRD-003～004`。
> **状态**：目标设计，未实现；没有已核实的专业审阅者与安全内容，不能开放确认计划功能。

## 1. 条目而非整份文档作为最小发布单位

`PlanItem` 包含 `item_id`、`space_id`、适用情境和限制、行动文本、依据及版本、内容分类、提出者、确认责任人、版本、状态、最近确认时间与失效条件。多个条目组成计划视图，条目间可注明依赖；共享材料引用条目 id/版本，而不将自由文本复制成无法撤回的第二份当前计划。

内容分类为 `logistics`（分工、时间、联系人及已确认偏好的呈现）和 `specialist_strategy`（对风险、诱因、沟通干预、行为应对等提出新的可反复执行主张）。分类不确定时进入专业审阅，不由模型自判低风险。明显诊断、用药决策、身体控制或强制惩罚等禁止内容即使由专业身份提交也不能发布。原始观察和经记录者核对的 AI 整理独立于计划存在，不因记录成功被升级为 `active`。

对 `logistics`，仅获独立计划确认授权的人员可确认，成员访问管理员无默认确认权；对 `specialist_strategy`，必须由经核实资质且职责范围覆盖该策略的专业人员审阅，记录依据、审阅范围与有效期。多人意见相左保留来源，不能按人数表决成“有效”。没有合适人选时条目停留草案或待审，不默认为普通安排。

## 2. 状态与转移

```text
draft → pending_confirmation → active → superseded/retired
                    ↑             ↘ suspended（正式安全异议）
                    └── 生成新 revision ← suspended
suspended → active（原等级责任人核验未发现问题并明确恢复）
```

状态取值权威见[枚举与错误码 §2.2](../枚举与错误码.md)。`revision` 是版本不是状态：修改已发布条目生成新 revision，旧 revision 持续按其当前有效状态供读取，直至新版本确认或旧版停用；提交者不能借编辑直接覆盖发布版。

`draft` 可由有权编辑者提出；`pending_confirmation` 需要提交明确分类和来源；`active` 的进入条件是合法关系、所需确认者、有效来源、适用条件和版本均通过服务端检查。

正式异议包含 `item_id`、目标版本、情境、观察到的风险/本人拒绝、提交者与时间。能查看该条目的成员可提交；事务内先锁定条目并写入异议，再把该条目及明确依赖它的当前材料置为 `suspended`，递增发布版本，成功响应前读取路径必须停止分发。普通措辞/编辑意见记为建议，不触发停用。若提交信息不足以识别任何具体条目，仍可即时向用户展示公开安全内容和人工补充入口，但不能自动停用整份空间；提交者可选择多个有证据关联的条目逐项异议。

停用不改变其他独立条目，也不意味着要求现实世界停止药物或治疗。`suspended` 不因超时、通知失败、原确认人缺席而自动恢复。复核者记录事实、理由、处理时间和涉及情境；原确认层级或更有资质且有相应空间权限的人才能恢复或用新 revision 取代。提交异议不授予任何替代策略发布权；确认人不能绕过未解决异议仅换措辞重新发布同一建议。

## 3. 同步强制与衍生物

授权与计划停用共享强一致的主库读取约束：每次分发按 `space_id`、条目 id、版本、状态和授权检查。条目更新提交与正式异议同时发生时以行锁/版本校验串行化；异议一旦成功，较早或并发中的确认/生成不得产生当前有效的新版本。后台 Worker 可异步重建计划页面、撤下通知和索引，但不能充当停用生效的唯一开关。

摘要、交接卡、情景演练和 AI 回答记录其所依赖的条目 id/版本。在读取与生成发布前核验依赖的**当前**状态；可准确移除受影响建议时只停用相关片段，若删除后会扭曲材料含义则整份标记不可用。旧导出无法回收，按可达渠道发送版本失效提醒并显示“此副本可能过时”，不宣称对方已删除。公开基础安全内容使用独立版本，不因一条个人计划异议同时消失。

## 4. 失败与滥用处理

- 主数据库或状态校验故障：停止发布/读取个人计划，改为公开基础内容；不能使用已缓存的 `active` 标志兜底。
- 通知/索引失败：异议仍已生效，待处理 outbox 重试并告警；故意断开 Worker 验证停用仍有效。
- 多人重复正式异议：按提交者和条目幂等去重，后续不同观察保留但不改变已停用事实。怀疑恶意滥用由独立人员核查，若限制提交通道，应提供本人拒绝和紧急安全问题的人工反映渠道。
- 计划确认超时：保持待确认，不“降级”为日常；缺乏专业人员时关闭专业策略发布能力。
- 已撤销成员再次打开旧卡或使用 AI 改写：先查空间授权及计划当前状态，不返回已停用内容或他人记录。

## 5. 验证矩阵

以日常更改接送时间、修改联系人、提出新的“安抚方法”、怀疑药物不适、明确拒绝、普通文字润色、误报、多人并发确认/异议、模型改写停用建议及通知失败分别验证。公开/个人资料分界、专业审核资质与具体条目粒度须由专业与权益审阅者签收；技术测试无错误不证明建议对个人有效。
