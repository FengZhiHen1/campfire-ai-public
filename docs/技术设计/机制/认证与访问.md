# 认证与访问

> **本文唯一拥有**：用户身份模型、认证渠道与凭证、账号与角色生命周期、邀请码机制、Token 会话管理、全局 RBAC 语义、登录安全与认证体系迁移设计。
> **追溯**：需求基线 M6 协作照护（志愿者角色）、非功能需求（安全性：手机号仅管理员可见）、风险约束（老师/专家实名认证双保险）；决策 ADR-006（平台分工）、ADR-012（邀请码制、手机号锚点、过审后微信登录）、ADR-013（本体系重大取舍）。
> **边界**：各模块数据级授权（档案关联、协作照护权限、案例可见性分级）由对应模块机制文档拥有；本文只定义全局身份与角色准入语义。

## 一、设计原则

1. **身份与凭证分离**：用户主体与认证渠道解耦，一个用户可挂多个渠道凭证（密码、微信），渠道可增删而不动身份；
2. **单角色显式授权**：一个用户一个角色，角色→能力显式映射，无数值层级隐式继承；
3. **危机零门槛由渠道解决**：终态以微信静默登录消除登录摩擦，不设匿名访问轨；
4. **最小状态**：服务端只持有凭证哈希、Token 家族与邀请码三类认证状态，其余无状态。

## 二、身份模型

### 2.1 实体

**User（身份主体）**

| 字段 | 说明 |
|---|---|
| `id` | UUID v4 主键 |
| `phone` | 手机号，全局唯一，**账号合并统一锚点**（ADR-012） |
| `real_name` | 真实姓名；teacher/expert 必填（准入审核依据），其余可选 |
| `role` | 六角色枚举之一（见 §3.1） |
| `status` | 账号状态（见 §3.2 状态机） |
| `created_at` / `updated_at` | 时间戳 |

**Credential（渠道凭证）**

| 字段 | 说明 |
|---|---|
| `id` | UUID 主键 |
| `user_id` | 所属用户（外键，级联删除） |
| `type` | 渠道类型：`password` / `wechat`（预留，可扩展） |
| `identifier` | 渠道内唯一标识：password 渠道为 `phone`；wechat 渠道为 `unionid`（优先）或 `openid` |
| `secret` | 凭证机密：password 渠道存 bcrypt 哈希；wechat 渠道为空（以 code2session 结果为准） |
| `created_at` | 绑定时间 |

唯一约束：`(type, identifier)` 全局唯一；`User.phone` 全局唯一。

**废除字段**：`username`（登录标识统一为手机号，减少概念）、`device_id`（匿名演示轨废除，见 §8）。

### 2.2 认证渠道

| 渠道 | 服务场景 | 状态 |
|---|---|---|
| **密码（手机号 + 密码）** | Web 端全部用户；内测期唯一渠道 | 现行 |
| **微信（code2session）** | 小程序需求侧静默登录 | 预留（微信开放平台认证完成后落地，见需求延期项） |

**微信绑定合并流程**（预留机制，ADR-012 手机号锚点的具体化）：

1. 小程序 `wx.login` → 后端 `code2session` → 得 `openid`（+`unionid`，优先）；
2. 该标识已绑定 → 直接签发 Token（静默登录，零感知）；
3. 未绑定 → 引导输入手机号 → **短信验证码校验**（此时引入短信服务商依赖）→ 命中既有 User → 创建 wechat Credential 完成合并，内测期档案与咨询记录无缝保留；未命中 → 注册新 User（选 family/volunteer）并同时创建双渠道凭证。

## 三、角色与账号生命周期

### 3.1 六角色

| 角色 | 画像 | 平台归属（ADR-006/012） |
|---|---|---|
| `family` | 监护人 | 小程序（内测期 Web） |
| `volunteer` | 志愿者（协作照护者） | 小程序（内测期 Web） |
| `teacher` | 老师 | Web |
| `expert` | 专家 | Web |
| `admin` | 管理员（业务运营：用户/审核/邀请码/内容） | Web |
| `maintainer` | 维护人员（技术运维，无业务数据权限） | Web |

单角色互斥（需求 M6「注册时选角色，区别于家属」）；一人多职业身份为 `missing evidence`，出现明确诉求前不建多角色结构。

### 3.2 账号状态机

```
注册（family/volunteer）──────────────→ active
注册（teacher/expert，提交实名+资质）→ pending_review ──审核通过──→ active
                                            └──审核驳回──→ rejected（可补材料重提）
active ──管理员禁用──→ disabled ──管理员恢复──→ active
```

- `pending_review`：可登录，仅见「审核中」状态页，无任何业务能力；
- `rejected`：可登录查看驳回原因并补交材料，回到 `pending_review`；
- `disabled`：所有凭证立即不可签发新 Token（refresh 家族吊销），存活 access 自然到期（≤15min）；
- admin/maintainer 不开放注册，由既有 admin 在管理端分配（维持现状语义）。

## 四、注册与邀请码

### 4.1 邀请码实体（内测期机制，随 ADR-012 退役而退役）

| 字段 | 说明 |
|---|---|
| `code` | 8–12 位可读码（字母数字，剔除易混淆字符） |
| `channel` | `demand`（可注册 family/volunteer）/ `supply`（可注册 teacher/expert） |
| `max_uses` | 可用次数，默认 1；机构批量邀请场景按人数批量生成单次码 |
| `used_count` | 已用次数 |
| `expires_at` | 过期时间（必填，时长由运营配置） |
| `status` | `active` / `revoked`（运营可停用） |
| `created_by` | 生成的管理员（批次追溯） |

### 4.2 注册流程（内测期 Web 端）

1. 提交：手机号 + 密码 + 邀请码 + 角色（受码 channel 约束）+ real_name（teacher/expert 必填）；
2. 校验：邀请码有效（active、未过期、有余量）→ 手机号未被注册（仅格式校验，**短信验证延至微信绑定时**，ADR-013）→ 密码复杂度（维持现状规则）；
3. 落库：创建 User + password Credential，**原子消费邀请码**（`used_count` 条件自增，防并发复用）；teacher/expert 置 `pending_review`，其余置 `active`；
4. 注册不自动登录，引导至登录页（维持现状语义）。

### 4.3 登录

| 渠道 | 流程 |
|---|---|
| Web（内测期唯一） | 手机号 + 密码 → 校验 Credential → 按 `status` 放行（`disabled` 拒绝）→ 签发 Token |
| 小程序（过审后） | `wx.login` 静默登录（见 §2.2），无密码交互 |

登录失败不区分「用户不存在」与「密码错误」，统一 401（维持现状防枚举语义）。

### 4.4 过审后的形态收敛

ADR-012 退役时：邀请码停止发放并废止注册校验；小程序微信渠道成为需求侧主入口（无门槛）；Web 供给侧注册保留 `pending_review` 准入审核（长期机制，不随邀请码退役）。

## 五、Token 与会话

### 5.1 双 Token 模型（维持现状选型）

- access token：JWT，15 分钟，承载 `sub` / `role` / `status` / `jti` / `exp`；
- refresh token：JWT，7 天，仅用于续期，**单次使用 + 轮换**：每次续期签发新对并标记旧 refresh 已用；
- 校验无状态（python-jose 验签），吊销状态存 Redis。

### 5.2 会话安全增强：refresh 家族盗窃检测

- 每次登录创建一个 Token 家族（family_id），轮换在同一家族内延续；
- 已使用的 refresh 被再次出示 → 判定令牌泄露，**吊销全家族**并记录安全审计事件；
- logout：access jti 入黑名单 + refresh 家族吊销，Redis 故障时 fail-open 返回 204（维持现状语义）。

### 5.3 多端与状态生效

- 多端共存不互踢（家属手机 + Web 并存是正常形态）；
- `role`/`status` 变更：refresh 家族吊销强制重新登录，存活 access ≤15min 自然收敛——不建实时权限推送机制。

## 六、全局 RBAC 语义

废除「数值越大权限越高」的隐式继承，改为显式角色→能力映射：

| 能力域 | family | volunteer | teacher | expert | admin | maintainer |
|---|---|---|---|---|---|---|
| 应急咨询 / 科普 | ✓ | ✓ | — | — | — | — |
| 档案（自有家庭，共建/协作细节归档案库文档） | ✓ 全权 | 受邀受限 | 受邀共建 | 受邀共建 | — | — |
| 案例录入 | — | — | ✓ | ✓ | — | — |
| 案例审核 / 下架 | — | — | — | ✓ | ✓（强制下架） | — |
| 工单 | 家属侧 | — | 普通/紧急接单 | 专家侧（特急仅专家） | 转派 | — |
| 平台管理（用户/准入审核/邀请码） | — | — | — | — | ✓ | — |
| 系统运维（健康/监控/维护） | — | — | — | — | — | ✓ |

- 守卫实现：依赖注入 `require_roles(…)` 显式集合匹配（替代数值比较）；
- 字段级敏感数据：手机号仅管理员可见（NFR，维持）；
- 矩阵变更属设计变更，需更新本文档——不允许代码中出现表外角色-能力组合。

## 七、登录安全与审计

| 机制 | 语义 |
|---|---|
| 失败限流 | 同手机号连续失败触发阶梯锁定（复用 Redis 滑动窗口限流基础设施），阈值与时长为配置项 |
| 密码策略 | bcrypt（salt rounds ≥ 12）+ 现状复杂度规则 |
| 密码重置 | 内测期：管理员后台重置；短信验证落地后：手机号 + 验证码自助重置 |
| 审计事件 | 注册/登录成功/登录失败/续期/登出/令牌复用检测/准入审核/邀请码生成与消费，统一走 py_logger 结构化日志（维持现状 `op_type` 模式） |

## 八、迁移设计（从演示轨到本体系）

**现状基线**：全部业务路由挂在 `get_anonymous_user` 评委演示轨；前端无登录/注册界面；`users` 表含 username/device_id；正式 JWT 轨未被前端使用。产品处于预发布状态，**无真实用户数据，允许破坏性切换**。

**数据迁移**（Alembic 单次迁移，中文注释业务意图）：

1. 新建 `credentials` 表；`users` 表现有 `password_hash` 数据迁入（identifier = phone）；
2. `users` 表：删除 `username`、`device_id` 列，新增 `status` 列（存量置 `active`）；`user_role` 枚举新增 `volunteer`；
3. 评委演示账号：删除或由种子脚本重建为正式 expert 演示账号（配置注入，不走匿名轨）。

**代码迁移**：

1. 业务路由依赖 `get_anonymous_user` → 正式认证守卫（consultation / profiles / cases 全量切换）；
2. `py-auth`：TokenManager 增加家族语义；RBACGuard 数值比较 → 显式集合匹配；
3. 前端：react-web 新增登录/注册界面与路由守卫（内测先行）；mini-program 待微信渠道落地；
4. 死链清理：代码注释中 `docs/contracts/AUTH-01/` 引用（目录不存在）随重构移除，契约事实归本文档与 py-schemas。

**切换策略**：预发布直接切换，不做双轨并行期；内测邀请码随新体系上线同步启用。

## 九、失败语义

| 失败 | 处置 |
|---|---|
| Redis 不可用 | 续期/登出 fail-open（维持）；登录限流 fail-open 并告警（可用性优先，阈值内风险可接受） |
| code2session 失败 | 微信渠道登录不可用 → 提示稍后重试；不影响 Web 密码渠道 |
| 邀请码消费并发冲突 | 条件自增保证仅一个请求成功，其余报「邀请码已用完」 |
| 短信服务不可用（落地后） | 绑定/重置流程降级为管理员人工处理 |

## 十、非目标与延期

- 多角色/一人多角（`missing evidence`）；SSO/OAuth 开放；设备管理后台；
- 短信验证与微信登录实现（机制已预留，重访条件：微信开放平台认证完成，见需求延期项）；
- 各模块数据级授权（档案关联、协作照护、案例分级可见）——归各模块机制文档。

## 十一、验证

- 权限矩阵越权用例（含协作照护越权，对应需求 4.2 隐私验收）；
- 账号状态机流转测试（pending/rejected/disabled 各路径）；
- 邀请码并发消费、过期、撤销用例；
- refresh 复用触发全家族吊销用例；
- 迁移演练：dev 库执行 Alembic 迁移 + 业务路由守卫切换后的端到端注册-登录-咨询链路。
