# 人工兜底通道（机制）

> **本文唯一拥有**：工单触发/分级/分配/流转/闭环规则与工单数据模型。
> **来源**：[references/原始设计意图/篝火智答-人工兜底通道-原始设计意图_v0.md](../../references/原始设计意图/篝火智答-人工兜底通道-原始设计意图_v0.md)（2026-05-23 用户确认）+ 原技术栈设计 §4.4 实现方案。
> **运行方式**：工单创建由应急面白名单工具 `ticket_create` 承载；工单预组装（上下文 + 置信度分析 + 专家匹配建议）由异步面 `ticket-enrich` Skill 执行（见[Agent 基座](../Agent基座.md)）。
> 危机等级与工单优先级的映射规则由[危机分级与兜底策略](./危机分级与兜底策略.md)拥有。

## 一、功能定位

P1 模块，AI 应急建议的兜底保障。当 AI 置信度不足、涉及高风险场景（自伤/攻击/用药等）、用户连续追问未解决，或用户主动要求时，将问题转接给真人专家/老师处理，确保家属在紧急时刻始终能获得专业人工支持。

## 二、触发来源

1. **AI 置信度不足自动触发**：AI 生成建议时置信度低于阈值（< 0.7），系统自动生成人工工单并引导家属；
2. **高风险场景强制转人工**：涉及自伤、攻击、用药等高风险场景，无论 AI 置信度如何一律强制转人工，AI 仅给出初步安全提示；
3. **连续追问未解决**：用户多轮追问仍表示未解决，系统建议并生成人工工单；
4. **用户主动转人工**：家属随时可点击「转人工」按钮，主动发起工单。

## 三、工单流转规则

### 3.1 紧急分级与响应

| 级别 | 判定 | 响应时效 | 通知方式 |
|---|---|---|---|
| **普通** | 轻度场景，家属手动发起 | 按排队顺序 | 常规推送 |
| **紧急** | 中度场景，系统自动生成 | 30 分钟内响应，超时提醒 + 转派 | 推送通知 |
| **特急** | 重度场景（自伤/攻击/逃跑/用药），系统自动生成并标红 | 即时响应（先抢先得，无硬性上限承诺） | 向所有在线专家群发即时通知（短信/电话） |

具体场景到等级的映射见[危机分级与兜底策略](./危机分级与兜底策略.md) §九。

### 3.2 分配机制

- **智能分配（优先）**：系统按专家专业领域（行为类型）匹配度、当前负载、历史响应速度自动派单；
- **超时转派/抢单**：30 分钟内专家未响应则提醒并转派；超时未接则转入公共池开放抢单；
- **特急**：向所有在线专家群发即时通知，先抢先得，无固定值班表；
- **专家接单**：专家/老师直接接取工单，无需管理员二次审核。

### 3.3 交互与闭环

- **异步工单交互**：专家基于完整上下文回复，家属可在同一工单内继续追问，**最多 3 轮**后自动关闭（超时 24 小时无追问自动关闭）；
- **工单内容继承**：完整对话上下文 + 患者个性化档案摘要 + AI 置信度分析 + 检索来源；
- **状态通知**：家属可见「待接单 → 处理中 → 已回复」，关键节点推送通知；
- **满意度闭环**：工单关闭时家属需星级评分并确认问题是否解决，未解决可重新打开或转派；
- **降级/升级**：中度/重度工单经专家处理后若判断实际为轻度，可标注并降级归档；轻度工单连续追问 3 轮仍未解决，系统自动建议生成紧急工单；
- **专家负载保护**：每位专家同时处理工单数量有限制（映射表建议值为 3 个普通/紧急 + 1 个特急，达到上限停止派单）；
- **价值沉淀**：工单解决后，专家可一键将本次问答（脱敏后）沉淀为真实案例库素材，必须走[标准案例库](./标准案例库.md) §八 的审核流程，不直接入库。

## 四、接口设计

- `POST /api/v1/tickets` — 系统/用户创建工单
- `GET /api/v1/tickets?status=open` — 待接工单列表（专家视角，紧急标注优先）
- `POST /api/v1/tickets/{id}/claim` — 专家接单
- `POST /api/v1/tickets/{id}/reply` — 专家回复

## 五、数据模型

```
tickets:
  - id: UUID (PK)
  - consultation_id: FK → consultations (nullable)
  - user_id: FK → users
  - assigned_expert_id: FK → users (nullable)
  - priority: ENUM('normal','urgent','critical')  -- critical 自动标红
  - trigger_reason: ENUM('low_confidence','user_request','high_risk_keyword')
  - status: ENUM('open','claimed','in_progress','resolved','closed')
  - expert_reply: TEXT
  - created_at / updated_at / resolved_at: TIMESTAMPTZ
```

**关键逻辑**：

- 应急咨询置信度 < 0.7 或用户请求「联系专家」时，由代码层触发 `ticket_create` 工具自动生成；
- 关键词检测（自伤/自杀/药物等）→ priority 自动升级为 critical；
- 工单创建后由 `ticket-enrich` Skill 异步完成预组装（补全对话上下文、档案摘要、置信度分析与专家匹配建议）；
- 专家接单无需管理员中转，直接 claim。

## 六、边界与约束

- **异步留言，不做实时聊天**：仅支持工单式异步交互，不要求双方同时在线；
- **不做固定专家值班表**：特急工单通过群发即时通知处理；
- **追问轮次限制**：同一工单内家属最多追问 3 轮，防止无限延伸；
- **沉淀需审核**：工单内容沉淀为案例后必须走案例审核流程；
- **不做通用客服功能**：仅处理 AI 无法覆盖的孤独症行为/情绪应急场景；
- **免责声明**：专家回复同样需附带「仅供参考，不构成医疗诊断或治疗建议」。

## 七、依赖项

- [智能应急咨询](./智能应急咨询.md)（触发来源判断、置信度评分、对话上下文）
- [个性化档案库](./个性化档案库.md)（档案摘要注入工单）
- [标准案例库](./标准案例库.md)（价值沉淀的审核流程）
- 推送通知系统（App 推送、短信、电话即时通知）
- 专家认证与权限体系、RBAC 权限体系（见[总体架构](../总体架构.md) §4 安全设计）

## 八、待明确项

- 专家处理上限 N 的具体数值（映射表建议 3 普通/紧急 + 1 特急，未最终确认）
- 特急 vs 紧急的判定标准（什么场景触发特急，什么场景触发紧急）
- 自动分配算法的权重比例（专业领域匹配度、当前负载、响应速度各占多少）
- 追问的超时时间（映射表建议 24 小时，未最终确认）
- 沉淀案例的触发权限（仅接单专家可操作，还是管理员/审核专家也可操作）
- 家属未评分时的默认行为（是否允许不评分直接关闭，或强制评分）
- 超时转派的最大次数（仅转派一次还是可多次转派，多次转派后如何兜底）
- 高风险场景的具体行为类型清单（现行清单见[危机分级与兜底策略](./危机分级与兜底策略.md) §三）
