# 红线安全门与兜底策略（机制）

> **历史分类规则，不是 v3 风险处置许可**：风险限制与已审阅公开内容由[情境支持目标机制](../目标机制/情境支持与事项.md)和真实专业审核拥有；旧关键词表不得代替专业安全审阅。

> **本文唯一拥有**：红线判定规则（行为桶分流、关键词库、否定过滤、档案叠加）、红线命中的系统行为、生成侧软兜底与词库迭代机制。
> **来源**：原 `功能设计/原始材料/细节设计/评定危机等级机制.md` 与 `细节设计/危机分级×兜底策略×工单优先级-映射表.md`；按 ADR-008 由「三级危机分级 + LLM 复审」演进为「二元安全门」；按 ADR-009 演进：前置勾选并入「点选行为桶」，红线命中行为升级为高危桶卡供给，置信度路由废除改确定性信号。
> **运行位置**：判定整体位于 **Agent 之外的代码层**——纯确定性规则，零 LLM 参与，Agent 无权触碰判定结果（ADR-007、ADR-008）。非红线侧的时刻分层链路与确定性兜底信号由智能应急咨询文档拥有；工单规则与优先级由人工兜底通道文档拥有。

## 一、设计原则

1. **安全底线不可突破**：涉及身体伤害、走失、用药等场景，必须引导至人工/医疗介入
2. **宁过度拦截，不漏风险**：规则宁可误判红线，也不允许真实高危漏判
3. **判定零 LLM 参与**：红线判定为纯规则，0ms、确定性、可测试；无 LLM 降级风险
4. **家属参与关键判定**：将「是否涉及身体安全」的初始判断交给家属（点选行为桶），降低规则漏判风险

## 二、二元安全门总览

```
家属点选行为桶（可附文字描述）
    ↓
[红线判定·代码层·0ms] 高危桶 或 规则命中
    ├── 命中红线 → 高危桶卡（专家审核静态内容 + 档案槽位）+ 就医/紧急求助指引，
    │              标红置顶；红线会话不进入完整方案层（AI 生成阻断保留）
    │              （不经 Agent；M4 落地后追加自动特急工单）
    └── 未命中 → 时刻分层链路（由智能应急咨询文档定义）
                   ├── 常驻专家入口 + 免责声明
                   └── 确定性兜底信号命中：强提示 + 求助指引，M4 后触发 ticket_create
```

「行为桶」不是定级维度：高危桶（自伤/攻击/走失/用药）兼任红线分流，全部桶兼任案例检索过滤维度（由智能应急咨询文档 §二 定义）。

## 三、红线判定规则

### 3.1 点选行为桶（家属主动选择，ADR-009 演进）

**触发时机**：打开应急咨询后、任何生成之前——桶选择本身就是应急链路的输入方式（原「输入文字 + 独立前置勾选」两步合并为一步）。

**交互设计**：大字按钮点选，危机中单手可操作：

> 情绪哭闹 / 刻板升级 / **自伤** / **攻击** / **走失** / **用药** / 其他

**判定规则**：点选 **自伤/攻击/走失/用药** 中任意一桶 → **直接命中红线**，跳过其余规则。

**设计意图**：将「是否涉及身体安全」这一最关键的判断从系统手里交还给家属；桶选择兼任输入方式、红线分流与检索过滤维度三职，不增加独立勾选步骤的认知负担。

### 3.2 关键词硬拦截

输入文本含高危词（撞墙、撞头、咬手、抓破、打别人、跑出去、吃药、吞药、割腕等）→ 命中红线。词库由运营持续迭代（见 §八）。

### 3.3 否定词过滤

输入含「没有/不会/以前」+ 高危词 → 排除触发，正常进入生成。

### 3.4 档案叠加

档案中该患者历史有自伤/攻击记录，且输入含「又/再次/还是」→ 命中红线（宁过度拦截）。

### 3.5 判定输出契约

| 输出项 | 说明 |
|---|---|
| `gate_result` | `redline` / `pass` |
| `gate_trigger` | 触发规则 ID（如 `KW_SELF_HARM_001`、`BUCKET_ATTACK`、`PROFILE_RECURRENCE`） |

## 四、红线命中的系统行为

**P0 阶段（M4 人工兜底通道落地前）**：

- **输出**：高危桶卡（专家审核静态内容 + 档案槽位填充，槽位机制由智能应急咨询文档 §三 定义）+ 就医与紧急求助指引（紧急电话、就近就医建议）；走失桶走独立一键应急流程（报警话术 + 档案填充，由智能应急咨询文档 §四 定义）
- **AI 生成阻断（保留）**：红线会话不进入完整方案层，不经 Agent
- **页面状态**：标红置顶消息样式，聊天容器内锁定视觉重心
- **事件记录**：红线事件落库（触发规则、输入摘要、时间），供词库迭代与 M4 冷启动使用

**M4 落地后追加**：自动生成特急工单，向在线专家群发即时通知（工单流转由人工兜底通道文档定义）。

## 五、非红线侧：正常生成与兜底

未命中红线的咨询进入时刻分层链路（此刻安全层 + 完整方案层，由智能应急咨询文档定义），并统一附带：

- **常驻专家入口**：所有咨询页面常驻「转人工」入口（M4 落地前为就医指引入口）
- **免责声明**：见 §九
- **确定性兜底信号**：检索质量不足 / 用户标记未解决 / 连续追问未解决时追加强提示与求助指引，M4 后触发 `ticket_create`（兜底信号由智能应急咨询文档 §七 定义，工单触发由人工兜底通道文档 §二 定义）

## 六、生成侧软兜底（红线判定的补漏层）

红线判定不引入 LLM，规则漏判的残余风险由三层软兜底承担：

| 层 | 机制 |
|---|---|
| **Skill 安全指令** | `emergency-consult` Skill 的工作流指令要求：模型在生成中发现描述涉及进行中的身体伤害/走失/用药风险时，优先输出安全提示并明确建议立即就医/联系专家 |
| **四段式第 4 段** | 「就医判断标准」为完整方案输出契约的强制段落，即使红线漏判，到达家属的内容仍内置升级路径 |
| **词库反哺** | 红线事件与工单日志周期性回流，补充关键词库（见 §八） |

> 软兜底不保证拦截——它是残余风险的缓解，不是判定机制。若运营数据显示漏判率不可接受，按 ADR-008 重访条件重新评估。

## 七、与工单优先级的衔接

工单优先级**按触发事实推导**，不经过危机等级中转（工单规则由人工兜底通道文档拥有）：

| 触发事实 | 工单优先级 |
|---|---|
| 红线命中 | 特急 |
| 确定性兜底信号命中（检索质量不足 / 用户标记未解决 / 连续追问未解决） | 紧急 |
| 家属主动发起 | 普通 |

## 八、持续优化机制

| 优化项 | 执行方式 |
|---|---|
| **规则词库迭代** | 每周审查红线事件与人工工单日志，将「规则未触发但事后确认高危」的案例反向补充进关键词库 |
| **家属反馈闭环** | 若家属勾选「其他」但后续被专家确认为高危，触发词库补充流程 |

## 九、免责声明（统一附加）

> **AI 建议仅供参考，不构成医疗诊断或治疗建议。涉及身体伤害、走失风险或用药决策时，请立即联系专业医疗机构。**
