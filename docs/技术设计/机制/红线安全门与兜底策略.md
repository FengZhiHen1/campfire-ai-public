# 红线安全门与兜底策略（机制）

> **本文唯一拥有**：红线判定规则（前置勾选项、关键词库、否定过滤、档案叠加）、红线命中的系统行为、生成侧软兜底与词库迭代机制。
> **来源**：原 `功能设计/原始材料/细节设计/评定危机等级机制.md` 与 `细节设计/危机分级×兜底策略×工单优先级-映射表.md`；2026-07-02 按 [ADR-008](../决策/ADR-008-二元安全门取代三级危机分级.md) 由「三级危机分级 + LLM 复审」重构为「二元安全门」。
> **运行位置**：判定整体位于 **Agent 之外的代码层**——纯确定性规则，零 LLM 参与，Agent 无权触碰判定结果（[ADR-007](../决策/ADR-007-Agent化-统一基座与分面自治.md)、ADR-008）。非红线侧的生成链路与置信度兜底由[智能应急咨询](./智能应急咨询.md)拥有；工单规则与优先级由[人工兜底通道](./人工兜底通道.md)拥有。

## 一、设计原则

1. **安全底线不可突破**：涉及身体伤害、走失、用药等场景，必须引导至人工/医疗介入
2. **宁过度拦截，不漏风险**：规则宁可误判红线，也不允许真实高危漏判
3. **判定零 LLM 参与**：红线判定为纯规则，0ms、确定性、可测试；无 LLM 降级风险
4. **家属参与关键判定**：将「是否涉及身体安全」的初始判断交给家属（勾选），降低规则漏判风险

## 二、二元安全门总览

```
家属输入行为描述 + 前置勾选
    ↓
[红线判定·代码层·0ms] 勾选高危项 或 规则命中
    ├── 命中红线 → 硬拦截：安全提示 + 就医/紧急求助指引，页面进入应急模式
    │              （不经 Agent；M4 落地后追加自动特急工单）
    └── 未命中 → 应急面正常生成（见智能应急咨询）
                   ├── 常驻专家入口 + 免责声明
                   └── 置信度后校验：< 0.7 追加强提示并触发 ticket_create
```

「行为类型 × 情绪等级」不是定级维度，而是案例检索的过滤维度（见[智能应急咨询](./智能应急咨询.md) §二）。

## 三、红线判定规则

### 3.1 前置勾选（家属主动选择）

**触发时机**：家属输入文字描述后、系统生成建议前。

**交互设计**：

> 您描述的情况更接近以下哪类？（可多选）
>
> □ 情绪哭闹/尖叫  
> □ 刻板行为升级（重复动作/语言）  
> □ **自伤行为**（撞头/咬手/抓挠等）  
> □ **攻击他人**（推搡/踢打/咬人等）  
> □ **逃跑/走失**（冲向危险区域/找不到人）  
> □ **用药相关**（药物使用/剂量/副作用）  
> □ 其他日常行为问题

**判定规则**：勾选 **自伤/攻击/逃跑/用药** 中任意一项 → **直接命中红线**，跳过其余规则。

**设计意图**：将「是否涉及身体安全」这一最关键的判断从系统手里交还给家属；交互极简，危机时刻不增加认知负担（默认单选，多选仅用于复杂场景）。

### 3.2 关键词硬拦截

输入文本含高危词（撞墙、撞头、咬手、抓破、打别人、跑出去、吃药、吞药、割腕等）→ 命中红线。词库由运营持续迭代（见 §八）。

### 3.3 否定词过滤

输入含「没有/不会/以前」+ 高危词 → 排除触发，正常进入生成。

### 3.4 档案叠加

档案中该患者历史有自伤/攻击记录，且输入含「又/再次/还是」→ 命中红线（宁过度拦截）。

### 3.5 判定输出契约

| 输出项 | 说明 |
|---|---|
| `gate_result` | `redline` / `pass` |
| `gate_trigger` | 触发规则 ID（如 `KW_SELF_HARM_001`、`PRE_CHOICE_ATTACK`、`PROFILE_RECURRENCE`） |

## 四、红线命中的系统行为

**P0 阶段（M4 人工兜底通道落地前）**：

- **输出**：仅输出「初步安全提示」（如「请立即移除周围危险物品，确保患者安全」），**阻断 AI 深度回答**
- **指引**：展示就医与紧急求助指引（紧急电话、就近就医建议）
- **页面状态**：立即标红，锁定为应急模式
- **事件记录**：红线事件落库（触发规则、输入摘要、时间），供词库迭代与 M4 冷启动使用

**M4 落地后追加**：自动生成特急工单，向在线专家群发即时通知（见[人工兜底通道](./人工兜底通道.md)）。

## 五、非红线侧：正常生成与兜底

未命中红线的咨询进入应急面正常生成链路（预取预注入 + `emergency-consult` Skill 单轮生成，见[智能应急咨询](./智能应急咨询.md)），并统一附带：

- **常驻专家入口**：所有咨询页面常驻「转人工」入口（M4 落地前为就医指引入口）
- **免责声明**：见 §九
- **置信度兜底**：生成置信度 < 0.7 时追加强提示并触发 `ticket_create`（见[智能应急咨询](./智能应急咨询.md) §六、[人工兜底通道](./人工兜底通道.md) §二）

## 六、生成侧软兜底（红线判定的补漏层）

红线判定不引入 LLM，规则漏判的残余风险由三层软兜底承担：

| 层 | 机制 |
|---|---|
| **Skill 安全指令** | `emergency-consult` Skill 的工作流指令要求：模型在生成中发现描述涉及进行中的身体伤害/走失/用药风险时，优先输出安全提示并明确建议立即就医/联系专家 |
| **四段式第 4 段** | 「就医判断标准」为输出契约的强制段落，即使红线漏判，到达家属的内容仍内置升级路径 |
| **词库反哺** | 红线事件与工单日志周期性回流，补充关键词库（见 §八） |

> 软兜底不保证拦截——它是残余风险的缓解，不是判定机制。若运营数据显示漏判率不可接受，按 [ADR-008](../决策/ADR-008-二元安全门取代三级危机分级.md) 重访条件重新评估。

## 七、与工单优先级的衔接

工单优先级**按触发事实推导**，不经过危机等级中转（工单规则由[人工兜底通道](./人工兜底通道.md)拥有）：

| 触发事实 | 工单优先级 |
|---|---|
| 红线命中 | 特急 |
| 生成置信度 < 0.7 / 连续追问未解决 | 紧急 |
| 家属主动发起 | 普通 |

## 八、持续优化机制

| 优化项 | 执行方式 |
|---|---|
| **规则词库迭代** | 每周审查红线事件与人工工单日志，将「规则未触发但事后确认高危」的案例反向补充进关键词库 |
| **家属反馈闭环** | 若家属勾选「其他」但后续被专家确认为高危，触发词库补充流程 |

## 九、免责声明（统一附加）

> **AI 建议仅供参考，不构成医疗诊断或治疗建议。涉及身体伤害、走失风险或用药决策时，请立即联系专业医疗机构。**
