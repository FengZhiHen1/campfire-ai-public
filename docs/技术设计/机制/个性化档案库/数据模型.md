# 个性化档案库 · 数据模型

> **本文唯一拥有**：个人档案四层结构（身份基础层 / 危机预案层 / 事件时间线层 / 专业评估层）的数据模型、字段定义与枚举体系。
> **所属文档组**：个性化档案库。
> **来源与追溯**：原 `功能设计/原始材料/细节设计/个人档案库设计.md` §二；存储按 ADR-003 统一为 PostgreSQL；当前四层结构源于 ADR-010；`outcome` 字段为 2026-07 评审确认（路线 A：结构化结果标记）；Event Log 按存档《孤独症家庭应急干预与行为支持_科学资料综述》附录 A.4 结构化 ABC 标准重写。

档案按 `profile_id` 严格隔离，分四层组织：身份基础层（相对稳定的人口学与诊断信息）、危机预案层（应急槽位的唯一字段来源）、事件时间线层（结构化 ABC 事件记录）、专业评估层（老师/专家补充）。新增字段继承现有访问矩阵，不作权限模型变更。

## 1. 统一枚举体系（ADR-010 第 7 条）

### 1.1 行为类型枚举（`behavior_type` / `primary_behavior` / 应急行为桶共用）

```
情绪崩溃 / 刻板行为 / 自伤 / 攻击 / 走失 / 用药相关 / 社交退缩 / 多动 / 其他
```

- **应急行为桶**（情绪哭闹→情绪崩溃、刻板升级→刻板行为、自伤、攻击、走失、用药→用药相关、其他）为本枚举的直接子集，检索过滤零映射成本；
- 「情绪等级」维度退役：检索过滤统一为「年龄段 + 行为桶」，危机阶段概念（`consultation_sessions.crisis_stage`，由智能应急咨询机制文档拥有）接替其角色；`case_chunks.metadata.emotion_level` 对齐为案例库侧后续项。

### 1.2 行为形态词表（`behavior_form`，源自 BPI-01）

按行为类型分组的具体形态勾选词表（示例，完整词表需专业翻译审校后入库）：

| 行为类型 | 形态示例 |
|---|---|
| 自伤 | 撞头 / 咬手 / 抓挠皮肤 / 打脸 / 拔头发 |
| 攻击 | 推搡 / 踢打 / 咬人 / 抓人 / 摔物 |
| 刻板行为 | 摇晃身体 / 转圈 / 重复语言 / 排列物品 |
| 情绪崩溃 | 尖叫 / 哭喊 / 倒地 / 拒绝移动 |

### 1.3 其余枚举

| 枚举 | 取值 |
|---|---|
| `intensity`（强度 4 级） | 低 / 中 / 高 / 严重 |
| `antecedent_category`（前事预置分类） | 给指令 / 转换 / 被拒绝 / 感觉刺激 / 社交 / 常规改变 / 躯体不适 / 不明 |
| `physical_state`（身体状态，多选） | 饿 / 困 / 病 / 生理期 / 无 |
| `setting`（发生场景） | 家庭 / 学校 / 公共场合 / 机构 / **工作场所** / **托养机构** |
| `outcome`（干预效果） | 有效 / 部分有效 / 无效 |
| `function_hypothesis`（功能假设，预留） | 注意 / 逃避 / 实物 / 自动强化 / 躯体不适 |
| `comorbidities`（精神共病，多选） | 焦虑 / 抑郁 / ADHD / 癫痫 / 其他 / 无 / 不详 |

## 2. 身份基础层（Personal Profile）

**说明**：一个家属账号下可创建多个个人档案，应急咨询时自动关联默认档案。字段相对稳定，不随事件变化。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `profile_id` | UUID | 是 | 个人唯一标识 |
| `caregiver_id` | FK | 是 | 关联家属用户 |
| `nickname` | String | 否 | 家属自定义称呼（应急槽位：称呼来源；话术不得以「孩子」为默认） |
| `birth_date` | Date | 是 | 出生日期，系统自动计算年龄区间（全生命周期） |
| `diagnosis_type` | Enum | 是 | **冷启动必填**：诊断类型（ASD / 疑似 ASD / 其他发育障碍） |
| `primary_behavior` | Enum | 是 | **冷启动必填**：主要行为类型（§1.1 统一枚举） |
| `comorbidities` | JSON | 否 | 精神共病多选（§1.3），成年档案重点引导 |
| `sensory_profile` | JSON | 否 | 感官特征（听觉敏感 / 触觉敏感 / 味觉敏感 / 前庭寻求等），多选 |
| `triggers` | JSON | 否 | 已知情绪触发因素（噪音 / 环境变化 / 陌生人 / 任务中断等） |
| `is_default` | Boolean | 是 | 是否为该账号下默认关联档案 |
| `created_at` / `updated_at` | DateTime | 是 | 时间戳 |

> `language_level` 移入危机预案层 `communication_methods`；`medication_notes` 移入危机预案层（ADR-010 第 2 条）。

## 3. 危机预案层（Crisis Plan）

**说明**：**应急槽位的唯一字段来源**（ADR-009 此刻层卡片填充 + 完整方案层注入），每档案一份。冷启动仅走失史家庭重点引导走失组，其余渐进完善。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `profile_id` | FK (唯一) | 是 | 关联个人 |
| **走失专项组** | | | |
| `physical_description` | Text | 否 | 体貌特征（身高/发型/显著特征，报警话术填充） |
| `familiar_places` | JSON | 否 | 常去地点/可能去向（列表） |
| `water_risk` | JSON | 否 | 水体风险与游泳能力（附近水体/是否会游泳） |
| **干预偏好组** | | | |
| `soothing_items` | JSON | 否 | 有效安抚物/感官工具列表（家属显式维护；事件 `outcome=有效` 推导作兜底与更新建议来源） |
| `avoid_list` | JSON | 否 | 禁忌/无效方式（含针对性警示，如「不可强行抱他」；志愿者可见的预案摘要中本组置顶） |
| **沟通与联系组** | | | |
| `communication_methods` | JSON | 否 | 语言水平（无语言/单字词/短句/可对话）+ AAC/视觉支持方式多选 |
| `emergency_contacts` | JSON | 否 | 安全联系人（姓名+关系+电话），供危机预案与走失流程使用 |
| `medication_notes` | Text | 否 | 用药记录（仅家属和老师可见，应急安全参考） |
| `updated_at` | DateTime | 是 | 最后更新时间 |

## 4. 事件时间线层（Event Log，A.4 结构化 ABC）

**说明**：家属每次记录 = 新增一条事件。按存档《孤独症家庭应急干预与行为支持_科学资料综述》附录 A.4 标准重构：**结构化勾选为主、自由文本仅 1 个可选备注**。记录双模式由记录流程文档定义。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `event_id` | UUID | 是 | 事件唯一标识 |
| `profile_id` | FK | 是 | 关联个人 |
| `recorded_by` / `recorded_by_role` | FK / Enum | 是 | 记录人与角色（`parent` / `volunteer`）——老师/专家不直接新增事件，以 Professional Note 挂载表达（见 §5.1） |
| `event_time` | DateTime | 是（自动） | 事件发生时间（可补录历史事件） |
| `is_quick_log` | Boolean | 是 | **打点模式标记**：危机中一键打点为 `true`（仅 `behavior_type` + 自动时间戳），事后补全后可为 `false`；可挂应急咨询会话自动生成 |
| `behavior_type` | Enum | **打点必填** | 行为大类（§1.1 统一枚举） |
| `behavior_form` | Enum | 否 | 具体形态（§1.2 BPI-01 词表） |
| `intensity` | Enum | 否 | 强度 4 级（低/中/高/严重，ADR-010 破坏性变更：原 3 级轻/中/重） |
| `duration` | String | 否 | 持续时间（如「约 5 分钟」） |
| `setting` | Enum | 否 | 发生场景（§1.3，含工作场所/托养机构） |
| `activity` | String | 否 | 进行中的活动（预置分类 + 可选文本） |
| `people_present` | String | 否 | 在场人员（如「妈妈+奶奶」） |
| `physical_state` | JSON | 否 | 身体状态多选（§1.3） |
| `antecedent_category` | Enum | 否 | 前事预置分类（§1.3） |
| `trigger_description` | Text | 否 | 前事细节补充（原必填降为可选） |
| `consequence` | Text | 否 | 后果/应对（原 `intervention_tried` 重构，预置分类 + 可选文本） |
| `reaction` | Text | 否 | 当事人对后果的反应（原 `intervention_result` 重构） |
| `outcome` | Enum | 否 | 干预效果结构标记（应急注入加权依据，由应急联动注入文档定义） |
| `function_hypothesis` | Enum | 否 | **预留**：功能假设（§1.3），QABF 填表交互延至 M5 设计（ADR-010 第 5 条） |
| `manifestation` | Text | 否 | 具体表现补充描述（原必填降为可选） |
| `note` | Text | 否 | 自由备注（唯一自由文本字段） |
| `tags` | JSON | 否 | 自定义标签（最多 5 个/事件，规则见 §5） |
| `created_at` | DateTime | 是 | 记录时间 |

**容量限制**：单档案最多 500 条 Event Log，超出自动归档最早记录（仅保留基础字段，详细描述压缩存储）——沿用不变。

## 5. 专业评估层（Professional Note + 量表）

### 5.1 老师专业评估记录（Professional Note）

**说明**：老师/专家不直接修改家属的 Event Log，而是独立提交专业评估，系统将其**挂载**到相关 Event 下。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `note_id` | UUID | 是 | 评估唯一标识 |
| `event_id` | FK | 是 | 关联事件 |
| `teacher_id` | FK | 是 | 提交老师/专家 |
| `assessment` | Text | 是 | 专业评估（如功能行为分析 FBA 简要结论） |
| `recommended_action` | Text | 是 | 建议的干预策略 |
| `evidence_basis` | Enum | 否 | 依据：NCAEP EBP / 机构经验 / 个案观察 |
| `created_at` | DateTime | 是 | 提交时间 |

> 原 Event Log 的 `follow_up_by_teacher` / `is_professional` 字段由本表的挂载关系表达，不再冗余存储。

### 5.2 量表工具（ADR-010 第 5 条）

| 量表 | 形态 | 状态 |
|---|---|---|
| BPI-01 行为词表 | `behavior_form` 后台枚举（家属无感） | ✅ 引入（§1.2） |
| SC-ABC 严重度（58 项） | 老师侧 Web 可选工具 | ⏸ MVP 不内置家属填写 |
| QABF 功能假设（精简） | `function_hypothesis` 预留字段 | ⏸ 填表交互延至 M5 复盘阶段 |

## 6. 标签体系（Tag System）

预设标签 + 有限自定义，沿用原有规则（推荐标签池、归一化、档案内生效）：

| 类型 | 内容 | 使用场景 |
|---|---|---|
| **预设标签** | 年龄区间、诊断类型、语言水平、行为类型（§1.1 统一枚举）、感官特征、触发因素、前事分类（§1.3） | 冷启动必填 + 事件记录勾选 |
| **自定义标签** | 家属在限定范围内添加（如「害怕吹风机」「只肯穿蓝色衣服」），最多 5 个/事件，仅档案内生效 | 事件记录时添加 |
