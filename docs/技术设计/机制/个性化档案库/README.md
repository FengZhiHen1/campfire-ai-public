## 一、概述

### 1.1 核心定位

个性化档案库是**以单个孤独症人士为单位的干预事件时间线**。它不做知识检索，不做语义匹配，而是作为应急咨询时的**「个体上下文」**，在 RAG 生成建议前直接注入 Prompt，让 AI 知道「这位患者以前发生过什么、什么方法有效」。

### 1.2 与标准案例库的关系

| 维度 | 个性化档案库 | 标准案例库 |
|---|---|---|
| **本质** | 个人病史/干预史 | 通用医学知识 |
| **存储** | PostgreSQL 结构化数据 | pgvector 向量 + PostgreSQL 元数据 |
| **检索方式** | 精确匹配 `profile_id` | 语义相似度检索 |
| **消费方式** | 直接注入 Prompt（第一轮） | RAG 检索后注入 Prompt（第二轮） |
| **可见范围** | 仅关联家属 + 关联老师/专家 | 全员开放 |
| **内容来源** | 家属日常记录 + 老师补充 | 专家提炼 + 机构脱敏 + 工单沉淀 |

### 1.3 设计原则

- **家属主权**：家属拥有档案的绝对控制权，可随时解除老师关联
- **老师补充**：老师仅可补充专业评估，不可修改家属记录
- **轻量启动**：冷启动仅需 3 个必填标签，其余在使用中逐步完善
- **物理隔离**：按 `profile_id` 严格隔离，无关联者绝对不可访问

## 六、边界与约束

- **不入向量库**：个性化档案数据绝对不以任何形式进入 pgvector 或任何向量索引，避免语义检索导致的交叉污染
- **不做全文检索**：家属不可在档案库内搜索历史记录，仅支持按时间/行为类型筛选
- **不对外展示**：个性化档案内容不向其他家属、未关联专家、公众展示
- **无激励机制**：家属记录行为不设积分/奖励，避免记录失真
- **容量限制**：单个个人档案最多保留 500 条 Event Log，超出后自动归档最早记录（仅保留基础字段，详细描述压缩存储）

## 七、待明确项

1. **老师补充的触发方式**：是家属主动邀请老师补充某条记录，还是老师定期主动查看并补充？
2. **Event Log 的编辑窗口**：家属提交后是否允许修改？若允许，多长时间内可修改？
3. **多人切换的默认逻辑**：应急咨询时自动关联哪个患者？是否基于最近活跃记录自动推断？
