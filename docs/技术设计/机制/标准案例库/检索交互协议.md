# 标准案例库 · 检索交互协议

> **本文唯一拥有**：与个性化案例库的独立双库架构原则、检索流程与隔离规则。  
> **所属文档组**：[标准案例库](./README.md)。  
> **来源与追溯**：原 `功能设计/原始材料/细节设计/标准案例库设计.md` §七；个性化档案库注入规则见[个性化档案库/应急联动注入](../个性化档案库/应急联动注入.md)；Agent 基座编排与工具约定见[Agent 基座](../../Agent基座.md)。

标准案例库为 RAG 提供通用干预方案，必须与个性化档案库保持物理与语义隔离。本文档定义独立双库原则、应急咨询时的检索流程及隔离规则。

## 1. 与个性化案例库的检索交互协议（决策：独立双库）

### 1.1 架构原则

- **标准案例库**：pgvector 向量索引，供语义检索，全员共享
- **个性化案例库**：PostgreSQL 结构化存储，按 `profile_id` 隔离，仅关联用户可见，**不入向量库**（见[个性化档案库](../个性化档案库/README.md)）

### 1.2 检索流程

> 由 Agent 基座编排执行：步骤 1 为应急面代码预取（`profile_get`），步骤 2 为 `rag_search` 工具检索（见[Agent 基座](../../Agent基座.md) §五）。

```
家属发起应急咨询
    ↓
[步骤 1] 读取个性化档案
  - 按个性化档案库的注入筛选规则，读取该患者的基础档案摘要与历史干预事件（筛选规则的唯一事实源见[个性化档案库/应急联动注入](../个性化档案库/应急联动注入.md)）
  - 格式化为上下文文本，直接注入 Prompt（档案预取）
    ↓
[步骤 2] 标准案例库检索（rag_search 工具）
  - 将家属输入 + 档案标签（年龄、诊断类型、行为类型）组装为查询
  - 在 pgvector 中检索 Top-K 标准案例（K=3-5）
  - 结果注入 Prompt（案例预取）
    ↓
[步骤 3] Agent 单轮生成四段式输出
  - 结合个性化历史 + 通用方案，生成专属建议
```

### 1.3 隔离规则

| 规则 | 说明 |
|---|---|
| 个性化案例绝对不入向量库 | 避免其他患者检索时交叉污染 |
| 个性化案例仅作为结构化标签过滤 | 如档案显示「听觉敏感」，则在标准案例检索时优先返回含「降噪策略」的卡片 |
| 历史事件注入数量上限 | 总计不超过 5 条，避免挤占 Prompt 上下文窗口（筛选细则见[应急联动注入](../个性化档案库/应急联动注入.md)） |
