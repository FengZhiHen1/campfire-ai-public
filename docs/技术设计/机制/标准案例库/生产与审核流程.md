> **来源与追溯**：原 `功能设计/原始材料/细节设计/标准案例库设计.md` §四、§五；L2 字段契约见[双层存储与字段定义](./双层存储与字段定义.md)；索引异步流细节见[项目结构](../../项目结构/层间数据流与依赖.md) §7.2；Agent 基座与 Skill 分工见[Agent 基座](../../Agent基座.md)。

标准案例库的 L1 原始叙事经 Agent 提取、专家微调后进入审核流程；通过终审与异步索引后发布为 RAG 可用卡片。本文档定义完整的生产与审核规则。

## 1. 案例生产流程（自然语言 → Agent 提取 → 专家微调）

> 步骤 1 的 LLM 提取由 Agent 基座上的 `case-extraction` Skill 执行（异步面，完整工作流含 PII 检测与 EBP 标签建议，见[Agent 基座](../../Agent基座.md) §四），产出受 L2 卡片 Pydantic 契约校验。

```
专家/机构上传原始叙事（L1）
    ↓
[步骤 1] case-extraction Skill 自动提取结构化字段
  - 输入：L1 自然语言文本 + 四段式模板约束
  - 输出：L2 初稿（JSON 格式，含 immediate_action / comforting_phrase / observation_metrics / medical_criteria）
  - 模型建议：轻量级模型即可，不要求强推理
    ↓
[步骤 2] 专家微调确认
  - 专家在 Web 界面查看提取结果
  - 可修改、补充、删除字段
  - 关键校验：四段式字段是否完整、ebp_tags 是否准确、evidence_level 是否合理
    ↓
[步骤 3] 提交审核
  - L1 叙事 + L2 卡片一并进入审核队列
```

## 2. 审核流程

### 2.1 AI 辅助预审（1-2 个工作日）

> 由 `review-assist` Skill 执行（异步面），检查项与规则不变：

| 检查项 | 规则 |
|---|---|
| 格式完整性 | 四段式字段是否全部非空 |
| PII 脱敏 | L1 叙事中是否含真实姓名、地址、学校名 |
| 必填字段 | behavior_type / age_range / severity_level / ebp_tags 是否存在 |
| 循证等级一致性 | ebp_tags 与 evidence_level 是否匹配（如标注 EBP 但 ebp_tags 不在 28 种列表中则报错） |

### 2.2 专家终审（1-2 个工作日）

| 审核项 | 标准 |
|---|---|
| 专业性 | 干预动作是否符合孤独症干预规范，有无危险操作 |
| 四段式质量 | 即时动作是否可执行、安抚话术是否恰当、就医标准是否准确 |
| 循证准确性 | evidence_level 标注是否合理，是否夸大 |
| 通用化程度 | L1 叙事是否已脱敏，L2 卡片是否已剥离个体标识 |

**终审操作**：

- 通过：L2 卡片切片入 pgvector，L1 叙事标记发布
- 驳回：附修改意见，退回专家微调
- 标记为模板：若从多案例提炼，勾选 `is_template = true`

**索引异步流**：审核通过后投递 Redis 队列，Worker 执行切片 + 向量化 + pgvector 入库；失败重试 3 次，最终失败标记案例状态为 `indexing_failed`（见[项目结构](../../项目结构/层间数据流与依赖.md) §7.2 数据流）。
