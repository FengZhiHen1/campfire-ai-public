# 标准案例库 · 双层存储与字段定义

> **本文唯一拥有**：L1/L2 双层存储结构、字段定义表、NCAEP EBP 标签与家属端大类映射、循证等级标注规范、adaptation_tags 受控词表、生命周期状态机。  
> **所属文档组**：标准案例库。  
> **来源与追溯**：原 `功能设计/原始材料/细节设计/标准案例库设计.md` §二、§三；存储表述按 ADR-003 统一为 PostgreSQL + pgvector；双层模型取代原技术栈设计 §4.3 单表 cases 方案（原文见存档 docs/历史/）；`adaptation_tags` 受控词表与 `lifecycle_status` 生命周期状态机、OBSERVATIONAL 应急降权与生成标注均为 2026-07 评审确认的新增决策。

标准案例库采用 **L1 原始叙事层 + L2 结构化卡片层** 的双层分离存储，分别面向专家阅读与 RAG 检索消费。本文档定义两层存储的内容形态、字段契约、NCAEP 循证标签映射及循证等级标注规范。

## 1. 双层存储架构详解

### 1.1 L1 原始叙事层

**内容来源**：

- 专家基于多案例提炼的通用化叙事
- 机构合作脱敏后的真实干预记录
- 人工工单经专家改写后的沉淀记录

**内容形态**：以自然语言撰写的完整干预故事，包含：

- 场景背景（时间、地点、触发因素）
- 患者基本特征（年龄区间、诊断类型、能力水平）
- 行为表现细节
- 干预过程描述
- 结果与反思

**示例**：

> 「7 岁 ASD 男孩小明在商场因吹风机声音突然捂住耳朵蹲下，拒绝移动。妈妈尝试拉他起身无效。老师到场后，先关闭附近吹风机电源，提供降噪耳机和挤压玩具，3 分钟后患者平复，随后带离至安静角落。」

### 1.2 L2 结构化卡片层

**生产流程**（决策：自然语言 → LLM 提取 → 专家微调）：

1. **原始文本录入**：专家以自然语言撰写 L1 叙事
2. **LLM 自动提取**：系统调用 LLM 从 L1 文本中抽取结构化字段，生成 L2 初稿
3. **专家微调确认**：专家在 LLM 提取结果基础上修正、补充，确认后提交审核

**设计意图**：

- 降低专家录入负担（无需一开始就填表格）
- 保证结构化精度（LLM 提取 + 人工校验，比纯 LLM 生成更可控）
- 保留真实叙事（L1 供人阅读，建立信任）

### 1.3 两层关系

- **一对多**：一条 L1 原始叙事可衍生出多条 L2 结构化卡片（如一个复杂案例包含「感官过载应对」和「拒绝移动引导」两个独立干预协议）
- **审核绑定**：L2 卡片审核通过后，其关联的 L1 原始叙事同步标记为「已发布」
- **版本联动**：L2 卡片更新迭代时，可选择是否同步更新关联的 L1 叙事

## 2. 字段定义表

### 2.1 L1 原始叙事层字段

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `raw_id` | UUID | 是 | 原始叙事唯一标识 |
| `title` | String | 是 | 叙事标题（通用化描述） |
| `narrative` | Text | 是 | 完整自然语言叙事文本 |
| `source_type` | Enum | 是 | 来源：专家撰写 / 机构脱敏 / 工单沉淀 |
| `source_expert_id` | FK | 是 | 撰写或沉淀该案例的专家 |
| `derived_cards` | JSON | 否 | 关联的 L2 卡片 ID 列表 |
| `status` | Enum | 是 | 发布状态：草稿 / 已发布 / 已下架（随关联 L2 审核联动，见 1.3 节） |
| `created_at` | DateTime | 是 | 创建时间 |
| `updated_at` | DateTime | 是 | 最后更新时间 |

### 2.2 L2 结构化卡片层字段（核心）

#### 2.2.1 基础信息

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `card_id` | UUID | 是 | 卡片唯一标识 |
| `raw_id` | FK | 是 | 关联的 L1 原始叙事 |
| `title` | String | 是 | 卡片标题（通用化干预方案名） |
| `scenario` | Text | 是 | 适用场景描述 |
| `behavior_type` | Enum | 是 | 行为类型：情绪崩溃 / 刻板行为 / 自伤 / 攻击 / 走失 / 用药相关 / 社交退缩 / 多动 / 其他（统一枚举，由个性化档案库数据模型文档 §1.1 定义，ADR-010） |
| `age_range` | JSON | 是 | 适用年龄区间，如 `["3", "6"]` 表示 3-6 岁 |
| `severity_level` | Enum | 是 | 适用严重程度：低 / 中 / 高 / 严重（与档案事件强度枚举同构，ADR-010；原轻/中/重 3 级） |
| `setting` | Enum | 否 | 发生场景：家庭 / 学校 / 公共场合 / 机构 / 工作场所 / 托养机构 / 不限（与档案事件 setting 对齐，ADR-010；「不限」为案例库适用维度特有） |

| 字段名 | 类型 | 必填 | 说明 |

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|

| `comforting_phrase` | Text | 是 | **情绪安抚话术**（对应四段式第 2 段） |
| `observation_metrics` | Text | 是 | **后续观察指标**（对应四段式第 3 段） |
| `medical_criteria` | Text | 是 | **就医判断标准**（对应四段式第 4 段） |

#### 2.2.4 循证与质量

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|

| `contraindications` | Text | 否 | 明确不适用的人群或场景 |
| `vector_id` | String | 是 | pgvector 向量切片 ID |
| `audit_status` | Enum | 是 | 审核状态：待审 / AI预审通过 / 专家终审通过 / 已驳回 |
| `lifecycle_status` | Enum | 是 | 生命周期状态（见 2.6 节）：索引中 / 索引失败 / 已发布 / 已过时 / 已下架 / 已被新版取代 |
| `reviewed_by` | FK | 否 | 终审专家 ID |
| `published_at` | DateTime | 否 | 发布时间（审核通过后） |
| `next_review_date` | DateTime | 否 | 下次复核日期 |
| `is_template` | Boolean | 是 | 是否为从多案例提炼的标准化模板（**已废止**：标准化模板设计暂缓） |

### 2.3 NCAEP EBP 标签与家属端大类映射（决策：A+B 结合）

**专家端使用**：NCAEP 2020 确认的 28 种循证实践标签，包括但不限于：

- 前因干预（ABI）
- 辅助替代沟通（AAC）
- 行为动力干预（Behavioral Momentum Intervention）
- 认知行为策略（Cognitive Behavioral/Instructional Strategies）
- 差别强化（Differential Reinforcement）
- 直接教学（Direct Instruction）
- 离散试教学（DTT）
- 消退（Extinction）
- 功能行为评估（FBA）
- 功能沟通训练（FCT）
- 自然主义干预（Naturalistic Intervention）
- 家属实施干预（Parent-Implemented Intervention）
- 同伴教学（Peer-Based Instruction）
- 提示（Prompting）
- 强化（Reinforcement）
- 反应中断/重定向（Response Interruption/Redirection）
- 自我管理（Self-Management）
- 社交叙事（Social Narratives）
- 社交技能训练（Social Skills Training）
- 任务分析（Task Analysis）
- 视频示范（Video Modeling）
- 视觉支持（Visual Supports）
- …（其余 6 项依 NCAEP 完整列表补充）

**家属端展示映射**（5-6 大类）：

| 家属端大类 | 涵盖的 NCAEP EBP 标签 | 典型场景 |
|---|---|---|
| **环境调整** | ABI、Visual Supports | 减少触发因素、调整物理环境（感官适配手段见 2.5 节 `adaptation_tags`，不属于 EBP 映射） |
| **沟通替代** | AAC、FCT、Social Narratives | 替代问题行为的功能性表达 |
| **行为塑造** | DTT、Direct Instruction、Task Analysis、Prompting、Reinforcement、Differential Reinforcement | 分步骤教授新技能 |
| **危机安全** | Response Interruption/Redirection、Extinction、FBA | 阻断危险行为、紧急降级 |
| **社交引导** | Peer-Based Instruction、Social Skills Training、Naturalistic Intervention | 同伴互动、社交场景适应 |
| **自我管理** | Self-Management、Cognitive Behavioral Strategies、Video Modeling | 情绪调节、自我监控 |

### 2.4 循证等级标注规范（决策：选项 A）

| 等级 | 标识 | 判定标准 | 案例示例 |
|---|---|---|---|
| **NCAEP 循证实践** | `EBP` | 干预方法属于 NCAEP 2020 确认的 28 种 EBP 之一，且有明确的文献支持 | 使用 DTT 进行任务分解教学 |
| **机构经验总结** | `INSTITUTIONAL` | 基于合作机构（如大连爱纳）多年实战沉淀，尚未达到 NCAEP 循证标准，但经专家共识验证 | 特定感官角布置方案 |
| **个案观察记录** | `OBSERVATIONAL` | 单次或少数个案的成功干预记录，尚未经过系统性验证，仅作参考 | 某患者对特定安抚音乐的独特反应 |

**前端展示**：

- 每条 RAG 输出标注来源案例时，同步显示循证等级徽章（如「循证」「经验」「观察」）
- 家属端 hover 提示说明等级含义

**应急场景处置（决策：2026-07 评审确认）**：

- 应急检索中 `OBSERVATIONAL` 卡片得分 × 降级系数（<1，机制同时效权重衰减；系数值【待定，需检索质量测试】），仅影响排序、不过滤——避免误杀个体适配性高的个案方案；
- 生成输出引用 `OBSERVATIONAL` 案例时，必须显式标注「个案经验，仅供参考」，以推荐强度而非疗效承诺呈现；
- 依据：危机中照护者工作记忆受损、倾向相信第一条收到的信息，徽章提示在危机中不可见（存档《孤独症家庭应急干预与行为支持_科学资料综述》§4.1）；证据分层以推荐强度呈现（同存档综述 §1.3 设计启示 2）。

### 2.5 适配策略标签受控词表（决策：2026-07 评审确认）

**设计原则**：`adaptation_tags` 与 `ebp_tags` 是两条正交标签轴——`ebp_tags` 回答「这是什么干预方法」（学术方法学派），`adaptation_tags` 回答「这条卡片包含什么具体适配手段」（可操作的环境/沟通/感官调整）。检索加权机制由检索交互协议文档 §1.4 定义。

**词表（按证据锚点分组）**：

| 分组 | 标签 | 证据锚点 | 置信度 |
|---|---|---|---|
| 沟通支持 | `AAC辅助沟通`、`视觉支持`、`简化语言指令` | NCAEP 28 EBP 内含 AAC、Visual Supports；儿科急诊急性激越共识（PMC8383287）推荐视觉辅助沟通【专家共识】（存档《孤独症家庭应急干预与行为支持_科学资料综述》§1.2.2） | 高 |
| 结构预告 | `视觉时间表`、`任务转换预告`、`环境结构化` | NCAEP Visual Supports、ABI；视觉支持/结构化日程/转衔预告为预防「变化/转衔型」meltdown 的最实用工具【EBP 认定】（存档综述 §1.2.2 B） | 高 |
| 感官调节 | `降噪`、`视觉减刺激`、`深压/本体觉输入`、`前庭活动`、`感官撤离区` | `降噪`/`视觉减刺激`/`感官撤离区`：儿科急诊急性激越共识（PMC8383287，减少刺激、移到安静空间）+ NAS《Meltdowns》指南（感觉超载→低唤起环境/降噪耳机）【专家共识/权威机构指南】；`深压/本体觉输入`、`前庭活动`：【待补充，本综述未覆盖】 | 混合 |

**循证边界说明**：NCAEP 2020 的 28 项 EBP 全部面向教学与长期行为改变，**无一针对危机当刻**；危机当下策略整体为专家共识级（存档综述总体证据地图 #1，Meta分析/系统综述级结论）。因此：

- 感官调节组标签**不构成 EBP 主张**，仅作为检索加权元数据使用；标注 `adaptation_tags` 不改变卡片的 `evidence_level` 判定；
- 含危机当下策略的卡片，`evidence_level` 与前端展示均不得将其包装为「循证疗法」，应以「推荐强度」而非「疗效承诺」呈现（存档综述 §1.3 设计启示 2）。

**词表维护规则**：词表收敛管理，新增标签须经专家终审一并确认；禁止专家自由填写，避免同义异形导致加权失效。

### 2.6 生命周期状态机（决策：2026-07 评审确认）

`audit_status` 是**审核流程态**（卡片能否发布），`lifecycle_status` 是**发布生命态**（卡片当前是否可被 RAG 检索与人查阅）。两者独立：审核通过后进入生命周期流转。

| 状态 | 含义 | RAG 可检索 | 人可见 |
|---|---|---|---|
| `索引中` | 终审通过，待 Worker 切片向量化入库 | 否 | 否 |
| `索引失败` | 索引重试 3 次后最终失败（由生产与审核流程文档 §2.2 定义） | 否 | 否 |
| `已发布` | 正常在线 | **是（唯一可检索态）** | 是 |
| `已过时` | 专家标记「过时/有误/争议」，保留记录供追溯 | 否 | 专家可见 |
| `已下架` | 管理员强制下架（紧急修复或法律合规） | 否 | 否 |
| `已被新版取代` | 版本迭代后的旧版，RAG 默认使用最新版 | 否 | 专家可见 |

**状态联动**：向量索引的增删与 `lifecycle_status` 联动由 Worker 维护——进入「已发布」时写入 pgvector，离开「已发布」时从检索候选中排除。淘汰操作与状态的映射由有效期与淘汰文档 §1.4 定义。
