# 智能应急咨询（机制）

> **本文唯一拥有**：应急咨询链路、咨询数据模型、四段式输出契约、置信度兜底触发。
> **来源**：[references/原始设计意图/篝火智答-智能应急咨询-原始设计意图_v0.md](../../references/原始设计意图/篝火智答-智能应急咨询-原始设计意图_v0.md)（2026-05-22 用户确认）+ 原技术栈设计 §4.1 实现方案。
> 危机分级的判定机制由[危机分级与兜底策略](./危机分级与兜底策略.md)拥有；档案注入规则由[个性化档案库](./个性化档案库.md)拥有；案例检索与切片由[标准案例库](./标准案例库.md)拥有。

## 一、功能定位

核心 P0 模块。基于 RAG 引擎，在孤独症人士突发行为/情绪危机时，为家属提供即时、可执行、结构化的应急干预建议。聚焦「此刻该怎么办」，不做医疗诊断、治疗方案或泛科普。

## 二、核心场景与链路

家属发现患者出现刻板行为升级、情绪失控、自伤/攻击倾向等紧急状况，打开平台输入患者当前的行为与情绪表现。系统自动关联该患者的个性化行为-情绪档案，检索「同年龄段 + 同行为类型 + 同情绪等级」的真实干预案例，在数秒内生成结构化应急建议。

```
家属输入行为描述 → 前端 → Nginx → FastAPI /api/v1/consult/stream
  → [安全前置] 危机分级三层判定（见危机分级与兜底策略）
  → RAG 引擎检索（pgvector 语义匹配案例切片，PostgreSQL 过滤标签条件）
  → 组装 Prompt（系统指令 + 个性化档案 + 案例上下文 + 用户问题）
  → DeepSeek API 流式生成（SSE 逐 Token 返回）
  → 前端接收流式响应，逐句渲染
```

## 三、输出契约：四段式结构

| 段落 | 内容 |
|---|---|
| 1. 即时安全干预动作 | 当前可立即执行的安全动作 |
| 2. 情绪安抚话术 | 可直接使用的安抚语言 |
| 3. 后续观察指标 | 需要持续观察的行为/情绪指标 |
| 4. 就医判断标准 | 何种情况必须就医或联系专家 |

约束：每条建议必须标注来源案例/专家文章（来源溯源），并附「仅供参考，不构成医疗诊断或治疗建议」免责声明。

## 四、接口设计

- `POST /api/v1/consult/stream` — 应急咨询流式接口（SSE），接收行为描述，返回逐 Token 生成的应急方案
- `GET /api/v1/consult/history` — 查询当前用户的咨询历史记录
- `GET /api/v1/consult/{id}` — 查询单次咨询详情（含生成的完整方案与引用来源）

## 五、数据模型（关键表）

```
consultations:
  - id: UUID (PK)
  - user_id: FK → users
  - behavior_description: TEXT          -- 用户输入的行为描述
  - retrieved_case_ids: UUID[]          -- 检索命中的案例切片 ID
  - generated_plan: JSONB               -- 结构化应急方案 {immediate_action, soothing_script, observation, medical_judgment}
  - confidence_score: DECIMAL(3,2)      -- AI 置信度
  - sources: JSONB                      -- 来源引用 [{case_id, expert, title}]
  - disclaimer_served: BOOLEAN          -- 免责声明是否已呈现
  - created_at: TIMESTAMPTZ

case_chunks (向量表):
  - id: UUID (PK)
  - case_id: FK → cases
  - chunk_text: TEXT
  - embedding: vector(1024)             -- 阿里 text-embedding-v4 输出维度，pgvector HNSW 索引
  - chunk_type: ENUM('scene','behavior','intervention','result')
  - metadata: JSONB                     -- {age_range, behavior_type, emotion_level}
```

## 六、关键逻辑

1. 接收用户输入 → Pydantic 校验 + PII 脱敏检测；
2. 构建检索查询：从用户档案提取标签（年龄/诊断类型/行为类型），作为 SQL WHERE 过滤条件；
3. pgvector 混合检索：`SELECT * FROM case_chunks WHERE metadata->>'age_range' = $1 ORDER BY embedding <=> query_embedding LIMIT 10`；
4. Prompt 组装：系统指令（角色 + 合规声明模板）+ Top-K 案例上下文 + 用户问题（个性化档案的第一轮注入规则见[个性化档案库](./个性化档案库.md) §四）；
5. DeepSeek API 流式调用 → SSE 逐 Token 推送；
6. 置信度后校验：低于阈值（< 0.7）时追加强制免责提示并触发工单生成（见[人工兜底通道](./人工兜底通道.md)）。

## 七、异步流与失败语义

- 每次咨询完成后，异步记录咨询日志到 `consultation_logs` 表；
- 若触发兜底，异步投递工单创建任务到 Redis 队列；
- DeepSeek API 中断：熔断降级 + 本地缓存通用建议模板，故障时返回预设安全指导（见[总体架构](../总体架构.md) §6 风险表）；
- 危机分级判定的失败语义（LLM 复审超时兜底等）见[危机分级与兜底策略](./危机分级与兜底策略.md) §六。

## 八、边界与约束

- **明确不做**：医疗诊断、治疗方案开具、泛心智障碍科普、替代专业人员；
- **输入限制**：MVP 阶段仅支持文字输入，语音与图片输入为后续拓展；
- **合规要求**：所有建议必须附带免责声明。

## 九、待明确项

- 行为类型与情绪等级的具体枚举值及组合矩阵需进一步确定（分级判定的现行规则见[危机分级与兜底策略](./危机分级与兜底策略.md)）。
