# 智能应急咨询（机制）

> **本文唯一拥有**：应急咨询时刻分层链路（此刻安全层 + 完整方案层）、行为桶与危机阶段体系、安全卡槽位机制、走失一键流程、咨询会话数据模型、四段式输出契约、确定性兜底信号。
> **来源**：[references/原始设计意图/篝火智答-智能应急咨询-原始设计意图_v0.md](../../references/原始设计意图/篝火智答-智能应急咨询-原始设计意图_v0.md)（2026-05-22 用户确认）+ 原技术栈设计 §4.1 实现方案；2026-08-03 按 [ADR-009](../决策/ADR-009-应急链路时刻分层重构.md) 由「单次四段式生成」重构为「时刻分层」，证据基础为 [references/孤独症家庭应急干预与行为支持_科学资料综述.md](../../references/孤独症家庭应急干预与行为支持_科学资料综述.md)。
> **运行方式**：本模块在统一 Agent 基座上以「应急面受限自治」执行，对应 `emergency-consult` Skill，执行细节见[Agent 基座](../Agent基座.md) §五。
> 红线判定规则由[红线安全门与兜底策略](./红线安全门与兜底策略.md)拥有；档案注入规则由[个性化档案库](./个性化档案库/README.md)拥有；案例检索与切片由[标准案例库](./标准案例库/README.md)拥有；卡片内容的审核流程由[标准案例库](./标准案例库/README.md)拥有（ADR-009 第 8 条）。

## 一、功能定位

核心 P0 模块。孤独症人士突发行为/情绪危机时，为家属提供**按时刻分层**的应急支持：危机当下秒级获得可立即执行的安全动作，稍后获得结构化、可溯源的完整干预方案。聚焦「此刻该怎么办」，不做医疗诊断、治疗方案或泛科普。

**设计锚点**：危机当下正是照护者认知最差的时刻（急性应激损害工作记忆），链路按「认知受损用户」设计——先给确定性安全价值，再谈信息完整性。

## 二、时刻分层链路总览

```
打开应急咨询（小程序，自定义界面）
  → [代码层·0 输入] 通用安全卡（秒级：移危险物/降刺激/照护者保持冷静）
  → 家属点选行为桶（大字按钮）：情绪哭闹 / 刻板升级 / 自伤 / 攻击 / 走失 / 用药 / 其他
      ├─ 走失 → [独立一键应急流程]（见 §四），跳过常规链路
      ├─ 自伤/攻击/用药（红线桶）→ 红线命中行为（见红线安全门与兜底策略 §四）：
      │   高危桶卡 + 就医指引（标红置顶），不进入完整方案层
      └─ 非红线桶 ↓
  → [代码层] 桶专属安全卡（专家审核模板 + 档案槽位填充）
  → [代码层] 阶段单点问题（每次一问，quick-reply 大字按钮）→ 卡片按阶段替换
  → [编排代码] 并行预取：profile_get（档案）+ rag_search（案例检索，桶为过滤维度）
  → [编排代码] 预注入上下文（档案 + Top-K 3-5 案例 + 会话记录：桶/阶段/已展示卡内容）
  → [Agent 基座] 强制加载 emergency-consult Skill → 单轮生成完整方案
      （四段式 Pydantic 契约校验，SSE 逐 Token 返回）
  → [代码层] 确定性兜底信号后校验（见 §七）
  → 家属可选补充文字细节 → 触发精化重生成；追问轮按通用 Agent 会话组织（见 §五）
```

桶选择兼任三职：输入方式、红线分流（判定规则见[红线安全门与兜底策略](./红线安全门与兜底策略.md)）、案例检索过滤维度。

**界面形态**：桶选择为自定义界面；其余全程统一 AI 聊天容器，各层产出以 message 插入，样式分级——危机安全卡 / 阶段问题 / 红线指引用大字号强视觉样式（阶段问题内嵌 quick-reply 按钮），完整方案等事后内容用常规消息样式。

## 三、此刻安全层（代码层，零 LLM）

### 3.1 安全卡内容机制

- **卡体**：专家撰写的静态模板，按「行为桶 × 危机阶段」组织（阶段骨架为 Colvin 危机升级模型：触发/躁动/加速/高峰；高峰期只输出安全指令，主动抑制教学性内容）；
- **个性化**：档案字段确定性槽位填充，不经 LLM：

| 槽位 | 档案来源（危机预案层为主，ADR-010） |
|---|---|
| 称呼（不得以「孩子」为默认称呼） | `nickname` |
| 已知触发物（「远离 {触发物}」） | `triggers` + 事件前事记录 |
| 有效安抚方式（「拿出他的降噪耳机」） | `soothing_items`；空则推导最近 `outcome=有效` 事件 |
| 禁忌/无效方式 | `avoid_list`；空则推导最近 `outcome=无效` 事件 |
| 话术适配（无语言患者用视觉提示） | `communication_methods`（语言水平 + AAC） |
| 走失报警信息 | 走失专项组（`physical_description` / `familiar_places` / `water_risk`） |

- **内容生产**：专家撰写，作为独立内容类型复用 M3 案例库审核链路（录入 → AI 预审 → 专家终审 → 版本/下架）；无档案用户回退为纯模板（冷启动兼容）；
- **写作规范**（工程化强制）：祈使短句、一句一个动作、列表 ≤5 项、无术语无否定句、按低健康素养用户审校。

### 3.2 危机阶段判定

点选桶后立即出通用桶卡，卡上每次只挂一个单选问题（如「他现在还能听进你说话吗？」），回答后卡片按阶段替换内容。不做问卷式多题；阶段判定为代码层状态替换，零 LLM。

### 3.3 meltdown / tantrum 分流

情绪哭闹桶内以两个问题快速分流（「他这样做有没有明确想要的东西？」「满足他之后会停下来吗？」）：meltdown 路径永不推荐「故意忽视」，tantrum 路径适用不同安抚策略。分流结论注入会话记录。

## 四、走失一键应急流程

走失是唯一有明确致死数据的危机类型，走独立流程：点选走失桶后**跳过常规问答**，直接输出：

1. 报警话术模板（档案自动填充：姓名、体貌特征、诊断与无危险意识提示、常去地点/可能去向）；
2. **优先排查水体**提醒（走失相关死亡首因为溺水）；
3. 现场搜寻分工建议（一人留守、一人沿最后出现点搜索）。

该流程同时命中红线（见[红线安全门与兜底策略](./红线安全门与兜底策略.md)）：事件落库，M4 落地后追加特急工单。

## 五、完整方案层（Agent 层）

### 5.1 首份方案生成

桶与阶段确定后**后台自动触发生成**（保证「就医判断标准」段落主动到达），编排代码并行预取档案与案例、预注入上下文（含会话记录），强制加载 `emergency-consult` Skill 单轮生成，SSE 逐 Token 推送。家属补充文字细节后触发精化重生成。

### 5.2 输出契约：四段式结构（仅约束首份方案）

| 段落 | 内容 |
|---|---|
| 1. 即时安全干预动作 | 当前可立即执行的安全动作（与此刻层卡片一致并展开） |
| 2. 情绪安抚话术 | 可直接使用的安抚语言（适配语言水平与 meltdown/tantrum 分流） |
| 3. 后续观察指标 | 需要持续观察的行为/情绪指标 |
| 4. 就医判断标准 | 何种情况必须就医或联系专家（安全段落，强制输出） |

约束：每条建议必须标注来源案例/专家文章（来源溯源），并附「仅供参考，不构成医疗诊断或治疗建议」免责声明。

### 5.3 追问轮（通用 Agent 会话）

- 追问 = 同一会话内继续发消息，按通用 Agent 会话组织，**自由文本回复，不逐轮套四段式契约**；
- 追问轮放行 `rag_search` 自主调用（只读、自带权限校验），可按新细节重检索；
- 安全不变量：红线关键词门对每条用户输入生效、免责声明常驻、应急面受限自治与硬超时不变；
- 连续追问未解决（用户标记或轮次超阈值）纳入确定性兜底信号（见 §七）。

## 六、接口设计

- `POST /api/v1/consult/stream` — 应急咨询流式接口（SSE），接收桶选择/阶段回答/文字描述，返回各层产出（卡片消息 + 逐 Token 方案）
- `GET /api/v1/consult/history` — 查询当前用户的咨询历史记录
- `GET /api/v1/consult/{id}` — 查询单次咨询详情（含完整方案、引用来源与会话记录）

## 七、确定性兜底信号（取代置信度路由）

> ADR-009 第 6 条：LLM 自报置信度校准不良，兜底路由改为代码层确定性信号。`confidence_score` 字段保留落库，仅作离线观测，不驱动任何行为。

| 信号 | 判定（代码层） | 触发行为 |
|---|---|---|
| 检索质量不足 | `rag_search` 相似度低于阈值或命中数不足 | 追加强提示 + 求助指引；M4 后触发 `ticket_create`（紧急） |
| 用户标记未解决 | 家属点击「未解决」 | 同上 |
| 连续追问未解决 | 追问轮次超阈值且未标记解决 | 同上 |
| 红线命中 | 见红线安全门 | 高危桶卡 + 就医指引；M4 后特急工单 |

**MVP 阶段（M4 未落地）**：上述信号触发「强提示消息 + 求助指引消息 + 事件落库」（供 M4 冷启动），不建工单流转。信号阈值的具体数值为待明确项（§十），经线上数据校准。

## 八、数据模型（关键表）

```
consultation_sessions:                -- 一次危机会话
  - id: UUID (PK)
  - user_id: FK → users
  - profile_id: FK → profiles (nullable)    -- 关联档案（可无档案模式）
  - bucket: ENUM                          -- 行为桶（统一枚举子集：情绪崩溃/刻板行为/自伤/攻击/走失/用药相关/其他；UI 标签：情绪哭闹/刻板升级/用药，映射见个性化档案库/数据模型 §1.1）
  - crisis_stage: ENUM (nullable)           -- 危机阶段（触发/躁动/加速/高峰）
  - meltdown_type: ENUM (nullable)          -- meltdown / tantrum 分流结论
  - created_at: TIMESTAMPTZ

consultations:                        -- 会话内的一轮咨询（首份方案或追问轮）
  - id: UUID (PK)
  - session_id: FK → consultation_sessions
  - turn_type: ENUM('initial_plan','followup')  -- 首份方案 / 追问轮
  - behavior_description: TEXT (nullable) -- 用户补充的文字描述
  - retrieved_case_ids: UUID[]          -- 检索命中的案例切片 ID
  - generated_plan: JSONB (nullable)    -- 首份方案的结构化四段 {immediate_action, soothing_script, observation, medical_judgment}
  - reply_text: TEXT (nullable)         -- 追问轮自由文本回复
  - confidence_score: DECIMAL(3,2)      -- 仅离线观测，不驱动行为（ADR-009）
  - sources: JSONB                      -- 来源引用 [{case_id, expert, title}]
  - disclaimer_served: BOOLEAN
  - created_at: TIMESTAMPTZ

case_chunks (向量表):                  -- 不变
  - id: UUID (PK)
  - case_id: FK → cases
  - chunk_text: TEXT
  - embedding: vector(1024)
  - chunk_type: ENUM('scene','behavior','intervention','result')
  - metadata: JSONB                     -- {age_range, behavior_type, emotion_level}（behavior_type 为统一枚举，ADR-010 第 7 条；emotion_level 待退役对齐）

safety_cards:                         -- 此刻层安全卡（内容经 M3 审核链路生产）
  - id: UUID (PK)
  - bucket: ENUM
  - crisis_stage: ENUM (nullable)       -- 空为通用桶卡
  - card_template: TEXT                 -- 含槽位占位符的模板正文
  - review_status: ENUM                 -- 审核状态（复用案例审核状态机）
  - version: INT
  - created_at / updated_at: TIMESTAMPTZ
```

## 九、异步流与失败语义

- 每次咨询完成后，异步记录咨询日志到 `consultation_logs` 表；
- 兜底信号命中时，M4 后异步投递工单创建任务到 Redis 队列（工单预组装由 `ticket-enrich` Skill 完成）；MVP 阶段仅事件落库；
- DeepSeek API 中断：熔断降级 + 本地缓存通用建议模板，故障时返回预设安全指导（见[总体架构](../总体架构.md) §6 风险表）；**此刻安全层无 LLM 依赖，不受 LLM 故障影响**；
- 首份方案未通过四段式契约校验：阻断该次输出、记录审计日志、降级为检索结果直出模板，不允许未校验内容到达家属；追问轮回复不受契约约束，但受 Skill 安全指令与免责声明约束；
- 红线安全门判定为纯规则（0ms、无 LLM 调用，无超时语义），判定规则与红线命中行为见[红线安全门与兜底策略](./红线安全门与兜底策略.md)。

## 十、边界与约束

- **明确不做**：医疗诊断、治疗方案开具、泛心智障碍科普、替代专业人员；
- **输入形式**：桶选择 + 阶段 quick-reply + 可选文字补充；语音/图片输入为明确延期项（见[功能需求与验收](../需求/功能需求与验收.md) §五）；
- **红线会话不进入完整方案层**（ADR-009 第 4 条）；
- **合规要求**：所有建议必须附带免责声明。

## 十一、待明确项

- 「其他」桶的卡片内容策略（行为桶枚举已与档案统一，见[个性化档案库](./个性化档案库/数据模型.md) §1.1）；
- 桶 × 阶段卡片的内容生产排期与撰写责任人（依赖 M3 审核链路可用性）；
- 各桶阶段单点问题的具体清单与措辞（需专家审校）；
- meltdown/tantrum 分流两问的最终措辞；
- 确定性兜底信号的阈值数值（检索相似度、追问轮次），上线后经数据校准；
- 案例库 `case_chunks.metadata` 的「情绪等级」维度退役对齐（见 [ADR-010](../决策/ADR-010-档案四层结构与事件记录ABC标准化.md) 第 7 条，案例库侧后续项）。
