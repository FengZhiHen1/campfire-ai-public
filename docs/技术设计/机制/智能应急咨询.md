# 智能应急咨询（机制）

> **本文唯一拥有**：应急咨询链路、咨询数据模型、四段式输出契约、置信度兜底触发。
> **来源**：[references/原始设计意图/篝火智答-智能应急咨询-原始设计意图_v0.md](../../references/原始设计意图/篝火智答-智能应急咨询-原始设计意图_v0.md)（2026-05-22 用户确认）+ 原技术栈设计 §4.1 实现方案。
> **运行方式**：本模块在统一 Agent 基座上以「应急面受限自治」执行，对应 `emergency-consult` Skill，执行细节见[Agent 基座](../Agent基座.md) §五。
> 红线安全门的判定规则由[红线安全门与兜底策略](./红线安全门与兜底策略.md)拥有；档案注入规则由[个性化档案库](./个性化档案库/README.md)拥有；案例检索与切片由[标准案例库](./标准案例库/README.md)拥有。

## 一、功能定位

核心 P0 模块。基于 RAG 引擎，在孤独症人士突发行为/情绪危机时，为家属提供即时、可执行、结构化的应急干预建议。聚焦「此刻该怎么办」，不做医疗诊断、治疗方案或泛科普。

## 二、核心场景与链路

家属发现患者出现刻板行为升级、情绪失控、自伤/攻击倾向等紧急状况，打开小程序输入患者当前的行为与情绪表现。系统先经红线安全门判定（代码层纯规则），未命中红线时自动关联该患者的个性化行为-情绪档案，检索「同年龄段 + 同行为类型 + 同情绪等级」的真实干预案例，在数秒内生成结构化应急建议。

```
家属输入行为描述 → 小程序 → Nginx → FastAPI
  → [代码层·安全前置] 红线安全门判定（见红线安全门与兜底策略）
      ├─ 命中红线：仅输出安全提示 + 就医/紧急求助指引（不经 Agent；M4 后追加特急工单）
      └─ 未命中 ↓
  → [编排代码] 并行预取：profile_get（档案）+ rag_search（案例检索）
  → [编排代码] 预注入上下文（≤5 事件 + Top-K 3-5 案例）
  → [Agent 基座] 强制加载 emergency-consult Skill → 单轮生成
      （输出受四段式 Pydantic 契约校验，SSE 逐 Token 返回）
  → [代码层] 置信度后校验：< 0.7 触发 ticket_create（白名单唯一工具）
  → 小程序接收流式响应，逐句渲染
```

TTFT 工程前提与实测门禁（Agent 面相对纯管线编排开销 ≤ 1s，超标回退纯管线；绝对值目标见[需求/功能需求与验收](../需求/功能需求与验收.md) §二）见[Agent 基座](../Agent基座.md) §五。

## 三、输出契约：四段式结构

| 段落 | 内容 |
|---|---|
| 1. 即时安全干预动作 | 当前可立即执行的安全动作 |
| 2. 情绪安抚话术 | 可直接使用的安抚语言 |
| 3. 后续观察指标 | 需要持续观察的行为/情绪指标 |
| 4. 就医判断标准 | 何种情况必须就医或联系专家 |

约束：每条建议必须标注来源案例/专家文章（来源溯源），并附「仅供参考，不构成医疗诊断或治疗建议」免责声明。

## 四、接口设计

- `POST /api/v1/consult/stream` — 应急咨询流式接口（SSE），接收行为描述，返回逐 Token 生成的应急方案
- `GET /api/v1/consult/history` — 查询当前用户的咨询历史记录
- `GET /api/v1/consult/{id}` — 查询单次咨询详情（含生成的完整方案与引用来源）

## 五、数据模型（关键表）

```
consultations:
  - id: UUID (PK)
  - user_id: FK → users
  - behavior_description: TEXT          -- 用户输入的行为描述
  - retrieved_case_ids: UUID[]          -- 检索命中的案例切片 ID
  - generated_plan: JSONB               -- 结构化应急方案 {immediate_action, soothing_script, observation, medical_judgment}
  - confidence_score: DECIMAL(3,2)      -- AI 置信度
  - sources: JSONB                      -- 来源引用 [{case_id, expert, title}]
  - disclaimer_served: BOOLEAN          -- 免责声明是否已呈现
  - created_at: TIMESTAMPTZ

case_chunks (向量表):
  - id: UUID (PK)
  - case_id: FK → cases
  - chunk_text: TEXT
  - embedding: vector(1024)             -- 阿里 text-embedding-v4 输出维度，pgvector HNSW 索引
  - chunk_type: ENUM('scene','behavior','intervention','result')
  - metadata: JSONB                     -- {age_range, behavior_type, emotion_level}
```

## 六、关键逻辑

1. 接收用户输入 → Pydantic 校验 + PII 脱敏检测；
2. 红线安全门判定（代码层纯规则）：命中红线直接短路，不经 Agent；
3. 编排代码并行预取：从档案提取标签与近期事件（规则见[个性化档案库](./个性化档案库/README.md) §四）、调用 `rag_search` 做 pgvector 混合检索（向量相似 + SQL 标签过滤，Top-K 3-5）；
4. 预注入组装：系统指令（角色 + 合规声明，由 `emergency-consult` Skill 提供）+ 个性化档案 + 案例上下文 + 用户问题；
5. Agent 单轮生成（DeepSeek，SSE 逐 Token 推送），输出经四段式 Pydantic 契约校验；
6. 置信度后校验（代码层）：低于阈值（< 0.7）时追加强制免责提示，并触发 `ticket_create` 工具生成工单（见[人工兜底通道](./人工兜底通道.md)）。

## 七、异步流与失败语义

- 每次咨询完成后，异步记录咨询日志到 `consultation_logs` 表；
- 若触发兜底，异步投递工单创建任务到 Redis 队列（工单预组装由 `ticket-enrich` Skill 完成）；
- DeepSeek API 中断：熔断降级 + 本地缓存通用建议模板，故障时返回预设安全指导（见[总体架构](../总体架构.md) §6 风险表）；
- Agent 输出未通过四段式契约校验：阻断该次输出、记录审计日志、降级为检索结果直出模板，不允许未校验内容到达家属；
- 红线安全门判定为纯规则（0ms、无 LLM 调用，无超时语义），判定规则与红线命中行为见[红线安全门与兜底策略](./红线安全门与兜底策略.md)。

## 八、边界与约束

- **明确不做**：医疗诊断、治疗方案开具、泛心智障碍科普、替代专业人员；
- **输入限制**：MVP 阶段仅支持文字输入，语音与图片输入为后续拓展；
- **合规要求**：所有建议必须附带免责声明。
