# 机制：HTTP、AI 与跨域契约

> **权威范围**：`/api/v2` 业务 API 的资源寻址、请求/响应最小形状、错误与并发语义、AI 产出传输和异步事件契约。实体含义与授权状态由对应机制拥有；旧读路径与新路径的共存约束、迁移与发布门槛不归本文拥有。
> **状态**：目标设计，仓库根没有对应实现。

## 1. 总体契约

新业务使用 `/api/v2`，避免悄悄改变旧应急行为桶与四段式响应。JSON 使用 UTF-8、稳定错误码、服务端生成的 UUID、UTC ISO-8601 时间；对外 id 不包含个人姓名或诊断。写入请求带 `Idempotency-Key`、显式 `scope`、必要的 `expected_version`，同键同主体同操作同请求体在有效窗口内重复提交返回同一结果；同键不同请求体返回 409。幂等结果至少保留 24 小时，但资源本身的保留由数据生命周期机制规定。

`scope` 取 `private`（仅当前用户账号）或 `space`（必须有获准的 `space_id` 和用途）；没有支持空间的用户不能偷偷使用他人的空间 id。每个服务端读取、生成、恢复流、下载、导出和写入步骤都按当前身份与授权重新判定，不信任客户端传来的角色、对象或旧 AI 上下文。多个空间同时打开时，提交请求必须显式提供当前作用域；响应包含相同的 `scope` 与对象 id 供客户端拒绝跨对象迟到结果。

错误体统一：

```json
{"code":"GRANT_REVOKED","message":"当前无法访问这份资料","trace_id":"...","retryable":false}
```

400 格式错误，401 未登录，403 已登录但无许可，404 不可见或不存在资源（避免枚举他人对象），409 状态/幂等键冲突，412 版本不一致，422 字段校验失败，429 限额，503 必要的授权或供应商不可用。受限资源在授权库不可达时不得返回缓存的 200；公开已审阅内容可以独立返回。对不可向用户展示的内部故障，仅记录去敏 `trace_id`，不输出原始输入或他人的授权信息。

## 2. 资源族与授权范围

| 业务动作 | 资源根 | 准入条件 |
|---|---|---|
| 公开基础支持 | `/api/v2/public/support` | 无需登录，仅已发布内容 |
| 情境帮助 | `/api/v2/assist/turns` | 登录，`scope` 显式 |
| 私人事项 | `/api/v2/matters` | 登录，仅本人 |
| 空间事项 | `/api/v2/spaces/{id}/matters` | 空间授权 |
| 转入空间 | `/api/v2/matters/{id}/transfers` | 登录 + 目标空间授权 |
| 空间与授权 | `/api/v2/spaces`、`/api/v2/spaces/{id}/grants` | 合法主体或受限委托 |
| 观察与纠错 | `/api/v2/spaces/{id}/records` | 空间授权 |
| 计划与安全异议 | `/api/v2/spaces/{id}/plans`、`/api/v2/spaces/{id}/plan-items/{item_id}` | 空间授权 |
| 受限交接 | `/api/v2/spaces/{id}/handoffs` | 空间授权 + 接收者授权 |
| 证据与演练 | `/api/v2/evidence`、`/api/v2/practice` | 按阶段开放 |
| 数据权利 | `/api/v2/data-requests` | 登录 + 核验后 |
| 异步补查 | `/api/v2/operations` | 同发起请求 |

### 2.1 端点与强制边界

- `GET /api/v2/public/support?topic=<枚举>`：返回审阅版本、适用范围、更新时间与真实求助路径。
- `POST /api/v2/assist/turns`：请求含 `intent`（`prepare`、`now`、`review`、`handoff`）、`scope`、用户叙述、可选事项或空间 id、用户已知条件。返回结构化 `answer`、可核对依据、未知、限制与 `save_preview`；不自动创建事项；请求的空间未获授权则整次拒绝。
- `GET /api/v2/matters`、`POST /api/v2/matters`、`GET/PATCH/DELETE /api/v2/matters/{id}`：创建需 `preview_id`、`expected_preview_version` 与核对后修改的字段，生成 `private` 草稿，仅本人可回访；幂等提交不产生两个草稿；删除进入数据生命周期处置。
- `GET/POST /api/v2/spaces/{id}/matters`、`GET/PATCH /api/v2/spaces/{id}/matters/{matter_id}`：只保存本空间已获准资料与本次核对内容，按关系范围供成员查看；不能经私人端点复制空间来源以规避撤销。
- `POST /api/v2/matters/{id}/transfers`：请求含目标 `space_id`、逐项内容选择与确认。只有目标空间允许的内容进入新记录，原私人事项仍独立；未核验关系、任一条越权或版本冲突时不发生部分公开。
- `POST/GET /api/v2/spaces`、`GET /api/v2/spaces/{id}`、`GET/POST /api/v2/spaces/{id}/grants`、`POST /api/v2/spaces/{id}/grants/{grant_id}/revoke`：创建、委托与撤销在同一事务写审计和新授权版本；核验未通过不建立可共享空间；扩权或再委托返回 403。
- `GET/POST /api/v2/spaces/{id}/records`、`GET /api/v2/spaces/{id}/records/{record_id}`、`POST /api/v2/spaces/{id}/records/{record_id}/corrections`、`POST .../corrections/{correction_id}/resolve`：新观察带作者、来源、时间与情境；纠错提议经有权者处理后新增版本而非覆盖原文；错归个人信息先阻断分发；AI 整理未核对仅为草案。
- `GET/POST /api/v2/spaces/{id}/plans`、`GET .../plan-items/{item_id}`、`POST .../plan-items/{item_id}/confirm`、`POST .../plan-items/{item_id}/objections`、`POST .../objections/{objection_id}/resolve`：类型、审阅层级、确认者与版本明确；正式异议的成功响应前条目已停用；提交者不能经异议获得替代发布权。
- `POST /api/v2/spaces/{id}/handoffs/previews`、`POST .../handoffs/{handoff_id}/send`、`GET .../handoffs/{handoff_id}`：预览只取接收者当前可见内容；再次核验授权与来源并通过发送人明确确认后才站内发送；已受理不等于已送达。
- `GET /api/v2/evidence`、`GET /api/v2/evidence/{source_id}`、`GET /api/v2/practice/scenarios`、`POST /api/v2/practice/scenarios/{scenario_id}/attempts`、`POST/GET /api/v2/data-requests`、`GET /api/v2/data-requests/{request_id}`：只对获批资料检索与训练；导出删除请求返回任务 id 与可追查状态，不假装外发副本被收回。
- `GET /api/v2/operations/{id}`：补查超预算的异步操作。

这些端点是业务契约族，不规定网页布局或 Python 函数签名。每个 `save_preview` 由服务端返回 `preview_id`、`preview_version`、作用域、来源版本与失效时间；用户编辑字段后，创建请求引用该预览并由服务器重新验证来源、授予版本、保存用途和内容类别。过期、来源撤下或期间撤权则返回 412/403，不能用私人端点绕过空间来源，创建幂等失败不得留下半份事项。除公开内容外，受控试点阶段的登录、身份校验、请求限额和供应商数据告知均必须在真实资料输入前可验证。

## 3. AI 产出与异步通知

情境回答的操作状态为 `pending`、`completed`、`failed` 或 `cancelled`。简短请求可一次返回 200 的完整结果；超预算时返回 202 及 `operation_id`，由 `GET /api/v2/operations/{id}` 补查。只有完成身份、范围、资料来源和内容限制的服务端校验后才发布用户可执行建议；耗时期间只显示非行动性的等待状态及已审阅的基础内容，不能先流出尚未校验的医学或控制建议。旧 `/api/v1` 不属于本契约。

已完成的 `answer` 至少区分 `facts_from_user`、`unknowns`、`options`、`supporting_sources`、`limitations`、`save_preview` 和 `review_state`。引用绑定具体主张与可见来源版本；无资料、模型失败或检查不通过时，不制造格式正确但缺依据的肯定建议，只返回公开基础内容、已获准且当前有效的计划和现实求助路径。`save_preview` 从不等于已保存的个人记录。

异步通知包含 `operation_id`、资源 id、资源版本、事件类别和去敏摘要；队列至少一次投递，消费者按资源与版本去重。索引、通知或衍生材料撤下的后台失败不能撤销主事务已完成的关系撤销或条目停用；读取路径必须以主库最新状态过滤不合格结果。通知只发给当前获授权且确有职责的接收者，失败时保留重试状态而不伪报已送达。

## 4. 并发、取消与授权变化

- 所有共享写入带 `expected_version`；两人并发确认、纠错或撤销时，先提交者更新版本，后提交者收到 412 并重新核对，不用最后写入覆盖别人意见。
- 创建草稿、提交异议、撤销授权和审核发布都要求幂等键；重复异议不会使状态在停用与恢复之间振荡。事务必须先持久化关键状态，再发送成功响应。
- 用户取消生成时尽力停止模型与扣费，但已发送的外部请求无法保证收回；取消后的迟到结果不得保存为事项或出现在新空间页面。
- 生成期间授权被撤销、条目被停用或依据被撤下时，最终校验失败并阻止发布；补查、重连和浏览历史均重新核验，不能用创建请求时的旧许可继续分发。

## 5. 验证合同

契约测试须覆盖未登录静态内容、登录无空间的 AI、相同幂等键重试、同键不同体 409、失效授权 403/404、并发版本 412、停用成功响应前旧条目不再分发、生成中撤销后的迟到输出、Worker 重放与断网取消。故意禁用授权库和模型分别验证拒绝受限访问与公开基础内容继续可达。接口字段最终以可执行的 schema 与测试为规格；实现前的增减必须回到对应需求和机制核对，不能用前端适配静默改变业务边界。
