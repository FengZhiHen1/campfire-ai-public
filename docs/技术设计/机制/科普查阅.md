> **历史科普 RAG/SSE 路径**：当前公开内容与引用必须审核并受[目标证据机制](../目标机制/证据供给演练与复盘.md)约束；未登录仅可访问已审阅内容，不直接复用旧 SSE 生成。下文“唯一拥有”仅指旧机制组内部。

> **本文唯一拥有**：科普 RAG 形态、内容边界、应急引导与文章数据模型。
> **来源**：存档 references/原始设计意图/篝火智答-科普查阅-原始设计意图_v0.md（2026-05-22 用户确认）+ 原技术栈设计 §4.5 实现方案。
> **运行方式**：科普问答由 Agent 基座异步面的 `knowledge-qa` Skill 执行（含 `knowledge_search` 工具与关联案例推荐），SSE 流式输出由基座驱动（执行策略由 Agent 基座文档拥有）。

## 一、功能定位

P2 附带功能模块。基于 RAG 系统为平台用户提供孤独症相关的基础科普内容查询服务，涵盖术语解释、干预方法介绍、诊断标准说明和康复指南。采用 SSE 流式输出，无特殊格式约束。不做平台主入口，作为应急咨询的辅助与延伸。

**目标用户**：与智能应急咨询一致（家属 + 志愿者）。老师/专家为供给侧角色，不消费需求侧功能（由认证与访问文档 §六 RBAC 矩阵定义）。

## 二、核心场景

1. **日常知识查询**：家属/志愿者在日常非紧急场景下，查询孤独症相关术语、干预方法、诊断标准或康复指南；
2. **案例延伸学习**：获取科普回答的同时，系统自动推荐相关的真实干预案例，帮助用户从「知道」延伸到「看到怎么做」；
3. **紧急场景引导**：当用户输入涉及紧急/危机状况时，系统主动识别并引导至智能应急咨询模块获取即时建议。

## 三、关键功能点

1. **科普问答**：基于 RAG 引擎回答孤独症基础知识问题；
2. **内容覆盖**：术语解释、干预方法介绍、诊断标准（如 DSM-5）、康复训练指南；
3. **案例自动推荐**：科普回答中自动关联并推荐相关的真实干预案例；
4. **应急引导**：检测到紧急/危机关键词时，主动提示并支持一键跳转至应急咨询模块；
5. **SSE 流式输出**：采用 Server-Sent Events 实现流式回答生成（由 Agent 基座的流式能力驱动）；
6. **无格式约束**：回答以清晰说明型自然语言段落呈现，不做严格的结构化格式要求（与应急咨询的四段式契约不同）。

## 四、接口设计

科普问答端点遵循 AI 服务接口契约文档：执行引擎为异步面 `knowledge-qa` Skill，接口形态为生成型流式（执行面与接口形态解耦，用户在线等待）；文章列表/详情/搜索为普通 REST，不引入流式：

- `POST /api/v1/knowledge/ask` — 科普问答创建端点，返回 `task_id`；流式回答（`chunk`）与关联案例推荐（`result`）经任务事件流返回
- `GET /api/v1/tasks/{task_id}/events` — 事件流连接（生成型：`chunk`/`result`/`done`/`error` + 心跳）
- `GET /api/v1/knowledge?category={category}&page={n}` — 科普文章列表
- `GET /api/v1/knowledge/{id}` — 文章详情（含关联案例链接）
- `GET /api/v1/knowledge/search?q={keyword}` — 全文搜索（PostgreSQL `ts_vector` 中文分词）

## 五、数据模型

```
knowledge_articles:
  - id: UUID (PK)
  - title: VARCHAR(200)
  - category: VARCHAR(50)
  - content: TEXT
  - related_case_ids: UUID[]
  - search_vector: TSVECTOR          -- PostgreSQL 全文检索
  - published_at: TIMESTAMPTZ
```

## 六、边界与约束

- **入口边界**：不做平台主入口，定位为应急咨询的辅助功能；
- **场景边界**：不处理紧急应急场景，识别到后引导至应急咨询模块；
- **内容边界**：限于基础科普范畴，不提供医疗诊断或治疗建议；
- **输出边界**：无特殊格式约束，以清晰可读的自然语言为主；
- **知识来源**：独立维护的科普知识库，与案例库分离、各自独立更新。

## 七、依赖项

- 统一 Agent 基座（`knowledge-qa` Skill 与 `knowledge_search` 工具，执行策略由 Agent 基座文档拥有）
- 独立维护的科普知识库
- 标准案例库文档（自动推荐关联案例）
- 智能应急咨询文档（紧急场景的跳转目标）

## 八、待明确项

- 科普知识库的具体内容来源与更新维护机制（由谁录入、审核、更新）；
- 紧急/危机关键词的识别规则与触发阈值（现行红线关键词机制由红线安全门与兜底策略文档定义，科普侧的复用方式未定）；
- 案例自动推荐的排序逻辑（按相关度、时效性、专家认可度还是其他维度）。
