# 机制设计

> **目标**：定义各功能模块的机制、数据模型、接口契约、状态流转与失败语义。
> **状态**：技术基线。内容源自 2026-05 各模块设计对话的确认结论与细节设计（原稿见 [references/原始设计意图/](../../references/原始设计意图/)），并按 [ADR-003](../决策/ADR-003-向量检索-pgvector.md) 统一为 PostgreSQL + pgvector、按 [ADR-007](../决策/ADR-007-Agent化-统一基座与分面自治.md) 对齐 Agent 化运行方式。
> **Agent 化说明**：本文档组描述「做什么」，Agent 化的「怎么跑」（统一基座、工具注册中心、Skill 目录、分面执行策略）由[Agent 基座](../Agent基座.md)拥有。

## 推荐阅读顺序

按业务链路阅读：

1. [智能应急咨询](./智能应急咨询.md)：核心 P0，Agent 应急面的受限自治链路；
2. [危机分级与兜底策略](./危机分级与兜底策略.md)：应急咨询的安全前置（代码层，Agent 不可触碰）；
3. [个性化档案库](./个性化档案库/README.md)：应急咨询的个性化检索透镜（代码预取 + 预注入）；
4. [标准案例库](./标准案例库/README.md)：RAG 的主知识燃料，案例生产由 case-extraction Skill 驱动；
5. [人工兜底通道](./人工兜底通道.md)：P2（延后，初期专家资源整合途径不明），工单生成与预组装由 ticket-enrich Skill 驱动；
6. [科普查阅](./科普查阅.md)：P2，由 knowledge-qa Skill 驱动的轻量科普。
