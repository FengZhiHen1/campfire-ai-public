## 一、目标态

1. **物理五层**（`src/domain/`、`src/application/`、`src/viewModel/`、`src/view/`、`src/infrastructure/`），层内按特性组织（consult/profiles/cases/tickets/auth/shared），依赖方向严格单向：view → viewModel → application → domain；infrastructure 实现 application 端口 + domain Mapper；
2. **特性面**（ADR-006/012/014 收束）：consult + profiles（需求侧）、cases + tickets（供给侧）、auth（登录/注册/准入）；路由按角色收敛导航（S1 已建，迁移确认）；
3. **ts-shared 扩展**：六角色/账号状态/行为桶与 ABC 枚举/时刻分层契约（安全卡/阶段问题/兜底信号）/新 API DTO——后端契约变更同步（S1/S3/S4 已陆续同步，本轮收口）；
4. **删除 mock**（D8）：`services/mock/` 全部移除，infrastructure 只保留真实 HTTP 实现；开发环境依赖 `docker compose up -d` + api-server；
5. **auth/应急/档案前端资产**（S1/S3/S4 按五层与目标交互新建）迁移到位，与后端终态契约对齐。

## 二、现状与差距

| 现状 | 差距 |
|---|---|
| `src/logics/`（hooks/services/store/types）与 `src/views/` 两层，98 个 ts 文件 | → 五层目录重组，logics/views 拆解归位 |
| 服务层（`logics/*/services/`）直连 HTTP + 共享 `httpClient`/`tokenManager` | → infrastructure：`repositories/`（IXxxRepository 实现）+ `http/`（client/token 刷新）+ `mappers/`（DTO↔domain） |
| `logics/*/store/`（useConsultStore/profileStore/userStore/stateMachine）+ hooks | → viewModel：Hooks + Zustand store（跨介质 UI 状态）；domain 实体不依赖框架 |
| `views/*` 页面直接 import 服务与 store | → view 只经 viewModel Hooks 获取能力；Props 契约收敛到 `view/contracts/` |
| mock 服务（shared/services/mock：mockDatabase/mockRouter/mockSseSimulator/seedData + handlers） | → 删除（D8） |
| 路由无统一守卫（S1 已建 auth 守卫，其余页面未挂） | → router.tsx 全量收敛：登录守卫 + 角色收敛导航 |
| ts-shared 仅 cases/profiles/common | → 补齐 consult/auth/tickets 类型与枚举（与后端契约 1:1） |
| 无前端测试设施 | → 不引入新测试框架（保持 lint/build 门禁；契约校验靠 ts-shared 类型 + pnpm build） |

## 五、风险与注意

- **层间依赖纪律**：view 不得直接 import application/infrastructure；违反点以 lint 规则或 import 检查脚本兜底（参照《组织与工程约定》§十二）；
- **存量迁移逐特性进行**：consult → profiles → cases → tickets → shared，每特性迁移完即删对应 logics/views 旧件，保持可构建；
- S1/S3/S4 已按五层新建的 auth/应急/档案资产直接复用，不重复开发；若其结构与本阶段终态不一致，按终态调整（允许小幅迁移）；
- 前端测试设施不在本轮引入（AGENTS：禁止无关第三方依赖）；契约正确性由 ts-shared 类型 + build 门禁保障。
