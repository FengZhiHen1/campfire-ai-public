2. **agent_bootstrap（双端）**：api-server（应急面）与 worker（异步面）显式声明扩展清单与加载顺序（**security 首位**）+ 启动断言（缺失即拒绝启动）+ 面白名单注入（按工具名寻址）；断言自检代码 + 测试；

6. **SSE 完善**：内核事件总线 → SSE 全链路（审计、Token 追踪贯通）；
7. **py-llm 退役**：删除包、移除 workspace 成员与依赖；LangChain 无残留；
8. **可观测与评测**：工具调用审计（trace_id 贯通）、Token 按 Skill/面聚合、eval 集（emergency-consult/case-extraction/review-assist 完整；其余骨架）、内核批量评测入口接入。

## 五、风险与注意

- **扩展间零 import 是硬约束**：case 的 rag_search 被 emergency 白名单消费（寻址按工具名），不产生跨扩展 import；复用逻辑下沉内核或消费能力包；
- **安全不让渡**：红线门/权限/PII 全部在扩展事件 handler 中（扩展即代码层），LLM 不可触碰；S3 的代码层临时校验迁移到 security 扩展时保持行为等价（回归红线用例）；
- **case 迁移期间双轨**：先落 worker 任务与队列，再切 api-server 调用点，最后删旧实现；每个子步骤保持测试绿；
- ticket/knowledge 骨架不得包含未规划业务逻辑（「不为未规划功能预留代码实现」），只含契约与最小占位；
- 现有 `py_rag.indexing.worker`（api-server 内嵌协程）与独立 worker 应用并存：本轮以独立 `apps/worker` 为准，内嵌协程随 case 迁移移除。
