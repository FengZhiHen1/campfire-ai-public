# 阶段 3 · 应急时刻分层（emergency + crisis）

> **⚠️ 历史执行记录，不是当前计划**：行为桶、四段式与旧风险路由不是 v3 目标，见[情境支持机制](../目标机制/情境支持与事项.md)；不得按本文继续推进旧目标。

> **目标态依据**：ADR-008、ADR-009、《机制/智能应急咨询》（本文唯一拥有时刻分层链路/桶与阶段体系/安全卡槽位/会话模型/四段式契约/兜底信号）、《机制/红线安全门与兜底策略》（红线判定规则/命中行为/软兜底）、《AI服务接口契约》（SSE 协议）
> **前置**：S1（守卫）、S2（内核）。**衔接 S4**：安全卡槽位填充接口本阶段定义，档案数据源在 S4 落地后接线（空档案回退纯模板）。
> **状态**：【已完成】（2026-08-04，验证门全绿）

## 一、目标态

1. **模块重组**：`app/modules/consultation/` → `app/modules/emergency/`（与机制模块 1:1）；`crisis` 模块重写为红线安全门 + 此刻安全层；
2. **红线安全门**（代码层零 LLM，0ms）：
   - 桶分流：点选自伤/攻击/走失/用药 → 直接命中红线；
   - 关键词硬拦截 + 否定词过滤（没有/不会/以前）+ 档案叠加（历史自伤/攻击记录 + 又/再次/还是）；
   - 输出契约：`gate_result`（redline/pass）+ `gate_trigger`（规则 ID，如 `KW_SELF_HARM_001`/`BUCKET_ATTACK`/`PROFILE_RECURRENCE`）；
   - 命中行为：高危桶卡（专家审核静态内容 + 档案槽位）+ 就医/紧急求助指引（标红置顶），**不进入完整方案层**；红线事件落库；走失桶走独立一键流程（报警话术模板 + 优先排查水体 + 搜寻分工）；
3. **此刻安全层**（代码层零 LLM）：0 输入通用安全卡 → 桶选择 → 桶专属安全卡（模板 × 槽位）→ 阶段单点问题（每次一问 quick-reply，代码层状态替换）→ meltdown/tantrum 分流（情绪哭闹桶内两问）；卡片为 `safety_cards` 静态模板（桶 × 阶段 + 走失），槽位填充接口按《机制/智能应急咨询》§3.1 定义（称呼/触发物/安抚物/禁忌/话术适配/走失信息），S4 接档案数据源；
4. **完整方案层**（Agent，受限自治）：编排并行预取（profile_get + rag_search，桶为检索过滤维度）→ 预注入（档案 ≤5 事件 + Top-K 3-5 案例 + 会话记录：桶/阶段/已展示卡）→ 强制加载 `emergency-consult` Skill → 单轮生成四段式（即时安全干预动作/情绪安抚话术/后续观察指标/就医判断标准），Pydantic 契约校验，SSE 逐 Token；首份方案 max_steps=1、硬超时、工具白名单 `rag_search`+`ticket_create`（追问轮才放行 rag_search 自主调用）；
5. **追问轮**：同会话继续，通用 Agent 会话（自由文本不套契约），红线关键词门对每条输入生效、免责声明常驻；
6. **确定性兜底信号**：检索质量不足（相似度/命中数阈值）/用户标记未解决/连续追问超阈值 → 强提示 + 求助指引 + 事件落库（M4 前不建工单）；`confidence_score` 保留落库仅离线观测，**废除置信度路由**（删除 confidence_validator/ticket_trigger 的驱动逻辑）；
7. **数据模型**：`consultation_sessions`（bucket/crisis_stage/meltdown_type）+ `consultations`（turn_type/retrieved_case_ids/generated_plan JSONB/reply_text/sources/disclaimer_served）+ `safety_cards`（审核状态机复用案例审核链路）+ `consultation_logs`；`case_chunks.metadata` 的 `emotion_level` 退役对齐（检索过滤统一为年龄段+行为桶）；
8. **SSE**：`core/streaming` 改由内核事件总线驱动（S2 流式装配 → text/event-stream），协议按《AI服务接口契约》（chunk/result/done/error + 心跳 + Last-Event-Id 续传）；
9. **agent_bootstrap**：`app/core/agent_bootstrap.py` 建立——应急面扩展清单（security 首位）+ 启动断言 + 面白名单注入（S3 仅注册 security 扩展与应急面所需能力，扩展全量在 S5）；
10. **内容**：`safety_cards` 内置占位模板（seed，标注「待专家撰写」）（D7）；卡片内容管理走 M3 审核链路（录入→AI 预审→专家终审→版本/下架），本阶段实现数据模型与供给 API，预审环节的 Agent 化在 S5。
