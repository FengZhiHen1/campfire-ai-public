## 三、当前阻塞点（续跑第一优先级）

**现象**：`test_profiles_integration.py` 运行超时（300s+），前 5 个用例（档案 CRUD/隐私隔离/事件双模式/专业评估/关联解除）已通过。

**根因分析**：新写的 3 个槽位衔接测试（`TestSlotFillingIntegration`）经 SSE 事件流断言卡内容。`_collect_events` 用 `client.stream(...)` + `iter_lines()` 读取——**TestClient 对长连接 SSE 流的读取在非终态会话（阶段问答等待中，无 done/error）会挂住**，即使设了 deadline（`iter_lines()` 阻塞式读不受 deadline 控制）。已加 `stop_on="safety_card"` 提前返回参数，但单测仍超时（exit=124）——**疑似 stop_on 修改未生效或流建立前就挂起**，未定位完成。

**建议修复路径（按序尝试）**：
1. 首选：**放弃 SSE 流断言，改为直接断言 hub 缓冲**。`ConsultStreamHub` 的 `_SessionStream.events` 是内存列表——测试中 `POST /stream` 返回后，直接从 `get_stream_hub().get_or_create(session_id).events` 读已发布事件断言卡内容（同步、无流阻塞）。
2. 备选：给 `_collect_events` 的 `iter_lines` 加 read timeout（TestClient stream 支持 `timeout` 参数于 client 构造）。
3. 修复后跑 `uv run pytest apps/api-server/tests/integration/test_profiles_integration.py`，全绿即提交 S4 应用层 + 测试。
