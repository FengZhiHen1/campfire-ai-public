# 阶段 1 · 认证重构

> **目标态依据**：ADR-013、《机制/认证与访问》（本文唯一拥有身份模型/状态机/RBAC 矩阵/Token 家族/迁移设计的语义）
> **状态**：【已完成】（2026-08-04，验证门全绿）

## 一、目标态

1. **身份-凭证分离**：`User`（phone/real_name/role/status）+ `Credential`（type: password/wechat / identifier / secret），唯一约束 `(type, identifier)` 与 `User.phone`；
2. **六角色显式 RBAC**：family/volunteer/teacher/expert/admin/maintainer，单角色互斥，角色→能力显式映射（矩阵见《机制/认证与访问》§六），废除五级数值继承（`DefaultRBACGuard` 的 `min_level` 语义）；
3. **准入状态机**：family/volunteer 注册即 `active`；teacher/expert 提交实名+资质 → `pending_review` → 管理员审核 → `active`/`rejected`（可补材料重提）；`disabled` 由管理员禁用/恢复；
4. **邀请码制**：`invite_codes`（code 8-12 位 / channel: demand/supply / max_uses / used_count / expires_at / status / created_by），注册原子消费（条件自增防并发复用）；
5. **手机号登录标识**：废除 `username` 与 `device_id`；登录失败统一 401（防枚举）；
6. **Token 家族**：JWT 双 token + 轮换 + 复用检测（旧 refresh 复用 → 全家族吊销）；
7. **微信渠道预留**：`Credential.type='wechat'` + 绑定合并流程（短信验证延后），本期不实现 code2session；
8. **全站守卫**：废除 `get_anonymous_user` 演示轨，业务路由全部挂 `get_current_user` / `require_roles`；
9. **前端 auth 特性**：登录/注册（含邀请码与角色选择）/准入状态页/管理员审核与邀请码管理页——**按五层结构新建**（domain/application/viewModel/view/infrastructure），为 S6 五层重组铺路；路由守卫 + 角色收敛导航。

## 二、现状与差距

| 现状 | 差距 |
|---|---|
| `users` 单表（username/password_hash/role 五角色/phone/real_name） | → User + Credential + InviteCode 三表；role 枚举补 volunteer；phone 为唯一登录标识 |
| `py-auth/rbac.py` 五级数值继承（`min_level`） | → 显式角色→能力映射矩阵 |
| `get_anonymous_user` 演示轨（8 文件引用：main/routes 等） | → 全部废除，改正式守卫 |
| auth 模块已有 register/login/refresh/logout（正式 JWT 轨，前端未用） | → 保留骨架，按新模型重构：注册加邀请码、登录改手机号、新增准入审核/邀请码管理/me 端点 |
| `py-auth/jwt_utils.py` JoseTokenManager、`blacklist.py` RedisBlacklist | → 增强：refresh 轮换 + 复用检测 + 家族吊销 |
| 前端无登录/注册界面，路由无守卫 | → 新增 auth 特性（五层结构）+ 路由守卫 |
| `py-schemas/auth.py` 旧 DTO（username 语义） | → 重写（RegisterRequest 含邀请码/角色/real_name 条件必填、准入审核 DTO、角色六枚举） |

## 四、接口契约变更（影响面）

- `POST /api/v1/auth/register`：入参增 `invite_code`、`role`、`real_name`（teacher/expert 必填）；`username` 字段废除
- `POST /api/v1/auth/login`：`username` → `phone`
- 新增：`POST /api/v1/auth/invite-codes`、`GET /api/v1/auth/invite-codes`、`POST /api/v1/auth/invite-codes/{code}/revoke`、`GET /api/v1/auth/reviews`、`POST /api/v1/auth/reviews/{user_id}/approve|reject`、`POST /api/v1/auth/reviews/{user_id}/resubmit`、`GET /api/v1/auth/me`
- 全站受保护路由由匿名可访问变为需登录（`get_anonymous_user` 废除）
