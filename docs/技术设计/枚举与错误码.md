# 枚举与错误码

> **权威范围**：`/api/v2` 的业务错误码取值集合、全部状态与分类枚举、列表分页与幂等细则、超时与预算阈值。错误体形状、HTTP 状态映射与端点寻址由[接口契约](./机制/接口契约.md)拥有；各对象的业务语义与失效规则由对应机制拥有；本文只定义**取值**。
> **追溯**：`RQ-SP-02～04`、`RQ-REC-02`、`RQ-CTX-05`、`RQ-PLAN-03`、`RQ-OPS-03`、`AC-SP-05`、`AC-OPS-02`、`AC-NOW-01`。
> **状态**：目标设计，未实现。取值来源分两类：**「原文」**=机制文档或需求已给出的取值；**「待确认」**=本次为消除实现歧义提出的候选，需用户确认后才构成约束。所有枚举的增改必须回到对应机制文档核对，不得由前端适配或实现便利静默扩展。

## 1. 错误码

错误体统一为 `{"code": "...", "message": "...", "trace_id": "...", "retryable": false}`。`code` 取值如下（HTTP 映射见接口契约 §1）：

| code | HTTP | retryable | 触发场景 |
|---|---|---|---|
| `SCOPE_REQUIRED` | 400 | false | 写入或生成请求未显式携带 `scope` |
| `SCOPE_MISMATCH` | 400 | false | 多个空间同时打开但提交未指明当前作用域，或响应所属对象与请求作用域不一致 |
| `VALIDATION_FAILED` | 422 | false | 字段校验失败 |
| `PROHIBITED_CONTENT` | 422 | false | 输出或提交命中禁止内容清单（诊断、用药决策、身体控制、强制惩罚） |
| `UNAUTHENTICATED` | 401 | false | 未登录或凭证失效 |
| `SPACE_NOT_VERIFIED` | 403 | false | 空间仍处于 `pending_verification` |
| `GRANT_NOT_ACTIVE` | 403 | false | 无 Grant、未接受、已过期或已撤销 |
| `GRANT_SUSPENDED` | 403 | false | 争议冻结或上游失效 |
| `CATEGORY_NOT_GRANTED` | 403 | false | 请求的信息类别不在授权类别集合内 |
| `ACTION_NOT_GRANTED` | 403 | false | 请求的操作不在授权操作集合内 |
| `DELEGATION_EXCEEDED` | 403 | false | 受托人超出委托范围或自我提权 |
| `NOT_FOUND_OR_HIDDEN` | 404 | false | 资源不存在或不可见（避免枚举他人对象） |
| `PREVIEW_EXPIRED` | 412 | false | `save_preview` 或交接预览已过期/来源已撤下 |
| `VERSION_CONFLICT` | 412 | false | `expected_version` 或 `expected_preview_version` 不匹配 |
| `IDEMPOTENCY_CONFLICT` | 409 | false | 同一幂等键携带不同请求体 |
| `ITEM_SUSPENDED` | 409 | false | 目标计划条目已停用，不可作为当前建议分发 |
| `SOURCE_WITHDRAWN` | 409 | false | 依赖来源已撤下 |
| `RATE_LIMITED` | 429 | true | 限流 |
| `BUDGET_EXCEEDED` | 429 | true | 模型调用预算用尽 |
| `AUTH_STORE_UNAVAILABLE` | 503 | true | 授权库或主库不可达，受限操作 fail-closed |
| `MODEL_UNAVAILABLE` | 503 | true | 模型不可用，转公开基础内容 |
| `OPERATION_PENDING` | 202 | true | 超预算转异步，携带 `operation_id` |

新增码必须先在本文登记；实现中不得出现本文未定义的 `code`。`message` 面向用户，不得包含原始输入、他人授权信息或供应商原文。

## 3. 授权维度集合

授权判定取所有适用条件的**交集**，未明确的类别或动作一律拒绝（空间授权 §3）。以下三个集合必须封闭，新增值先在本节登记：

| 集合 | 取值 | 来源 |
|---|---|---|
| `actions[]` | `matter.read`、`matter.write`、`matter.delete`、`matter.transfer`、`record.read`、`record.create`、`record.correct`、`record.resolve`、`plan.read`、`plan.confirm`、`plan.object`、`plan.resolve`、`grant.read`、`grant.create`、`grant.revoke`、`handoff.preview`、`handoff.send`、`handoff.read`、`evidence.read`、`practice.attempt`、`data_request.create`、`data_request.read` | 待确认（按接口契约 §2 端点族推导） |
| `categories[]` | `basic_profile`、`observation`、`plan`、`handoff_material`、`contact`、`public_safety`、`evidence` | 待确认（按信息性质与页面“允许查看的信息类别”推导） |
| `purpose` | `daily_care`、`education`、`medical_prepare`、`temporary_handoff`、`practice` | 待确认（按四种场景闭环与演练推导） |

`Grant` 的期限与续期上限（临时支持者 7 天、受限管理员 90 天）由空间授权机制拥有，不在本文重复。

## 5. 分页、幂等与阈值

### 5.1 列表分页

全部列表端点统一采用游标分页：`?limit=<1..100，默认 20>&cursor=<opaque>`，响应含 `items`、`next_cursor`、`has_more`。排序键稳定为 `(created_at DESC, id DESC)`；不接受客户端指定排序字段，避免把未授权资源通过排序探测出来。过滤参数按端点在接口契约中声明。

### 5.2 幂等细则

- 幂等键作用范围为 `(account_id, method, path, body_hash)`；跨 `scope` 或跨主体视为不同操作。
- `GET`/`HEAD` 不要求也不消耗幂等键。
- 仅 2xx 与 `409`/`412` 结果被记录；`401`、`403`、`429` 不消耗键、不覆盖已有记录。
- 同键同主体同操作同请求体在 24 小时内返回首次结果；同键不同体返回 `IDEMPOTENCY_CONFLICT`。
- 该 24 小时是**幂等窗口**，与临时会话 24 小时 TTL 是不同常量，不得合并。

### 5.3 超时、预算与有效期

| 项 | 取值 | 来源 |
|---|---|---|
| 单次模型调用超时 | 20 秒，最多重试 1 次，仍失败转 `MODEL_UNAVAILABLE` | 待确认（需求第九节的 20 秒为退化阈值） |
| 完整校验结果目标 | P95 ≤15 秒；超过 20 秒转 `OPERATION_PENDING` 或已审阅内容退化 | 原文（需求第九节） |
| 公开基础内容 | P95 ≤2 秒可读 | 原文（需求第九节） |
| 旧流式指标（TTFT P50 ≤3s、P95 >5s 告警、chunk P95 ≤2s） | 仅作旧交互对照候选，不用于新 `/api/v2` 放行 | 原文（需求第九节、EVID-05） |
| `save_preview` 有效期 | 30 分钟 | 待确认（与临时会话闲置时限对齐） |
| `Handoff` 有效期 | 默认 7 天，且不得超过接收者 Grant 剩余期限 | 待确认 |
| `operation` 保留时长 | 24 小时 | 待确认（与幂等窗口对齐） |
| `DataRequest.due_at` 默认 | 30 天 | 待确认；`EVID-07` 审定前不得对真实用户承诺 |

## 6. 命名统一说明（消除既有冲突）

以下四处原有表述冲突，按本节统一，其余文档不再各自表述：

1. **事项保存结果**：统一用 `private_draft` / `space_draft` 表示状态；`private` / `space` 仅作 `scope` 取值。接口契约中“生成 `private` 草稿”已改为“生成 `private_draft`”。
2. **孤立状态 `ready_for_review`**：删除。事项状态集合为 `private_draft`、`space_draft`、`closed`；需要专业审阅的语义由 `PlanItem.state` 表达，事项不重复引入审阅状态。
3. **衍生材料失效**：统一以 `Artifact.state`（`valid`/`stale`/`invalidated`）表达“当前是否可作为依据”；`Handoff.status = invalidated` 与 `PlanItem.state = suspended` 是各自对象的具体取值，不作为第三套词汇。**来源停用、授权撤销与条目停用都不在 Artifact 上复制第二份状态**，读取时按依赖的当前状态判定。
4. **计划条目的“已确认”**：计划条目的“已确认可分发”取值是 `active`，**不存在** `confirmed` 状态。[视觉契约](../design/components.html)的 `.state-badge--confirmed` 与文案“已确认”是展示层用词，对应 `PlanItem.state = active`；视觉侧缺失 `superseded`/`retired` 的表示由页面设计补充，机制状态集合不为此改值。注意 `confirmed` 确为 `Handoff.status` 的合法取值（交接已确认待发送），两者对象不同，不得互换。

## 已知偏差与证据边界

- 标注「待确认」的取值是本次为消除实现歧义提出的候选，尚未经用户确认，不构成约束；确认后本标注应删除。
- 禁止内容清单本身（ADR-016 要求由业务代码强制）仍无权威所有者与版本，需专业审阅签收；本文只定义其触发的错误码 `PROHIBITED_CONTENT`。该缺口登记于[设计待办](../TODO.md)。
- 删除墓碑与计划条目依赖的形状未在任何文档中定义，本文不代为发明；二者被迁移与计划机制依赖，缺口同样登记于待办。
- 视觉侧仅定义三种状态徽章，未覆盖 `superseded`/`retired`；该缺口属页面设计范围，不在本文调整机制取值。
