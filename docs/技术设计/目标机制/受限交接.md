# 目标机制：受限交接

> **权威范围**：交接接收者、最小必要资料预览、用户确认、站内送达、版本失效与失败重试。关系授权由空间授权机制判定；计划条目有效性由计划机制判定；HTTP 外壳由接口契约拥有。
> **追溯**：`RQ-HAND-01`、`RQ-SP-03～04`、`RQ-PLAN-03`、`AC-HAND-01`。
> **状态**：目标机制；实时专家接单与站外联络未纳入当前发布能力。

## 1. 对象与不可越权边界

`Handoff` 包含 `handoff_id`、`space_id`、关联事项、发起人、明确接收用户、接收者职责与用途、选择的信息字段和来源版本、当前有效计划条目版本、发送确认人/时间、有效期、授权版本、状态及送达回执。接收者必须已经在当前 Space 接受了与交接用途匹配的 Grant；用户输入任意邮箱/手机号不构成可发送渠道，未登记的专家也不因被称作“专家”可接收。

每个候选字段取发送者可分享范围、接收者可读范围及本次事项需要的交集。AI 只能整理预览，不得自动邀请、提升接收者权限、发送或把完整对话附上。来源无权访问或已停用的条目在预览时剔除，并说明为什么不能包含。已被审核的公共基础信息可以随交接提供，但不能伪装成对该人的已确认计划。

## 2. 状态与原子边界

`draft_preview → confirmed → queued → delivered`，并允许 `draft_preview/confirmed/queued → cancelled/expired/invalidated`、`queued → delivery_failed`。预览是临时草案，不进入收件箱；发送人对接收者、范围、用途和版本逐项确认后，服务器再次核验授权与来源，主库事务写 Handoff、状态与 outbox，返回 `queued`，不能写成 `delivered`。Worker 根据幂等键投递站内通知并记录回执；超时保留失败并告知发送者，重试不重复创建新的公开副本。

接收者读取时重新验证当前 Grant、Handoff 的范围/期限与来源条目状态。成员授权被撤销、个人计划条目停用或来源撤下时，当前访问标为 `invalidated` 并阻断旧链接；通知/索引异步清理不能成为唯一阻断路径。已读、截图、外部转述无法强制回收，提示“此副本可能已过期”，可达时发送失效通知；平台不能声称已替接收者删除。

## 3. 并发与故障

- 预览后计划条目停用或接收者权限到期：`send` 返回 412/403，引导重新生成最小预览，不默默删改内容并仍发送。
- 发送请求重试：同一幂等键返回同一 Handoff；不同键确认相同事项可生成新交接，但需再次确认目的，避免重复通知。
- Worker 不可达：保留 queued 与待重试状态，发送者看见“尚未送达”；不得转成任何未获同意的站外消息。
- 授权库不可达：预览和读取都拒绝受限资料；公开基础内容仍可用。
- 新收件人在站内不存在或未接受成员邀请：不发个人内容，只能发起独立的邀请流程，获接受后重新生成预览。

## 4. 验证

对同一 Space 不同职责接收者生成两份材料并比较字段，跨 Space 未获授权者 404，未点击发送时通知数为零；再测试预览后停用、发送中撤销、通知失败与幂等重放、旧链接再读。内部日志不得携带原始叙述或附件 URL。专业接管是否真正可用仍需机构资源证据，本机制不承诺响应时限。
