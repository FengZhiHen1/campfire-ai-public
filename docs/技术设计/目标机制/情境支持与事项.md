# 目标机制：情境支持与事项

> **权威范围**：首次使用、三种情境入口、通用/个人化 AI 支持、事项形成和连续处理、依据适配与现场退化。认证及记录范围由空间授权机制拥有，公共资料审阅由证据机制拥有，HTTP 外壳由接口契约拥有。
> **追溯**：`RQ-CTX-01～06`、`RQ-NOW-01～02`、`RQ-PLAN-01`、`RQ-OPS-01`；`PRD-005～006`、`PRD-009`。
> **状态**：目标机制，既有行为桶/四段式会话不是当前目标行为；真实内容和模型数据处理须通过发布闸门。

## 1. 情境入口与即时输出

首次到达先展示三个自然入口：“接下来有件事”“现在遇到困难”“刚发生一件事”；用户也可直接叙述，无需先选诊断、行为桶或建立个人空间。公开安全内容、真实求助信息和服务边界在未登录也可读，不调用模型。登录后允许通用 AI 澄清，但没有空间就不读取任何他人的资料。提问最多围绕**会改变下一步行动**的未知条件；不知道就保留未知，不靠同年龄或同类行为补成事实。简单问题完成后可直接结束。

“现在遇到困难”先读取已发布的基础安全内容；若用户对某个已核验空间获授权，还可读取当前有效且未停用的适用计划与联系路径。上述两者不能等待生成；AI 只在场景允许时补充解释或准备建议。弱网/离线仅展示已取得的公共版本及更新时间，任何过期或未能核验的个人计划不标成当前有效。没有可达的专家值班时只展示现实求助渠道，不创建假想人工工单。

## 2. 受控 AI 处理流水

1. 服务端核验账户、输入用途、当前 `scope`、信息类别及是否有供应商处理资格；识别需要优先展示基础内容的危险线索，但不把关键词当成已诊断事实。
2. 检索仅限已发布且未撤下的公开研究/实践资料，加上当前用户在该 Space 明确获准且相关的记录。个人资料不经公共向量库；来源版本、适用条件与访问范围同查询返回。
3. 为模型构造最小上下文：用户本次叙述、已确认事实、互相冲突的观察、关键未知、当前角色可执行的行动范围；不得携带其他 Space 的隐藏资料、过期授权、停用计划或未经批准的案例。
4. 模型给出候选解释与下一步、所据来源、适用条件和不确定性。服务端独立检验来源确实支撑具体主张、格式及危险内容边界；失败时不展示未审查的可执行文字，转为已审阅内容、必要澄清与现实求助。
5. 返回结果区分“用户原话”“AI 整理草案”“已核对记录”“当前有效计划”，每条重要建议带具体来源与版本。用户可直接结束、继续提问或核对保存预览；模型输出不能自行创建可回访事项或更新档案。

若个人资料不足，回答只基于通用证据与本次明确输入，不伪称高度个性化；来源相互矛盾则并列限制。连续失败、超时、检索没有可用来源、模型不可用或费用预算用尽时提供明确错误状态及不依赖模型的基础内容。用户已经看到部分进度不表示生成成功，未完成结果不充当行动建议。

## 3. 事项保存、状态与反馈

`Matter` 独立于聊天的形状为 `matter_id`、`owner_scope`、`owner_account_id?`、`space_id?`、`objective`、`known_facts[]`、`unknowns[]`、`next_steps[]`、`source_refs[]`、`review_state`、`version`、`updated_at`。私人事项必须且只能绑定当前 Account，不携带受限 Space 来源；空间事项必须且只能绑定一个已获授权 Space，其可见条目按接收者过滤。允许同一用户支持多个 Subject，但单个事项不跨 Subject 混用。

受控结果返回有期限的 `preview_id`、版本、来源快照与作用域；用户可以逐项编辑 `save_preview`，但保存端必须重新验证当前来源与权限，不能盲信客户端拼出的草案。用户核对并明确提交后才产生草稿：仅使用通用资料的一轮可保存为 `private_draft`；已读取空间资料的一轮只能按当前授权保存为该空间的 `space_draft`，不可复制到私人事项保留已撤销资料。之后可在对应授权范围内继续、修订、关闭或删除。需要协作时，先核验空间，再逐项选择转入并在目标空间创建新来源记录/事项，不修改私人历史以伪装曾获其他人确认。`space_draft`、`ready_for_review`、`closed` 是事项状态，不等于计划条目的“已确认”；关闭事项也不会自动撤销成员访问。反馈记录行动与后续变化，不因“做完后平静”就推断因果或把结果变成永久偏好。

同一事项并发修改采用版本检查，冲突时提示人工合并；取消生成或关闭标签页不保存未确认 AI 草案。若授权在生成/交接过程中失效，拒绝原结果发布并清理服务端临时作用域；用户仍可继续无空间的通用帮助，但不能复制原受限内容到私人事项绕过撤销。

## 4. 边界样例与验收

| 输入情境 | 必须观察的结果 |
|---|---|
| 首次登录且无空间：“明天第一次去新医院” | 先给通用准备与需核实的问题；用户可以不填出生日期/诊断就结束，主动保存才有私人事项 |
| 用户说“让他别离开聚会” | 澄清安全和本人参与意愿，不提供身体控制、惩罚或羞辱式方案 |
| 同一老师切换两个 Space | 每次输出只使用当前授权范围，迟到回答不能在另一人页面显示 |
| 用户现正困难，模型或 Redis 失败 | 已审阅的基础安全内容与现实求助路径仍可达；不能伪称专家正在接单 |
| 已知资料互相冲突或依据撤下 | 显示冲突、未知和适用限制，不输出肯定的个人诱因或继续引用已撤下资料 |
| 生成期间关系被撤销或计划条目停用 | 原生成结果不能作为当前建议输出或转为事项草稿；基础公开内容保持可用 |

发布测试需要成对变化情境、不同表达方式、未登录/无空间/有空间、模型失败及权限变化。若测试仅覆盖预设成功脚本、把模型自己的判断当正确答案或未核验真实支持者能否使用，就不满足上述验收。
