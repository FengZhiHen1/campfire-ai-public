# 目标机制：迁移、验证与分阶段发布

> **权威范围**：旧架构到新对象及契约的非破坏迁移顺序、回退策略、试点证据采集、发布闸门与故障停用。发布的业务门槛由需求拥有；本文说明如何执行并证明。
> **追溯**：`RQ-OPS-03～05`、`AC-SP-01～05`、`AC-CTX-01～05`、`AC-PLAN-01～04`、`AC-OPS-02～04`；`PRD-007～009`。
> **状态**：待实施的执行设计；没有运行过数据清点、备份恢复、专业审阅或真实试点，不能据此批准生产迁移。

## 1. 先取得可回退的事实基线

迁移负责人先清点生产、试点和开发环境：账户、档案、事件、会话、案例、附件、访问关系、导出副本的数量与所有者；核查现有实例是否真的无真实用户。清点输出去敏统计及不可识别的样例，绝不把凭证或个人资料写入设计文档。盘点现有 `/api/v1` 消费者、定时任务、缓存和外部模型数据流，并记录真实的专业审核与核验责任人。获取经核实可恢复的备份、在隔离环境恢复演练并核对行数、权限与文件；备份或盘点失败时停止任何删表、截断或强制覆盖。

当前代码所见 `profiles.caregiver_id`、必填出生日期/诊断/行为类别、ABC 事件、基于行为桶的咨询与四段式产出属于旧现状，不是新版的必要资料。旧文档曾假定“无真实用户数据”，这不能作为生产删改的证据；迁移策略必须在清点后按实际数据分支执行。

## 2. 新旧对象映射与隔离

| 旧对象 | 目标处理 | 不允许的捷径 |
|---|---|---|
| `users/credentials` | 保留身份与凭证，迁移角色用于准入候选；所有个人空间权限重新核验 | 用 `family/teacher/expert` 全局角色直接授予空间访问 |
| `profiles` 及 `caregiver_id` | 建立待核验 Subject/Space 映射与旧 id 对照，原档案保留只读；核验后逐空间激活 | 把 caregiver_id 当作永久合法授权或自动向现有成员共享 |
| `profile_access` | 展示给合法主体复核类别、期限和用途，转为新 Grant 才生效 | 沿用旧关联状态、静默扩权或默认再委托 |
| `event_logs/professional_notes` | 复制原文、作者与时间并标记观察/解释/专业意见来源；缺失信息保留未知 | 以行为桶自动写成永久标签或把老师意见当策略确认 |
| `consultation_sessions/consultations` | 按真实用户与授权保留合法历史，未确认 AI 文本只作历史草案；用户可选择逐项转入私人事项 | 自动将四段式方案公开或转成当前有效计划 |
| `safety_cards/cases` | 逐项核实版权/许可、适用范围、专业审阅及版本后才发布；旧索引可隔离只读 | 以旧“已入库/已索引”状态等同于新审阅完成 |
| `py-llm` 与旧 Agent 扩展 | 清点调用点、验证新受限链路后退役旧入口；不在替代能力达标前移除依赖 | 新旧路径同时接受不同安全规则却共用一份可写资料 |

真实资料迁移采用新表/新版本与去敏映射报告；避免直接原位改写无法恢复的业务含义。先在隔离环境用生产形态样本演练，再安排有限维护窗口：冻结旧敏感写入、完成增量核对和行数/哈希/授权抽样验证、按服务端功能开关切到新读写；旧表暂只读并设明确退役审查期。若样本、审计或权限对不上，关闭新入口、恢复旧只读服务或公开基础内容；**不得**为回退而恢复被撤销的旧 Grant 或已停用的计划。

### 2.1 旧读路径必须在共享授权门之内

新旧并存期间，**旧读路径与新路径必须查询同一份当前授权、停用墓碑和计划状态**，否则回退或并存本身就是绕过撤销的通道：[接口契约](./接口契约.md)允许旧 `/api/v1` 继续服务旧界面，[需求](../../需求/功能需求与验收.md)要求在到期或撤销后任何平台读取都不得再提供受限信息。因此：

- 已迁移到新对象模型的资源，其旧端点读取**先经同一授权判定**：Grant 当前有效、`Space.auth_epoch` 匹配、无删除墓碑、条目未停用；任一不满足返回 403/404，不能因走旧端而放行。做不到这一点时，直接关闭该资源的旧敏感读取，而不是保留一条无守卫的旁路。
- 撤销、异议停用与删除墓碑是**新旧的唯一真相**。旧端点不得只信旧关联表、旧会话或缓存来判断；旧表在退役审查期内也不得被回写以“恢复”权限。
- 回退（恢复旧只读服务）同样受此门约束：回退只恢复**读取能力**，不恢复任何已撤销授权或已停用计划；回退验证须包含“撤销后经旧端点再读仍失败”的用例。
- 旧演示轨/匿名访问路径在真实资料可及的部署中必须关闭或降级为仅公开内容，不能与个人空间数据同库可用。

`EVID-06` 的数据盘点与本节的门控测试必须在任何真实资料迁移前完成；未完成时只能使用虚构样例。

## 3. 分段切换与可撤销开关

1. **公开底座**：批准内容版本、撤下能力、无登录路由、弱网缓存和真实求助路径均经人工演练。没有专业审阅就只在内部用虚构内容测试。
2. **通用 AI 与私人事项**：供应商数据条款、登录和输入告知、禁止内容测试、保存预览及生命周期清理通过后，仅对受控试点账户打开；不依赖新空间表即可工作。
3. **授权空间与记录**：真实核验者、合法关系证明、独立审计、撤销同步生效及双空间隔离通过后，按参与者白名单放开；疑义空间停留不可共享状态。
4. **共享计划、演练与公共案例**：确认人员资质/容量、异议复核、衍生材料撤下与素材许可逐项签收后分别开放；没有合格审阅者则不发布该能力。

功能开关在服务端强制，关掉某能力立即拒绝新生成、发布和读取其当前成果（公开底座除外）；前端隐藏按钮不足以算关闭。上线后按空间、资料类别与风险事件监测，不在日志存原始叙述。开关回滚不得清除异议或删除墓碑。

## 4. 验证矩阵与测量

自动化及人工共同覆盖：未登录拿公开内容、登录无空间保存私人事项、家属与老师跨空间隔离、受托自我提权、并发授权撤销、生成中撤销、**撤销或停用后经旧 `/api/v1` 再读仍失败**、错误主体纠错、专业策略错归日常、异议停用与重新生成绕过、旧摘要及索引撤下、缓存滞后、Worker 重放、模型/数据库/Redis/网络失败、备份恢复删除复活、前端空间切换迟到结果。每条需求验收 ID 关联一项可复跑用例及具名责任人，失败不可通过跳过、降低覆盖或只留演示脚本消除。

性能按需求第九节采集旧场景可比项与新链路各自延迟；报告设备、网络、窗口、负载、成功率与用户获得**可行动**内容的时间，不能把只有“正在思考”进度的 TTFT 算作解决问题。试点至少十二名真实支持者与两类情境，设置静态资料对照、独立评审、个性化/反馈消融；这只是可用性/行动质量线索，不是临床疗效证明。专业/权益审阅、法律依据、供应商合同及机构投入必须附真实证据，均未由本设计替代。

## 5. 停止、通报与重新开放

出现严重危险建议、本人明确拒绝仍被忽略、跨人泄漏、无授权共享、未经审阅策略发布、异议停用失效或删除后数据复活时，具名试点负责人立即关停受影响能力、保留去敏证据并联系有权参与者；公开基础安全内容在自身无问题时保持可达。排查原因、纠正资料与代码、执行反向故障注入和完整回归，经相应专业/数据负责人签收后才能重新开放。无人承担这一职责时不开展真实用户试点。
