# v3.0 目标机制

> **目标与状态**：把授权收敛的目标需求转换为可施工的数据、接口、状态及失败语义。2026-09-26 形成设计基线；本目录不代表代码已迁移、专业审阅完成或真实试点可发布。

## 推荐阅读顺序

1. [空间授权与数据生命周期](./空间授权与数据生命周期.md)：先理解个人范围、共享范围和外部资料边界。
2. [情境支持与事项](./情境支持与事项.md)：理解首次使用、AI 处理和私人事项。
3. [计划确认与安全异议](./计划确认与安全异议.md)：理解发布和即时停用。
4. [受限交接](./受限交接.md)：理解接收者预览、用户确认与送达失败。
5. [证据供给、演练与复盘](./证据供给演练与复盘.md)：理解依据与演练的审核边界。
6. [HTTP、AI 与跨域契约](./接口契约.md)：对照实现端点及并发错误语义。
7. [迁移、验证与分阶段发布](./迁移验证与发布.md)：核实旧数据、切换和停止条件。

## 已知偏差与证据边界

- 旧 `/api/v1`、现有 ORM/前端路由和旧技术文档尚未迁移；新端点、表与发布开关都是目标设计。
- 真实核验、专业审核、法律保留例外、外部模型条款、试点样本和性能结果均需独立证据；没有这些证据的能力保持关闭，不以设计完稿当作验收通过。
- 旧数据量与是否含真实个人资料未经生产盘点；不能沿用历史“无真实用户数据”陈述作破坏性迁移依据。
