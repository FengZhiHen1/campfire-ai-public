# 目标机制：证据供给、演练与复盘

> **权威范围**：公开资料与案例的来源、许可、审阅、索引和撤下；有依据的情景演练与事件复盘如何使用这些资料。个人记录的授权归空间机制；共享计划发布归计划机制。
> **追溯**：`RQ-EVID-01～02`、`RQ-TRAIN-01～02`、`RQ-REVIEW-01～02`、`RQ-CTX-05`；`PRD-001`。
> **状态**：目标机制；机构资料使用许可、可用专业审阅时间及 AI 增益是 `missing evidence`，不能凭样例通过就宣称临床有效。

## 1. 区分来源而不混合背书

`EvidenceSource` 至少记录来源 id、来源类别（研究/指南/实践案例/个人历史）、作者或供给者、发表与更新日期、适用人群与场景、原始出处、使用许可、方法局限、审阅者与资质范围、版本和发布状态。个人历史仅在获准的 Space 内作为情境信息，不能作为外部公共案例的真实性或科学依据；研究提供支持其具体主张的证据，不保证当前个体有效。实践案例允许记录无明显效果、失败与未知，并保留发生情境。

公共供给状态为 `draft → rights_checked → expert_review → approved → indexed`，任一阶段可进入 `rejected/withdrawn`。真实个人经历须先取得相应用途的授权，再做人工复核的去标识化；AI 改写不替代本人或合法主体授权，也不能把虚构演练材料标注为真实案例。专业人员审阅的是内容是否与其职责及证据一致，不自动为产品效果作背书。

经审阅的公开基础安全内容独立发布版本，包含适用范围、行动限制、现实求助方式、最后审阅时间与撤下人。没有可用且经审阅的基础内容时，不把模型自由生成当作替代安全底座。内容审阅者或合法权利人要求撤下时，首先在主数据中标为非当前有效并阻断检索与引用，再异步删除索引和缓存；旧模型上下文中的来源在出答案前再次验证状态。

## 2. 检索与引用约束

公开资料可使用 PostgreSQL/pgvector 索引并按来源类别、版本、许可与批准状态过滤；个人空间内容不放入公共索引，只在授权检查后以必要字段直取。检索返回带 `source_id`、版本、许可及适用标签的候选；生成只在候选确实支持该主张时附引用，引用须指出支持哪一句建议、适用于什么人和情境、缺少什么条件。检索失败时不能把存在的文献标题贴在未经支持的回答上；撤下来源及其衍生材料的当前可用状态要随版本失效。

专业内容审核与向量索引解耦：索引写入成功不代表内容已批准，索引落后也不允许召回已撤下资料。Worker 可重试、去重和重建，失败发告警；公开基础安全页面用已批准的非向量来源提供，不依赖嵌入服务。

## 3. 情景演练

`PracticeScenario` 记录目标技能、非个人化情境、可接受的多种行动、风险边界、来源版本、专业审阅和生效版本。AI 可以理解支持者自由回答并根据已审核原则给出反馈和反问，但不得编造“采取某动作后这个人必然平静”的反应，也不能输出真实个体的内心模拟。若来自个人事项，用户必须另行获授权将素材用于演练，发布给他人的情景还需独立许可与去标识化审核。

演练输出区分“已确认依据”“可讨论的替代方案”“未知条件”，保留使用者的自我判断权。模型反馈不直接更新个人计划；发现潜在策略问题时生成待审提议。审核依据撤下或过期则相应情景暂停使用，不能继续以旧版本给人打分。

## 4. 复盘与经验修订

复盘按时间线分别记录谁观察到什么、原话/转述、采取何种行动、随后发生什么、尚不清楚的条件；AI 草案由记录者核对后才能加入获授权 Space。不同支持者的分歧并存，不因投票或生成摘要成为唯一真相；行动后短期变化不等于证明该行动有效。可输出值得查证的下一步或修订建议，但共享计划和公共案例各自重新走相应授权与审阅链。

当本人明确表示拒绝或不适时，不等待模型确认其是否属于永久偏好；先尊重当下表达，将解释及长期适用性留给后续专业判断。复盘跨空间复用须另取许可，不能将个人信息直接变成“匿名素材”。

## 5. 评测、失败与重访

抽取研究结论支持/不支持的成对资料验证引用；撤下来源但故意留下向量和旧摘要，证明主库状态阻断重新分发。模拟索引延迟、审核者不在线、无许可的真实经历、多人不同观察与模型过度肯定的行为预测，任何越权或虚假专业背书均阻断发布。

演练效果与复盘价值用未见情景、独立评审及静态材料/人工帮助作对照；分别移除个性化和反馈做消融，记录行动质量、遗漏、审阅时间与负担。无法观察真实行动结果时只能报告可用性与训练内表现，不能宣称改善孤独症人士的危机结局。
