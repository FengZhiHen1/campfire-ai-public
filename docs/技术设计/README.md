# 篝火智答 技术设计

> **目标**：说明篝火智答如何满足已确认的[需求基线](../需求/README.md)。
> **状态**：现有技术基线，尚未按 2026-09-21 确认的产品方向重定。详细需求仍有阻塞项，不可将现有机制直接作为新方向的目标实现；代码细节以代码库与 Alembic 迁移为准。

## 推荐阅读顺序

1. 先阅读[需求基线](../需求/README.md)；
2. 阅读[总体架构](./总体架构.md)，了解技术选型、部署拓扑、安全设计与技术风险；
3. 阅读[Agent 基座](./Agent基座.md)，了解 Campfire 的分面自治策略、领域工具与 Skill 体系；如需 Agent 内核本身的契约（ExtensionAPI、事件总线、Session、Skill 加载），阅读[Agent 内核框架](./Agent内核框架.md)；
4. 编写/消费 AI 服务 HTTP 接口前阅读 [AI 服务接口契约](./AI服务接口契约.md)，了解统一 SSE 协议、错误语义与端点组织；
5. 按[机制设计](./机制/README.md)的业务链路顺序阅读各模块机制与契约；
6. 阅读[项目结构](./项目结构/README.md)，了解仓库形态、分层架构、目录骨架与模块边界；
7. 按需查阅[技术决策记录](./决策/README.md)；
8. 阅读[设计待办](../TODO.md)确认阻塞项；现有[重构计划](./重构计划/README.md)面向旧技术基线，尚不能指导本轮新产品方向的实施。

## 已知偏差与 missing evidence

- **新需求未转化为技术基线**：[PRD-001](../需求/产品方向决策.md)确认了产品方向变化；总体架构、项目结构、Agent 基座、机制和旧 ADR 正文尚未重写。本轮未审计实现，不宣称新能力已落地。
- **直接波及的机制**：旧家属绝对控制、老师不写事件、固定角色权限、行为桶及四段式输出，需要与新需求逐项对齐；本文不提前决定其替代机制。
- **定调先于机制**：在需求阻塞项解决后先重访总体架构与项目结构，再形成契约及迁移方案。现有 DSR-006 的“项目结构 v3.0”与本轮“需求 v3.0”是不同版本序列，不代表已对齐。
- **存量文档漂移**：旧需求 v2.0 的趋势复盘、协作照护机制本身仍未全面补齐；更早的代码增量也可能超出文档记载。
- **未决项归属**：本轮未决项由[设计待办](../TODO.md)统一登记；存量技术正文中的分散待办尚未全量迁移。
- **包管理器版本**：文档记 pnpm 10+，精确版本以代码库 lockfile 为准。
