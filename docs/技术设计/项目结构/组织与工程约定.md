# 项目结构 · 组织与工程约定

> **本文唯一拥有**：包/模块命名与组织约定、模块边界、前端五层规则、内核与扩展工程纪律、特殊文件说明、测试规划、扩展预留。
> 所属文档组：[项目结构](./README.md)。

## 一、命名规范

| 元素 | Python（packages + apps） | TypeScript（react-web + mini-program + ts-shared） |
|:---|:---|:---|
| **包目录** | snake_case：`py_config/`、`py_agent_kernel/` | kebab-case 或小写：`ts-shared/`、`consult/` |
| **层目录（前端）** | — | 固定五名：`domain/` `application/` `viewModel/` `view/` `infrastructure/` |
| **模块文件** | snake_case：`auth_service.py`、`jwt_utils.py` | PascalCase（组件）：`ChatBubble.tsx`；camelCase（工具/Hook/Service）：`httpClient.ts`、`useConsult.ts` |
| **类 / 接口** | PascalCase：`AuthService`、`CaseRepository` | PascalCase：`IConsultRepository`、`ConsultRequest`；Props 契约：`XxxProps` |
| **函数 / 变量** | snake_case：`get_user_by_id()` | camelCase：`getCaseById()` |
| **常量** | `UPPER_SNAKE_CASE` | `UPPER_SNAKE_CASE` |
| **Agent 扩展** | 目录 snake_case：`py_agent_extensions/emergency/`；入口 `extension.py` + 声明 `extension.yaml` | — |
| **Agent Skill** | 目录 kebab-case：`skills/emergency-consult/`；入口 `SKILL.md` | — |
| **私有成员** | `_leading_underscore` | `private` 关键字 |
| **测试文件** | `test_<模块名>.py` | `*.test.ts` |

## 二、文件组织规则

1. 每个文件只导出一个主要的类/函数/组件，辅助类型与工具可共存；
2. **Barrel 导出**：Python 包经 `__init__.py`（显式 `__all__`）；TypeScript 包经 `index.ts`；
3. **api-server 模块内部约定**：`routes.py`（接口层）/ `<模块>_service.py`（业务编排）/ `<模块>_contract.py`（服务抽象）/ `exceptions.py`（业务异常）；机制模块即目录（单一边界轴，见[目录骨架](./目录骨架.md) §三）；
4. **测试镜像**：`apps/*/tests/`、`packages/*/tests/`；根级 `tests/` 放跨服务集成与 E2E；
5. **跨层 import 禁令**：`modules/*/routes.py` 不可直接 import `py_db/models/`（经 service 与 repository）；`apps/` 之间禁止互相 import；
6. **临时产物**：对抗性测试、试验脚本等放 `.tmp/`（Git 忽略），不入正式目录；
7. **行数控制**：前端单文件 ≤ 200 行；Python 函数 50–80 行内，超出拆分。

## 三、模块边界（workspace 成员与依赖）

**Python workspace**（根 `pyproject.toml`）：

- apps：`api-server`、`worker`
- packages：`py-agent-kernel`、`py-agent-extensions`、`py-db`、`py-schemas`、`py-rag`、`py-auth`、`py-security`、`py-cache`、`py-storage`、`py-config`、`py-logger`、`py-health`

| 成员 | 允许依赖 |
|:---|:---|
| `api-server` | 全部 py-* packages |
| `worker` | `py-agent-kernel`、`py-agent-extensions`、`py-db`、`py-schemas`、`py-rag`、`py-security`、`py-cache`、`py-config`、`py-logger` |
| `py-agent-extensions` | `py-agent-kernel`、`py-rag`、`py-db`、`py-schemas`、`py-security`、`py-config`、`py-logger` |
| `py-agent-kernel` | **零 Campfire 依赖**（仅 pydantic-ai 与三方库） |
| `py-rag` | `py-db`、`py-config` |
| `py-auth` | `py-config`、`py-cache` |
| 其余能力包 | `py-config`（+ 按需 `py-logger`） |

**Node workspace**（`pnpm-workspace.yaml`）：

- apps：`react-web`（`mini-program` 冻结保留于仓库、移出 active workspace，ADR-014）；package：`ts-shared`（经 `"@campfire/ts-shared": "workspace:*"` 引用）
- `ts-shared` 仅含纯类型、枚举、常量，禁止运行时逻辑；应用级类型（Store State 等）留在各应用 `domain/` 或 `viewModel/`，不迁入

**跨生态禁令**：Python 不 import TypeScript 包，反之亦然；共享契约经 HTTP API 与 DTO 对齐。

## 四、内核与扩展工程纪律

> 契约语义（ExtensionAPI、事件总线、Session、skill-loader）归 [Agent内核框架](../Agent内核框架.md)；本节只规定工程组织。

1. **加载装配集中**：api-server 与 worker 各自在 `agent_bootstrap.py` 显式声明扩展清单与加载顺序（`security` 首位）并注入面白名单；启动时断言 security 已加载且首位，缺失即拒绝启动（附一条测试）；
2. **扩展物理约定**：目录型扩展含 `extension.py`（默认导出工厂，接收 `ExtensionAPI`）+ `extension.yaml`（名称/版本/内核版本兼容声明）；`skills/` 子目录由内核自动发现；
3. **Skill 包约定**：`SKILL.md` frontmatter 遵循 Agent Skills 标准；Campfire 扩展字段挂 `metadata`（`output-schema` / `surface` / `eval-set`，归 [Agent基座](../Agent基座.md)）；评测集放 `skills/<skill>/evals/`；
4. **输出契约不进扩展**：Agent 结构化输出 Pydantic 契约统一归 `py-schemas/agent/`（DSR-002）；
5. **孵化期纪律**：`py-agent-kernel` 自带 `docs/` 与 `tests/`，零 Campfire 依赖由依赖声明保证；扩展 API 变更须同步[Agent内核框架](../Agent内核框架.md)与 ADR。

## 五、前端五层规则（DSR-006）

**依赖方向**：`view → viewModel → application → domain`；`infrastructure → application（实现端口）、→ domain（仅 Mapper）`。禁止反向、禁止跨层穿透。

| 层 | 允许 import | 禁止 |
|:---|:---|:---|
| `view/` | `viewModel/` 的 Hooks、`view/contracts/` 的 Props、`@campfire/ts-shared` 类型 | `application/`、`domain/`、`infrastructure/`、`fetch`/`axios`/`Taro.request`、直接读写 store、数据转换/校验/格式化逻辑 |
| `viewModel/` | `application/` 用例、`domain/` 类型 | `view/`、`infrastructure/` |
| `application/` | `domain/`、`application/ports/` 自身接口 | `view/`、`viewModel/`、`infrastructure/`、任何框架/HTTP 库 |
| `domain/` | 无（纯 TS，零框架依赖） | 一切外层与其他三方库 |
| `infrastructure/` | `application/ports/`（implements）、`domain/`（仅 Mapper）、HTTP 客户端 | `view/`、`viewModel/` |

**状态归属**：

- 跨介质 UI 状态（`isLoading` / `error` / `data`）：viewModel 的 Hooks/store，view 只读取；
- GUI 视觉状态（`isHovered` / `isFocused`）：view 组件内部 `useState`；
- 业务驱动视觉决策（`canClose` / `isEditable`）：viewModel 透传，view 经 Props 接收。

**Props 衔接契约**：页面/组件的输入输出类型定义集中在 `view/contracts/`，命名 `XxxProps`；view 与 viewModel 之间只经 Hooks 返回值与 Props 契约衔接。

## 六、特殊文件说明

| 文件 | 位置 | 作用 | 注意事项 |
|:---|:---|:---|:---|
| `pyproject.toml` | 根目录 | uv workspace 配置 | 成员清单随包增删同步（py-llm 已移除；kernel/extensions 落地时加入） |
| `pnpm-workspace.yaml` | 根目录 | pnpm workspace 配置 | 双前端 + ts-shared |
| `.env.example` | 根目录 | 环境变量模板 | 不存真实密钥；开发用 `.env`（Git 忽略） |
| `apps/api-server/app/main.py` | api-server | FastAPI 入口 | lifespan 内初始化连接池 + 调用 `agent_bootstrap`；中间件顺序影响鉴权与审计 |
| `apps/api-server/app/core/agent_bootstrap.py` | api-server | Agent 启动装配 | 扩展清单/顺序（security 首位）+ 启动断言 + 面白名单 |
| `apps/worker/src/worker/main.py` | worker | Worker 入口 | 队列消费循环 + 优雅关闭；lifespan 同样装配扩展 |
| `packages/py-db/py_db/database.py` | py-db | AsyncSession 工厂 | 所有应用经此获取数据库连接 |
| `packages/py-db/migrations/` | py-db | Alembic 迁移 | schema 单一真相来源；迁移文件必须中文注释业务意图 |
| `packages/py-schemas/py_schemas/agent/` | py-schemas | Agent 输出契约 | Skill metadata `output-schema` 指向此处 |
| `packages/py-agent-extensions/*/extension.yaml` | py-agent-extensions | 扩展声明 | 内核版本兼容校验；自造契约（见[Agent内核框架](../Agent内核框架.md) §十偏差清单） |
| `infrastructure/nginx/nginx.conf` | infrastructure | 生产反向代理 | HTTPS/TLS 1.3 终结、`/api/v1/*` 代理、SSE 长连接超时 |
