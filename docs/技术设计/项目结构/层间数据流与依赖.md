## 七、层间数据流

### 7.1 场景一：应急咨询 SSE 流式响应

```
家属输入行为描述
       │
       ▼
┌──────────────────┐  POST /api/v1/consult/stream (SSE)  ┌─────────────────────┐
│  mini-program     │ ───────────────────────────────────►│   api-server         │
│  (L1 前端)        │                                     │   (L1 应用层)         │
│                   │                                     │                      │
│  views/consult/   │  useConsult() Hook 编排              │  api/v1/consult.py   │
│   → logics/       │   1. consultApi.streamConsult()     │   → consult_service  │
│     consult/      │   2. useSSEStream() 消费事件流       │                      │
│     hooks/        │   3. consultStore 更新消息列表       │                      │
│                   │                                     │  consult_service.py  │
│                   │                                     │   1. 危机分级判定     │──► 代码层安全前置
│                   │                                     │   2. 并行预取档案/案例 │──► py_db + py_rag
│                   │                                     │   3. 预注入+强制加载   │──► py_agent/skill_loader（规划）
│                   │                                     │      emergency-consult Skill
│                   │                                     │   4. Agent 单轮生成   │──► py_agent/runtime（规划）
│                   │                                     │   5. 输出契约校验     │──► py_schemas
│                   │◄── SSE Token Stream ────────────────│   6. 低置信度 → 兜底   │──► ticket_create 工具
│                   │                                     │                      │
│                   │                                     │  StreamingResponse    │
│                   │                                     │  (media_type=        │
│                   │                                     │   text/event-stream) │
└──────────────────┘                                     └─────────────────────┘
```

数据形态变化：
```
User Input (string) [L1 views]
  → Hook call (string) [L1 logics]
  → ConsultRequest (py_schemas.consult) [L2]
  → Profile Entity (py_db.models.profiles) [L2]
  → query_embedding (vector[1024]) [py_rag.embedding]
  → List[CaseChunk Entity] (py_db.models.consult) [L2]
  → 预注入上下文 (str) [py_agent.skill_loader，规划]
  → SSE Token Stream (AsyncGenerator[str]) [py_agent.runtime → L1-sub，规划]
  → JSON partial plan → Store State [L1 logics]
  → Props → Rendered UI [L1 views]
  → ConsultResponse (py_schemas.consult) + Optional Ticket Entity [L2]
```

### 7.2 场景二：案例提交 + 异步索引入库

```
老师提交案例
       │
       ▼
┌──────────────────┐  POST /api/v1/cases                    ┌─────────────────────┐
│  mini-program     │ ──────────────────────────────────────►│   api-server         │
│  (L1 前端)        │                                        │   (L1 应用层)         │
│                   │                                        │                      │
│  views/cases/     │  useCases() Hook                       │  api/v1/cases.py     │
│   → logics/cases/ │   → caseApi.createCase()              │   → case_service    │
│                   │   → caseStore 刷新列表                  │                      │
│                   │                                        │  case_service.py     │
│                   │                                        │   1. Pydantic 校验   │──► py_schemas.cases
│                   │                                        │   2. 写入元数据       │──► py_db/repositories/
│                   │                                        │   3. 投递索引任务     │──► py_cache Redis 队列
│                   │◄── 201 Created ───────────────────────│                      │
└──────────────────┘                                        └────────┬────────────┘
                                                                     │ Redis Queue
                                                                     ▼
                                                            ┌─────────────────────┐
                                                            │   worker             │
                                                            │   (L1 应用层)         │
                                                            │                      │
                                                            │  tasks/case_indexer  │
                                                            │   1. Redis 消费任务   │
                                                            │   2. 读取案例全文     │──► py_db/repositories/
                                                            │   3. 语义切片         │──► py_rag/splitters.py
                                                            │   4. 向量化嵌入       │──► py_rag/embedding.py
                                                            │   5. pgvector 写入    │──► py_db/repositories/
                                                            │   6. 状态扭转为已索引  │──► py_db/repositories/
                                                            │                      │
                                                            │  失败处理：重试3次     │
                                                            │  最终失败 → indexing_failed
                                                            └─────────────────────┘
```

数据形态变化：
```
CaseFormData (TS interface) [L1 views → L1 logics]
  → CaseCreate (py_schemas.cases) [L2]
  → Case Entity (py_db.models.cases) [status: pending_review] [L2]
  → Redis Task Message (JSON) [py_cache]
  → [Worker 异步消费]
  → Full Case Text (str) [L2 py_db]
  → Semantic Chunks (List[str]) [py_rag.splitters]
  → Embedding Vectors (List[vector(1024)]) [py_rag.embedding]
  → CaseChunk Entities (py_db.models.consult) [pgvector INSERT] [L2]
  → Case Entity [status: approved] [L2 py_db]
```

### 7.3 场景三：用户认证与 RBAC 授权

```
用户登录
       │
       ▼
┌──────────────────┐  POST /api/v1/auth/login               ┌─────────────────────┐
│  mini-program     │ ──────────────────────────────────────►│   api-server         │
│  (L1 前端)        │                                        │   (L1 应用层)         │
│                   │                                        │                      │
│  logics/shared/   │  useAuth() Hook                        │  api/v1/auth.py      │
│   hooks/useAuth   │   1. httpClient POST /auth/login       │   → auth_service     │
│                   │   2. tokenManager 存储 Token            │                      │
│                   │   3. userStore 更新登录态               │  auth_service.py     │
│                   │                                        │   1. 查询用户         │──► py_db/repositories/
│                   │                                        │   2. 密码校验         │──► py_auth/hashing.py
│                   │                                        │   3. JWT 签发         │──► py_auth/jwt_utils.py
│                   │◄── 200 {access, refresh} ─────────────│                      │
│                   │                                        │                      │
│  [后续请求]        │  GET /api/v1/profiles/{id}             │                      │
│  httpClient       │  Authorization: Bearer <AT>            │                      │
│  拦截器自动注入     │ ──────────────────────────────────────►│  dependencies/       │
│                   │                                        │   auth_deps.py       │
│                   │                                        │   → get_current_user │──► py_auth/jwt_utils.py
│                   │                                        │   → require_role     │──► py_auth/rbac.py
│                   │◄── 200 {profile} ─────────────────────│                      │
│                   │                                        │                      │
│  [AT 过期]        │  POST /api/v1/auth/refresh             │                      │
│  httpClient       │ ──────────────────────────────────────►│  auth_service.py     │
│  401 拦截 → 刷新   │                                        │   → refresh_token    │
│  → 重放原请求      │◄── 200 {new_access_token} ───────────│                      │
└──────────────────┘                                        └─────────────────────┘
```

数据形态变化：
```
{username, password} (JSON) [L1 logics]
  → LoginRequest (py_schemas.auth) [L2]
  → User Entity (py_db.models.auth) [L2]
  → TokenResponse {access_token, refresh_token} (py_schemas.auth) [L2]
  → [L1 logics: tokenManager 持久化 + userStore 更新]
  → [后续请求]
  → Authorization: Bearer <token> (HTTP Header) [L1 logics httpClient 自动注入]
  → JWT Payload {sub, roles, exp} (Dict) [py_auth.jwt_utils]
  → User Entity + CurrentUser (FastAPI request.state) [L1-sub dependencies]
  → 200 OK or 403 Forbidden
```

## 八、模块间依赖关系（Mermaid）

```mermaid
graph TB
    subgraph 前端层["L1 应用层 — 前端"]
        MP[mini-program<br/>Taro + React]
        TS[ts-shared<br/>共享类型]
    end

    subgraph 后端层["L1 应用层 — 后端"]
        API[api-server<br/>FastAPI]
        WORKER[worker<br/>Redis Queue Consumer]
    end

    subgraph 共享层["L2 共享能力层"]
        CONFIG[py-config<br/>全局配置]
        DB[py-db<br/>ORM/迁移/仓储]
        SCHEMA[py-schemas<br/>DTO 契约]
        RAG[py-rag<br/>RAG 引擎]
        LLM[py-llm<br/>LLM 客户端（将退役）]
        AGENTP[py-agent<br/>Agent 基座（规划）]
        CACHE[py-cache<br/>Redis 缓存/队列]
        STORAGE[py-storage<br/>MinIO 对象存储]
        AUTH[py-auth<br/>JWT/RBAC]
        LOG[py-logger<br/>结构化日志]
    end

    subgraph 数据层["L3 工程支撑层 — 数据"]
        PG[(PostgreSQL<br/>+ pgvector)]
        REDIS[(Redis 7)]
        MINIO[(MinIO)]
    end

    subgraph 外部["外部服务"]
        DS[DeepSeek API]
        ALI[阿里 text-embedding-v4]
    end

    MP -->|@campfire/ts-shared| TS
    MP -->|HTTP /v1 + SSE| API
    API --> AUTH
    API --> DB
    API --> SCHEMA
    API --> RAG
    API --> LLM
    API --> CACHE
    API --> STORAGE
    API --> CONFIG
    API --> LOG
    API -->|任务投递| REDIS

    WORKER --> REDIS
    WORKER --> DB
    WORKER --> RAG
    WORKER --> CACHE
    WORKER --> CONFIG

    DB --> PG
    RAG -->|向量检索| PG
    RAG -->|嵌入向量化| ALI
    LLM -->|OpenAI 兼容 API| DS
    STORAGE --> MINIO
```

**依赖规则要点**：

1. `mini-program` 通过 HTTP/SSE 调用 `api-server`，前端绝不直连数据库、向量库或外部 API
2. `api-server` 和 `worker` 通过 Redis 队列解耦，禁止应用间直接 RPC
3. 跨应用共享能力必须通过 `packages/` 传递，禁止 `apps/` 间直接 import
4. `py-db` 的 ORM 模型和 Alembic 迁移是单一真相来源，所有应用共享同一套数据库 schema
5. `py-schemas` 是前后端数据契约的权威定义，前端 `ts-shared` 中的类型应与之对齐
6. 循环依赖由 uv workspace 和 pnpm workspace 构建时自动检测并报错
