# 会话归属单立 `campfire_session` 表，归 accounts

> **决定**：新增 `campfire_session`（`session_id` 主键 + `account_id` + 创建时间），归 `modules/accounts`，作为**会话归属的唯一判定真源**；它只承载归属与登记，**不存消息**——对话内容仍唯一归 SDK 的会话存储（[通用基座](../technical-details/通用基座.md)第 2 节单真源）。注销时该账号的行**真删**。**理由**：会话真源是 SDK 的 `agent_sessions` 表，实测**没有 `account_id` 列**；而既有的 `campfire_session_object` 只在会话**已绑定对象**时才有行（[支持对象](../technical-details/支持对象.md)第 6 节允许"无绑定"）——两者叠加的结果是**没有任何真源能判定一个会话属于哪个账号**。**被否决项**：把 `account_id` 编进 `session_id`；复用 `campfire_session_object` 并允许对象为空；改 SDK 的会话表。
> **状态**：**2026-09-30 经用户裁决**。不代表已实现（表、用例与迁移均未落地）。

## 上下文与证据

写[咨询面 HTTP/SSE 契约](../面/consult/HTTP与SSE契约.md)时发现：历史水合与会话列表两个端点都要做越权校验，而校验依据不存在。

| 事实 | 证据 |
|---|---|
| 对话真源是 SDK 的会话存储，表由 SDK 拥有 | [通用基座](../technical-details/通用基座.md)第 2 节；`agent/runtime/session.py` 用 `SQLAlchemySession`（其两张表 `agent_sessions` / `agent_messages` 至今未登记归属） |
| 该表没有 `account_id` | 表由 SDK 定义，我方不得改其 schema（改它等于把业务字段塞进框架表，且 SDK 升级会牵连） |
| `campfire_session_object` 只在已绑定对象时有行 | [支持对象](../technical-details/支持对象.md)第 6 节：无对象账号建立会话时"先落无绑定"，引导中建第一个对象才**补绑** |
| 越权校验的既有纪律 | 同文档第 5.3 节：对象不存在与不属于当前账号，**文案逐字相同**（不泄露存在性） |

**因此**：越权校验、会话列表、`AC-24`（注销后该账号的全部内容不再存在）三处都没有承载。缺归属判定不是"少一个字段"，而是**没有地方问"这个会话是谁的"**。

## 备选与评价

| 方向 | 何时成立 | 代价 |
|---|---|---|
| **单立归属表归 `accounts`（选定）** | 归属事实需要一个业务真源，而它不能是框架表 | 新增一张表与一次迁移；`accounts` 的用例表需补一行（定调级改动） |
| `account_id` 编进 `session_id` | 零新表 | 会话标识出现在 **URL、前端路由、日志与事件里**，等于把账号标识外露到每一处；且注销后无行可判、无痕可查 |
| 复用 `campfire_session_object`，允许 `support_object_id` 为空 | 零新表 | 让"绑定表"同时承担"会话存在"，与"绑定不可变 + 首对象补绑只发生一次"纠缠；无对象会话要靠空值表达，语义污染 |
| 改 SDK 的会话表加列 | 一处解决 | 违背单真源划分（对话存储由 SDK 拥有）；SDK 升级时表结构变更牵连业务字段；且该表尚未登记归属，改它等于先制造一个未登记的自定义分叉 |

**为什么归 `accounts` 而不是 `profile`**：这张表回答的是"会话属于哪个账号"，与"会话绑定哪个对象"是两个问题——后者已有 `campfire_session_object` 归 `profile`。且 `accounts` 已有两个以 `account_id` 为键的业务状态表先例（邀请码 `used_by_account_id`、`campfire_onboarding`），同法不引入新概念。另有一层硬约束：注销编排需要删它，而 `cli` 的依赖白名单已放行 `accounts`。

## 决定与影响

**决定**：`campfire_session` 归 `modules/accounts`；[项目结构设计](../../项目结构设计.md)第 6 节 `accounts` 行补「会话归属与登记」用例；[认证与账号](../technical-details/认证与账号.md)第 8 节的注销处置纳入它（真删，在身份用户删除之前）。

由此确定的边界（实现时必须遵守）：

- **不存消息内容**，也不存会话标题等派生值——标题由会话真源的首条使用者消息推导（[HTTP/SSE 契约](../面/consult/HTTP与SSE契约.md)第 3.2 节）。存了就构成第二份对话真源。
- **归属即判定真源**：历史水合、会话列表、发消息、订阅、取消五处越权校验都查它；不属于当前账号一律 **404**，文案与"会话不存在"逐字相同。
- **创建时机**：会话创建端点在写 SDK 会话之前落行；写行失败则不建会话（不得出现"能读但无归属"的会话）。

## 重访条件

- SDK 的会话存储若将来提供官方的归属或多租户维度（可承载 `account_id`），则重估本表是否退化为冗余——判据是"能否不再另存归属"。
- 出现跨账号共享会话的真实需求（一期不存在），归属将从一对一变为多对多，本表形状需重定。
