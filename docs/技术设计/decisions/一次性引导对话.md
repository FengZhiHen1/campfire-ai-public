# 一次性引导对话（onboarding）

> **决定**：账号**首次创建日常会话**时程序注入一次性引导 skill（`autoload: "false"`，应急会话永不触发）；引导做四件事——告知（`RQ-LIM-03`）、创建第一个支持对象、以 `emergency_context` 八组为纲的档案种子（6–8 问，一次一问、可跳过、跳过即留空）、使用者认知（写通用记忆）——收束给使用说明页跳转。一次性状态由 `campfire_onboarding` 状态表承载（`modules/accounts`，`account_id` 主键）：`completed` 由模型经 `finish_onboarding` 工具写入，`skipped` 由 UI 跳过入口写入，**不从档案或会话推导**。引导会话**延续为日常对话**，会话中创建的第一个对象**补建**该会话的唯一绑定。工具池 7→9（新增 `create_support_object`、`finish_onboarding`）。
> **状态**：**2026-09-30 经用户裁决**（四项分叉逐项选定：一次性自动触发而非常驻入口；同会话延续 + 首对象补绑；状态表 + 工具/UI 双通道；范围四件事全做、种子以应急八组为纲）。不代表已实现。

## 上下文与证据

用户诉求：首次使用者登录后进入一次引导对话（有对应 skill、走 Agent 基座与对话界面），用于建立档案、形成对用户的基本认知、告知使用方式（可做使用说明页并初次对话时给跳转）。既有机制的事实基础（可查，未新增发明）：

- 基座第 3 节已有**应用侧程序注入激活**（emergency 即此形状）；咨询对话界面第 6 节已定应急与日常**共用同一对话页与同一 adapter**——引导复用此路，前端近零新增。
- `RQ-ACC-02`（无档案不阻断咨询）⇒ 引导必须可跳过；`RQ-LIM-03` ⇒ 告知须先于询问。
- 档案 origin 分流裁决 ⇒ 监护人陈述在引导中**零确认直接入稳定层**，与引导节奏天然契合。
- `emergency_context` 八组 + 「组未预存返回 absent」⇒ 种子问题集与八组同构时**每问有明确下游消费者**（首次应急即吃到档案预取红利）。
- 约束碰撞：支持对象第 6 节「绑定在会话开始时确定」与「会话开始时账号无对象、对象在会话中创建」冲突——由「首对象补绑」修正（首次绑定不是改绑）。
- 「不建映射表」裁决（认证与账号第 3 节）反对的是第二套账号身份，不禁止以 `account_id` 为键的业务状态表（邀请码表是先例）。

## 备选与评价

| 分叉 | 被否决项 | 否决依据 |
|---|---|---|
| 承载形式 | 常驻第三入口 / 独立 onboarding 面 / 复用 profile-curation | 用户定「仅第一次对话自动触发」；独立面要跨面耦合 consult 机制；复用 profile-curation 会污染两者的触发准确性（被动整理 vs 主动提问） |
| 会话收场 | 同会话不绑定（档案不注入）/ 独立会话即终 | 前者体验缺口（同会话后续咨询吃不到刚建的档案）；后者多一步且引导中途问真实问题时进退两难 |
| 状态与完成信号 | 从档案/会话推导状态 / 纯 UI 完成信号 | 推导不可靠（跳过建对象与未经引导建对象都会误判）；纯 UI 漏点即永久 in_progress、反复注入 |
| 范围与深度 | 只告知+导览 / 对象走表单 / 极简 4 问 / 只问称呼 | 用户核心意图即「建档 + 认知」；表单路径留下 TODO 待定项不解决冷启动；种子浅则应急八组多数 absent，差异化最重的场景吃不到红利 |

## 决定与影响

- 新增第四个 skill `onboarding`（含两个 `references/`）；共用纪律**豁免**（语义前提「产出咨询输出」不成立），不含 `shared:` 标记块。
- 工具池 7→9：`create_support_object`（profile，对话式创建成为一等入口，档案页表单退为补充路径）、`finish_onboarding`（accounts）。**档案写工具仍只有 `propose_profile_item`**——onboarding 经同一工具写种子，不违反档案单写入路径裁决。
- [支持对象](../technical-details/支持对象.md)第 6 节补首对象补绑规则；[认证与账号](../technical-details/认证与账号.md)第 8 节声明 `campfire_onboarding` 表并列入注销真删清单（第 7 步）。
- 新增使用说明页（`docs/design/pages/使用说明.md`，常驻次级页：引导收束跳转 + 设置页入口；与设置页分工——本页「怎么用」、设置页「数据与边界」）。
- `finish_onboarding` 的完成判定是**提示词层约束**（与 `RQ-LIM-05` 同源，不构成安全边界）：漏写最坏后果是重复注入，UI 跳过入口可补救，不损失数据。

## 重访条件

- 真实使用显示引导完成率低（跳过率高）：重估种子题数与分段节奏，方向是减题而非去告知。
- 使用说明页访问数据（若可得）显示设置页入口不可发现：增加首页次级入口。
- 二期机构协作时：引导中「创建第一个对象」与组织持有对象的授权缝冲突，须重估对象创建段。
