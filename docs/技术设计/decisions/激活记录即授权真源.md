# 激活记录即授权真源

> **决定**：激活的授权时效从「一次运行」改为「会话」。无论激活由谁发起（模型匹配、使用者手选、程序注入），落库形态统一为会话历史中的 skill 工具调用记录（模型侧真实调用；应用侧在触发条件成立时写**合成同形记录**——function_call + 携带 `<skill_content>` 的结果对）。每次运行开始时从**全量历史**的激活记录推导可用工具集（各记录 `allowed-tools` 的并集），跨运行持续、**只增不减**；`autoload: "false"` 的门保持原位（只拒模型发起的调用，合成记录由应用侧触发条件把关）。发消息端点 `skill` 参数的合法值域收敛到模型可见目录集（`daily-consulting`、`profile-curation`），应急与 onboarding 传入即 422。
> **状态**：**2026-10-01 经用户裁决**（分叉逐项选定：纯并集只增不减，而非最新激活为准或并集+单点终结；`skill` 值域收到「仅自动匹配集」，而非含应急的目录集；`create_support_object` 跨会话缺口登记 TODO 不扩范围）。设计已落稿，**实现未落地**（登记于 [TODO](../../TODO.md) 第四节）。

## 上下文与证据

生产缺陷触发本次裁决：引导会话中使用者答完第一题后，模型调用 `create_support_object` 等五个工具全部被 `tool_not_available` 拒绝（四次调用、五次相同报错）。根因链（代码已核实）：

- [activation_state.py](../../../apps/api/src/campfire/agent/tools/activation_state.py) 明写「不回写 `RunRequest` 或会话」——运行时激活只活一次运行；
- [routes.py](../../../apps/api/src/campfire/surfaces/consult/routes.py) 的 `_first_run_injection` 判据是 `first_run_injected` 为假：首次运行起步成功即置位，此后同会话不再注入 onboarding；
- onboarding 要求「八问一次一问」且 `ask_user` 提问即中止当次运行——**引导的交互形态必然跨多次运行**，与「注入只挂首次运行」自相矛盾；`finish_onboarding` 因此永不可达。
- 应急会话同构中招：`autoload: "false"` + 追问跨运行，唯一自救是使用者每条消息手动重选技能（前端选择器含应急芯片）。
- 基座文档第 3 节本已写明「应用侧激活与模型调用**同形，差别只在发起者**」——实现只做到了内容同形，未做到机制同形。本次裁决是恢复文档承诺的对称性。
- 测试 `test_second_run_of_the_same_session_does_not_inject_onboarding` 把「第二次不注入」钉成正确行为——当时的语义是防重复注入，未覆盖引导中途跨运行的授权需求。

## 备选与评价

| 分叉 | 被否决项 | 否决依据 |
|---|---|---|
| 授权语义 | 最新激活为准（一次一套方法论） | 模型自动激活多技能时工具集随激活来回切换（激活 profile-curation 丢 daily 的检索工具）；引导延续段的建档工具在切换时丢失；与「一次对话先后激活多个 skill」的既有设计场景冲突 |
| | 并集 + `finish_onboarding` 单点终结 | 引入第二种记录类型（终结记录），机制复杂化；且与本会话内「引导之外也可建后续对象」的工具说明相抵触 |
| `skill` 值域 | 目录集含应急（选择器保留应急芯片） | 砍掉使用者明知应急却被迫浏览目录的路径不成立——**应急是分秒必争的场景**，表单入口的八项采集（结构化、可跳过）比自由文本入口更适合时延目标；值域等于模型可见目录集，语义自洽：使用者手选只能选模型自己也能选的 |
| `create_support_object` 跨会话缺口 | 本轮一并修（加入 profile-curation 的 allowed-tools） | 属技能内容层、可分离；涉及多支持对象的产品定位，登记 TODO 单独裁决 |

## 决定与影响

- **授权推导**：本次运行可用集 = 历史激活记录的 `allowed-tools` 并集 ∪ 本轮新增激活 ∪ 机制工具（`skill` / `read_skill_resource` / `ask_user`）。默认可用集是「历史并集为空」时的兜底，不是常驻底集。推导扫**全量历史**而非模型窗口（激活记录可能被窗口裁掉，授权不得随窗口丢失）。
- **「发送即消费」保留**：它说的是选择器 UI 状态与本次运行的激活写入，不是授权——选择消费于本次运行（写一条激活记录），授权随记录跨运行持续。契约 4.1 无破坏性变更，只补值域与授权说明。
- **首次注入语义收窄**：`first_run_injected` 只结算「告知消息 + 首条合成激活记录」；引导状态表 `in_progress` 判定只管「另开新会话是否再注入」，不承担授权续期。
- **`run_started.activated_skills` 口径**改为「本次运行生效集合（历史推导 ∪ 本轮新增）」——该数组会有多个成员，前端徽标呈现登记 TODO。
- **原「同时激活数量上限待确认」关闭**：纯并集下没有「同时激活」概念，只有集合成员关系。
- 引导完成后的工具不回收（`finish_onboarding` 之后同会话仍可建对象、写档案）——与「对话式创建是一等入口」的产品定调相容，接受。
- 应急入口唯一性：`skill` 参数不接受 `emergency-consulting`，应急只走表单入口；前端应急芯片随值域收敛下架。
