# 应急判据内联，去除框架节号指针

> **决定**：把应急框架中**本产品所依赖的规范内容**内联进[emergency-consulting](../面/consult/skills/emergency-consulting.md)——六层闸门具名判据、医疗红灯清单与医疗层待获取信息、`baseline_deviation` 取值、沟通层字段与措辞纪律、环境层字段、七类原因排查、安全风险模型八维、Action Card 七节与取值映射、来源六类与置信四级；该 skill 文档成为这些事实的唯一权威，正文不再出现框架节号指针。需求稿 `RQ-EMG-01`～`RQ-EMG-04` 的节号指针改为出处说明（**语义不动**）。框架内一期无消费者的部分**明列不内联**并写明重访条件。**理由**：① 框架文件位于 `/references/`，被 `.gitignore` 排除且被仓库明确标注「不作为设计权威」（`.gitignore` 第 5–6 行），而指针承载的是**规范判据**——判据悬在一个不进版本库、且声明不作权威的文件上，文件丢失即无法复核，而 `RQ-EMG-02` 明确要求「追问判据由具名清单定义，不由模型临时决定」，判据不可复核等于该要求落空；② 应急 skill 声明 `references/gates.md` 要写「六层闸门各自的**具名判据**」，但当时文档只给了闸门**名称**与两张清单，七类原因的排查内容、安全风险八维的维度定义**在文档内根本不存在**——实现者只能去读那份未入库文件，与档案一路的内联结论同源。**被否决项**：只处理已显式写了 `§X` 的几处（最小内联，七类原因与安全八维仍无着落）；把框架移入 `docs/` 当作设计文档（它是外部调研材料而非本项目的设计，混入会污染事实所有权）；把框架作为资料摄进 `library` 后按路径引用（**该方向不解决本问题**：资料库的条目是咨询的检索对象，不是设计规范的权威来源，且 `EVID-B` 素材授权未落实前不得建索引）。
> **状态**：**2026-09-29 经用户裁决**（选定「全面内联」与「允许改需求稿引用形式、语义不动」）。这是对[emergency-consulting](../面/consult/skills/emergency-consulting.md)既有设计内容的**实质补充**（新增此前缺失的具名判据），不是措辞润色。不代表已实现。

## 上下文与证据

**外部依赖的实测边界**（沿用档案一路的同一组证据，本轮复核未变）：

| 事实 | 证据 |
|---|---|
| 框架未进版本控制 | `git check-ignore -v` 命中 `.gitignore:6:/references/` |
| 仓库明确定位其非权威 | `.gitignore` 第 5 行注释：「本地参考资料与研究材料（**不作为设计权威**）」 |
| 指针规模（修正前） | 应急 skill 15 处、需求稿 5 处、TODO 3 处，合计 **23 处** `框架 §X` |
| 框架规模 | 1267 行，24 个一级节 |

**判据缺失的实测结论**（这是本次内联的实质理由，不只是"换个引用方式"）：把应急 skill 声明的 `references/gates.md` 内容边界与本文实际写下的内容逐项对照——

| `gates.md` 应含 | 修正前文档是否有实际内容 |
|---|---|
| 六层闸门各自的**具名判据** | **无**：只有闸门名称与"命中后动作"，第 2 层"明显偏离"、第 3 层"可靠通道"都无判定依据 |
| 医疗红灯完整清单 | 有（7.1 节已列 9 项） |
| 七类可能原因的快速排查 | **无**：只有七个类别的英文名，各类排查内容全无 |
| 安全风险八维 | **无**：只写了"安全风险八维"五个字 |
| Action Card 取值 | **部分**：卡片给的是显示档位（如"无/轻度/明显"），而框架的细则枚举（`none`/`mild`/`moderate`/`marked`/`unknown`）与两者的映射**从未写出**——实现者无法知道 `moderate` 该落在哪一档 |

即：**声明要写的内容有近一半在库内不存在**，只能去读那份未入库文件。这与档案一路"摘要十二字段无载体"是同一类缺陷。

**顺带发现并修正的一处文档间不一致**：`emergency_context` 的返回形状列了 **8** 个键（框架七组 + `unhelpful_strategies`），而[技能设计](../technical-details/技能设计.md)、[咨询面](../面/consult/README.md)、[通用记忆](../technical-details/通用记忆.md)三处都写"档案**七组**"。框架的长期预存项（Baseline / Communication / Sensory triggers / Known medical risks / Known safety risks / Helpful strategies / Unhelpful strategies / Emergency contacts）本身是 **8** 项，其中"有效策略"与"无效策略"本就成对。三处"七组"已改为**八组**。

## 备选与评价

| 方向 | 何时成立 | 代价 |
|---|---|---|
| 最小内联（只处理已显式引用的） | 指针承载的只是出处、内容已在库内 | 七类原因排查与安全八维仍无着落，`gates.md` 无法按声明写出 |
| 框架移入 `docs/` 作设计文档 | 若它是本项目的设计产物 | 它是**外部调研材料**，混入设计根会污染事实所有权（本项目的设计事实须可追溯到用户裁决或本项目证据） |
| 框架摄进 `library` 后按路径引用 | — | **不解决本问题**：资料库条目是咨询的**检索对象**，不是设计规范的权威来源；且 `EVID-B` 未落实前不得建索引 |
| **规范内容内联进 skill 文档（选定）** | 判据是实现与评测的直接依赖时 | skill 文档变长（161 → 281 行）；须明确哪些**有意不内联**，否则会变成整篇框架的抄本 |
