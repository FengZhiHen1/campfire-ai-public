# 何谓值得沉淀，以及三分判定

本文件是 `profile-curation` 的 `references` 之一，由该 skill 正文按需读取。它只写**判据**，不写字段定义——字段形状归档案设计文档。

## 1. 值得沉淀的具名判据

一条信息值得沉淀，当它**同时**满足：

1. **长期有效**：不是当次情境的临时状态，而是下次对话仍会用到的事实或模式。
2. **对支持有影响**：知道它会让支持方式不一样（沟通方式、感觉特征、触发因素、有效或无效策略、日常规律、风险、偏好）。
3. **已经说过或明确观察到了**：来自本次或既往对话中的陈述、观察、转述或文档；不是我们推测补全出来的。

反过来，**不值得沉淀**的**典型**：

- 寒暄、临时情绪、与长期陪伴无关的一次性内容；
- 只是当次问题的背景，下次不会再使用的细节；
- 我们已经给出的建议（那属于「我们的建议」，不是支持对象的属性）；
- 为凑条目完整而推想出来的内容。

## 2. 三分：使用者陈述／他人观察／系统推断

三类信息的**判定**、**去向**与**要不要确认**各不相同。

| 分 | 判定方式 | 去向 | 是否需使用者确认 |
|---|---|---|---|
| 使用者陈述 | 语句的发出者是使用者本人，且内容是「据我所知/我观察到我的孩子…」的事实性陈述 | 进稳定层 | **不需要**（零确认入档，只回执） |
| 他人观察 | 发出者不是本人（监护者、老师、支持员、第三方转述、文档），或内容是他人对当事人的描述 | 进稳定层（`origin` 标为该来源） | 不需要，但来源必须如实标注 |
| 系统推断 | 发出者是我们自己——由本次对话内容归纳、概括或补全出的判断 | **只进候选层** | **需要**（确认才进稳定层） |

**边界情形**：

- 使用者说「他可能是想逃避」——发出者是使用者，但内容是**使用者自己的推测**。按陈述入档，条目标注该内容为使用者的推测表述，不由我们升级为事实。
- 使用者引用他人（「老师说他上课坐不住」）——按**他人观察**入档，来源标为第三方转述，不标为本人陈述。
- 我们把使用者的多句话归纳成一句模式（「他在嘈杂环境里容易捂耳」）——这是**系统推断**，只进候选层。

## 3. 禁止写法

- **不得**用推断描述当事人的内心状态（「他其实是想逃避」）。
- **不得**给行为定性（「他在故意拖延」）。
- **允许**写观察到的外显事实（「观察到他在嘈杂环境中捂耳」）。
- **不得**用 `user_statement` 提交自己的归纳——那是冒充来源。

## 4. 一次观察即可成候选

**一次观察就是一条候选**，不需要等「同一主题再次出现」。

**为什么**：重复阈值约束的是跨对话的模式归纳，那部分一期不做；把「重复 ≥2 次」当作候选门槛，会让第一次出现的重要信息永远进不了候选——而那往往正是最该问使用者的一句。

**判别性**：构造单次观察的输入，验证仍产出候选；若产出被「重复不足」拦下，即为违反本条。

## 5. 写入前先读现有条目的去重规则

`propose_profile_item` 调用**之前**先 `read_profile_items` 读该对象现有条目，按下面顺序判定：

1. **同主题同内容已存在** → 不新建候选，改为在输出中说明「这条已在档案里」。
2. **同主题但新增了信息** → 产出候选，说明它与既有条目的关系（补充，不是取代）。
3. **与既有条目冲突** → 不覆盖；两条并列保留，并在输出中把冲突摆给使用者。监护者观察与本人自述冲突时，**本人自述优先保留，观察条目同样保留**。
4. **既有条目是 rejected** → 同一内容不得再被提为候选（否定不回潮）。

## 6. 条数与粒度

- 一次最多提出**三条**候选，每条一句话。
- 粒度是「一条可独立确认的信息」，不是「一个领域的总结」——把十件事写进一条，使用者只能整条接受或整条拒绝。
- 十次输出各一条，好过一次输出十条。

## 7. 本文件不含的内容

- 确认入口的交互形态（属页面设计）。
