# 来源、确认状态与陈述／推断的分道

本文件是 `profile-curation` 的 `references` 之一，由该 skill 正文按需读取。它只写**标注与转换**，不写确认入口的交互（属页面设计）。

## 1. 来源标注

每条条目都要能回答「这句话是谁说的」。来源取值与对应的卡片表述：

| 来源 | 含义 |
|---|---|
| 本人自述 | 当事人自己说出的事实性陈述 |
| 监护者观察 | 监护者对当事人的描述或观察 |
| 第三方转述 | 老师、支持员、文档等非在场一方的说法；标注时写明是哪一类第三方 |
| 文档 | 已有的书面材料 |

**来源不是「谁提交的」，而是「这句话出自谁」**——我们归纳出来的内容，来源是系统推断，不是使用者。

## 2. 时间标注

- 记录该信息的**发生时间**与**来源时间**：前者是哪件事发生的时间，后者是这句话被说出的时间。
- 两者都不是当前时间时，不得用「最近」这类相对措辞代替时间标注。
- 时间不明时显式留空并标注为未知，不猜。

## 3. 确认状态的含义

| 状态 | 含义 | 能否作为「现在该信什么」的依据 |
|---|---|---|
| 已确认（稳定层） | 使用者已确认，或属于零确认入档的直接陈述 | 是 |
| 待确认（候选层） | 由观察或推断产生，尚未经使用者确认 | **否**——只能以「待确认」呈现 |
| 已否定 | 使用者显式否定过 | **否**，且同一内容不得再被提为候选 |

**只把稳定层内容当事实**：候选层内容在输出中必须带「待确认」标记，不得与稳定层内容混在同一句陈述里。

## 4. 陈述与推断的分道

落层由 `origin` 决定，**不由模型在提交时自行选择**：

| `origin` | 去向 | 是否需确认 |
|---|---|---|
| `user_statement` | 直接进稳定层 | 否（零确认） |
| 监护者／第三方等陈述类来源 | 直接进稳定层 | 否 |
| `system_observation` | **只进候选层** | **是** |
| `ai_inference` | **只进候选层** | **是** |

**硬约束（工具实现层）**：`system_observation` 与 `ai_inference` **不得**写成 `confirmation = confirmed`——请求被**拒绝**，而不是被静默降级改写。

**为什么落在工具实现层而不是提示词里**：提示词层的约束可以绕过，**不是安全边界**。落在这里，越界载荷根本到不了存储层。

## 5. 候选 → 稳定的转换条件

候选条目进稳定层，**唯一**路径是使用者确认。具体：

- **谁确认**：账号属主（一期只有属主一个授权主体）。
- **确认什么**：确认的是**这一条候选的内容**，不是「以后这类都由你决定」——逐条确认。
- **确认后发生什么**：条目进稳定层，此后可作为「现在该信什么」的依据；候选标记消失。
- **确认前不能做什么**：不得作为事实引用，不得被写进应急上下文等只取稳定层的通道。

**纠正与删除即时生效**：使用者说「这条不对/删掉」，立即反映到稳定层与后续输出，而不是「下次整理时处理」。

## 6. 冲突并列的处理

当事人自述与监护者观察冲突时：

- **并列保留两条**，不做覆盖、不做合并、不挑一条当结论。
- 输出中把冲突摆给使用者，说明两条各自的来源。
- **不得**用监护者观察去否定当事人的表达。

**为什么并列而不是择一**：择一意味着我们替使用者裁决了「谁说的算」，而这是档案所有权分歧，一期没有裁决机制；并列保留是这一分歧在一期的缓解手段。

## 7. 回执措辞

写入经待处理记录与 Worker 异步完成，因此回执只能承诺：

- **可以**写：「已提交，稍后生效」。
- **不得**写：「已保存」「已生效」「已经记录在案并生效」。

**为什么这条要紧**：回执说「已保存」会让使用者以为档案此刻已经变了，而此时写入可能尚未被消费、甚至可能失败；措辞承诺了系统不具备的能力。
