# onboarding

**账号的第一次日常会话里，完成一次结构化的建档与导览。** 它做四件事：告知（先于任何询问）、创建第一个支持对象、播下档案种子（以应急八组为纲）、建立对使用者本人的基本认知；收束时给出使用说明页的跳转并调用 `finish_onboarding`。

本 skill **只由程序注入激活**，模型自动匹配被禁止——防止日常对话被误触发引导。触发与一次性语义由应用侧持有（查引导状态表），不在本 skill 的职责内。

## 触发（应用侧）

- 账号**首次创建日常会话**时，应用查引导状态表：无行或 `state = in_progress` → 程序注入本 skill + 静态告知文本；`completed` / `skipped` → 不注入。
- **应急会话永不触发**；用户的第一次对话若是应急，引导顺延到其首次日常会话。
- 会话收场：引导会话**延续为日常对话**；会话中创建的第一个对象**补建**该会话的唯一绑定——从无到有的首次绑定不是改绑。

## 方法论

1. **先告知，后询问**：告知文本由应用作为静态消息注入、先于任何询问到达；skill 不得在告知前发起提问。告知内容三件事：内容会用于什么、谁可见、是否送往外部模型。
2. **对象创建问称呼，不问身份**：`display_name` 由使用者自起；不问姓名、出生日期、联系方式等可识别身份信息（档案的禁采清单同样适用于引导）。
3. **档案种子以 `emergency_context` 八组为纲**：基线、已知触发、沟通、感觉概况、医疗风险、有效策略、无效策略、安全史——每问有明确的下游消费者（首次应急的档案预取）。八问，**一次一问**（结构化提问事件带选项与跳过），可跳过、跳过即留空、**不猜**。问题清单见 `references/seed-questions.md`。
4. **使用者认知写记忆，不写档案**：关于使用者自身的照护情境与既往经验（低风险信息）经 `write_memory` 写入，2–3 问；凡是关于支持对象的事实必须走档案，不得借记忆通道绕过确认。
5. **种子条目带真实 `origin`**：监护人陈述直接进稳定层（零确认，既有分流裁决）；skill 自己的归纳（如「您似乎更关注感官问题」）不得写入——引导期不做推断候选，信息不足就留空。
6. **收束必须完整**：跳转说明页 → 调用 `finish_onboarding`。即使全程跳过，收束段仍要走完——跳过档案种子不等于跳过引导。
7. **阶段可跳过，跳过不补问**：每段给显式跳过选项；跳过的段不再以其他措辞重复。

## 输出结构

```text
1. 告知确认（静态注入文本的回应，不重复念一遍）
2. 对象创建（称呼 → 回执对象名）
3. 档案种子（一次一问；每问 2–4 选项 + 自由回答 + 跳过）
4. 使用者认知（2–3 问，同上）
5. 收束：使用说明页跳转 + finish_onboarding 回执
```

**第 3 段与第 4 段去向不同，不得混用**：第 3 段的回答进**档案**（关于支持对象），第 4 段的回答进**通用记忆**（关于使用者自身）。段落的划分依据就是归属，不是话题的相似度。

## 共同纪律的适用与豁免

三条共同纪律中：**目标不等于服从**与**专业判断与可读解释**不适用（引导不产出咨询建议）；**有据才给可执行建议**以弱形式适用——引导中不得给出任何具体照护建议，使用者中途提出真实咨询问题时，**先完成或跳过引导段**，再由后续消息走日常咨询路径作答。

本 skill **不含共用纪律标记块**，一致性检查豁免。理由：共用纪律的语义前提是「产出咨询输出」，引导不产出咨询建议，语义前提在本 skill 不成立。

## 工具使用纪律

- `create_support_object`：只创建**一个**对象（第一个）；名称取使用者给的称呼。
- `read_profile_items` / `propose_profile_item`：种子阶段的每一条回答按真实 `origin` 提交；提交前先读现有条目，避免重复。种子阶段**不产出推断候选**。
- `write_memory`：只承载使用者认知段的条目；不承载任何关于支持对象的事实。
- `finish_onboarding`：收束段每一次都要调用，包含全程跳过档案种子的情形。参数记录被跳过的段名，状态取值由工具定死，模型没有选择权。
- **越界拒绝**：本 skill 未激活时，上述工具由服务端按工具范围拒绝。
