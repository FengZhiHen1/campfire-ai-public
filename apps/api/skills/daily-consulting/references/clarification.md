# 澄清顺序与停问条件

本文件是 `daily-consulting` 的 `references` 之一，由该 skill 正文按需读取。它只写**顺序与停问判据**，不写问句本身——问句由当次情境决定。

## 1. 澄清顺序

1. **先定问题**：使用者给的是困扰的整体。第一件事是把「你最想弄清楚的是什么」定下来，再动工具。
2. **再一次只推进一件事**：一轮澄清只解决一个未知；多个未知同时追问会让使用者无法判断该回答哪个。
3. **先检索再问**：能从 `read_profile_summary`、`read_profile_items`、`read_memory` 或检索拿到的，不要拿去问使用者。
4. **简单问题允许直接回答并结束**：不是每个咨询都需要澄清轮次。若使用者的问题本身就是可回答的简单问题，直接回答并结束，不要为了「走流程」而制造追问。

## 2. 停问条件

追问必须**服务于改变下一步行动**。判断方式是一个反事实问句：

> 如果使用者给出了这个答案，我的下一步会不一样吗？

- **会不一样** → 这个追问值得问。
- **不会不一样**（无论答案是什么，我的下一步都一样）→ 不问。这是「为问而问」，它消耗使用者的耐心，不改变任何输出。
- **答案只影响措辞、不影响行动** → 同样不问；措辞可以在给出行动时附带说明。

追问的**额度**：一轮最多一到两项，且必须能一句话问完。其余未知一律显式标注为未确定，不要用追问补齐。

## 3. 「为什么问」自检

每次追问发出前，必须能在心里说出一句完整的「为什么问」：

```text
我之所以问〈这一项〉，是因为它决定〈下一步的哪一件事〉。
```

三条件全过才问：

1. 这一项**我拿不到**（档案、记忆与检索都没有覆盖）；
2. 这一项**会影响下一步行动**（不是只影响措辞）；
3. 这一项**一句话问得完**，且答案的形式我能预判。

任意一条不成立，就不问，改为在输出中说明「这一项尚未确定」。

## 4. 问不出口时的处置

- 说不出理由 → 不问，并在输出里如实标注该未知项。
- 使用者已经明确表示不想回答 → 不再以其他措辞重复追问，按未确定处理。

## 5. 与「沉淀」的分工

澄清是**为了当次回答**，不是为了把档案问全。识别到值得长期记住的信息时，提示可以整理进档案，由 `profile-curation` 承担写入——**澄清阶段不承担补全档案的职责**。

- **通用问句库**：问句由当次情境决定，本文件不给可套用的句子清单。
