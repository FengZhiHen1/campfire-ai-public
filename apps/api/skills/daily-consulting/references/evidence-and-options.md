# 依据、引用与可选方向的呈现纪律

本文件是 `daily-consulting` 的 `references` 之一，由该 skill 正文按需读取。它只写**怎么呈现**，不写资料清单本身——资料在库里，经工具检索。

## 1. 依据的呈现纪律

每条建议都要能回指到它的来源。呈现时带三件事：

1. **来源**：这条来自哪条资料或案例条目（写明条目标识，供使用者核对）。
2. **适用范围**：这份资料面向什么人群、什么情境。
3. **局限**：什么情况下这条不适用。这一项不能省——只写适用范围不写局限，等于把一条有边界的建议说成普适结论。

**无依据时的显式标注**：检索不到就明说「这是通用做法，没有找到对应资料」。不得用含糊措辞让通用做法看起来像有依据的建议。

**资料冲突时的标注**：两份资料结论不一致时，把冲突摆出来并说明各自的适用条件，不自行挑一个当成结论。

## 2. 案例的标注纪律

引用案例时标明**两个性质**：

- **真实案例还是虚构样例**；
- **有无授权**。

未经授权或不具备这两项标注的案例不引用为「案例」——它可以作为一般性说明，但不得以案例形态出现。

案例表述用**转述语**（「有位家长在访谈中提到她这样做过」），不用祈使句。

## 3. 事实与推测的分道

- 观察到的行为 → 陈述为**事实**。
- 「可能是为了回避」「大概是想引起注意」→ 必须标为**推测**，并说明推测依据。
- **不得**用推测描述当事人的内心状态或给行为定性。
- 使用者本人的直接陈述优先于我们的推断；两者冲突时并列保留，不用推断否定陈述。

## 4. 可选方向的呈现模板

当使用者在几种做法之间选择时，每个方向按同一模板呈现，缺项即视为该项未说清。

```text
方向名称
适用条件：什么情况下这个方向成立（人群、情境、前提）
做法：具体做什么（可执行，不是抽象标签）
代价：选了它要付出什么（时间、配合度、可能的副作用、需要的人手或资源）
不适用：什么情况下不要选它
依据：来自哪条资料或案例；无依据时显式标注
```

**为什么必须写「代价」**：只列好处会让使用者以为某个方向没有成本。代价缺位的选项不是选项，是宣传。

**为什么方向之间要可比**：每个方向按同一组字段写，使用者才能在同样的维度上比较；字段不一致时，使用者实际是在比较我们的措辞而不是做法本身。

## 5. 输出结构中的落位

对应 `SKILL.md` 的输出结构：

```text
1. 回应（先确认我听懂了什么）
2. 建议与依据（每条建议对应的资料或案例条目；无依据时显式标注）
3. 适用范围与局限（什么情况下这个建议不适用）
4. 下一步或可沉淀的事（需要澄清什么、是否要整理进档案）
```

第 1 节「回应」是确认理解，不是复述使用者的原话——复述原话会让使用者以为我们在走流程。
